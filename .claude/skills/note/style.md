# riverlog 지식 노트 스타일

기준 예시: `content/knowledge/AI-Data/loop-engineering.md`, `AI-Data/ai-frontend-design-prompting.md`, `AI-Data/claude-skill-building-guide.md`. 애매하면 이 세 편을 열어 보고 맞춘다.

## frontmatter

```yaml
---
title: "루프 엔지니어링"            # 한국어 제목. 고유명사·용어는 원어 유지 가능
concept: "Loop Engineering"        # 지도에 뜨는 짧은 개념어 (1~3단어, 보통 영어)
summary: "한두 문장. 무엇을 다루고 핵심 결론이 뭔지. 목록·카드에 그대로 보인다."
tags: ["ai", "llm", "agent"]       # 3~6개, 소문자 kebab-case
source: other                      # til | notion | mixed | other — 외부 글·자료 정리는 other
date: "2026-10-12"                 # 오늘 날짜
sources: ["https://..."]           # 선택. 원문 URL (http/https만 표시됨)
publish: false                     # --draft일 때만
---
```

### 태그

태그가 2개 이상 겹치는 노트끼리 지도에서 연결된다. **새 태그를 만들기 전에 기존 태그를 먼저 쓴다.**

```bash
grep -rhoE '^tags: .*' content/knowledge | tr -d '[]"' | sed 's/tags: //' | tr ',' '\n' | sed 's/^ //' | sort | uniq -c | sort -rn | head -60
```

분야 대표 태그(frontend, backend, ai, career, algorithm, database …) 1개 + 구체 태그 2~5개가 보통이다.

## 문체

- 노트 본문은 **평서체 "~다"**. (분야 인덱스 노트 머리말만 "~습니다")
- 출처 인용 블록만 "~노트입니다."로 끝낸다.
- 한 문장에 한 주장. 짧게 끊는다. 핵심 문장은 **굵게**.
- 원문 표현을 옮기지 말고 내 말로 다시 쓴다. 영어 원문의 핵심 용어는 `한국어(English)`로 한 번 병기.
- 원문 주장과 내 판단을 섞지 않는다. 덧붙이는 의견은 `정리` 섹션에서 분명히 내 말로 쓴다.

## 노트 모양: 주제순 vs 시간순

| 재료 모양 | 판정 | 처리 |
| --- | --- | --- |
| 개념 하나를 정의·설명 | ✅ | 그대로 노트 |
| 한 주제 아래 팁·항목 모음 (예: Claude Code 활용 팁) | ✅ | 주제별 소제목으로 묶는다 |
| 트러블슈팅 일지 (상황 → 시도 → 결과) | ⚠️ | `증상 · 원인 · 해결` 표나 "~할 때 ~가 안 되는 이유"로 일반화 |
| 날짜·회차·주차별 TIL, 프로젝트 pjt별 기록 | ❌ | 개념만 뽑아 기존 노트에 보강 |
| 회고, 소감, 「오늘 ~했다」 | ❌ | 지식 창고에 넣지 않는다 (블로그 후보) |

제목과 소제목에 날짜·`n일차`·`pjt0n`·`회고`가 들어가면 로그 모양이다. `check-note.mjs`가 경고한다.

## 본문 구성

```markdown
> 글쓴이의 「[원제](URL)」(YYYY.MM)를 요약·재구성한 노트입니다. [시점 경고 필요 시]

## <개념>이란          ← 한 문단 정의 + 왜 중요한지

## 구성 요소 / 핵심 원칙  ← 항목이 3개 이상이면 표 (| 항목 | 역할 | 예시 |)

### 1. 소제목         ← 팁·단계형 자료는 번호 붙인 h3

## 예시 / 흐름         ← 절차·구조는 ```text 블록의 트리 다이어그램

## 한계와 위험 (있으면)

## 정리               ← 3~5개 불릿, 마지막에 한 줄 결론

관련 노트: [[slug|제목]], [[slug|제목]]
```

- h1(`#`)은 쓰지 않는다. 제목은 frontmatter의 title이 맡는다.
- 분량은 대략 50~190줄. 원문이 길어도 줄이고, 짧은 팁 모음이면 50줄 안팎이면 충분하다.

## 분량과 해체

노트는 **나중에 찾아 읽는 사전 항목**이다. 읽는 사람이 한 번에 소화할 분량을 넘기거나, 다른 항목에 이미 있는 말을 되풀이하면 사전으로서 가치가 떨어진다. 그래서 길고 장황한 노트와 기록성 노트는 해체해서 간결한 주제 노트로 다시 묶어도 된다.

| 신호 | 판단 | 처리 |
| --- | --- | --- |
| 190줄을 훌쩍 넘고, 소제목이 강의·책의 장 순서를 그대로 따른다 | 장황 | 개념 단위로 소제목을 다시 묶고, 예제는 하나만 남긴다. 그래도 길면 개념별로 쪼갠다 |
| 같은 알고리즘·명령의 문제 풀이, 실습 코드가 3개 이상 나열 | 풀이 로그 | 패턴을 보여 주는 1~2개만 남기고 삭제. "문제 N번 풀이" 자체는 지식이 아니다 |
| 같은 비교표·정의·"A와 B의 차이"가 다른 노트에도 있다 | 중복 | 가장 포괄적인 노트 한 곳에만 두고, 나머지는 한 줄 요약 + `[[링크]]` |
| 제목에 연도·행사명이 있다 (「2021 ~」, 「~ 컨퍼런스에서 들은 이야기」) | 기록성 | 시간이 지나도 남는 원칙·개념만 뽑아 관련 노트에 보강하고 원 노트는 지운다 |
| 「요금제」, 「최신 버전」처럼 시점이 중요한 사실만 모아 둔 섹션 | 시한부 | 외부 링크 한 줄로 대체하거나 "글 작성 시점 기준"을 붙여 2~3줄로 줄인다 |
| 2KB가 안 되는데 상위 주제 노트가 따로 있다 | 조각 | 상위 노트의 섹션으로 흡수. 독립된 개념이면 그대로 둔다 |

해체 뒤 남는 분량의 기준은 "소제목 5~8개, 표 2~3개, 코드 블록은 핵심 1~2개"다. 원 노트가 길었다는 사실은 남길 이유가 아니다.

병합·삭제의 구체적 절차(링크 치환, 인덱스 갱신, 커밋 메시지)는 SKILL.md 7번에 있다.
- 코드·명령어는 언어 표시를 단 코드 블록으로.
- 이미지가 필요하면 `content/attachments/`에 넣고 `![[파일.png]]`.

## 링크

- 지식 노트끼리: `[[slug|보일 제목]]` (slug = 확장자 뺀 파일 이름)
- 인덱스 노트의 하위 목록: `- [제목](AI-Data/slug.md): 한 줄 설명` — content/knowledge 기준 상대 경로
- 책·블로그: `[[books/파일명]]`, `[[blog/파일명]]`
- 외부: 일반 마크다운 링크
