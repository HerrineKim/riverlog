## 사전체: 늘 지금 기준으로 쓴다

지식 창고는 **언제 열어도 지금(오늘 날짜) 기준으로 맞는 백과사전**이다. 원문을 읽은 기록이 아니다.

| 하지 않는다 | 대신 이렇게 쓴다 |
| --- | --- |
| 「테오는 ~라고 본다」, 「글쓴이는 ~를 권한다」, 「원문은 ~」 | 주어는 개념이다. 「~는 ~다」, 「~할 때는 ~한다」 |
| 「현재(2021)는 ~」, 「요즘 뜨는 ~」, 「최근 ~」 | 오늘 기준 사실로 쓴다. 꼭 필요하면 「2026년 기준」처럼 연도를 박는다 |
| 「글 작성 시점 기준」, 「바뀌었을 수 있습니다」 | 바뀌었는지 **직접 확인**해서 지금 기준으로 고쳐 쓴다. 확인할 수 없는 시한부 사실은 뺀다 |
| 원문이 추천한 옛 도구·버전을 그대로 옮김 (Enzyme, Karma, PhantomJS, IE 우회법 등) | 지금 표준을 본문에 쓰고, 옛것은 「과거에는 ~를 썼다」 한 줄이나 `## 역사` 섹션으로 내린다 |
| 글쓴이의 경험담, 회사 소개, 채용 광고, 강의 홍보 | 뺀다. 경험에서 나온 원칙만 일반화해서 남긴다 |
| 「~라는 의견도 있다」를 늘어놓기 | 합의된 원칙은 단정한다. 논쟁적인 것만 `| 관점 | 근거 |` 표로 나란히 둔다 |

- 원문이 오래됐으면 원문보다 **최신 공식 문서**가 우선이다. 원문은 뼈대와 관점을 빌려 오는 재료다. 원문 시점 이후 바뀐 사실(API 이름, 기본값, 권장 도구, 브라우저 지원)은 웹 검색이나 공식 문서로 확인해 반영한다.
- 원문의 시대가 내용의 일부일 때(기술의 역사, 변천사)만 연도를 쓴다. 그때도 「언제 무엇이 바뀌었나」를 사실로 쓰고, 「누가 그렇게 봤나」는 쓰지 않는다.
- `## 한계` 섹션에 「원문은 오래된 글이다」 같은 출처 비평을 쓰지 않는다. 한계는 **개념 자체의 한계**만 쓴다.
- 출처는 인용 블록 한 줄과 frontmatter `sources`에만 둔다. 본문 어디에도 원저자 이름이 주어로 나오지 않는다.

## 문체

- 노트 본문, 분야 인덱스 노트 머리말, 출처 인용 블록까지 **모두 평서체 "~다"**로 쓴다. 존댓말(~습니다·~세요·~해요)은 쓰지 않는다. 예문·UI 문구처럼 인용한 텍스트만 예외다.
- 한 문장에 한 주장. 짧게 끊는다. 핵심 문장은 **굵게**.
- 원문 표현을 옮기지 말고 내 말로 다시 쓴다. 영어 원문의 핵심 용어는 `한국어(English)`로 한 번 병기.
- 사전 항목은 의견이 아니라 설명이다. 덧붙일 판단이 있으면 `정리`에서 원칙의 형태로 쓴다.

## 노트 모양: 주제순 vs 시간순

| 재료 모양 | 판정 | 처리 |
| --- | --- | --- |
| 개념 하나를 정의·설명 | ✅ | 그대로 노트 |
| 한 주제 아래 팁·항목 모음 (예: Claude Code 활용 팁) | ✅ | 주제별 소제목으로 묶는다 |
| 트러블슈팅 일지 (상황 → 시도 → 결과) | ⚠️ | `증상 · 원인 · 해결` 표나 "~할 때 ~가 안 되는 이유"로 일반화 |
| 날짜·회차·주차별 TIL, 프로젝트 pjt별 기록 | ❌ | 개념만 뽑아 기존 노트에 보강 |
| 회고, 소감, 「오늘 ~했다」 | ❌ | 지식 창고에 넣지 않는다 (블로그 후보) |

제목과 소제목에 날짜·`n일차`·`pjt0n`·`회고`가 들어가면 로그 모양이다. `check-note.mjs`가 경고한다.

## 본문 구성

```markdown
> 글쓴이의 「[원제](URL)」(YYYY.MM)를 요약·재구성한 노트다. [시점 경고 필요 시]

## <개념>이란          ← 한 문단 정의 + 왜 중요한지

## 구성 요소 / 핵심 원칙  ← 항목이 3개 이상이면 표 (| 항목 | 역할 | 예시 |)

### 1. 소제목         ← 팁·단계형 자료는 번호 붙인 h3

## 예시 / 흐름         ← 절차·구조는 ```text 블록의 트리 다이어그램

## 한계와 위험 (있으면)

## 정리               ← 3~5개 불릿, 마지막에 한 줄 결론

관련 노트: [[slug|제목]], [[slug|제목]]
```

- h1(`#`)은 쓰지 않는다. 제목은 frontmatter의 title이 맡는다.
- 분량 상한은 없다. 개념을 설명하는 데 필요한 만큼 쓴다. 다만 원문 순서를 그대로 따른 장황함과 다른 노트와의 중복은 줄인다.

## 분량과 해체

노트는 **나중에 찾아 읽는 사전 항목**이다. 읽는 사람이 한 번에 소화할 분량을 넘기거나, 다른 항목에 이미 있는 말을 되풀이하면 사전으로서 가치가 떨어진다. 그래서 길고 장황한 노트와 기록성 노트는 해체해서 간결한 주제 노트로 다시 묶어도 된다.

| 신호 | 판단 | 처리 |
| --- | --- | --- |
| 소제목이 강의·책의 장 순서를 그대로 따른다 | 장황 | 개념 단위로 소제목을 다시 묶고, 예제는 하나만 남긴다. 서로 다른 개념이 섞여 있으면 개념별로 쪼갠다 |
| 같은 알고리즘·명령의 문제 풀이, 실습 코드가 3개 이상 나열 | 풀이 로그 | 패턴을 보여 주는 1~2개만 남기고 삭제. "문제 N번 풀이" 자체는 지식이 아니다 |
| 같은 비교표·정의·"A와 B의 차이"가 다른 노트에도 있다 | 중복 | 가장 포괄적인 노트 한 곳에만 두고, 나머지는 한 줄 요약 + `[[링크]]` |
| 제목에 연도·행사명이 있다 (「2021 ~」, 「~ 컨퍼런스에서 들은 이야기」) | 기록성 | 시간이 지나도 남는 원칙·개념만 뽑아 관련 노트에 보강하고 원 노트는 지운다 |
| 「요금제」, 「최신 버전」처럼 시점이 중요한 사실만 모아 둔 섹션 | 시한부 | 오늘 기준으로 확인해 고쳐 쓰거나, 확인할 수 없으면 공식 링크 한 줄로 대체한다 |
| 「~가 본 현재」, 「(2021)」, 「글쓴이는」, 「글 작성 시점 기준」 같은 화자·시점 서술 | 기록체 | 「사전체」 규칙대로 개념을 주어로, 오늘 기준 사실로 다시 쓴다 |
| 2KB가 안 되는데 상위 주제 노트가 따로 있다 | 조각 | 상위 노트의 섹션으로 흡수. 독립된 개념이면 그대로 둔다 |

길이 자체는 해체 사유가 아니다. 기준은 장황함, 중복, 기록성이다.

병합·삭제의 구체적 절차(링크 치환, 인덱스 갱신, 커밋 메시지)는 SKILL.md 7번에 있다.
- 코드·명령어는 언어 표시를 단 코드 블록으로.
- 이미지가 필요하면 `content/attachments/`에 넣고 `![[파일.png]]`.

## 링크

- 지식 노트끼리: `[[slug|보일 제목]]` (slug = 확장자 뺀 파일 이름)
- 인덱스 노트의 하위 목록: `- [제목](AI-Data/slug.md): 한 줄 설명` — content/knowledge 기준 상대 경로
- 책·블로그: `[[books/파일명]]`, `[[blog/파일명]]`
- 외부: 일반 마크다운 링크
