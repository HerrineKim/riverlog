입사하고 두 달 동안 현장과 본사를 인터뷰해서 개선할 업무 28건을 찾았습니다. 그중 효과가 가장 큰 것부터 **"먼저 적용하고 나중에 다듬기"** 원칙으로 1~3개월 안에 현장에 내보냈어요. 시판 솔루션도 비교해 봤지만, 전산화만 될 뿐 자동화가 아니었고, 솔루션끼리 데이터가 끊기고, 회사 양식과 맞지 않았습니다. 그래서 자체 개발로 결정했습니다.

팀은 3~4명이었고, 개발에는 Claude Code 같은 AI 코딩 도구를 적극적으로 썼습니다.

## AXWORKS 포털 · 공통 조직 데이터(SSOT)

> 흩어진 사내 업무 앱 10여 개를 하나의 로그인(SSO)과 하나의 조직 데이터 위에 올린 사내 플랫폼

앱이 늘어날수록 사용자·부서·권한 데이터가 앱마다 따로 생기고 어긋나기 시작했습니다. 그래서 인증과 조직 정보를 한 곳으로 모으는 작업을 맡았습니다.

- **공통 조직 데이터**: ERP와 그룹웨어에서 조직·인사 데이터 9종을 매일 자정 자동으로 가져와 공통 스키마에 합칩니다. 모든 앱은 이 테이블만 읽습니다.
  - 9종을 다 받은 뒤 **한 트랜잭션으로 통째로 교체**합니다. 중간에 실패하면 직전 상태가 그대로 남아요.
  - 서버가 꺼져 있다 켜지면 밀린 회차를 몰아서 돌리지 않고 한 번만 실행합니다. 전체·ERP만·그룹웨어만 수동으로 실행할 수 있고 실행 이력이 남습니다.
  - ERP와 그룹웨어의 재직 여부가 서로 다르면 "확인 필요"로 따로 표시합니다.
- **포털과 SSO**: 권한에 따라 서비스 카드에 사용 가능 / 권한 없음 / 보기 권한 배지가 붙고, 포털에서 발급한 티켓으로 각 앱에 바로 로그인합니다. 권한 신청, 오류 제보, 관리자 콘솔(서비스·권한·동기화 관리, 이용 통계)도 만들었습니다.
- **데이터 구조**: Supabase 하나에 업무 도메인별 PostgreSQL 스키마 15개를 나누고, 행 단위 보안 정책(RLS)으로 앱별 접근 범위를 제한했습니다.
- **배포**: GitHub Actions로 앱별 CI/CD를 구성했습니다.

공개 후 90일 동안 순 방문자 932명, 서비스 클릭 3,484회를 기록했고, 방문의 90%가 업무시간에 몰렸습니다. 사내 도구가 실제 업무 흐름 안에서 쓰이고 있다는 뜻으로 읽었어요.

## 콘크리트 품질 관리 시스템

> 시험 보드판 사진과 레미콘 송장 사진을 올리면 AI가 읽어서 품질 서류와 대시보드를 자동으로 만듭니다.

2024년 7월부터 콘크리트 시험 결과를 건설품질관리 사이트(CSI)에 올리는 것이 의무가 됐습니다. 현장에서는 타설할 때마다 사진 촬영, 보고서 작성, CSI 업로드를 손으로 반복했어요. 공시체 시험은 한 번 타설에 1·7·28일 세 차례씩 이어집니다. 인터뷰에서 "야근하는 직원 대부분이 이런 서류를 한다"는 말까지 들었습니다.

- **사진 → 데이터**: 모바일로 시험 사진을 올리면 **Roboflow** 객체 탐지 모델이 보드판 영역을 찾고, **Gemini**가 손글씨 수치(슬럼프, 공기량, 염화물, 온도, 단위수량, 압축강도)를 읽어 저장합니다. 사용자는 판정 기준과 비교해 보고 다시 찍거나 고칠 수 있습니다.
  - 인식률을 올리려고 모델만 바꾸지 않고 **보드판 양식 자체를 표준화**했습니다.
- **송장 자동 매칭**: 송장의 날짜·규격·업체 세 조건이 타설 기록과 맞으면 자동으로 연결합니다. 후보가 2건 이상이면 사람이 고르도록 했고, 송장은 첫차와 막차만 등록하게 설계해 입력량을 줄였습니다. 한 현장 기준 432세트 중 **408건(94%)이 자동 매칭**됐습니다.
- **서류 자동 생성**: 하나의 타설 데이터에서 품질시험대장 등 **13종 엑셀 보고서**를 템플릿 엔진으로 만들어 냅니다. 현장마다 다른 양식은 현장별 템플릿으로 관리합니다.
- **품질 도메인 규칙의 코드화**: 동절기·간절기 압축강도 보정, 염화물 계산, 규격별 배합 정보를 반영했고, 기상청 관측 데이터도 연동했습니다.
- **CSI 자동 업로드**: 현장 CSI 계정을 연동해 결과를 자동으로 올립니다.

![[portfolio/namkwang/nk-concrete-dashboard.png|타설 대시보드 — 한 달간 타설 45회, 약 12,700㎥, 물성시험 121건, 공시체시험 171건]]

파일럿(2/27)부터 정식 오픈(3/19)까지 약 3주가 걸렸습니다. 현장 미팅과 단톡방 피드백을 반영하며 그룹 건설사의 여러 현장으로 넓혔어요.

## 경력 산정 자동화 시스템

> 이력서와 건설기술인협회 경력증명서 PDF를 AI가 읽고, 회사 기준에 따라 인정 경력 연차를 자동으로 계산합니다.

경력직을 채용할 때 인사 담당자는 지원자의 이전 회사 규모(도급순위 100위 안인지), 직무 연관성, 고용형태를 하나하나 검색해서 추정했습니다. 한 명에 10~30분이 걸렸고, 기준도 관행적으로 해석되어 사람마다 달랐어요.

- **추출과 병합은 AI, 계산은 코드**: Gemini Vision으로 두 문서에서 경력을 뽑아 합칩니다. 합치다 생긴 충돌은 "미해소 항목"으로 따로 보여 주고 원본 문서를 기준으로 고칩니다.
  - 결과가 매번 같아야 하는 산정 규칙(도급순위 100위 안 100%, 그 밖 64%, 비정규직 0%, 기간 중복 차감, 학력 차감, 프로젝트 기준/재직기간 기준 두 모드)은 LLM에 맡기지 않고 **함수 엔진으로 코드화**했습니다.
- **일괄 분석**: `이름_이력서.pdf`, `이름_경력증명서.pdf` 파일명으로 자동으로 짝을 짓고, **asyncio**로 동시에 분석합니다. 50명도 약 3분이면 끝납니다.
- **도급순위 관리**: 시공능력평가 명단(약 2,800개 회사)을 엑셀로 올리면 바로 반영되고, 사명 변경 때문에 생기는 회사명 불일치는 별칭 매핑으로 해결했습니다.

![[portfolio/namkwang/nk-career-batch-upload.png|일괄 분석 화면 — 업로드 → 자동 매칭 확인 → 동시 분석의 3단계]]

그룹 3사 인사총무팀이 실제 채용에 썼고, 분석 이력은 200건을 넘었습니다. 기준을 코드로 옮기다 보니 모호했던 기준이 드러나서, 인사팀과 기준을 다시 정의하는 논의로 이어졌어요.

## 기술인력 배치 시스템

> 입찰 때 발주처·공종별로 배치할 수 있는 기술자가 누구인지 자동으로 판정하고 순위를 매깁니다.

조달청, 지자체, 한국도로공사, 국가철도공단, LH 등 발주처마다 현장대리인·시공책임자 요건이 달라서 담당자도 헷갈리는 경우가 많았습니다. 기술자 경력증명서는 엑셀에 손으로 옮겨 관리했고, 인력이 자주 들고 나서 정리 부담이 컸습니다.

- **구조화 OCR**: Gemini의 구조화 출력으로 경력증명서에서 기술경력, 건설사업관리경력, 자격, 교육, 학력을 뽑아 DB에 저장합니다.
  - 수백 페이지짜리 문서에서는 응답이 중간에 잘렸습니다. **페이지를 재귀적으로 나눠 병렬로 다시 추출**하고, 잘린 JSON은 **스택 기반 파서로 복구**하는 방식으로 해결했습니다.
- **규정을 데이터로**: 발주처·공종별 요건을 규정 테이블로 관리하고, 후보자마다 적격 여부를 평가해 순위를 매깁니다.
- **데이터 품질 도구**: 동명이인 병합 후보, 퇴사자 정리, ERP 인사정보와 대조해 경력증명서 미등록자를 표시합니다.

## 회의록 관리 시스템

> 회의 녹음을 올리면 회의록 초안을 만들고, 확정하면 참석자에게 업무를 배정하고 추적합니다.

- **오디오 파이프라인**: 긴 녹음은 오디오를 잘라 → 클립별로 병렬 추출하고 → 병합하는 Gemini 파이프라인으로 구조화 요약을 만듭니다.
- **맥락 주입**: ERP 인사정보(부서·직위), 지난 회차의 미완료 업무, 회의 시리즈별 도메인 지식, 첨부 자료를 프롬프트에 자동으로 넣어 요약 정확도를 높였습니다. 첨부 자료가 너무 크면 용량 가드가 걸러 냅니다.
- **업무 추적**: 회의록을 확정하면 참석자별 할 일이 만들어지고, 다음 회차에 이어서 확인합니다.

## 돌아보며

- **LLM과 코드의 경계를 나누는 것**이 가장 중요했습니다. 문서를 읽고 분류하는 일은 LLM에 맡기고, 결과가 매번 같아야 하는 계산과 판정은 코드로 옮겼어요. 덕분에 결과를 설명할 수 있었고, 사람이 검수할 수 있었습니다.
- 현장 사용자는 기다려 주지 않습니다. 3주 만에 파일럿을 내보내고 단톡방 피드백으로 고치는 방식이, 완벽한 기획서를 쓰는 것보다 빨리 신뢰를 얻었습니다.
