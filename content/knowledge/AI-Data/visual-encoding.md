## 왜 숫자 대신 그림인가

요약 통계만 보면 같은 데이터처럼 보여도 그려 보면 전혀 다른 경우가 있다. 대표 예가 **앤스컴 콰르텟(Anscombe's quartet)** 이다. 네 데이터셋의 평균, 분산, 상관계수, 회귀선이 거의 같은데, 산점도로 그리면 하나는 직선 관계, 하나는 곡선, 하나는 이상치 하나가 회귀선을 끌고 가는 모양, 하나는 x값이 한 점만 빼고 모두 같은 모양이다.

시각화의 쓰임은 크게 두 가지다.

| 쓰임 | 하는 일 | 예 |
| --- | --- | --- |
| 탐색 | 숫자 표로는 안 보이던 패턴과 이상치를 찾는다 | EDA 단계의 산점도 행렬, 분포 확인 |
| 전달 | 분석 결과를 근거로 상대를 설득한다 | 보고서의 핵심 차트 한 장 |

분석의 어느 단계에서든 쓰이고, 숫자를 대체하기보다 숫자와 함께 둘 때 전달력이 가장 높다. 정답 차트는 없다. 데이터 특성과 목적을 보고 여러 방식으로 그려 본 뒤 사람이 고른다. 분석 흐름 안에서 시각화가 놓이는 자리는 [[python-data-analysis|파이썬 데이터 분석 프로세스]]에 있다.

남이 만든 시각화를 읽을 때도 같은 틀로 본다. 입력 데이터가 무엇이고 어떻게 가공됐나, 왜 이 형태를 골랐나, 어떤 시각 요소와 상호작용을 썼나.

## 그래픽 문법: 차트를 일곱 부품으로 나누기

**그래픽 문법(Grammar of Graphics)** 은 릴런드 윌킨슨(Leland Wilkinson)이 정리한 틀로, 모든 차트를 같은 부품의 조합으로 본다. 막대 차트와 산점도를 별개의 "차트 종류"로 외우는 대신, 어떤 부품을 바꿨는지로 설명할 수 있다. R의 ggplot2, 파이썬의 plotnine·Altair(Vega-Lite)가 이 문법을 API로 그대로 옮겼다.

| 요소 | 묻는 것 | 예 |
| --- | --- | --- |
| 데이터(data) | 어떤 열을 그리나 | 월, 지역, 매출 |
| 시각 속성 매핑(aesthetics) | 어느 열을 어느 채널에 대응시키나 | 월 → x 위치, 매출 → y 위치, 지역 → 색 |
| 스케일(scale) | 값의 범위를 채널의 범위로 어떻게 바꾸나 | y축 0~120, 지역 3개 → 색 3개 |
| 기하 객체(geometry) | 표시를 어떤 모양으로 하나 | 점, 선, 막대, 면 |
| 통계 변환(statistics) | 원값을 그리나, 계산한 값을 그리나 | 원값, 평균, 구간별 개수, 회귀선 |
| 면분할(facets) | 데이터를 쪼개 여러 패널로 나누나 | 지역별 작은 차트 3개 |
| 좌표계(coordinates) | 위치를 어떤 공간에 놓나 | 직교 좌표, 극좌표, 지도 투영 |

같은 데이터에서 기하 객체만 점에서 선으로 바꾸면 산점도가 선 그래프가 되고, 좌표계만 극좌표로 바꾸면 누적 막대가 파이 차트가 된다.

```python
# Altair: 문법 요소가 코드에 그대로 드러난다
import altair as alt

alt.Chart(df).mark_line().encode(   # geometry: 선
    x="month:T",                     # 매핑 + 데이터 유형(T=시간)
    y="sales:Q",                     # Q=정량
    color="region:N",                # N=명목 범주
).facet(column="channel:N")          # 면분할
```

## 데이터 유형이 채널을 정한다

시각화 매핑은 **데이터 공간에서 시각 공간으로의 변환**이다. 데이터 쪽에서 먼저 볼 것은 각 열의 유형이다.

| 유형 | 예 | 성질 |
| --- | --- | --- |
| 정량 · 연속 | 기온 23.4, 매출 | 어떤 실수든 가능 |
| 정량 · 이산 | 방문 횟수 1, 2, 3 | 단위가 끊겨 있다 |
| 범주 · 명목 | 개, 고양이 / 부서명 | 순서가 없다 |
| 범주 · 순서 | 좋음, 보통, 나쁨 / 사원·과장·부장 | 순서는 있지만 간격은 정해지지 않았다 |
| 날짜 · 시간 | 2024-01-01, 오전 8시 | 연속으로도 이산으로도 다룬다 |
| 텍스트 | 자유 서술 | 필요하면 범주로 바꿔 처리한다 |

시각 쪽 채널에는 위치, 길이, 각도, 면적, 밝기, 색조, 채도, 모양, 기울기, 질감, 움직임이 있다. 매핑을 고를 때 기준은 두 가지다.

- **표현성(expressiveness)**: 데이터에 있는 정보를 담되, 없는 정보를 암시하지 않는다. 순서 없는 부서명을 밝기 단계로 칠하면 부서 사이에 서열이 있는 것처럼 읽힌다.
- **효과성(effectiveness)**: 중요한 열일수록 눈에 잘 띄고 정확히 읽히는 채널에 둔다.

채널마다 읽는 정확도가 다르다. 클리블랜드와 맥길(Cleveland & McGill, 1984)의 실험 이후 널리 받아들여진 순서는 대략 이렇다.

| 정량값을 읽는 정확도 | 채널 |
| --- | --- |
| 높음 | 같은 축 위의 위치 |
| ↓ | 축이 다른 위치, 길이 |
| ↓ | 각도, 기울기 |
| ↓ | 면적 |
| 낮음 | 부피, 색의 밝기·채도 |

그래서 핵심 비교는 위치나 길이로 하고, 색과 크기는 보조 변수에 쓴다. 범주를 구분할 때는 반대로 색조와 모양이 강하다.

면적 채널에는 함정이 있다. A가 100, B가 200일 때 원의 **지름**을 두 배로 하면 면적은 네 배가 되어 B가 실제보다 훨씬 커 보인다. 값은 면적에 비례시켜야 한다.

## 색 인코딩

색은 색조(hue), 채도(chroma), 밝기(luminance)로 나눠 생각한다.

| 스케일 | 쓰는 데이터 | 만드는 법 |
| --- | --- | --- |
| 순차(sequential) | 순서·연속값(인구 밀도) | 한 방향으로만 변하는 밝기 단계 |
| 범주(qualitative) | 순서 없는 범주(지역) | 서로 잘 구별되고 밝기가 비슷한 색조들 |
| 발산(diverging) | 기준점 양쪽으로 갈리는 값(전년 대비 증감) | 가운데 중립색, 양끝에 서로 다른 색조. 중립점을 0이나 평균 같은 의미 있는 값에 맞춘다 |

- RGB 값의 차이와 눈이 느끼는 차이는 다르다. CIELAB처럼 지각 거리에 맞춘 색 공간에서 만든 스케일(matplotlib의 `viridis`, `cividis` 등)은 같은 값 차이가 같은 색 차이로 보인다.
- **무지개 색 스케일은 피한다.** 밝기가 오르내려 순서가 직관적이지 않고, 색이 바뀌는 지점에 데이터에 없는 경계가 생긴다.
- 사람은 범례보다 강한 색에 먼저 눈이 간다. 범주 색들의 눈에 띄는 정도를 비슷하게 맞추고, 강조할 대상에만 강한 색을 쓴다.

밝기와 색조의 지각 차이는 [[interface-psychology|인터페이스 심리학]]에, 색각 이상을 고려한 대비 기준은 [[color-motion-accessibility|색과 움직임의 접근성]]에 더 자세히 있다.

## 좌표계와 축

**직교 좌표계**가 기본이다. 몇 가지 규칙이 있다.

- 축에는 단위를 적는다.
- 두 축의 단위가 같으면(예: 섭씨 대 섭씨) 격자 간격도 같게 둔다. 단위가 다르면 종횡비는 전하려는 메시지에 맞춰 조절한다. 선 그래프는 종횡비만 바꿔도 변화가 가파르게도 완만하게도 보인다.
- 값이 몇 자릿수에 걸쳐 퍼져 있거나 비율(배수)이 의미 있는 데이터는 **로그 축**을 쓴다. 로그 축에서는 같은 간격이 같은 배수를 뜻하므로, 로그 스케일이라는 사실과 눈금 값을 분명히 적는다.

곡선 축도 있다.

| 좌표계 | 맞는 데이터 |
| --- | --- |
| 극좌표 | 끝이 처음과 이어지는 순환 데이터(12개월, 풍향 360도) |
| 지도 투영(로빈슨, 빈켈 트리펠 등) | 위경도 데이터. 지구는 둥글어서 위경도를 그냥 직교 좌표에 펴면 고위도가 부풀려진다 |

## 사람은 어떻게 보나: 지각과 주의

### 첫눈: 요지와 앙상블

차트를 처음 보는 짧은 순간에 사람은 세부가 아니라 **요지(gist)** 를 잡는다. 전체 윤곽과, 점들의 평균 크기·퍼짐 같은 집합 수준의 특징(앙상블 코딩)이다. 차트를 흐리게 했을 때 보이는 모양이 대략 첫인상이다. 그래서 같은 데이터도 인코딩에 따라 "최댓값이 있는 달"이 먼저 보이기도, "평균이 높은 달"이 먼저 보이기도 한다.

### 사전 주의 속성과 게슈탈트

색조, 기울기, 길이, 크기, 밝기, 채움 같은 속성은 하나만 다르면 찾으려 애쓰지 않아도 튀어나온다(pop-out). 강조는 이 속성 하나로 한다. 두 가지를 섞어야 구별되는 대상(빨간 원들 사이의 빨간 네모와 파란 원 사이)은 하나씩 살펴야 찾는다.

묶음은 게슈탈트 원리를 따른다. 가까우면(근접), 비슷하면(유사), 같은 영역 안에 있으면(공통 영역), 선을 따라 늘어서 있으면(연속) 한 그룹으로 본다. 끊긴 모양도 닫힌 하나로 보고(폐쇄), 강조 대상과 배경을 나눠 본다(전경-배경). 레이아웃 쪽 설명은 [[web-layout-design|웹 레이아웃 디자인]]과 [[ui-density|UI 밀도]]에 있다.

### 주의는 좁고 기억은 짧다

시야 전체가 선명하다고 느끼지만 실제로 해상도 높게 보는 곳은 시선이 머무는 작은 중심부뿐이다.

| 주의 방식 | 무엇이 시선을 이끄나 | 언제 |
| --- | --- | --- |
| 하향식(top-down) | 보는 사람의 목적과 지식 ("B가 A보다 얼마나 큰가") | 찾을 것이 정해진 확인·비교 |
| 상향식(bottom-up) | 색·모양·크기 같은 차트의 특징 | 처음 보는 데이터를 탐색할 때. 인코딩이 결론을 유도한다 |

- **변화 맹시(change blindness)**: 장면이 바뀔 때 일부가 달라져도 잘 알아채지 못한다. 시간에 따라 바뀌는 애니메이션보다 나란히 놓은 정지 화면을 비교하기가 쉽다. 애니메이션을 쓰면 한 번에 담는 정보를 줄인다.
- **분리 가능성(separability)**: 여러 채널을 한 표시에 겹쳐 쓰면 각각을 떼어 읽기 어려운 조합이 있다. 너비와 높이는 한 덩어리(면적)로 읽히기 쉽고, 위치와 색은 따로 읽힌다.
- **중복 인코딩(redundant encoding)**: 중요한 범주는 색과 모양을 함께 바꿔 두 경로로 찾게 한다. 흑백 인쇄와 색각 이상에도 견딘다.
- **시각적 어수선함(clutter)**: 표시가 너무 많으면 묶거나(육각형 구간으로 집계하고 이상치만 남기기), 정렬해서 패턴이 드러나게 한다. 데이터를 전하지 않는 잉크를 줄이는 원칙은 [[chart-design-principles|그래프 디자인 원칙]]에 정리했다.

## 정리

- 시각화는 데이터 열을 시각 채널에 대응시키는 매핑이다. 그래픽 문법의 일곱 요소로 차트를 분해해 설명한다.
- 정량값의 정확한 비교는 위치와 길이로, 범주 구분은 색조와 모양으로 한다. 면적은 값에 비례시킨다.
- 순서 있는 값은 한 방향 밝기 스케일, 범주는 구별되는 색조, 기준점이 있으면 발산 스케일. 무지개는 피한다.
- 사람은 첫눈에 요지를 잡고, 튀는 속성 하나에 끌리며, 한 번에 적은 것만 기억한다.
