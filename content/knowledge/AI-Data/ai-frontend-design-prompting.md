> OpenAI Developers 블로그의 「Designing delightful frontends with GPT-5.4」(2026.03, Brian Fioca 외)와 SNS에서 돌던 「HOW TO VIBE CODE BEAUTIFUL UI」 팁 7가지를 함께 재구성한 노트다.

## 왜 AI가 만든 화면은 비슷비슷할까

프롬프트가 구체적이지 않으면 모델은 학습 데이터에서 **가장 자주 본 패턴**으로 되돌아간다. 그중엔 검증된 관례도 있지만, 단순히 많이 쓰였을 뿐인 습관도 섞여 있다. 그래서 결과물은 밋밋한 구조, 약한 시각적 위계, 의도 없는 카드 나열처럼 "동작은 하지만 어디서 본 듯한" 화면이 되기 쉽다.

바꿔 말하면 **AI는 모방은 잘하고 상상은 못 한다.** "모던하고 깔끔하게"는 AI가 추측할 여지만 남기고, 추측은 늘 같은 기본값으로 돌아간다. 좋은 디자인은 오래 검증된 패턴(절제)과 새로운 시도(발명) 사이의 균형이고, 그 균형은 사람이 방향을 먼저 정해 줘야 잡힌다.

## 모델 능력을 활용하기

| 능력 | 프론트엔드 작업에서의 의미 |
| --- | --- |
| 이미지 이해·생성 | 무드보드를 먼저 만들고 그중에서 시각 방향을 고르게 할 수 있다 |
| 기능적 완성도 | 긴 작업에서도 실제로 동작하는 앱·게임을 끝까지 만든다 |
| 도구 사용(브라우저 조작) | Playwright 같은 도구로 렌더링 결과를 직접 보고, 여러 뷰포트·흐름을 테스트하며 스스로 고친다 |

특히 **검증 도구를 쥐여 주는 것**이 효과가 크다. 화면을 직접 열어 보고, 레퍼런스 이미지와 비교하고, 상태·내비게이션 버그를 찾게 하면 완성도가 눈에 띄게 올라간다.

## 바로 써먹는 4가지

1. **추론 강도는 낮게 시작**: 단순한 웹사이트는 오래 생각할수록 오히려 과하게 만든다. 낮음~중간에서 시작하고 야심찬 디자인일 때만 올린다.
2. **디자인 시스템과 제약을 먼저**: 타이포그래피, 색, 레이아웃 규칙을 프롬프트 앞부분에 못 박는다. 바이브 코딩한 앱이 어색한 가장 흔한 이유는 페이지 간 일관성이 없다는 것이다.
3. **시각 레퍼런스 제공**: 스크린샷이나 무드보드가 레이아웃 리듬, 글자 크기 체계, 여백, 이미지 톤의 가드레일이 된다. 구체적인 방법은 아래 「시각 자료로 보여 주기」.
4. **서사(콘텐츠 전략) 정의**: 무엇을 어떤 순서로 말할지 정해 주면 섹션 구성이 자연스러워진다.

## 시각 자료로 보여 주기

보여 줄 수 있는 것은 글로 설명하지 않고 **이미지로 보여 준다.** 시각 맥락이 많을수록 AI가 추측할 부분이 줄어든다.

| 전달할 것 | 방법 | 지시문 |
| --- | --- | --- |
| 레이아웃 | [Excalidraw](https://excalidraw.com) 같은 도구로 박스·버튼·이미지 자리만 그린 와이어프레임을 내보내 붙인다 | "이 구조를 그대로 따라 해" |
| 스타일 | Dribbble, Mobbin, 마음에 든 사이트에서 내비게이션 바·가격 카드·히어로처럼 **원하는 부분만** 잘라 캡처한다 | "이 스타일을 따라 해" |
| 색 | 이미지 생성 도구로 무드보드를 만들어 넣는다. "따뜻하고 모던한 느낌"이라고 말하면 매번 비슷한 파란색이 나온다 | "색 팔레트는 이걸 참고해" |
| 수정 요청 | 현재 화면을 캡처해서 어디가 문제인지 짚는다 | "이 부분이 어색하다" |

여기에 두 가지를 더한다.

- **디자인 스킬과 안티패턴 규칙**: UI/UX Pro Max류 오픈소스 스킬은 UI 코드를 쓰기 전에 추론 단계를 거치게 하고, 업종에 맞는 디자인 시스템을 만들어 주며, 뻔한 AI식 그라데이션 같은 패턴을 금지한다. "다른 AI 앱처럼 보이지 마"를 강제하는 장치다.
- **폰트와 아이콘 바꾸기**: AI는 거의 항상 **Inter + Lucide** 조합을 기본으로 쓰고, 보는 순간 티가 난다. Google Fonts에서 개성 있는 서체를 고르고 아이콘은 Phosphor 같은 다른 라이브러리로 바꾼다. 작은 변화지만 템플릿 인상이 바로 사라진다.

## 프롬프트에 넣을 "하드 룰" 요약

랜딩 페이지를 기준으로 한 규칙 목록이다. 요지는 **"덜어내라"** 다.

- **첫 화면은 하나의 구성**: 대시보드가 아니라면 첫 뷰포트는 한 장의 그림처럼 읽혀야 한다.
- **브랜드가 주인공**: 내비게이션을 가렸을 때 다른 회사 사이트라고 해도 믿길 정도면 브랜딩이 약한 것이다.
- **히어로 예산**: 브랜드, 헤드라인 하나, 짧은 보조 문장 하나, CTA 묶음 하나, 대표 이미지 하나. 통계·일정·배지 같은 부가 정보는 첫 화면에서 뺀다.
- **카드는 기본값이 아니다**: 테두리·그림자·배경을 지워도 이해와 조작에 지장이 없다면 카드일 필요가 없다. 히어로에는 카드 금지.
- **섹션당 하나의 역할**: 섹션마다 목적 하나, 헤드라인 하나.
- **진짜 시각적 앵커**: 추상 그라데이션 말고 제품·장소·맥락을 보여 주는 이미지를 중심에 둔다.
- **잡동사니 줄이기**: 알약(pill) 묶음, 통계 띠, 아이콘 줄, 경쟁하는 텍스트 블록을 피한다.
- **의도 있는 모션**: 소음이 아니라 존재감과 위계를 만드는 움직임을 2~3개.
- **분명한 색 방향**: CSS 변수로 토큰을 정의하고, "흰 배경에 보라색" 같은 기본값 편향을 피한다.
- **기본 폰트 스택 지양**: 목적이 있는 서체를 고른다.
- 데스크톱·모바일 모두 확인한다.
- 단, **기존 디자인 시스템 안에서 작업할 때는 그 규칙을 우선**한다.

## 더 나은 결과를 위한 기법

### 원칙을 수치로 정하기

"H1은 하나, 섹션은 6개 이하, 서체는 2개까지, 강조색 1개, 첫 화면 CTA 1개"처럼 셀 수 있는 제약을 준다.

### 페이지를 이야기로 구성하기

마케팅 페이지라면 보통 이런 흐름이 된다.

1. **히어로**: 정체성과 약속
2. **보조 이미지**: 맥락·분위기
3. **상세**: 무엇을 제공하는지
4. **사회적 증거**: 신뢰
5. **마지막 CTA**: 행동 유도

### 디자인 토큰부터 세우기

배경·표면·본문·보조 텍스트·강조색 같은 색 토큰과, display·headline·body·caption 같은 타이포 역할을 먼저 정의하게 하면 화면 전체가 일관된다. React + Tailwind처럼 익숙한 스택이 반복 수정에 유리하다.

```css
:root {
  --bg: #0a0e13;
  --surface: #10161e;
  --text: #e4ebf2;
  --muted: #8a9aad;
  --accent: #5eead4;
}
```

### 떠 있는 요소의 안전 규칙

고정·플로팅 UI가 본문 텍스트나 버튼을 가리지 않도록, 화면 크기별 안전 영역에 두라는 지시를 함께 넣는다.

### 실제 콘텐츠로 시작하기

진짜 문구, 제품 맥락, 프로젝트 목표를 주는 것이 가장 쉬운 개선책이다. 자리표시 텍스트로 시작하면 구조와 메시지도 자리표시 수준에 머문다.

## 핵심 정리

| 하지 말 것 | 대신 할 것 |
| --- | --- |
| "랜딩 페이지 만들어 줘" | 와이어프레임 + "이 구조 그대로" |
| "깔끔하게" | 레퍼런스 스크린샷 + "이 스타일로" |
| "따뜻하고 모던한 색" | 무드보드 이미지 + "이 팔레트 참고" |
| 페이지마다 즉흥 스타일 | 색·서체·간격 토큰을 먼저 정의 |
| Inter + Lucide 기본값 | 고른 서체 + 다른 아이콘 세트 |
| 결과만 받아 보기 | 브라우저 도구로 직접 확인·수정하게 하기 |

- AI의 "평균적인 디자인"은 **지시가 비어 있을 때** 나온다. 문제는 AI가 아니라 한 줄 치고 잘되길 바라는 방식이다.
- **제약(디자인 시스템) + 레퍼런스(이미지) + 서사(콘텐츠 구조) + 검증 도구(브라우저 테스트)** 네 가지를 갖추면 결과물이 확실히 달라진다.
- 규칙의 대부분은 사람 디자이너에게도 통하는 이야기다. **하나의 화면에는 하나의 메시지**다.
