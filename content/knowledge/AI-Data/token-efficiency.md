> Gergely Orosz(The Pragmatic Engineer)의 「[The Pulse: 'Tokenmaxxing' as a weird new trend](https://blog.pragmaticengineer.com/the-pulse-tokenmaxxing-as-a-weird-new-trend/)」(2026.04)와 Korean FE Article이 소개한 「5가지 도구, 커스텀 훅, 강제 적용으로 Claude Code 토큰 사용량을 90% 이상 줄인 방법」(2026.05), 전종현의 인사이트 #121(2026.07)의 토큰 효율성 논의를 바탕으로, Claude Code 기능은 [공식 비용 관리 문서](https://code.claude.com/docs/en/costs)로 확인해 재구성한 노트다.

## 토큰 효율이란

**토큰 효율(token efficiency)** 은 같은 결과를 더 적은 토큰으로 얻는 정도다. 에이전트는 사람이 없을 때도 돌고, 루프 한 번마다 맥락 전체를 다시 보내므로 토큰이 사람의 예상보다 훨씬 빨리 쌓인다. 개인은 사용량 한도에 막혀 작업이 멈추고, 조직은 월 청구서가 예산을 넘는다.

토큰을 쓰는 것 자체가 나쁜 것은 아니다. 문제는 **결과로 이어지지 않는 토큰**이다. 이 노트는 그 낭비가 어디서 생기는지와 줄이는 방법, 그리고 무엇으로 재야 하는지를 다룬다.

## 안티패턴: 토큰맥싱

**토큰맥싱(tokenmaxxing)** 은 AI를 많이 쓰는 것처럼 보이려고 토큰을 일부러 태우는 행위다. 토큰 사용량을 생산성 지표로 공개하거나 평가에 넣으면 생긴다. 측정값이 목표가 되면 좋은 측정값이 아니게 된다는 굿하트의 법칙 그대로이고, 코드 줄 수 채우기의 AI 시대 판이다. 개념과 결과 지표로 바꾸는 원칙은 [[ai-slop|AI 슬롭]]의 「토큰맥싱」 절에 있다.

| 운영 방식 | 결과 |
| --- | --- |
| 사내 토큰 순위표(리더보드)를 공개 | 적게 쓰는 사람으로 보일까 봐 겁이 나서 토큰을 태운다 |
| 월 최소 사용 금액을 정하고 못 채우면 표시 | 사용량이 바닥 기준이 되어 의미 없는 프롬프트와 에이전트 실행이 늘어난다 |
| 순위표를 「사용량 대시보드」로 바꾸고 이상 사용에 차단기(circuit breaker)를 둠 | 폭주하는 에이전트를 잡고 인프라 버그까지 찾는다. 많이 쓰는 사람은 사람이 직접 살펴본다(Shopify) |

사용량은 **관찰할 가치가 있는 신호**다. 잘 쓰는 사람의 패턴을 배우거나 안 쓰는 사람을 돕는 데 쓴다. 다만 평가 지표가 되는 순간 부풀려진다. 토큰 사용량은 결과를 낸 비용이지 결과가 아니다.

## 토큰은 어디로 새나

에이전트 루프는 매 회차 지시·도구 정의·대화 기록 전체를 다시 보낸다([[coding-agent-loop|코딩 에이전트의 작동 원리]]). 그래서 한 번 맥락에 들어간 토큰은 이후 모든 회차에서 다시 비용이 된다.

| 새는 곳 | 모습 |
| --- | --- |
| **도구 출력** | 빌드 로그, 테스트 전체 출력, `git log`, 브라우저 스냅샷, MCP 응답이 걸러지지 않고 그대로 들어온다 |
| **파일 읽기** | 필요한 함수 하나를 보려고 수천 줄 파일을 통째로 읽고, 같은 파일을 여러 번 다시 읽는다 |
| **상시 맥락** | 긴 `CLAUDE.md`·규칙 파일, 켜 둔 MCP 서버의 도구 정의, 스킬 목록이 질문하기 전부터 자리를 차지한다 |
| **긴 세션** | 끝난 작업의 탐색 기록이 남은 채로 다음 작업을 이어 간다 |
| **모델 출력** | 장황한 설명, 요청하지 않은 요약, 불필요한 코드 재출력 |
| **과한 병렬** | 서브에이전트·병렬 에이전트는 각자 맥락을 새로 채우므로 사용량이 몇 배로 는다 |
| **캐시 깨짐** | 대화 중간에 도구 목록·모델·설정을 바꿔 앞부분이 달라지면 캐시 할인을 못 받는다 |

## 줄이는 방법

**핵심은 더 나은 기본값, 더 나은 라우팅, 더 나은 캐싱이다.** 사용을 막거나 비용 경고를 띄우는 방식으로는 사용량이 늘어나는 흐름을 이기지 못한다.

### 1. 출력을 거른다

도구 결과가 맥락에 들어가기 **전에** 줄인다.

- 명령에 필터를 붙인다: `npm test 2>&1 | tail -50`, `jq`로 필요한 필드만, 실패한 테스트만 출력하는 옵션. 이를 매번 부탁하지 않으려면 PreToolUse 훅으로 테스트 명령에 `| tail -n 100`을 자동으로 붙이거나, 로그에서 `ERROR` 줄만 돌려주게 한다.
- 셸 출력을 자동으로 압축하는 프록시를 둔다. 예: RTK(Rust Token Killer)는 자주 쓰는 명령의 출력을 요약해 돌려준다.
- 큰 출력을 샌드박스에서 실행하고 필요한 부분만 맥락에 넣는 도구를 쓴다. 예: context-mode는 원시 출력을 맥락 밖에 두고 색인해 검색하게 한다.
- MCP 응답이 크면 Claude Code는 파일로 돌리고 경로만 넣는다([[claude-code-guide#MCP 응답이 클 때|Claude Code 활용 가이드]]). 도구 결과를 코드에서 걸러 최종값만 넣는 방식은 [[claude-advanced-tool-use|Claude API 고급 도구 사용]]에 있다.

### 2. 필요한 부분만 읽는다

- 파일 전체 대신 `grep`·심볼 검색으로 위치를 찾고 그 범위만 읽는다. 코드를 심볼 단위로 색인해 주는 도구(LSP, 코드 그래프 MCP)가 탐색 토큰을 크게 줄인다.
- 이미 읽은 파일을 다시 읽지 않게 한다. 훅으로 같은 파일 재읽기나 원시 도구 사용(`cat`으로 큰 파일 출력 등)을 막는 방법도 있다.
- 큰 파일 읽기 같은 I/O성 작업은 싼 모델에 넘기는 훅으로 돌린다([[claude-code-hooks|Claude Code 훅]]).

**규칙은 권고, 훅은 강제다.** `CLAUDE.md`에 「출력을 거르라」고 적어도 모델은 가끔 잊는다. 반드시 지켜야 할 절약 규칙은 훅이나 권한 규칙으로 막는다.

### 3. 맥락을 가볍게 유지한다

| 방법 | 효과 |
| --- | --- |
| 상시 맥락 다이어트 | `CLAUDE.md`는 꼭 필요한 것만 둔다(공식 문서 권장은 200줄 이하). 특정 작업에만 쓰는 지시는 필요할 때만 올라오는 스킬로 옮긴다. `/context`로 무엇이 자리를 차지하는지 본다 |
| 도구 정의 미루기 | 드물게 쓰는 도구는 정의를 빼 두고 검색해 불러온다(도구 검색). Claude Code는 MCP 도구 정의를 기본으로 미뤄 이름만 싣는다. 그래도 `gh`·`aws` 같은 CLI는 도구 목록 자체가 없어 더 가볍고, 쓰지 않는 MCP 서버는 `/mcp`에서 끈다 |
| 작업이 바뀌면 `/clear` | 끝난 작업의 기록을 다음 작업에 끌고 가지 않는다. `/clear`는 비용이 들지 않는다 |
| 힌트를 준 압축 | `/compact <남길 것>`으로 필요한 것만 남긴다. 압축도 대화 전체를 읽는 큰 요청이므로, 이어 갈 필요가 없으면 압축보다 `/clear`가 싸다. 압축 전에 진행 상태를 파일로 넘겨 두면 압축 뒤에도 이어 간다 |
| 서브에이전트로 격리 | 탐색·조사처럼 출력이 큰 일은 서브에이전트에 맡기고 요약만 받는다. 메인 맥락이 깨끗하게 유지된다. 다만 서브에이전트 자체도 토큰을 쓰므로 결과가 다시 필요 없는 큰 탐색에만 쓴다([[claude-code-extensions\|커맨드·스킬·서브에이전트 고르기]]) |

### 4. 캐시를 살린다

프롬프트 캐시는 앞부분이 정확히 같을 때만 맞고, 캐시된 입력은 일반 입력보다 훨씬 싸다. 세션 중간에 모델·도구 목록·시스템 지시를 바꾸지 않는다. 바뀌는 내용은 프롬프트 뒤쪽에 둔다. 원리는 [[harness-engineering|프롬프트에서 하네스로]]의 KV 캐시 절에 있다.

### 5. 작업에 맞는 모델로 보낸다(모델 라우팅)

- **평소에는 가격 대비 성능이 좋은 모델, 필요할 때만 상위 모델.** 기획·설계·어려운 디버깅은 상위 모델, 계획대로 구현하거나 반복 작업은 저렴한 모델에 맡긴다.
- 추론 강도(effort)도 같다. 간단한 작업에 높은 추론을 쓰지 않는다.
- 모델 선택은 토큰 **단가**만이 아니라 **작업을 끝내기까지의 총 토큰**으로 본다. 단가가 싸도 단계가 많이 필요하면 비싸다. 같은 작업을 더 적은 단계로 끝내는 모델이 실제로는 쌀 수 있다.

### 6. 출력을 짧게 한다

모델이 쓰는 토큰은 입력보다 단가가 높다. 「설명은 짧게, 바뀐 부분만 보여 줘」처럼 출력 형식을 정하거나, 응답 문체를 간결하게 바꾸는 플러그인(예: Caveman)을 쓴다. 다만 출력을 지나치게 줄이면 사람이 결과를 이해하기 어려워지므로 리뷰에 필요한 설명은 남긴다.

## 측정: 사용량이 아니라 작업당 비용

| 지표 | 쓰임 |
| --- | --- |
| 작업당 비용 | 이슈 하나, PR 하나를 끝내는 데 든 토큰·금액. 같은 종류 작업끼리 비교한다 |
| 결과 대비 비용 | 머지된 변경, 해결한 버그처럼 결과물 단위로 나눈다. 광고가 노출당 과금(CPM)에서 클릭당 과금(CPC)으로 옮겨 가며 성과를 재기 시작한 것처럼, 토큰 지출도 결과로 재는 단계로 간다 |
| 맥락 구성 | `/context`로 무엇이 맥락을 차지하는지 본다. Claude Code의 `/usage`는 세션 토큰과 캐시 적중률, 그리고 구독 플랜에서는 최근 사용량을 스킬·서브에이전트·MCP 서버별로 나눈 비중과 개선 권고(예: 「이 CLAUDE.md를 줄여라」)를 보여 준다 |
| 이상 탐지 | 평소보다 급증한 세션·에이전트에 차단기와 알림을 둔다 |

**절약 도구의 효과는 내 작업으로 직접 잰다.** 도구마다 「90% 절감」 같은 수치를 내세우지만 대개 셸 출력, 재읽기처럼 좁은 구간의 최대값이다. 여러 도구를 한꺼번에 붙이면 설정이 복잡해지고, 오히려 맥락과 응답 품질을 해칠 수 있다. 하나씩 붙이고 전후를 비교한다. 토큰 사용량이 갑자기 늘었을 때 원인을 찾는 표는 [[ai-delegation-toolkit|AI에게 일 맡기기]]의 「토큰 사용량이 갑자기 늘면」에 있다.

## 정리

- 토큰 사용량은 관찰할 신호이지 성과 지표가 아니다. 평가에 넣으면 토큰맥싱이 생긴다.
- 토큰은 도구 출력, 통째로 읽은 파일, 매 회차 다시 실리는 상시 맥락, 긴 세션, 과한 병렬에서 샌다.
- 맥락에 들어가기 전에 거르고, 필요한 부분만 읽고, 작업이 바뀌면 비우고, 큰 탐색은 격리한다.
- 앞부분을 고정해 캐시를 살리고, 작업 난이도에 맞는 모델로 보낸다.
- 비용은 작업당·결과당으로 재고, 절약 도구의 효과는 내 작업으로 확인한다.

적게 쓰는 것이 목표가 아니라, 쓴 만큼 결과를 내는 것이 목표다.
