> SNS에서 돌던 이미지 「ChatGPT Cheat Sheet」를 뼈대로, Anthropic의 [Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)로 원칙을 확인해 재구성한 노트입니다.

## 핵심: 맥락 없는 신입에게 일을 맡기듯

LLM은 **똑똑하지만 우리 규칙과 사정을 전혀 모르는 신입**과 같다. 원하는 것을 정확히 설명할수록 결과가 좋아진다. 검사법은 간단하다. 프롬프트를 이 일을 모르는 동료에게 보여 줬을 때 헷갈려 한다면 모델도 헷갈린다.

역할 부여("너는 숙련된 마케팅 컨설턴트다")는 답의 관점과 어휘를 그 분야에 맞춘다. 한 문장으로도 효과가 있지만, 역할만으로는 부족하다. **무엇을, 왜, 어떤 모양으로** 원하는지가 함께 있어야 한다.

## 프롬프트를 채우는 7칸

| 칸 | 할 일 | 효과 |
| --- | --- | --- |
| 1. 목표 | 이 결과로 무엇을 하려는지 밝힌다 | 모델이 우선순위를 판단할 기준이 생긴다 |
| 2. 맥락 | 역할, 배경, 독자, 지금까지의 사정을 준다 | 답의 기준점이 생긴다 |
| 3. 과제 | 수행할 작업을 구체적으로, 순서가 중요하면 번호 목록으로 | 결과물이 분명해진다 |
| 4. 세부 사항 | 고려할 조건과 **그 이유**를 덧붙인다 | 이유를 알면 모델이 규칙을 일반화한다 |
| 5. 제약 | 지킬 한계와 범위를 적는다 | 엉뚱한 답을 막는다 |
| 6. 형식 | 결과물의 구조·분량을 지정한다 | 바로 쓸 수 있는 모양으로 나온다 |
| 7. 예시 | 원하는 답의 샘플을 3~5개 보여 준다 | 형식·어조·구조를 가장 확실하게 맞춘다 |

## 원칙

| 원칙 | 덜 효과적 | 더 효과적 |
| --- | --- | --- |
| **분명하게** | "대시보드 만들어 줘" | "관련 기능과 상호작용을 최대한 넣은 분석 대시보드를 만들어 줘" |
| **이유를 붙인다** | "말줄임표 쓰지 마" | "음성 합성으로 읽히니 말줄임표는 쓰지 마. 읽을 방법이 없다" |
| **금지 대신 할 일을** | "마크다운 쓰지 마" | "매끄럽게 이어지는 산문 문단으로 써 줘" |
| **예시는 다양하게** | 비슷한 예시 하나 | 실제 쓰임과 닮고, 가장자리 경우까지 다른 예시 여러 개를 `<example>` 태그로 |
| **구조를 나눈다** | 지시·자료·입력을 한 덩어리로 | `<instructions>`, `<context>`, `<input>`처럼 태그나 소제목으로 구분 |
| **복잡하면 단계로** | 한 번에 모든 것 | "먼저 분석하고, 그다음 요약하고, 그다음 실행 항목을 만들어 줘" 또는 프롬프트 여러 개로 연결 |
| **프롬프트 문체 = 출력 문체** | 글머리표 범벅인 프롬프트로 산문을 요구 | 원하는 출력과 비슷한 모양으로 프롬프트를 쓴다 |

- **대문자 강조는 아낀다.** `CRITICAL`, `MUST`를 남발하면 최신 모델은 오히려 과하게 반응한다. 평범한 문장으로 쓰고 이유를 붙이는 쪽이 낫다.
- **"10점 만점짜리로"보다 평가 기준을 준다.** 스스로 점수를 매기게 할 때도 무엇을 기준으로 볼지 적어야 개선이 일어난다.
- **추론 모델에는 생각 과정을 일일이 지시하지 않는다.** 단계별 사고는 모델이 스스로 한다. 대신 성공 기준과 확인 방법을 준다.

## 고를 수 있는 값

| 항목 | 예 |
| --- | --- |
| 역할 | 제품 디자이너, 역사학자, 번역가, 카피라이터, UX 리서처, 데이터 사이언티스트, 법률 자문, 영양사, 커리어 코치, SEO 전문가 등 |
| 어조(Tone) | 친근한, 흥미진진한, 혁신적인, 진취적인, 안정적인, 일관된 |
| 문체(Writing style) | 전문적, 정보 전달형, 교육용, 사실 기반, 비교형, 이점 중심, 해결책 중심, 스토리텔링, 유머, 감성, 명령형, 캐주얼, 대화체 |
| 출력 형식(Format) | 표, 목록, 요약, 일반 텍스트, JSON, HTML, CSV, XML, Markdown, 글머리표, 긴 글 |

역할에는 「숙련된」「공감하는」「전략적인」 같은 수식어를 붙여 전문성의 결을 한 번 더 지정한다.

## 제약 템플릿

`{TYPE}` 자리에 값을 넣어 프롬프트 끝에 붙여 쓴다.

```text
Language: {TYPE}로 답한다.
Tone: {TYPE} 어조를 유지한다.
Sentence length: 간결한 문장을 선호한다.
Style: {TYPE} 문체를 쓴다.
Sources: 신뢰할 수 있는 출처에 근거하고, 출처를 밝힌다.
Names: 구체적인 이름은 {Var: Name} 같은 변수로 바꾼다.
Output format: 일반 텍스트로 답한다.
```

## 그 밖의 요령

1. **목표를 먼저 정의한다.** 무엇을 얻고 싶은지 모르면 프롬프트도 흐려진다.
2. **결과를 확인할 기준을 정해 둔다.** 기준이 있어야 프롬프트를 고쳤을 때 나아졌는지 안다.
3. **세부 사항은 많을수록 좋지만, 정리해서 준다.** 긴 자료는 앞에, 질문은 끝에 둔다.
4. **여러 모델·대화를 역할별로 나눠 쓴다.** 한 결과를 다음 단계의 입력으로 넘긴다.
5. **답을 평가하고 피드백한다.** 한 번에 끝내지 말고 고쳐 가며 다듬는다.

## 정리

- 프롬프트는 **목표 + 맥락 + 과제 + 제약 + 형식 + 예시**의 조합이다.
- 규칙에는 이유를 붙이고, 금지보다 할 일을 적는다.
- 예시는 형식을 맞추는 가장 확실한 방법이다.
- 어조·문체·형식은 목록에서 골라 끼우면 매번 고민하지 않아도 된다.
- 결국 **AI는 마음을 읽지 못한다**. 원하는 것을 말로 꺼내 놓는 만큼 답이 좋아진다.
