차트 종류를 맞게 골라도([[chart-selection-guide|데이터 종류별 차트 고르기]]) 축 하나, 색 하나 때문에 메시지가 틀어질 수 있다. 문제 있는 차트는 심각도로 나눠 보면 고칠 순서가 잡힌다.

| 등급 | 뜻 | 예 |
| --- | --- | --- |
| 조악함(ugly) | 내용은 맞지만 보기에 거슬린다 | 어긋난 패널 정렬, 어울리지 않는 글꼴 |
| 모호함(bad) | 오해하게 만들 수 있다 | 패널마다 다른 y축 범위, 의미 없는 색 |
| 틀림(wrong) | 수학적으로 사실과 다르다 | 합이 135%인 파이, 0이 아닌 곳에서 시작한 막대 |

## 잉크 비례 원칙

**값을 나타내려고 칠한 면적은 그 값에 비례해야 한다.**

- **막대와 면적 차트는 0에서 시작한다.** 중위 소득 막대를 5만 달러에서 시작하면 작은 차이가 몇 배처럼 보인다.
- 차이를 강조하고 싶으면 축을 자르지 말고 **차이 자체를 그린다.** "5년간 소득 변화량" 막대는 0에서 시작해도 차이가 선명하다. 주가라면 "고점 대비 하락률"을 그린다.
- 칠하지 않은 선 그래프는 축을 0에서 시작하지 않아도 되지만, 축 범위가 변동 폭을 얼마나 과장하는지 의식한다.
- **로그 축 막대**는 0을 그릴 수 없어 시작점이 임의로 정해진다. 그 시작점에 따라 막대 길이가 달라지니 점으로 바꾸거나, 비율 데이터라면 기준값 1(어떤 대상 대비 배수)에서 막대를 시작한다.
- 파이 조각의 면적은 각도에 비례하므로 원칙에 맞다. 다만 같은 데이터를 막대로 그리면 차이가 더 크게 보인다. 사람이 면적보다 길이를 더 민감하게 비교하기 때문이다. 트리맵도 마찬가지다.

## 겹친 점 풀기(오버플로팅)

점이 같은 자리에 쌓이면 데이터가 몇 개인지, 뒤에 무엇이 숨었는지 알 수 없다. 데이터가 많을 때뿐 아니라 반올림으로 같은 값이 많을 때도 생긴다.

| 방법 | 원리 | 한계 |
| --- | --- | --- |
| 반투명 | 겹친 곳이 진해진다 | 몇 개가 겹쳤는지 정확히 모른다. 점이 수만 개면 진한 얼룩과 흐린 영역만 남는다 |
| 지터(jitter) | 점마다 위치를 살짝 흔든다 | 너무 많이 흔들면 데이터가 왜곡된다 |
| 2차원 히스토그램 / 육각형 구간(hexbin) | 평면을 칸으로 나누고 칸마다 개수를 색으로 | 개별 점은 사라지지만 수만~수십만 점도 요약된다 |
| 등고선 | 점 밀도를 추정해 등고선을 긋는다 | 범주 두세 개까지는 색으로 구분되지만, 범주가 많고 서로 겹치면 읽을 수 없다. 그때는 범주별 패널로 나눈다 |

```python
import matplotlib.pyplot as plt

fig, axes = plt.subplots(1, 3, figsize=(12, 4))
axes[0].scatter(x, y, alpha=0.2, s=8)                    # 반투명
axes[1].hexbin(x, y, gridsize=40, cmap="viridis", mincnt=1)  # 육각형 집계
import seaborn as sns
sns.kdeplot(x=x, y=y, ax=axes[2], fill=True, levels=8)   # 등고선
```

## 색은 적게, 의미 있게

- 범주를 색으로 구분하는 건 **3~5개**까지가 편하다. 8~10개를 넘으면 범례를 오가며 맞추기 어렵다. 그보다 많으면 중요한 몇 개에만 색을 주고 나머지는 회색으로 둔다.
- 색이 아무 뜻 없이 들어가면 오히려 방해다. 넓은 면적에는 채도를 낮춘다. 진한 색이 넓게 깔리면 눈이 피로하고 세부를 보기 어렵다.
- **색각 이상**을 고려한다. 적록 구분이 어려운 경우가 가장 흔하다. ColorBrewer의 색각 친화 팔레트, Okabe-Ito 팔레트, `viridis`·`cividis` 같은 스케일을 쓰고, 시뮬레이터로 확인한다.
- 표시가 작아지면(작은 점, 가는 선) 색 구별이 급격히 어려워진다. 작은 표시일수록 대비가 큰 색을 쓴다.

색 스케일의 종류는 [[visual-encoding|시각화 인코딩]]에, 웹 화면의 대비 기준은 [[color-motion-accessibility|색과 움직임의 접근성]]에 있다.

## 범례보다 직접 레이블

- **중복 코딩**: 범주를 색과 모양으로 함께 구분한다. 색이 비슷한 두 범주도 구별되고, 흑백 인쇄와 색각 이상에서도 읽힌다. 반대로 데이터와 무관한 장식용 색·패턴을 넣으면 없는 의미가 생긴다.
- 범례를 써야 한다면 **범례 순서를 데이터 순서와 맞춘다.** 선 그래프의 마지막 값이 위에서부터 A, B, C면 범례도 A, B, C로. 도구가 자동으로 정한 순서는 대개 이렇지 않다.
- 가능하면 범례를 없앤다. 선 끝, 밀도 곡선 옆, 점 무리 근처에 이름을 직접 쓴다. 그룹을 타원으로 감싸 이름을 다는 방법은 타원 자체가 무언가를 뜻하는 것처럼 오해될 수 있다.
- 연속 색 스케일은 축과 합칠 수 있다. 기온 x축 아래에 같은 색 띠를 깔면 범례가 따로 필요 없다.
- 점선·쇄선으로 범주를 나누면 선 그래프가 산만해진다. 색을 먼저 쓴다.

## 제목, 축, 캡션

| 실리는 곳 | 제목 위치 |
| --- | --- |
| 책, 논문, 보고서 | 그림 아래 캡션의 첫 문장이 제목 역할을 한다. 그림 안에는 제목을 넣지 않는다 |
| 웹, 슬라이드, SNS에 그림만 단독으로 | 그림 안에 제목을 넣는다 |

- 축 레이블에는 변수 이름과 **단위**를 적는다.
- 맥락만으로 분명한 레이블(범례 제목 "species"처럼)은 지워서 간결하게 한다. 다만 y축 레이블은 제목에서 짐작할 수 있어도 남기는 편이 안전하다.

## 표를 그릴 때

차트보다 표가 나은 경우도 많다(정확한 값을 찾아봐야 할 때). 표에도 규칙이 있다.

1. 세로선을 넣지 않는다.
2. 데이터 행 사이에 가로선을 넣지 않는다. 가로선은 머리글과 본문 경계, 표 위아래에만.
3. 글자 열은 왼쪽 정렬, 숫자 열은 오른쪽 정렬하고 소수점 자릿수를 맞춘다.
4. 한 글자짜리 열은 가운데 정렬한다.
5. 머리글은 아래 데이터 열과 같은 정렬을 따른다.

## 여러 패널: 면분할과 복합 도표

- **면분할(faceting)**: 변수 하나로 데이터를 쪼개 같은 형식의 작은 차트를 나란히 놓는다. 패널 순서를 논리적으로(연도순, 값 크기순) 정한다.
- 패널끼리 비교가 목적이면 **축 범위를 통일한다.** 패널마다 y축이 다르면 작은 변화가 큰 변화처럼 보인다.
- **복합 도표**: 전체 추세는 선 그래프, 상위 다섯 항목은 경사 차트처럼 서로 다른 차트를 묶어 큰 그림과 세부를 함께 보여 준다.
- 묶은 패널끼리는 **같은 범주에 같은 색과 같은 위치**를 쓴다. 한 패널에서 여성이 왼쪽 주황이면 다른 패널에서도 그렇게. 패널 정렬을 맞추고, 패널 번호(a, b, c)는 읽기를 방해하지 않는 위치에 본문 글꼴로 둔다.

## 맥락 요소: 격자, 테두리, 기준선

에드워드 터프티(Edward Tufte)의 **데이터-잉크 비율**은 전체 잉크 중 데이터를 전하는 잉크의 비율을 높이라는 원칙이다. 다만 비데이터 잉크를 무조건 지우면 레이블과 패널 경계까지 흐려져 오히려 읽기 어렵다. 목표는 **타당한 범위 안에서** 높이는 것이다. UI 전반에 이 원칙을 적용한 이야기는 [[ui-density|UI 밀도]]에 있다.

- 테두리와 격자는 연한 회색으로. 진하고 촘촘한 격자는 데이터 선만큼 눈에 띄어 데이터를 묻는다.
- 값을 읽는 방향의 격자만 남긴다. 세로 막대면 가로 격자만, 가로 막대면 세로 격자만.
- 의미 있는 기준값(지수 100, 목표치, 0)이 있으면 **기준선** 하나를 긋는다. 격자 여러 줄보다 강력하다.
- 쌍 데이터 산점도에는 격자보다 **y=x 대각선**이 낫다. 격자와 대각선을 둘 다 넣으면 복잡해진다.
- 다중 패널에서 비데이터 잉크를 다 빼면 패널 경계가 사라진다. 옅은 배경이나 가는 기준선으로 구획을 남긴다.

```python
ax.grid(axis="y", color="0.85", linewidth=0.8)
ax.set_axisbelow(True)                 # 격자를 데이터 뒤로
for side in ("top", "right"):
    ax.spines[side].set_visible(False)
ax.axhline(100, color="0.3", linewidth=1)   # 기준선
```

## 피해야 할 것

### 너무 작은 글자

기본 설정의 축 글자는 화면에서도 작고, 슬라이드나 문서에 줄여 넣으면 읽을 수 없다. 글자만 키우면 점과 선이 상대적으로 작아져 균형이 깨지니, **글자·점·선을 함께 키운다.** 최종 크기로 줄여서 확인하는 습관이 좋다.

### 선만 있는 그림

손으로 그려 흑백 복사하던 시절의 관습이 남은 것이다. 윤곽선만 있는 막대·박스·밀도 곡선은 안팎 구분이 어렵다. **연한 색으로 채운다.** 겹치는 밀도 곡선은 반투명으로 칠하고, 범주를 점 모양으로 구분할 때도 속이 찬 모양과 색을 함께 쓴다.

### 3차원

사람의 눈은 평면에 투영된 3차원 그림을 머릿속에서 다시 입체로 복원하면서 크기를 보정한다. 그 과정에서 값이 틀어진다.

| 3D 차트 | 문제 | 대안 |
| --- | --- | --- |
| 3D 파이 | 기울인 각도 때문에 앞쪽 조각이 커 보인다 | 2D 파이나 막대 |
| 3D 막대 | 벽에서 떨어진 막대가 실제보다 작게 읽힌다. 뒤 막대가 가려진다 | 변수별로 2D 막대를 나눠 그린다 |
| 3D 산점도 | 정지 화면으로는 점의 깊이를 알 수 없다 | 2D 산점도 두 개로 나누거나(세 변수가 다 중요할 때), 세 번째 변수를 점 크기·색으로(부차적일 때) |

3차원이 괜찮은 경우는 사용자가 직접 돌려 볼 수 있을 때, 천천히 회전하는 영상일 때, 지형이나 단백질 구조처럼 **원래 3차원인 대상**을 보여 줄 때다.

## 점검 목록

- [ ] 칠한 막대·면적은 0에서 시작하나
- [ ] 점이 겹쳐 숨은 데이터는 없나
- [ ] 색은 5개 이하이고 각각 뜻이 있나, 색각 이상에서도 구별되나
- [ ] 범례 대신 직접 레이블을 쓸 수 있나, 범례 순서가 데이터 순서와 같나
- [ ] 축 레이블에 단위가 있나
- [ ] 패널끼리 축 범위와 색 배정이 같나
- [ ] 격자와 테두리가 데이터보다 눈에 띄지 않나
- [ ] 최종 크기에서 글자가 읽히나
- [ ] 3D나 선만 있는 표현을 쓰지 않았나
