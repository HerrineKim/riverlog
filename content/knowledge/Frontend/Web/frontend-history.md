## 웹의 세대 구분

프론트엔드는 처음부터 있던 직군이 아니다. 2000년대 초에 생겼고, 웹이 바뀐 흐름과 같이 보면 이해하기 쉽다.

| 세대 | 시기 | 성격 | 필요했던 사람 |
| --- | --- | --- | --- |
| Web 1.0 | 1990년대 ~ 2004 | 정적인 사이트. 사용자는 읽기만 한다 | 웹 디자이너. 페이지 제작 기술은 단순했다 |
| Web 2.0 | 2004 ~ | 사용자가 콘텐츠를 만들고 고치는 상호작용 사이트 | 숙련된 웹 개발자 |
| Web 3.0 | 앞으로 | AI·블록체인·IoT 기반의 지능형·시맨틱 웹 | 정의가 아직 논쟁 중이다 |

## 프론트엔드를 만든 기술들

```text
1991 HTML 태그 ─ 1993 <img> ─ 1995 JavaScript ─ 1996 CSS ─ 2004~05 AJAX(Gmail, Google Maps) ─ 2010 무렵 Flash 퇴장
                                                                                                     │
                                                       트래픽·데이터 증가 → 프론트엔드 / 백엔드 분리 ◀┘
```

| 기술 | 바꾼 것 |
| --- | --- |
| `<img>` 태그 (1993) | 페이지가 풍성해졌다. 아직은 전문가가 따로 필요할 만큼 복잡하지 않았다 |
| CSS (1994 제안, 1996 공개, 1998 W3C 권고) | **문서 구조와 시각 디자인을 분리**했다 |
| JavaScript (1995) | 사용자와 페이지가 상호작용할 수 있게 했다. Web 2.0의 바탕이 됐다 |
| AJAX | 페이지 전체를 다시 불러오지 않고 **일부만 비동기로 갱신**한다. Gmail(2004)과 Google Maps(2005)가 보여 줬고, Jesse James Garrett이 이름을 붙였다. JavaScript의 위상이 크게 올라갔다 |
| Flash의 퇴장 (2010 무렵) | 그 자리를 HTML5와 AJAX가 채웠다 |

### Flash가 밀려난 이유

- 보안 취약점이 잦았다.
- 모바일에서 성능이 나쁘고 배터리를 많이 썼다.
- 스크린 리더가 읽지 못해 접근성이 떨어졌다.
- 검색 엔진이 내용을 색인하기 어려웠다.
- HTML5와 AJAX라는 표준 대안이 생겼다.

## 프론트엔드와 백엔드의 분리

트래픽과 데이터가 커지자 한 사람이 모두 맡기 어려워졌다. 역할이 나뉘었다.

| 영역 | 맡는 일 |
| --- | --- |
| 프론트엔드 | 가공된 데이터를 받아 사용자가 보고 조작하는 화면을 만든다 |
| 백엔드 | 서버에서 데이터를 처리하고 저장한다 |

## 정리

- 프론트엔드는 한 사건이 아니라 **기술이 쌓이며 생긴** 영역이다.
- CSS는 구조와 표현을, AJAX는 페이지와 데이터 요청을 떼어 냈다.
- 표준 기술(HTML5·JS)이 독자 플러그인(Flash)을 대체하면서 브라우저가 앱 플랫폼이 됐다.
- 사용자가 웹에 기대하는 것이 커질수록 화면을 만드는 일도 전문화됐다.
