## 제스처 기반 인터페이스란

제스처 기반 인터페이스는 버튼을 누르는 대신 **화면을 직접 밀고, 당기고, 끌고, 집는 동작**으로 조작하는 UI다. 터치스크린이 보편화되면서 아이들도 설명 없이 익힐 만큼 자연스러운 조작이 됐다.

작은 화면에서 위아래 고정 바는 화면의 상당 부분을 차지한다. 제스처는 그 자리를 **콘텐츠에 돌려준다.** 처음엔 실험적이던 제스처가 표준이 된 예가 많다. "당겨서 새로고침(pull-to-refresh)"은 한 트위터 클라이언트 앱에서 시작해 사실상 모든 목록 화면의 기본 동작이 됐다.

## 대표 제스처와 쓰임

| 제스처 | 흔한 쓰임 |
| --- | --- |
| 탭 / 길게 누르기 | 선택 / 보조 메뉴, 미리 보기 |
| 아래로 당기기 | 목록 새로고침 |
| 항목 좌우 스와이프 | 삭제·보관 같은 항목별 빠른 동작 |
| 화면 가장자리 스와이프 | 뒤로 가기, 서랍 메뉴 |
| 드래그 | 순서 바꾸기, 두 영역의 비율 조절, 바텀 시트 높이 조절 |
| 핀치 / 회전 | 확대·축소 / 이미지·지도 회전 |

## 설계 원칙

### 1. 화면은 콘텐츠의 뷰포트로

모든 내비게이션이 항상 보여야 한다는 의무감을 버린다. 메뉴와 보조 기능을 메인 화면의 옆, 아래, 뒤에 있는 가상의 공간에 두고 제스처로 꺼낸다. 콘텐츠마다 똑같은 버튼 두세 개를 반복해 붙이는 대신 **맥락 제스처**(항목 스와이프)로 바꾸면 화면이 정리된다.

### 2. 제스처로 연속적인 조절을 준다

버튼은 "A냐 B냐"를 고르게 하지만 드래그는 **그 사이 어디쯤**을 고르게 한다. 예를 들어 음악과 뉴스 두 콘텐츠 영역의 경계를 끌어서 비율을 바꾸게 하면, 사용자가 탭을 오가지 않고 두 콘텐츠를 동시에 보며 관심사에 맞게 조절한다.

### 3. 화면이 아니라 시간과 움직임으로 생각한다

제스처 UI에서는 "어떤 화면인가"보다 다음이 중요하다.

- 탭하면 무엇이 일어났다는 걸 어떻게 보여 주나
- 요소가 얼마나 빠르게 들어오고 나가나
- 손가락을 떼면 어디로 스냅되나, 중간에 놓으면 되돌아가나
- 몇 초 동안 입력이 없으면 사라지나

정적 와이어프레임 스크린샷으로는 이것을 설명할 수 없다. Figma의 스마트 애니메이트나 ProtoPie 같은 도구로 **조작 가능한 프로토타입**을 만들어 흐름과 막히는 지점을 일찍 테스트한다. 이해관계자 설득에는 짧은 콘셉트 영상도 효과적이다.

### 4. 학습 곡선을 관리한다

제스처는 눈에 보이지 않는다. **UI를 덜어 낼수록 배울 것이 늘어난다.**

- 첫 실행 전체 튜토리얼보다 **점진적 공개(progressive disclosure)**가 낫다. 해당 기능을 처음 쓰는 순간에 맞춰 힌트를 보여 준다(카메라를 처음 열 때 "가로로 돌리세요").
- 스와이프 가능한 항목은 살짝 밀려 보이는 애니메이션, 바텀 시트는 손잡이(grabber)처럼 **조작 가능하다는 시각 단서**를 남긴다.
- 사용자가 모르는 제스처에만 기능을 숨기지 않는다.

## 한계와 주의점

| 문제 | 대응 |
| --- | --- |
| 운영체제 제스처와 충돌 | iOS·Android는 화면 가장자리 스와이프를 뒤로 가기·홈 이동에 쓴다. 앱이 가장자리 제스처를 가로채면 시스템 동작을 방해한다. 가장자리 근처에는 커스텀 제스처를 두지 않는다 |
| 쓸 수 없는 사용자 | 손 떨림, 한 손가락만 쓰는 사용자, 스위치·음성 같은 보조 기술 사용자는 경로 기반·다중 손가락 제스처를 하기 어렵다. WCAG 2.2는 이런 제스처(2.5.1)와 드래그(2.5.7)에 **한 번의 탭·클릭으로 되는 대안**을 요구한다 |
| 발견 가능성 | 숨은 제스처는 쓰는 사람만 쓴다. 핵심 기능은 보이는 버튼으로도 제공한다 |
| 실수 | 스와이프 삭제처럼 되돌리기 어려운 동작에는 실행 취소(undo)를 준다 |
| 플랫폼 관례 | 서랍 메뉴보다 하단 탭 바가 모바일 주 내비게이션의 기본이 됐다. 관례를 벗어나는 제스처는 테스트로 근거를 확인한다 |

## 정리

- 제스처는 버튼과 바를 줄여 화면을 콘텐츠에 내준다.
- 드래그 같은 연속 조작은 버튼의 양자택일을 넘어서는 경험을 준다.
- 화면이 아니라 시간·속도·스냅으로 설계하고, 조작 가능한 프로토타입으로 검증한다.
- 보이지 않는 조작이므로 점진적 힌트와 시각 단서로 가르친다.
- **모든 제스처에는 버튼 대안을 둔다.** 시스템 제스처와 겹치지 않게 한다.
