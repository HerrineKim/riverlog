## UX 라이팅이란

UX 라이팅(UX writing)은 버튼, 안내 문구, 오류 메시지, 빈 화면처럼 **제품 화면 안의 글**을 사용자가 목표를 이루도록 쓰는 일이다. 광고 카피가 관심을 끄는 글이라면, UX 라이팅은 사용자가 **멈추지 않고 다음 단계로 가게 하는 글**이다. 문구는 화면 흐름의 일부라서, 흐름 자체에 문제가 보이면 문구를 다듬기 전에 디자인·기획에 의견을 내는 것도 UX 라이터의 몫이다.

## 문서의 세 층

| 층 | 담는 것 | 성격 |
| --- | --- | --- |
| 원칙(principle) | 회사의 가치·비전, 서비스가 지향하는 바, 비즈니스 방향 | 추상적. 경영진·구성원과 깊이 논의해 정한다 |
| 가이드라인(guideline) | 원칙을 글쓰기 방법으로 옮긴 것. 명확성·간결성·일관성·사용성 같은 축과 표기 규칙 | 원칙과 체크리스트 사이를 잇는 방법론 |
| 체크리스트(checklist) | 문장 하나를 검토할 때 던질 구체적인 질문 | 실무용. 작성자 누구나 스스로 점검한다 |

가이드라인의 목적은 두 가지다.

- **제작자(Makers) 간 일관된 문구**: 누가 써도 같은 서비스의 말투가 된다.
- **효율적인 커뮤니케이션**: "왜 이렇게 고쳐야 하죠?"라는 질문에 "가이드라인 기준"이라는 한마디로 답이 끝난다. 이것이 가능하려면 가이드라인이 UX 라이터 혼자 만든 문서가 아니라 **경영진부터 실무자까지 합의한 규범**이어야 한다.

가이드라인과 보이스 톤은 디자인 시스템의 파운데이션에 함께 두면 컴포넌트와 같은 방식으로 관리된다([[design-system|디자인 시스템]]).

## 체크리스트 8가지

### 1. 이 화면의 문제를 해결하는 글인가

만드는 사람은 사용자가 될 수 없으니, 흐름 전체에 걸쳐 질문으로 확인한다.

- 이 화면의 목표는 무엇이고, 사용자는 쉽게 달성할 수 있나?
- 사용자가 이 화면에서 얻는 것은 무엇인가?
- 목표와 관련 있고 쓸모 있는 정보만 보이고 있나?
- 이전 화면의 맥락을 이어받아 다음 화면을 준비시키고 있나?
- 사용자는 무엇을 보고 성공했다고 판단하나?
- 내 표현에 대한 애착이 판단을 흐리고 있지 않나?

### 2. 모바일에서 읽히는가

| 기준 | 방법 |
| --- | --- |
| 짧게 | 한 문장은 짧게(영어 기준 약 20단어 이하), 단락도 짧게 |
| 구조 | 제목·부제목·글머리 기호로 나눈다 |
| 우선순위 | 다음 단계에 필요한 정보부터. 중요한 정보와 CTA는 스크롤하지 않아도 보이는 첫 화면(above the fold)에 |
| 환경 | Android·iOS, 모든 화면 크기에서의 가독성을 확인한다 |
| 번역 | 다른 언어로 옮기면 길어지므로 문구 영역에 여유를 둔다([[multilingual-pages\|다국어 페이지]]) |

### 3. 훑어보는 사용자를 위한 글인가

사용자는 화면의 글을 다 읽지 않는다. 제목과 각 줄의 첫머리, 버튼을 따라 F자 모양으로 **훑어보고** 넘긴다.

- 할 일을 분명히 쓰고, 정보를 그 할 일 중심으로 묶는다.
- 제목에는 사용자에게 필요한 내용과 결과를 짧게 넣는다.
- 여백과 글머리 기호를 쓰고, 필요 없는 말은 과감히 덜어 낸다.

### 4. 방법보다 이유가 먼저 보이는가

사용자를 움직이는 것은 "어떻게"보다 "왜"다. 문장 앞쪽에 **사용자가 얻는 것(목적)** 을 두고, 방법은 뒤에 둔다.

| 방법이 먼저 | 목적이 먼저 |
| --- | --- |
| 다른 사람의 프로필로 이동해 연결 요청을 보내세요. | 연결 요청을 보내려면 상대의 프로필로 이동하세요. |

### 5. 전문 용어를 피했는가

- B2C에서는 업계 용어·내부 용어를 일상어로 바꾼다. 모르는 단어 하나가 이탈로 이어진다.
- B2B에서는 반대로 조심한다. 전문가에게는 **업무에서 매일 쓰는 용어가 곧 일상어**라서, 억지로 풀어 쓰면 더 헷갈린다. 기준은 "사용자가 평소에 쓰는 말인가"다.

### 6. 다크 패턴을 쓰지 않았는가

다크 패턴(dark pattern)은 사용자의 결정을 의도적으로 조작해 원치 않는 결과로 이끄는 화면 설계다. 글에서는 거절 버튼에 죄책감을 씌우는 **컨펌셰이밍**(confirmshaming, 예: "아니요, 저는 할인이 싫어요")이 대표적이다.

- 단기 전환은 오를 수 있지만 신뢰를 잃고, 사용자가 실제로 원하는 가치가 무엇인지 데이터로 알 수 없게 된다.
- 한국에서는 개정 전자상거래법(2025년 2월 시행)이 숨은 갱신, 순차 공개 가격 책정, 특정 옵션 사전 선택, 잘못된 계층 구조, 취소·탈퇴 방해, 반복 간섭을 다크 패턴으로 규제한다.

### 7. 일관된가

같은 행동을 화면마다 다른 말로 부르면 사용자는 다른 기능으로 오해한다. 용어집과 표기 규칙(띄어쓰기, 숫자·단위, 문장 부호, 존댓말 수준)을 정해 두고 지킨다. 일관된 경험이 안정감을 주고, 그것이 브랜드에 대한 신뢰가 된다.

### 8. 브랜드의 목소리가 담겼는가

브랜드다움을 글로 드러내는 도구가 **보이스 톤**(voice and tone)이다. 보이스는 늘 같은 개성이고, 톤은 상황(축하, 오류, 경고)에 따라 조절하는 온도다.

- "다른 서비스가 친근하니까 우리도"로 정하면 오히려 개성이 사라진다. 브랜드 이미지와 브랜드 퍼소나에서 출발한다.
- 공개된 보이스 톤 가이드(국내 토스, 해외 Mailchimp 등)를 참고해 구조를 빌린다.

## 정리

- UX 라이팅은 사용자가 화면에서 멈추지 않고 목표를 이루게 하는 글이다.
- 원칙(왜) → 가이드라인(어떻게) → 체크리스트(검토 질문)로 문서를 쌓고, 가이드라인은 조직 전체가 합의한 규범으로 만든다.
- 문구는 화면 목표에 맞는지, 짧고 훑어보기 좋은지, 목적이 먼저 보이는지, 사용자의 말인지 확인한다.
- 다크 패턴은 신뢰와 데이터를 함께 망치고 법적 규제 대상이기도 하다.
- **일관성과 보이스 톤이 쌓여 브랜드가 된다.**
