## 웹은 크기가 정해지지 않은 매체다

인쇄 디자인과 웹 디자인은 선·도형·색·균형·대비·여백·게슈탈트 같은 **기본기가 같다.** 좋은 것과 나쁜 것을 알아보는 눈, 좋은 결과를 위한 인내가 둘 다 핵심이다. 다른 것은 매체의 성질이다.

| 항목 | 인쇄 | 웹 |
| --- | --- | --- |
| 캔버스 | 너비·높이가 고정된 페이지. 네 가장자리 모두 기준이 된다 | 너비가 기기마다 다르고 세로는 스크롤로 무한하다. 확실한 기준은 위쪽 가장자리뿐이다 |
| 결과 확인 | 인쇄소에서 실물을 보고 확정한다 | 브라우저·기기·화면 설정·사용자 글꼴 크기가 제각각이라 **결과를 확정할 수 없다** |
| 도구 | 상자를 끌어다 놓으면 그대로 남는 WYSIWYG | 코드가 최종 결과물이다. 디자인 도구는 의도를 전달하는 시안이다 |
| 글꼴 | 어떤 글꼴이든 쓴다 | 웹폰트 라이선스와 파일 용량을 고려한다. 가변 폰트(variable font) 하나로 여러 굵기를 담을 수 있다 |
| 해상도 | 300dpi 출력 기준 | CSS 픽셀은 논리 단위다. 실제 기기 픽셀 밀도는 1x~3x로 다양하다 |

"72ppi 웹 해상도"는 과거의 관행이다. 지금은 CSS 픽셀과 기기 픽셀 비율을 구분하고, 고밀도 화면에는 벡터나 여러 해상도 이미지를 준다. 자세한 내용은 [[responsive-design|반응형 디자인과 다국어 타이포그래피]]와 [[responsive-images|반응형 이미지: srcset·sizes와 picture]]에 있다.

## 인쇄의 스타일 개념은 CSS와 닮았다

InDesign 같은 편집 도구의 스타일 체계는 CSS로 거의 그대로 옮겨진다. 편집 디자이너가 웹으로 넘어올 때 가장 쉽게 이어지는 부분이다.

| 편집 도구 | CSS | 공통점 |
| --- | --- | --- |
| 단락 스타일 (글꼴, 크기, 색, 들여쓰기, 단락 간격) | `p`, `h2` 같은 블록 요소 규칙 | 한 곳을 고치면 문서 전체에 반영된다 |
| 문자 스타일 (글꼴, 색. 간격은 못 바꿈) | `strong`, `em`, `span` 같은 인라인 요소 규칙 | 줄 안의 일부만 꾸민다 |
| 다단 텍스트 | `columns` (multi-column) | 긴 글을 여러 단으로 흘린다 |
| 커닝 | `font-kerning`, `letter-spacing` | 글꼴의 커닝 정보를 쓰거나 자간을 조절한다 |

## 본질의 웹 디자인 (Intrinsic Web Design)

본질의 웹 디자인은 젠 시먼스(Jen Simmons)가 2018년에 붙인 이름으로, **CSS에 내장된(intrinsic) 레이아웃 기능만으로 콘텐츠에 맞게 늘고 줄어드는 레이아웃을 만드는 방식**이다.

```text
테이블 레이아웃 ─→ float·position 편법 ─→ 편법을 묶은 CSS 프레임워크·JS 그리드
        ─→ 플렉스박스 + CSS 그리드 + 컨테이너 쿼리 (CSS가 직접 레이아웃을 이해)
```

과거에는 원하는 배치를 위해 float와 절대 위치를 섞는 편법, 그리고 그 편법을 모은 프레임워크가 필요했다. 지금은 CSS 자체가 레이아웃 도구다.

| 기능 | 하는 일 |
| --- | --- |
| 플렉스박스 | 한 방향으로 늘어놓고 남는 공간을 나눈다 |
| CSS 그리드 | 행과 열을 함께 다룬다. `fr`, `minmax()`, `auto-fill`로 열 개수가 콘텐츠에 맞게 바뀐다 |
| 서브그리드 | 중첩된 요소가 부모 그리드 선에 맞춘다 |
| 컨테이너 쿼리 | 화면이 아니라 **컴포넌트가 놓인 공간**의 크기에 반응한다 |
| `aspect-ratio`, `object-fit` | 이미지·영상의 비율을 지키며 칸을 채운다 |
| `shape-outside`, multi-column | 인쇄물처럼 글이 도형을 감싸거나 여러 단으로 흐른다 |

반응형 웹 디자인이 "화면 크기마다 브레이크포인트로 바꾼다"였다면, 본질의 웹 디자인은 **"콘텐츠와 공간에 맞게 스스로 크기를 정하게 한다"**에 가깝다. 고정 칼럼 수와 유동 칼럼, 고정 크기와 비율을 한 페이지에서 섞는다. 그래서 레이아웃 아이디어가 다시 잡지처럼 다양해질 수 있다.

디자이너가 코드를 쓰지 않더라도 이 기능들로 **무엇이 가능한지** 알면 시안이 달라진다. 구현은 [[css-grid|CSS 그리드 레이아웃]]과 [[flexbox|Float와 Flexbox 레이아웃]]에 있다.

## 이미지 위에 텍스트 올리기

큰 배경 이미지와 짧은 문구 조합은 랜딩 페이지의 단골 레이아웃이다. 두 가지를 먼저 확인한다.

- **용량.** 큰 이미지는 로딩을 늦추고 이탈을 늘린다. 장식용 배경이라면 정보 가치에 비해 비싼지 따져 본다. 어두운 영역, 흐림(아웃포커스), 단색 하늘·물처럼 **디테일이 적은 사진**은 압축이 잘되고 텍스트 놓을 자리도 넉넉하다.
- **구체성.** 모호한 분위기 사진보다 메시지를 바로 전하는 구체적인 이미지를 고른다. 이미지의 분위기와 문구의 어조가 맞아야 한다.

그다음 세 가지로 텍스트를 읽히게 한다.

| 방법 | 내용 |
| --- | --- |
| 1. 대비 | 이미지에 어두운 오버레이를 깔거나 `filter: brightness()`로 밝기를 낮춘다. 흰 글자가 사진의 밝은 부분과 겹치면 읽히지 않는다. 명암만이 아니라 보색 대비도 쓸 수 있다. 텍스트 대비 기준(4.5:1)은 이미지 위에서도 같다 |
| 2. 크기와 위치 | 같은 사진에서도 글자를 비어 있는 하늘 쪽으로 옮기기만 해도 가독성이 확 오른다. 바닥처럼 글자와 비슷한 색의 영역은 피한다 |
| 3. 심도 | 초점이 맞은 피사체 위가 아니라 **흐린 배경 영역**에 텍스트를 둔다. 흐린 영역은 사실상 단색 배경처럼 작동한다 |

```css
.hero {
  background: linear-gradient(rgb(0 0 0 / .45), rgb(0 0 0 / .45)),
              url(hero.avif) center / cover;
  color: #fff;
}
```

반응형에서는 화면 비율이 바뀌면 이미지가 잘리는 위치도 바뀐다. `object-position`이나 `<picture>`의 아트 디렉션으로 텍스트 자리와 초점이 겹치지 않게 한다.

## 정리

- 인쇄와 웹은 기본기가 같고 매체가 다르다. 웹은 **크기와 결과를 확정할 수 없는** 매체다.
- 편집 도구의 단락·문자 스타일은 CSS의 블록·인라인 규칙으로 이어진다.
- 본질의 웹 디자인은 플렉스박스·그리드·컨테이너 쿼리로 콘텐츠에 맞게 스스로 크기를 정하는 레이아웃이다.
- 이미지 위 텍스트는 대비, 위치, 심도로 읽히게 하고, 이미지 용량을 함께 따진다.
