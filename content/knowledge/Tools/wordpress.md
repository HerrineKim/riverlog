## 워드프레스란

워드프레스(WordPress)는 PHP와 MySQL(MariaDB)로 돌아가는 오픈 소스 콘텐츠 관리 시스템(CMS)이다. 2003년 블로그 도구 b2/cafelog를 포크해 시작했고, 지금은 블로그를 넘어 회사 사이트, 쇼핑몰(WooCommerce), 뉴스 사이트까지 만드는 범용 CMS다. 전체 웹사이트의 약 40%, CMS를 쓰는 사이트 가운데서는 약 59%가 워드프레스로 돌아간다([W3Techs](https://w3techs.com/technologies/details/cm-wordpress), 2026년 10월).

| 구분 | 내용 |
| --- | --- |
| wordpress.org | 직접 설치해 쓰는 오픈 소스 소프트웨어. 호스팅은 알아서 고른다 |
| WordPress.com | Automattic이 운영하는 호스팅 서비스. 설치 없이 바로 쓴다 |
| 편집기 | 블록 에디터(Gutenberg)가 기본이다. 과거에는 하나의 큰 텍스트 상자에 글을 쓰는 클래식 에디터였다 |
| 테마 | 사이트의 생김새. 블록 테마는 `theme.json`과 사이트 편집기로 머리글·바닥글까지 코드 없이 바꾼다 |
| 플러그인 | 기능 확장. 공식 디렉터리에 수만 개가 있다 |

인기의 이유는 단순하다. **쉽고 싸다.** 소프트웨어는 무료이고, 기술을 몰라도 사이트를 만들 수 있으며, 플러그인과 테마로 거의 모든 요구를 채운다.

## 설계 철학

wordpress.org가 밝힌 철학은 CMS를 넘어 제품 설계 일반에 통하는 원칙이다.

| 원칙 | 내용 |
| --- | --- |
| 설치 즉시 동작(Out of the Box) | 따로 설정하지 않아도 바로 동작해야 한다. 설치는 몇 분이면 끝난다 |
| 다수를 위한 디자인 | 사용자 대부분은 AJAX나 PHP 버전에 관심이 없다. 그냥 글을 쓰고 싶다 |
| 옵션이 아닌 결정(Decisions, not Options) | 옵션을 하나 줄 때마다 사용자에게 결정을 떠넘긴다. 이해 못 하는 옵션은 불만만 남긴다. 현명한 기본값을 정하는 것이 개발자의 일이다 |
| 가볍게(Clean, Lean, and Mean) | 코어에는 사용자 80% 이상이 실제로 쓸 기능만 넣는다. 나머지 20%는 플러그인과 테마가 맡는다 |
| 계속 단순하게 | 수동으로 하던 업데이트를 클릭 한 번으로, 지금은 자동 업데이트로 바꿔 온 것처럼 매 버전 더 쉬워져야 한다 |
| 마감은 임의가 아니다 | 출시 일정은 약속이다. 마감은 기능을 덜어 내게 해 준다. 출시를 미뤄 기능 하나를 더 넣으면 지연이 지연을 낳는다. 자주, 규칙적으로 내면 이번에 빠진 기능도 곧 다음 버전에 들어간다 |
| 목소리 큰 소수 | 포럼에 의견을 남기는 사람은 실사용자의 1%도 안 된다. 그들의 말을 듣되, 행사 등에서 조용한 다수를 직접 만나 균형을 잡는다 |
| 권리 장전(GPL) | GPLv2 이상 라이선스로 실행·학습·수정·재배포의 네 가지 자유를 보장한다. 테마와 플러그인 같은 파생 저작물에도 이어진다 |

오픈 소스 도구에 익숙한 직원들은 몇 초면 끝날 일을 몇 분씩 붙잡게 하는 낡은 사내 CMS를 참지 않는다. 오픈 소스 CMS가 기업 시스템으로 들어가는 이유다.

## 테마 고르기

선택지가 거의 무한하면 오히려 나쁜 테마를 고르기 쉽다. **원하는 것을 먼저 정하고** 아래 기준으로 거른다.

| 기준 | 확인 방법 |
| --- | --- |
| 품질과 유지보수 | 최근 업데이트 이력, 지원 포럼에서 개발자가 문제를 어떻게 푸는지 본다. 오래 방치된 테마는 보안과 호환성이 무너진다 |
| 무료 vs 유료 | 가격은 더 이상 품질의 지표가 아니다. 유료는 잦은 업데이트·문서·지원이 장점이고, 대신 관리 패널이 복잡하고 안 쓰는 기능(슬라이더, 포트폴리오 관리자)으로 무겁다 |
| 무게 | 데모 주소를 PageSpeed Insights나 WebPageTest에 넣어 요청 수와 로딩 시간을 본다. 슬라이더·애니메이션 스크립트가 잔뜩 붙은 테마는 피한다 |
| 디자인과 UX | 데모를 직접 써 본다. 여백, 가독성, 접근성, 여러 브라우저 동작을 확인한다 |
| 반응형 | 모든 화면 크기에서 동작해야 한다. 지금 쓸 만한 테마는 거의 다 반응형이지만 데모를 휴대폰으로 열어 본다 |
| 검색 최적화 | "SEO ready" 표시를 그대로 믿지 않는다. 제목 구조, 이미지 대체 텍스트, 중복 콘텐츠를 직접 확인한다 |
| 사용자 정의 | 블록 테마라면 사이트 편집기에서 원하는 만큼 바뀌는지 시험한다 |
| 보안과 평판 | 다운로드 수와 리뷰가 많은 곳(공식 디렉터리, 리뷰가 공개된 마켓)에서 고른다. 만든 사람·회사의 평판이 가장 좋은 지표다 |

결국 기준은 하나로 모인다. **잘 만들어진 테마를 고른다.** 완벽한 테마는 없으니 핵심 요구에서 타협하지 않는 선을 찾는다.

## 사이트를 빠르게 하는 순서

빠른 사이트는 사용자 경험, 검색 순위, 전환율을 모두 올린다. 성능 개선은 한 번의 작업이 아니라 **측정 → 원인 분리 → 개선 → 재측정**의 반복이다.

```text
1. 기준 측정   PageSpeed Insights(Core Web Vitals), WebPageTest
2. 원인 분리   Query Monitor로 느린 쿼리·훅 확인, 플러그인을 하나씩 꺼 보고 테마를 바꿔 본다
3. 호스팅      싸다고 좋은 게 아니다. 관리형 워드프레스 호스팅은 캐시·백업·보안을 기본 제공한다
4. 군살 빼기   플러그인 최소화, 오래 방치된 플러그인 제거, 댓글 스팸 정리(Akismet), 필요 없으면 댓글 끄기
5. 자산 줄이기 CSS·JS 압축·결합, 이미지 압축과 WebP·AVIF, 지연 로딩(기본 내장)
6. 캐시        페이지 캐시 플러그인이나 호스팅 캐시로 PHP·DB 실행 없이 정적 HTML 제공
7. CDN         방문자가 많거나 전 세계 대상이면 정적 자산을 CDN에서 제공
```

플러그인을 고를 때는 평점, 활성 설치 수, 최근 업데이트, 지원 포럼 응답을 본다. **확신이 없으면 설치하지 않는다.** 잘 만든 사이트는 대개 플러그인이 적다.

## 반응형 테마를 만들 때

워드프레스는 테마의 프런트엔드에 무엇을 쓰든 관여하지 않는다. 어떤 CSS 기법이나 JS 라이브러리도 쓸 수 있다. 워드프레스에서 특히 챙길 것은 **미디어**다.

- 편집기로 넣은 이미지와 동영상이 화면 폭을 넘지 않게 유동 미디어 CSS를 둔다. 워드프레스는 업로드 이미지에 여러 크기를 만들고 `srcset`을 자동으로 붙인다.
- 반응형은 고정 레이아웃보다 조금 더 어렵다. 디자인이니까 어렵다. 브라우저 창을 수시로 줄였다 늘리며 시험하는 습관이 가장 좋은 교재다.

## 실력을 쌓는 길

| 단계 | 할 일 |
| --- | --- |
| 꾸준히 배운다 | 하루 한 시간처럼 방해 없는 학습 시간을 정한다. 공식 개발자 문서(developer.wordpress.org)와 Learn WordPress에서 시작한다 |
| 기술을 이해한다 | PHP·MySQL을 최신 기준으로 익힌다. 코어 코드를 읽고, `WP_Query`·`wpdb` 같은 핵심 클래스와 훅·REST API·블록 API를 직접 써 본다 |
| 직접 만든다 | 튜토리얼을 따라 한 뒤 혼자 다시 만든다. 배운 것과 해결책을 기록한다 |
| 실전 경험 | 고객 일을 한다. 혼자서는 만나지 못할 문제를 만난다. 목표는 수백이 아니라 수천 시간이다 |
| 공개 작업 | 테마·플러그인을 공개하고 사용자 피드백으로 고친다. 이미 넘치는 분야에 하나 더 얹지 말고 실제 필요를 채운다 |
| 디버깅 | `WP_DEBUG`, Query Monitor로 문제를 찾는다 |
| 커뮤니티 | 지원 포럼과 WordPress Stack Exchange에서 질문에 답하고, 문서를 고치고, 패치를 보내고, WordCamp에 참여한다. make.wordpress.org에서 코어 논의를 따라간다 |

가르칠 수 있어야 전문가다. 성공의 일부는 생태계에 되돌려 준다.

## 워드프레스 생태계의 비즈니스

코어는 무료인데 수많은 사람이 워드프레스로 먹고산다. GPL 아래에서 **코드는 자유롭게, 돈은 서비스와 지원에서** 나온다.

| 모델 | 돈이 나오는 곳 |
| --- | --- |
| 테마 판매·마켓 | 디자인 품질, 업데이트, 지원. 무료 테마와 가격으로는 못 싸우니 품질로 승부한다 |
| 프리미엄(freemium) 플러그인 | 기본은 무료로 배포하고, 추가 기능·업데이트·지원을 판다. 무료 플러그인에 지원 요청이 밀려들 때 자연스럽게 생긴다 |
| 관리형 호스팅 | 트래픽 폭주에도 버티는 서버, 캐시, 백업, 보안을 묶어 판다 |
| 컨설팅·개발 | 플러그인·테마 선택과 함정을 미리 아는 경험, 비즈니스 목표에 맞춘 범위 조정 |
| 번역·다국어 | 다국어 사이트를 만드는 도구와 번역 서비스 |

공통 패턴은 **자기 불편에서 출발**했다는 것이다. 트래픽이 몰릴 때마다 블로그가 죽는 문제가 호스팅 회사가 되고, 번역의 고통이 번역 서비스가 된다. 다만 좋은 아이디어가 모두 좋은 비즈니스는 아니다. 시장에서 직접 확인해야 하고, 수익이 나기까지 몇 달이 걸린다. 프로젝트 값을 정하는 법은 [[project-pricing|웹 프로젝트 가격 책정]]에 따로 정리했다.

## 정리

- 워드프레스는 쉽고 무료라서 웹의 큰 몫을 차지한다. 블록 에디터와 블록 테마가 지금의 기본이다.
- "옵션이 아닌 결정", 80% 규칙, 마감 지키기는 어떤 제품에도 통하는 설계 원칙이다.
- 테마는 가격보다 품질·업데이트·무게·평판으로 고른다.
- 속도는 측정에서 시작한다. 호스팅, 플러그인 정리, 자산 압축, 캐시, CDN 순으로 손댄다.
- 실력은 학습·실전·공개 작업·커뮤니티 기여로 쌓이고, 생태계의 돈은 코드가 아니라 서비스에서 나온다.
