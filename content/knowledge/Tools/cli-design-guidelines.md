> Command Line Interface Guidelines(「[clig.dev](https://clig.dev/)」)와 Node Weekly(2026.07)가 소개한 Liran Tal의 「[Node.js CLI Apps Best Practices](https://github.com/lirantal/nodejs-cli-apps-best-practices)」를 바탕으로 재구성한 노트다.

## CLI도 사용자 인터페이스다

명령줄 도구는 예전에 다른 프로그램이 부르는 부품으로 설계됐다. 지금은 사람이 가장 많이 쓰는 인터페이스이자, 셸 스크립트와 **AI 코딩 에이전트**가 호출하는 API이기도 하다. 좋은 CLI는 이 셋을 함께 만족시킨다. 사람에게는 친절하고, 프로그램에게는 예측 가능하다.

| 원칙 | 뜻 |
| --- | --- |
| 사람이 먼저(human-first) | 주 사용자가 사람이면 사람 기준으로 설계한다. 기계용 출력은 옵션으로 더한다 |
| 조합되는 부품 | stdin·stdout·stderr, 종료 코드, 시그널, 줄 단위 텍스트와 JSON으로 다른 도구와 이어진다([[shell-pipeline\|셸이 명령을 실행하는 방식]]) |
| 일관성 | 기존 관례를 따른다. 깨야 하면 이유를 갖고 의도적으로 깬다 |
| 딱 필요한 만큼 말하기 | 오래 걸리는데 침묵하지도, 화면을 쏟아 내지도 않는다 |
| 쉬운 발견 | 도움말, 예시, 다음에 칠 명령 제안, 오류 힌트 |
| 대화로서의 사용 | 사용은 여러 번 주고받는 대화다. 오타를 고쳐 주고, 상태를 보여 주고, 위험하면 확인한다 |
| 견고함과 공감 | 잘못된 입력을 우아하게 다루고, 사용자가 성공하기를 바라는 쪽에 선다 |

## 기본: 종료 코드와 두 출력 스트림

| 규칙 | 이유 |
| --- | --- |
| 성공은 `0`, 실패는 0이 아닌 값 | 스크립트·CI·`&&`가 종료 코드로 성공을 판단한다. 주요 실패 유형마다 코드를 나누고 문서에 적는다. 관례로 `2`는 사용법 오류, `130`(128+SIGINT)은 Ctrl-C 중단이다 |
| 결과는 stdout, 나머지는 stderr | 진행 메시지·경고·오류를 stderr로 보내야 `mycli --json \| jq`가 깨지지 않는다 |
| 인자 파싱은 라이브러리로 | 직접 파싱하면 `--flag=value`, 묶음 단축 플래그(`-abc`), `--` 같은 POSIX 관례를 놓친다. Node.js는 내장 `util.parseArgs`나 commander·yargs 같은 프레임워크를 쓴다 |

Node.js에서는 `process.exit(1)` 대신 `process.exitCode = 1`을 정하고 이벤트 루프가 자연히 끝나게 한다. `process.exit()`는 아직 쓰이지 않은 stdout 출력을 잘라 먹을 수 있다.

## 도움말

- `-h`와 `--help`는 어디에 붙어도 전체 도움말을 보여 주고, 다른 인자는 무시한다. `-h`를 다른 뜻으로 쓰지 않는다.
- 필수 인자 없이 실행하면 짧은 도움말(설명 한 줄, 예시 1~2개, 주요 플래그, `--help` 안내)을 보여 준다.
- **예시를 먼저 보여 준다.** 사람은 설명보다 예시를 복사한다. 자주 쓰는 플래그와 명령을 위에 둔다.
- 웹 문서와 이슈 제기 경로를 도움말에 링크한다.
- 오타면 「혹시 `mycli status`인가요?」처럼 제안하되 **묻지 않고 고쳐서 실행하지 않는다.** 조용한 자동 교정은 틀린 문법을 굳히고, 나중에 그 이름의 명령이 생기면 동작이 바뀐다.
- stdin으로 입력을 기대하는데 터미널에서 그냥 실행됐으면 멈춰 기다리지 말고 도움말을 보여 준다.

## 출력

### 사람용과 기계용

**TTY 감지**로 사람이 보고 있는지 판단한다. stdout이 터미널이 아니면(파이프·파일·CI) 색, 애니메이션, 진행 막대를 끈다.

| 옵션 | 쓰임 |
| --- | --- |
| 기본 출력 | 사람용. 바뀌어도 되는 형식이다 |
| `--json` | 구조화된 출력. 스크립트와 에이전트가 쓴다 |
| `--plain` | 한 줄에 한 레코드인 안정된 표 형식. `grep`·`awk`용 |
| `-q`, `--quiet` | 꼭 필요하지 않은 출력을 끈다 |
| `--verbose`, `--debug` | 개발자용 세부 정보. 기본으로는 숨긴다 |

- 성공 출력은 짧게, 하지만 **상태를 바꿨으면 무엇을 바꿨는지** 말하고 다음에 칠 명령을 제안한다(`git status`, `git commit` 뒤의 안내처럼).
- 프로그램 범위 밖에 영향을 주는 동작(요청하지 않은 파일 읽기·쓰기, 네트워크 요청)은 드러낸다.
- stderr를 로그 파일처럼 쓰지 않는다. `ERR`·`WARN` 같은 레벨 표시는 verbose 모드에서만.
- 출력이 길면 TTY일 때만 페이저(`less -FIRX`)를 쓴다.

### 색

색은 의미가 있을 때만 쓰고, 다음 중 하나라도 해당하면 끈다.

- 해당 스트림(stdout, stderr 각각)이 TTY가 아니다.
- 환경 변수 `NO_COLOR`가 비어 있지 않다.
- `TERM=dumb`이다.
- `--no-color`를 받았다(도구 전용 `MYAPP_NO_COLOR`도 둘 수 있다).

반대로 `FORCE_COLOR`가 있으면 켠다. 빨간색은 아껴 써야 눈에 띈다.

## 인자와 플래그

- **인자보다 플래그.** 플래그는 이름이 있어 읽기 쉽고 나중에 늘리기 쉽다. 위치 인자는 `cp <src> <dst>`처럼 주 동작이 분명할 때만 여럿 둔다.
- 모든 플래그에 긴 이름을 주고, 짧은 이름은 자주 쓰는 것에만 준다.
- 기존 관례의 이름을 쓴다.

| 플래그 | 뜻 |
| --- | --- |
| `-a`, `--all` | 전부 |
| `-d`, `--debug` | 디버그 출력 |
| `-f`, `--force` | 확인 없이 강제 |
| `-n`, `--dry-run` | 실제로 바꾸지 않고 무엇을 할지만 보여 줌 |
| `-o`, `--output` | 출력 파일 |
| `-q`, `--quiet` | 조용히 |
| `--json`, `--no-input`, `--version` | 기계 출력, 프롬프트 금지, 버전 |

- `-v`는 verbose와 version 사이에서 모호하니 피한다.
- `-`는 stdin·stdout을 뜻하게 한다.
- 인자·플래그·하위 명령의 순서에 의존하지 않게 한다.
- **시크릿을 플래그로 받지 않는다.** 셸 기록과 `ps` 출력에 남는다. `--password-file`이나 stdin으로 받는다([[secrets-management|시크릿 관리]]).

## 대화형 동작

- 프롬프트는 **stdin이 TTY일 때만** 띄운다. CI·파이프에서 프롬프트가 뜨면 영원히 멈춘다.
- `--no-input`이면 모든 프롬프트를 끄고, 입력이 필요하면 **어느 플래그로 주면 되는지** 알려 주며 실패한다.
- 빠진 값을 프롬프트로 물을 수는 있지만 **프롬프트를 유일한 방법으로 만들지 않는다.** 같은 값을 플래그로도 받는다.
- 비밀번호 입력은 화면에 표시하지 않는다.

위험한 작업은 위험도에 맞춰 확인한다.

| 위험도 | 예 | 확인 |
| --- | --- | --- |
| 가벼움 | 파일 하나 삭제 | 선택 |
| 중간 | 디렉터리·원격 리소스 삭제 | 프롬프트, `--dry-run` 제공 |
| 심각 | 앱·서버 전체 삭제 | 이름을 직접 입력하게 하는 확인 + 스크립트용 `--confirm="<이름>"` |

## 견고함

- **입력을 일찍 검증하고**, 무언가 바꾸기 전에 실패한다.
- **100ms 안에 무언가 출력한다.** 속도보다 반응이 중요하다. 네트워크 요청 전에 무엇을 하는지 먼저 찍는다.
- 오래 걸리면 진행 상황(남은 시간 추정이나 움직이는 표시)을 보여 준다. 병렬 진행은 줄이 섞이지 않게 라이브러리로 그리고, 오류가 나면 숨긴 로그를 보여 준다.
- 네트워크 타임아웃은 적당한 기본값을 두고 설정할 수 있게 한다.
- **다시 실행하면 이어서 하게** 만든다. 멱등하고(idempotent) 크래시 전용(crash-only)으로 설계한다. 실패하면 바로 끝내고, 정리는 다음 실행이 맡는다.
- 오용을 예상한다: 스크립트 호출, 나쁜 네트워크, 동시 실행, 낯선 환경.

### 시그널

- Ctrl-C(SIGINT)를 받으면 **즉시 무언가 출력하고** 최대한 빨리 끝낸다. 정리 작업에는 시간 제한을 둔다.
- 정리가 오래 걸리거나 위험하면 두 번째 Ctrl-C로 정리를 건너뛰게 하고, 그것이 무엇을 뜻하는지 알려 준다.
- 이전 실행의 정리가 안 됐을 수 있다고 가정한다.
- 컨테이너의 PID 1로 돌면 시그널 기본 동작이 달라지므로 직접 처리한다([[dockerfile|Dockerfile 작성과 컨테이너의 PID 1]]).

## 오류

- 예상되는 오류는 잡아서 **사람 말로 다시 쓰고 해결책을 붙인다.** 「EACCES」 대신 「`/etc/foo`에 쓸 권한이 없다. `sudo`로 실행하거나 `--output`으로 다른 경로를 지정하라」.
- 같은 오류가 반복되면 한 제목 아래 묶는다. 가장 중요한 정보는 마지막 줄에 둔다(사람의 눈이 거기서 멈춘다).
- 오류마다 코드를 붙이고 문서로 연결하면 검색과 지원이 쉬워진다.
- 예상 못 한 오류는 디버그 정보를 파일로 남기고, 내용이 채워진 이슈 링크로 버그 제보를 쉽게 한다. 버전 정보를 함께 찍는다.

## 설정

| 종류 | 예 | 두는 곳 |
| --- | --- | --- |
| 실행마다 다른 것 | 디버그 수준, dry run | 플래그 |
| 사용자·기계마다 다른 것 | 프록시, 색 설정 | 플래그, 환경 변수, 사용자 설정 파일 |
| 프로젝트마다 공유하는 것 | `Makefile`, `docker-compose.yml` 같은 것 | 버전 관리되는 프로젝트 설정 파일 |

```mermaid
flowchart LR
  f["플래그"] --> e["셸 환경 변수"] --> p["프로젝트 설정 (.env 등)"] --> u["사용자 설정 (~/.config)"] --> s["시스템 설정"]
```

왼쪽이 가장 우선한다. 사용자 설정은 XDG Base Directory 규약(`~/.config/<도구>`)을 따른다. 내 것이 아닌 설정 파일을 고치려면 먼저 묻고, 덧붙이기보다 새 파일을 만든다.

환경 변수는 이름에 대문자·숫자·밑줄만 쓰고, `NO_COLOR`, `FORCE_COLOR`, `DEBUG`, `EDITOR`, `PAGER`, `HTTP_PROXY`·`NO_PROXY`, `TMPDIR`, `HOME`, `TERM` 같은 기존 변수를 존중한다. `.env`는 프로젝트 설정을 읽는 곳이지 제대로 된 설정 파일의 대체물이 아니다. **시크릿은 환경 변수로도 받지 않는 편이 낫다.** 프로세스 목록, 로그, `docker inspect`로 샌다. 자격 증명 파일이나 시크릿 매니저를 쓴다.

## 하위 명령과 하위 호환

- 하위 명령끼리 플래그 이름과 출력 형식을 맞춘다. `docker container create`처럼 `명사 동사` 순서가 흔하다.
- `update`와 `upgrade`처럼 헷갈리는 이름을 나란히 두지 않는다.
- **하위 명령, 인자, 플래그, 설정 파일, 환경 변수는 모두 인터페이스다.** 바꾸면 누군가의 스크립트가 깨진다([[semantic-versioning|유의적 버전]]).
- 변경은 가능하면 추가로 한다. 깨는 변경은 프로그램 안에서 미리 경고하고 이전 방법을 알려 준다.
- 사람용 출력은 바뀌어도 된다. 그래서 스크립트에는 `--plain`·`--json`을 쓰라고 안내한다.
- 아무 명령이나 받아 주는 기본 하위 명령과 임의 접두어 축약(`ins` → `install`)을 두지 않는다. 나중에 그 이름의 명령을 못 만든다. 축약이 필요하면 명시적인 별칭을 둔다.

## 에이전트가 쓰기 좋은 CLI

코딩 에이전트는 셸로 CLI를 부르고 출력을 읽는다. 위 원칙 중 몇 가지가 에이전트에게 특히 중요하다.

| 원칙 | 에이전트에게 주는 것 |
| --- | --- |
| `--json` 출력 | 표를 파싱하지 않고 필드를 읽는다 |
| TTY 감지, `--no-input` | 프롬프트에 걸려 멈추지 않는다 |
| 정확한 종료 코드 | 성공·실패를 출력 문구가 아니라 코드로 판단한다 |
| 해결책을 담은 오류 | 다음 시도를 스스로 고친다 |
| `--dry-run`, 위험 작업 확인 | 믿을 수 없는 호출자의 실수를 CLI 수준에서 막는다 |
| 짧은 기본 출력, `-q` | 맥락 창을 덜 채운다 |

Liran Tal의 가이드는 같은 원칙을 에이전트가 읽을 수 있는 `SKILL.md`로도 제공한다. 에이전트용 CLI를 따로 만들 때의 설계(JSON 페이로드 입력, 스키마 인트로스펙션)와 MCP와의 선택 기준은 [[model-context-protocol|MCP의 구조와 CLI와의 선택 기준]]에 있다.

## Node.js CLI 실무

| 항목 | 내용 |
| --- | --- |
| `bin` 필드 | `package.json`의 `bin`을 객체로 써서 실행 파일 이름을 패키지 이름과 분리한다 |
| 셔뱅 | `#!/usr/bin/env node`. 절대 경로를 박지 않는다 |
| `files` 필드 | 게시할 파일만 화이트리스트로 넣어 패키지를 작게 한다 |
| 작은 의존성 | `npx`로 실행되는 CLI는 설치 시간이 곧 첫 실행 시간이다. 내장 `util.parseArgs`, `util.styleText`로 줄인다([[small-modules\|작은 모듈 철학]]) |
| 지원 Node 버전 | 지원하지 않는 런타임에서는 알기 쉬운 메시지로 끝낸다 |
| 경로 | 사용자가 준 경로는 `process.cwd()` 기준, 패키지 안 파일은 모듈 위치 기준으로 푼다 |
| 크로스 플랫폼 | 경로는 `path.join`, 셸 문법(`;`, 따옴표) 의존을 피한다 |
| 상태 저장 | 설정·캐시는 XDG 경로에. 삭제 방법을 문서화한다(npm에는 제거 훅이 없다) |
| 버전 | `--version`, 유의적 버전, 오류·도움말에 버전 표시, 변경 기록 |
| 분석 | 사용 통계는 명시적 동의(opt-in)로만, 무엇을 모으는지 공개한다 |
| 보안 | 신뢰할 수 없는 입력이 파일 접근·명령 실행 플래그로 흘러드는 인자 주입을 막는다 |
| 배포 | Node가 없는 사용자를 위해 Docker 이미지나 단일 실행 파일도 고려한다 |

## 정리

- 종료 코드와 stdout·stderr 구분이 모든 조합의 바탕이다.
- 사람용 기본 출력과 기계용 `--json`·`--plain`을 함께 두고, TTY가 아니면 색·애니메이션·프롬프트를 끈다.
- 표준 플래그 이름을 쓰고, 위험한 작업은 위험도에 맞춰 확인하고, 시크릿은 플래그·환경 변수로 받지 않는다.
- 100ms 안에 반응하고, 다시 실행하면 이어서 하고, Ctrl-C는 늘 통하게 한다.
- 명령·플래그·설정은 인터페이스다. 에이전트도 그 인터페이스의 사용자다.
