> 가정용 장비로 커뮤니티 서비스를 운영할 때의 점검 항목을 종합하고, 무료 클라우드 한도는 Oracle의 「[Always Free Resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)」 문서로 확인해 정리한 노트다.

## 가정용 장비가 먼저 막히는 지점

집의 노트북이나 미니 PC는 개인 프로젝트와 소규모 서비스에는 충분하다. 사용자가 늘면 CPU보다 **장비와 회선의 물리적 조건**이 먼저 한계가 된다.

| 지점 | 문제 | 대응 |
| --- | --- | --- |
| 배터리와 발열 | 노트북을 전원에 꽂은 채 24시간 돌리면 배터리가 부풀고(스웰링) 열이 쌓인다 | 충전 상한을 걸거나 배터리를 분리하고, 가능하면 미니 PC로 옮긴다 |
| 업로드 대역폭 | 가정용 회선은 내려받기보다 올리기가 느리고, 하루 사용량을 넘기면 속도를 제한(QoS)하는 약관이 있다 | 약관의 일일 트래픽 한도를 확인하고, 이미지 같은 큰 파일은 밖으로 뺀다 |
| 전원 | 정전이나 실수로 뽑힌 플러그가 곧 서비스 중단이다 | UPS를 달고, 전원이 돌아오면 자동으로 켜지게 설정한다 |
| 디스크 | 디스크 하나가 죽으면 데이터가 사라진다 | DB 디스크는 RAID 1로 미러링하고, 별도로 외부 백업을 둔다. RAID는 백업이 아니다 |
| 가용성 | 장비가 한 대라 재부팅·업데이트가 곧 중단이다 | 집 밖에서 접속할 길(VPN)과 상태 알림을 둔다 |

동시 접속이 100명을 넘어가는 서비스라면 월 몇만 원대 VPS나 클라우드로 옮기는 편이 운영 부담까지 따졌을 때 싸다.

## 사양을 올리기 전에 볼 것

느려졌을 때 원인이 사양인 경우는 생각보다 적다. 다음 순서로 본다.

1. **실제 사용자 수를 센다.** 접속의 대부분이 크롤러와 봇인 경우가 흔하다. 봇을 막고 나면 2코어 4GB 서버로 충분한 서비스가 많다.
2. **반복 조회를 캐싱한다.** 목록, 인기글처럼 모두에게 같은 결과를 주는 조회를 매번 DB에서 읽으면 작은 서버가 먼저 버벅인다. [[redis|Redis]] 같은 캐시에 올리면 체감 성능이 크게 오른다([[caching-strategies|캐싱 전략]]).
3. **정적 파일을 분리한다.** 이미지와 첨부 파일은 오브젝트 스토리지와 [[cdn|CDN]]으로 보낸다. 가정용 회선의 업로드 대역폭을 가장 많이 먹는 것이 이 트래픽이다.
4. **커널 한도를 확인한다.** 동시 연결이 많아지면 사양이 남아도 한도에서 막힌다.

| 한도 | 기본값 | 볼 것 |
| --- | --- | --- |
| 열 수 있는 파일 수 (`ulimit -n`) | 소프트 한도 1024가 흔하다 | 연결 하나가 파일 디스크립터 하나다. 모자라면 `Too many open files`가 난다. 서비스 단위로 65535 정도로 올린다([[linux-server-monitoring\|리눅스 서버 점검]]의 「자원 한도」) |
| `net.core.somaxconn` | 리눅스 5.4부터 4096, 그 전은 128 | `accept()`를 기다리는 연결 큐의 상한이다. 옛 커널이나 낮춰 둔 배포판이면 올린다 |
| `net.ipv4.tcp_max_syn_backlog` | 메모리 크기에 따라 정해진다 | 핸드셰이크 중인 연결 큐의 상한이다. 접속이 몰릴 때 SYN이 버려지면 올린다 |

```bash
ulimit -n                                  # 현재 셸의 파일 수 한도
sysctl net.core.somaxconn net.ipv4.tcp_max_syn_backlog
```

## 무료 대안: Oracle Cloud Always Free

기간 제한 없이 서버를 무료로 주는 대형 클라우드는 드물다. Oracle Cloud Infrastructure(OCI)의 Always Free가 대표적이다. 2026년 11월 공식 문서 기준 한도는 다음과 같다.

| 자원 | 무료 한도 |
| --- | --- |
| Ampere A1 (`VM.Standard.A1.Flex`, ARM) | 월 1,500 OCPU 시간과 9,000GB 시간. 한 달 내내 켜면 **2 OCPU, 메모리 12GB**에 해당한다 |
| AMD 마이크로 (`VM.Standard.E2.1.Micro`, x86) | 인스턴스 2개까지. 각각 1/8 OCPU(버스트 가능), 메모리 1GB |
| 블록 볼륨 | 부트 볼륨 포함 합계 200GB, 볼륨 백업 5개 |
| 오브젝트 스토리지 | 20GB |
| 아웃바운드 데이터 전송 | 월 10TB |

- ARM 기반 A1 Flex가 x86 마이크로보다 훨씬 쓸 만하다. 다만 ARM이므로 쓰려는 이미지와 바이너리가 `arm64`를 지원하는지 확인한다.
- **유휴 인스턴스는 회수될 수 있다.** 7일 동안 CPU 사용률(95번째 백분위수)이 20% 미만, 네트워크 사용률이 20% 미만, 메모리 사용률이 20% 미만(A1만 해당)이면 유휴로 본다.
- 유료 계정으로 올려도 Always Free 한도 안의 자원에는 요금이 붙지 않고, 한도를 넘는 사용량에만 붙는다.
- 무료 한도는 바뀐다. 인스턴스를 만들기 전에 공식 문서의 숫자를 다시 확인한다.

무료 제공의 경계와 데이터 전송 요금 같은 숨은 비용은 [[cloud-cost-optimization|클라우드 비용 최적화와 숨은 비용]]에 있다.

## 정리

- 가정용 장비의 한계는 CPU가 아니라 배터리, 업로드 회선, 전원, 단일 디스크에서 먼저 온다.
- 느려지면 사양을 올리기 전에 봇 트래픽, 캐싱, 정적 파일 분리, 커널 한도를 본다.
- 사용자가 늘면 저가 VPS나 무료 클라우드로 옮긴다. OCI Always Free의 A1 Flex는 2 OCPU·12GB까지 무료지만 유휴 상태가 이어지면 회수된다.
