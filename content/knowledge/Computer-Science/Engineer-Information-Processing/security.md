> 안전한 프로그램의 원칙, 익스플로잇·취약점 생명주기, 포트 스캔, 고전 암호 부분은 팔만코딩경(42Seoul 커뮤니티 위키)의 「해킹/보안) 0. 안전한 프로그램을 만들기 위해 생각해야 하는 것들」, 「1-1. 포트 스캔」, 「1-2. 익스플로잇」, 「42 Common Core 암호문 해독 입문」·「실전」을 바탕으로 보강했다.

보안 문제는 "무엇을 지키는가(3요소) → 어떻게 공격받는가(공격 기법) → 무엇으로 막는가(암호, 접근 통제, 보안 프로토콜)"의 흐름으로 정리하면 기억하기 쉽다.

## 보안 3요소 (CIA)

| 요소 | 의미 |
| --- | --- |
| 기밀성 (Confidentiality) | 인가되지 않은 사용자에게 정보가 공개·노출되지 않음 |
| 무결성 (Integrity) | 정당한 방법 없이는 데이터가 변경되지 않음 |
| 가용성 (Availability) | 권한 있는 사용자가 원할 때 서비스를 지속적으로 사용할 수 있음 |

## 주요 공격 기법

### 서비스 거부(DoS) 계열

| 공격 | 방식 |
| --- | --- |
| Land Attack | 출발지와 목적지 주소(포트)를 **모두 피해자**로 위조 → 자기 자신에게 계속 응답하다 마비 |
| Smurfing | 출발지를 피해자 IP로 위조한 ICMP Echo를 **브로드캐스트** → 수많은 응답이 피해자에게 몰림 |
| Ping of Death | 허용 크기를 넘는 ICMP 패킷을 보내 잘게 쪼개진 조각을 대량으로 처리하게 함 |
| HTTP GET Flooding | 과도한 GET 요청으로 웹 서버를 과부하시키는 응용 계층 DDoS |
| SYN Flooding | TCP 3-way handshake의 구조를 악용해 SYN만 대량으로 보내 연결 대기열을 가득 채움 |
| UDP Flooding | 대량의 UDP 패킷을 임의의 포트로 보내 응답(ICMP Unreachable) 처리로 자원 고갈 |
| Teardrop | IP 단편(fragment)의 Offset 정보를 조작해 재조합 과정에서 오류를 일으킴 |

**DDoS**는 여러 대의 좀비 PC(에이전트)를 조종해 위 공격을 한 대상에 동시에 퍼붓는다.

### 네트워크 엿보기·위장

| 공격 | 방식 |
| --- | --- |
| Sniffing | 네트워크 패킷을 몰래 엿보는 **수동적** 공격 |
| Spoofing | 신뢰된 대상으로 위장 (IP·ARP·DNS 스푸핑). ARP 스푸핑은 MAC 주소를 위조해 트래픽을 가로챔 |
| Session Hijacking | 정상 연결을 RST로 끊고 재연결 시 공격자와 연결되게 해 세션을 가로챔 |

SYN Flooding·Session Hijacking이 악용하는 TCP 연결 과정은 [[tcp|TCP]], ARP 스푸핑의 대상인 ARP는 [[network-layer|네트워크 계층]]에 정리했다.

### 애플리케이션·사용자 대상

| 공격 | 방식 |
| --- | --- |
| SQL Injection | 검증되지 않은 입력값에 SQL을 삽입해 DB를 열람·조작 |
| XSS | 게시판 등에 악성 스크립트를 심어 다른 사용자의 쿠키·정보 탈취 |
| Smishing / Qshing | SMS / QR 코드를 이용한 피싱 |
| Spear Phishing | 특정 개인·조직을 겨냥한 맞춤형 피싱 |
| Key Logger | 키 입력을 가로채 ID·비밀번호 탈취 |
| Zero-day | 취약점 패치가 나오기 전에 이루어지는 공격 |

XSS와 CSRF의 원리와 실제 방어법은 [[web-security|웹 보안: CSRF와 XSS]]를 참고한다.

### 악성 소프트웨어

| 종류 | 하는 일 |
| --- | --- |
| Worm | 스스로 복제해 퍼진다 |
| Spyware | 동의 없이 설치되어 정보를 수집·전송한다 |
| Ransomware | 파일을 암호화하고 복호화 대가로 돈을 요구한다 |
| Backdoor | 정상 인증을 거치지 않고 들어오는 통로. 유지보수용으로 일부러 남기기도 하지만 공격자가 악성 코드를 숨기는 통로가 된다. 심은 쪽만 쓰도록 암호 기법을 쓴 **비대칭 백도어**도 있다 |

### 익스플로잇과 취약점의 생명주기

**취약점**(vulnerability)은 시스템의 보안 결함이고, **익스플로잇**(exploit)은 그 결함을 실제로 이용하는 코드나 기법이다. 공개된 취약점에는 CVE 번호가 붙고 CVSS 점수로 심각도를 매긴다(NVD, cve.org에서 조회).

| 익스플로잇이 노리는 결과 | 예 |
| --- | --- |
| 원격 코드 실행(RCE) | 버퍼 오버플로, 역직렬화 취약점으로 서버에서 임의 명령 실행. 가장 심각 |
| 권한 상승 | 일반 사용자 → root. setuid 프로그램, 커널 버그 |
| 서비스 거부(DoS) | 자원을 고갈시켜 서비스 중단 |
| 데이터 탈취·조작 | SQL Injection, 경로 조작(path traversal) |

| 시점 | 상태 | 위험 |
| --- | --- | --- |
| 제로데이(0-day) | 공급자가 모르거나 패치가 없음 | 막을 수단이 없다. 고가에 거래된다 |
| 원데이·N데이 | 패치는 나왔지만 적용되지 않음 | 패치 내용을 분석하면 공격법이 드러나므로 공개 직후가 가장 위험하다 |
| 패치 미적용이 방치된 상태 | 오래전 패치가 있는데도 관리 소홀로 남음 | **실제 침해의 대부분이 여기서 일어난다** |

방어의 기본은 화려한 대책보다 **빠른 패치와 의존성 업데이트**다(`npm audit`, Dependabot 같은 도구로 알림을 받는다).

### 포트 스캔

포트 스캔은 대상 호스트의 어떤 포트가 열려 있고 무슨 서비스가 도는지 알아내는 일이다. 공격의 정찰 단계이자, 관리자가 자기 시스템의 노출면을 점검하는 수단이다. 대표 도구는 Nmap이다.

| 기법 | 방식 |
| --- | --- |
| TCP 연결 스캔 | 3-way handshake를 끝까지 맺어 열림·닫힘 판단. 기록이 남는다 |
| SYN 스캔(반개방) | SYN만 보내고 SYN-ACK이 오면 열림, RST로 끊는다. 연결이 완성되지 않아 덜 드러난다([[tcp\|TCP]]) |
| UDP 스캔 | 응답이 없으면 열림·필터링, ICMP port unreachable이면 닫힘. 느리다 |
| 서비스·버전 탐지, 스크립트 스캔 | 배너와 응답으로 소프트웨어 버전을 알아내고 알려진 취약점을 점검 |

방어 측은 불필요한 포트를 닫고(방화벽 `ufw`, 클라우드 보안 그룹), IDS·IPS로 비정상 스캔을 탐지한다. **허가받지 않은 시스템을 스캔하는 것은 불법이 될 수 있다.** 자기 시스템이나 허가된 범위에서만 한다.

### 안전한 프로그램의 원칙

| 원칙 | 뜻 |
| --- | --- |
| 입력을 믿지 않는다 | 길이·형식·범위를 서버에서 검증하고, 출력할 곳(SQL, HTML, 셸)에 맞게 이스케이프한다. 버퍼 오버플로·SQL Injection·XSS가 모두 여기서 나온다 |
| 최소 권한 | 필요한 코드에, 필요한 권한만, 필요한 동안만 준다. 침해돼도 피해가 갇힌다([[linux-access-control\|리눅스 접근 제어]]) |
| 검증된 암호를 쓴다 | 직접 만든 비공개 알고리즘은 결함을 찾을 사람이 없을 뿐이다. 알고리즘은 공개되고 키만 비밀이어야 한다는 **케르크호프스 원칙**을 따른다 |
| 안전한 기본값 | 기본 설정이 닫혀 있어야 한다. 관리자 비밀번호 기본값, 디버그 모드 노출 금지 |

## 암호 알고리즘

### 대칭 키 (암호화 키 = 복호화 키)

| 알고리즘 | 특징 |
| --- | --- |
| DES | IBM 개발, 64비트 블록, 56비트 키, 16라운드. 지금은 안전하지 않음 |
| AES | DES를 대체한 NIST 표준, 128비트 블록, 128/192/256비트 키 |
| SEED | KISA 개발, 128비트 블록 |
| RC4 | 스트림 암호. 취약점이 밝혀져 TLS에서는 사용이 금지되었다(RFC 7465) |

### 비대칭 키 (공개키 / 개인키)

**RSA**는 큰 수의 소인수분해가 어렵다는 점을 이용하고, **디피-헬만**은 안전하지 않은 통신망에서 공통 비밀키를 교환한다.

### 해시 (일방향)

원문을 고정 길이 값으로 바꾸며 **되돌릴 수 없다.** 무결성 검사와 비밀번호 저장에 쓴다. MD5(128비트)와 SHA-1은 충돌 공격이 알려져 보안 용도로 쓰지 않는다. 지금은 NIST 표준인 SHA-2(SHA-256 등, NSA 설계)와 공개 공모로 뽑힌 SHA-3(Keccak)를 쓴다.

### 보안 프로토콜

- **TLS**: 응용 계층과 TCP 사이에서 통신을 암호화한다. SSL과 TLS 1.0·1.1은 폐기되어 TLS 1.2·1.3만 쓴다([[https|HTTPS와 TLS]]).
- **IPSec**: 네트워크 계층(3계층)의 IP 보안 프로토콜. **AH**로 무결성·인증, **ESP**로 기밀성(암호화) 제공

### 고전 암호와 인코딩은 보안이 아니다

| 방식 | 원리 | 깨는 법 |
| --- | --- | --- |
| 카이사르 암호, ROT13 | 알파벳을 일정 칸 밀기 | 키가 25가지뿐. 전수 대입 즉시 |
| 치환 암호 | 글자마다 다른 글자로 | 글자 빈도 분석 |
| 모스 부호, 리트(leet, `1337`) | 표기 방식만 바꿈 | 대응표만 있으면 누구나 읽음 |
| Base64, URL 인코딩 | 이진 데이터를 텍스트로 옮기는 **인코딩** | 키가 없으므로 그냥 디코딩된다 |

- **인코딩은 형식 변환, 암호화는 키가 있어야 풀리는 변환, 해시는 되돌릴 수 없는 변환**이다. Base64로 감싼 비밀번호는 평문과 같다([[base64-encoding|Base64 인코딩]]).
- 현대 암호(AES, ChaCha20)는 알고리즘을 공개해도 키 없이는 풀 수 없다. 남는 공격은 키 자체를 맞히는 것이다. **무차별 대입**(모든 키)과 **사전 공격**(사람이 쓸 법한 단어·이름 목록)이 그것이고, 사람이 정한 비밀번호가 짧고 뻔할수록 쉽게 뚫린다.
- 그래서 비밀번호 저장에는 일부러 느리게 만든 해시(bcrypt, scrypt, Argon2)와 솔트를 쓴다. bcrypt는 블록 암호 Blowfish의 비싼 키 설정 과정을 반복해 대입 속도를 늦춘다. Blowfish 자체는 블록이 64비트로 작아 새 시스템에서는 AES를 쓴다.

## 접근 통제

접근 통제는 정책, 메커니즘, 보안 모델의 3요소로 구성된다.

| 방식 | 권한 부여 기준 | 권한 지정 주체 |
| --- | --- | --- |
| DAC (임의 접근 통제) | 사용자 신원 | 데이터 **소유자**가 다른 사용자에게 허가 가능 |
| MAC (강제 접근 통제) | 주체와 객체의 **보안 등급** 비교 | 시스템 |
| RBAC (역할 기반 접근 통제) | 사용자의 **역할** | 중앙 관리자 |

리눅스의 파일 권한이 DAC, AppArmor·SELinux가 MAC의 구현이다([[linux-access-control|리눅스 접근 제어]]).

### AAA

**인증**(Authentication, 누구인지 확인) → **인가**(Authorization, 어떤 권한을 줄지 결정) → **계정 관리**(Accounting, 사용 시간·위치 등 사용 기록 수집)의 묶음이다.

관련 노트: [[https|HTTPS와 TLS]], [[linux-access-control|리눅스 접근 제어: DAC, MAC, sudo]], [[web-security|웹 보안: CSRF와 XSS]]
