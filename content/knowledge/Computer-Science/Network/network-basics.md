네트워크는 여러 노드(컴퓨터 같은 시스템)가 데이터를 공유할 수 있도록 연결한 디지털 전기 통신망이다. 분산된 컴퓨터를 통신망으로 묶고, 노드 간 연결을 통해 서로 데이터를 주고받는다. 우리가 매일 쓰는 인터넷도 문서·그림·영상 같은 데이터를 공유하게 해 주는 네트워크 통신망 중 하나일 뿐이다.

## 네트워크의 분류

### 크기에 따른 분류

| 구분 | 설명 | 예 |
| --- | --- | --- |
| LAN (Local Area Network) | 가까운 지역을 하나로 묶은 근거리 통신망 | 같은 회사·사무실 안의 컴퓨터들 |
| WAN (Wide Area Network) | 멀리 떨어진 곳들을 묶은 네트워크. 여러 LAN 대역을 서로 연결한 것 | 인터넷 |

### 연결 형태(토폴로지)에 따른 분류

| 형태 | 설명 | 주 용도 |
| --- | --- | --- |
| 성형(Star) | 중앙 장비에 모든 노드가 연결 | LAN (예: Wi-Fi 공유기) |
| 망형(Mesh) | 네트워크 장비들이 서로 모두 연결 | WAN (예: 국가 간 연결) |
| 혼합형 | 여러 형태를 섞은 구조 | 실제 인터넷 — LAN들이 서로 연결되어 결국 WAN을 이룬다 |

## 통신 방식

| 방식 | 대상 | 비고 |
| --- | --- | --- |
| 유니캐스트 | 특정 대상 하나와 1:1 | 가장 많이 사용 |
| 멀티캐스트 | 같은 네트워크 대역의 특정 다수와 1:N | |
| 브로드캐스트 | 같은 네트워크 대역의 모든 대상 | ARP 요청 등 |

## 프로토콜: 누구와 어떻게 통신할까

노드끼리 통신하려면 정해진 양식, 즉 **프로토콜**이 필요하다. 통신 거리와 대상에 따라 쓰는 주소와 프로토콜이 다르다.

| 하고 싶은 일 | 사용하는 주소 | 프로토콜 |
| --- | --- | --- |
| 가까운 곳(같은 LAN)과 연결 | MAC 주소 | Ethernet |
| 멀리 있는 곳(다른 네트워크)과 연결 | IP 주소 | IPv4, ARP, ICMP |
| 특정 프로그램과 연결 | 포트 번호 | TCP, UDP |

예를 들어 친구에게 메시지를 보낼 때, 카카오톡으로 보낼지 디스코드로 보낼지는 **포트 번호**로 구분한다([[transport-layer|전송 계층과 포트]]). 실제로는 프로토콜 하나만 쓰지 않고 여러 개를 함께 사용한다. "어느 프로그램으로(포트), 어느 지역으로(IP), 그 지역의 어느 컴퓨터로(MAC)"를 모두 담아야 데이터가 제대로 도착한다.

## 계층 모델

| 모델 | 구성 | 분리 기준 |
| --- | --- | --- |
| OSI 7계층 | 물리 - 데이터 링크 - 네트워크 - 전송 - 세션 - 표현 - 응용 | ISO 표준. 통신 전반을 **논리적·역할 기반**으로 분리 |
| TCP/IP 4계층 | 네트워크 인터페이스 - 네트워크(인터넷) - 전송 - 응용 | 실제 인터넷에서 데이터를 전달하는 **실무 기반**으로 분리 |

두 모델 모두 계층적 구조이고 계층마다 역할을 정의한다는 공통점이 있다. 계층별 역할은 [[osi-7-layer|OSI 7계층]]에 자세히 정리했다.

## 패킷과 캡슐화

**패킷**은 네트워크에서 전달되는 데이터를 통칭하는 말로, 여러 제어 정보(누가 누구에게, 무엇을 요청하는지)와 사용자 데이터로 이루어진 하나의 블록이다.

```text
[ 헤더 | 페이로드(실제로 보내려는 데이터) | 푸터 ]
```

프로토콜 정보는 마트료시카 인형처럼 **순서를 지켜** 겹겹이 감싸진다.

- **캡슐화**: 보낼 때 상위 계층에서 하위 계층으로 내려가며 프로토콜 헤더를 붙여 패킷을 만든다. 예: HTTP → TCP → IPv4 → Ethernet
- **디캡슐화**: 받을 때 하위 프로토콜부터 상위 프로토콜 순으로 하나씩 벗겨 내며 데이터를 확인한다.

### 계층별 PDU(Protocol Data Unit)

| 계층 | 구성 | PDU 이름 |
| --- | --- | --- |
| 4계층(전송) | TCP + 데이터 | 세그먼트 |
| 3계층(네트워크) | IPv4 + TCP + 데이터 | 패킷 |
| 2계층(데이터 링크) | Ethernet + IPv4 + TCP + 데이터 | 프레임 |

## 2계층: 같은 LAN 안에서 주고받기

### 2계층이 하는 일

- 하나의 네트워크 대역(LAN) 안에 있는 노드들끼리 데이터를 전달한다.
- **오류 제어**(전달한 데이터에 오류가 있는지)와 **흐름 제어**를 수행한다.
- 2계층 통신은 같은 LAN 안에서만 쓰인다. 다른 네트워크 대역과 통신하려면 반드시 3계층 주소와 프로토콜을 거쳐야 한다([[network-layer|네트워크 계층]]).

### MAC 주소

- 물리적인 네트워크 장비마다 부여된 고유한 **물리 주소**
- 16진수 12자리, 총 **6바이트**(16진수 두 자리 = 1바이트). 예: `AA:AA:AA:AA:AA:AA`

### 이더넷 프레임 헤더

| 필드 | 크기 | 설명 |
| --- | --- | --- |
| Destination Address | 6바이트 | 목적지 MAC 주소 |
| Source Address | 6바이트 | 출발지 MAC 주소 |
| Ethernet Type | 2바이트 | 페이로드에 담긴 **상위(3계층) 프로토콜**의 종류 |

데이터는 전기 신호로 흘러오기 때문에, 받는 쪽이 페이로드를 해석하기 전에 그 안에 어떤 프로토콜(IPv4, ARP 등)이 들어 있는지 Ethernet Type으로 미리 알려 준다.

## 핵심 정리

- LAN은 가까운 곳, WAN은 LAN들을 이은 먼 곳의 네트워크. 실제 인터넷은 혼합형이다.
- MAC 주소로 같은 LAN, IP 주소로 다른 네트워크, 포트 번호로 특정 프로그램을 찾는다.
- 보낼 때는 캡슐화(상위 → 하위), 받을 때는 디캡슐화(하위 → 상위). PDU는 세그먼트 → 패킷 → 프레임.
