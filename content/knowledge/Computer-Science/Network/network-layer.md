네트워크 계층(3계층)은 여러 네트워크를 거쳐 패킷을 목적지 호스트까지 보내는 일을 한다. 핵심인 IP는 "최선을 다해 전달하지만 보장은 하지 않는" 프로토콜이고, 주변 프로토콜들이 주소 변환·오류 보고·경로 선택을 돕는다.

## IP (Internet Protocol)

- 출발지·목적지 IP 주소를 지정하고 최적 경로로 패킷을 전달한다.
- **비신뢰성·비연결성**: 도착·순서를 보장하지 않는다. 신뢰성은 상위 계층(TCP)이 맡는다.
- 헤더 주요 필드
  - **IHL**: 헤더 길이를 4바이트 단위로 표시 (옵션 없는 20바이트 → 5)
  - **Flags**: Reserved, DF(Don't Fragment), MF(More Fragments)로 단편화를 제어
  - TTL, 프로토콜, 체크섬, 출발지·목적지 주소 등
- 서로 다른 LAN을 연결하려면 **라우터**가 필요하다.

### IP 주소와 PC의 네트워크 설정

PC의 네트워크 설정에는 보통 세 값이 들어간다.

| 항목 | 의미 |
| --- | --- |
| IPv4 주소 | 현재 PC에 할당된 IP 주소. 8비트(0~255)짜리 필드 4개로 표현 |
| 서브넷 마스크 | IP 주소에서 어디까지가 **네트워크 대역**이고 어디부터가 **호스트**인지 규정 |
| 기본 게이트웨이 | 외부 네트워크와 통신할 때 거쳐 가는 출입구(라우터) 주소 |

- **Classful 주소**: A·B·C 클래스처럼 정해진 크기로 네트워크를 나눠 쓰는 방식. 대역이 경직되어 IP 주소가 낭비·부족해지는 문제가 있었다.
- **Classless 주소**: 서브넷 마스크로 네트워크 부분과 호스트 부분을 자유롭게 나눈다(CIDR).
- **공인 IP와 사설 IP**: 인터넷에서는 공인 IP로만 통신하고, 외부에서는 내부의 사설 IP 대역이 보이지 않는다. 공인 IP 하나 뒤에 여러 사설 IP 기기를 둘 수 있게 해 주는 것이 아래의 NAT다.

## 주소 변환: ARP와 RARP

| 프로토콜 | 변환 | 동작 |
| --- | --- | --- |
| ARP | IP 주소 → MAC 주소 | 요청은 브로드캐스트, 응답은 유니캐스트. 결과를 ARP 캐시에 일정 기간 저장 |
| RARP | MAC 주소 → IP 주소 | 디스크 없는 시스템이 자기 IP를 얻을 때 사용. 지금은 BOOTP·DHCP로 대체 |

```bash
arp -a    # ARP 캐시 보기
arp -d    # 항목 삭제
arp -s    # 정적 항목 추가
```

ARP는 요청하지 않은 응답도 받아들이기 때문에, 위조된 응답으로 캐시를 오염시키는 **ARP 스푸핑(ARP Cache Poisoning)** 공격에 취약하다. 스푸핑·스니핑 같은 공격 기법은 [[security|정보 시스템 보안]]에 정리했다.

## ICMP와 IGMP

- **ICMP**: IP의 비신뢰성을 보완해 **오류·제어 메시지를 출발지에 보고**한다(해결은 하지 않음). 대표 도구가 `ping`, `traceroute`.
  - 주요 타입: 8 Echo Request, 0 Echo Reply, 3 Destination Unreachable, 5 Redirect, 11 Time Exceeded
- **IGMP**: 멀티캐스트 그룹의 가입·탈퇴를 관리한다.

## IPv6

IPv4(32비트, 8비트씩 4부분)의 주소 고갈 문제를 해결하려고 만든 **128비트** 주소 체계로, 16비트씩 8부분을 `:`으로 구분한다. IPv4 주소는 실제로 2011년 2월 IANA의 미할당 주소 풀이 바닥났고, 이후 지역 인터넷 레지스트리(RIR)들도 차례로 소진되어 지금은 NAT와 IPv6로 버티고 있다.

- IPsec(인증·기밀성·무결성)을 염두에 두고 설계되었다. 초기 표준(RFC 4294)은 모든 IPv6 노드에 IPsec 구현을 **필수**로 요구했지만, RFC 6434 이후로는 **권장(SHOULD)** 으로 완화되었다(현행 RFC 8504).
- Traffic Class, Flow Label 필드로 서비스 품질(QoS)을 다루기 쉽다.
- 주소 종류

| IPv4 | IPv6 |
| --- | --- |
| 유니캐스트, 멀티캐스트, **브로드캐스트** | 유니캐스트, 멀티캐스트, **애니캐스트**(가장 가까운 수신자 하나) |

## NAT (Network Address Translation)

사설 IP와 공인 IP를 서로 변환하는 기술. 라우터가 패킷의 출발지·목적지 IP 주소와 TCP/UDP 포트 번호를 바꿔 기록하면서 여러 내부 기기가 하나의 공인 IP를 공유할 수 있게 한다. 즉 "특정 IP·포트로 가는 패킷을 다른 IP·포트로 바꿔 주는 것"이다. P2P 통신(예: [[webrtc|WebRTC]])에서는 NAT 뒤의 기기끼리 직접 연결하기 어려워 별도의 우회 기법이 필요하다.

**목적**

1. 공인 IP 주소 절약: 한정된 IPv4 주소 문제 해결
2. 보안: 외부에서 내부 기기의 실제 주소가 보이지 않음

**예: AWS NAT Gateway**

프라이빗 서브넷의 인스턴스는 VPC 밖 서비스에 연결할 수 있어야 하지만, 외부에서는 이 인스턴스에 직접 접속할 수 없어야 한다. NAT Gateway가 이를 처리한다.

- **Public NAT Gateway**: 퍼블릭 서브넷에 만들고 탄력적 IP(Elastic IP)를 연결한다. 인스턴스의 출발지 IP를 NAT Gateway의 IP로 바꿔 인터넷으로 내보낸다.
- **Private NAT Gateway**: 프라이빗 서브넷에 만들며 탄력적 IP를 붙일 수 없다. Transit Gateway나 가상 프라이빗 게이트웨이를 통해 다른 VPC·온프레미스로 트래픽을 라우팅한다.

### NAT와 프록시 서버 비교

| 구분 | 프록시 서버 | NAT |
| --- | --- | --- |
| 공통점 | IP 변환이 일어나 목적지는 실제 출발지 IP를 알 수 없음. 내부 서버와 직접 통신하지 않아 보안이 강화됨 | (동일) |
| 동작 계층 | 응용 계층 (HTTP 등) | 네트워크 계층 (IP 패킷 수정) |
| 역할 | 출발지와 목적지 사이의 대리인 — 클라이언트 대신 정보를 가져옴 | 사설 IP ↔ 공인 IP 변환 |
| 위치 | 주로 사내망의 DMZ(내부·외부 네트워크 사이 영역) | 라우터나 방화벽 |
| 캐싱·인증 | 가능 | 불가 |

### 포트 포워딩

NAT를 응용한 기술로, **특정 IP·포트로 들어온 요청을 미리 정한 다른 IP·포트로 전달**한다. 게이트웨이(외부망) 반대편 사설 네트워크에 있는 호스트의 서비스를 외부에 공개할 때 쓴다.

- `[외부(호스트) 포트]:[내부 포트]` 형식으로 표현한다.
- 예: `docker run -p 8080:9090 ...` → 호스트의 8080 포트로 들어오는 트래픽을 컨테이너의 9090 포트로 전달([[vm-vs-container|VM과 컨테이너]])
- 용도: 원격 데스크톱, 집 안 서버에 외부에서 접속하기 등 가정용 네트워크와 원격 기기를 직접 연결할 때

## 라우팅 프로토콜

라우터끼리 네트워크 상태 정보를 교환해 목적지까지의 경로를 정하는 프로토콜이다.

- **정적 라우팅**: 관리자가 경로를 직접 입력
- **동적 라우팅**: 라우터 간 정보 교환으로 자동 결정
  - **거리 벡터**: 거쳐 가는 라우터 수(홉 수) 기준 (예: RIP)
  - **링크 상태**: 대역폭·지연 등 링크 상태 기준, 다익스트라 알고리즘으로 최단 경로 계산 (예: OSPF)

| 구분 | 프로토콜 | 특징 |
| --- | --- | --- |
| IGP (자율 시스템 내부) | RIP | 거리 벡터, 최대 15홉, 소규모 |
| IGP | OSPF | 링크 상태, 대규모 네트워크에 적합 |
| EGP (자율 시스템 간) | BGP | 인터넷 사업자(AS) 사이의 라우팅 |

## 데이터 교환 방식

| 방식 | 특징 |
| --- | --- |
| 회선 교환 | 통신 전에 물리적 경로를 확보해 전용선처럼 사용. 지연이 적지만 데이터가 없어도 회선을 점유 (전화) |
| 메시지 교환 | 메시지 전체를 저장했다가 순서대로 전달. 지연이 큼 |
| 패킷 교환 | 데이터를 일정 크기의 패킷으로 나눠 전송. 회선 효율이 높고 재전송 가능 (인터넷) |

패킷 교환은 다시 두 가지로 나뉜다.

- **가상 회선 방식**: 논리적 경로를 먼저 설정(호 설정 → 전송 → 해제)하고 패킷이 순서대로 같은 길로 간다. 연결형.
- **데이터그램 방식**: 경로 설정 없이 패킷마다 독립적으로 전송. 유연하지만 도착 순서가 바뀔 수 있어 재조립이 필요하다. 비연결형 (IP).
