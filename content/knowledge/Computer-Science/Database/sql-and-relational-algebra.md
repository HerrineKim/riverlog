SQL은 관계형 데이터베이스를 다루는 표준 언어이고, 관계대수는 그 바탕이 되는 수학적 연산 체계다. SQL은 "무엇을 원하는지"만 적는 비절차적 언어, 관계대수는 "어떻게 구할지"를 연산 순서로 적는 절차적 언어라는 차이가 있다.

## SQL 명령어 분류

| 분류 | 의미 | 명령어 |
| --- | --- | --- |
| DDL (정의어) | 스키마·테이블·뷰·인덱스 등 구조 정의 | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` |
| DML (조작어) | 데이터 조회·삽입·수정·삭제 | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| DCL (제어어) | 권한과 트랜잭션 제어 | `GRANT`, `REVOKE`, `COMMIT`, `ROLLBACK` |

`GRANT`는 사용자에게 권한을 부여하고 `REVOKE`는 회수한다.

## 자주 쓰는 문법

```sql
-- 조회: 조건, 정렬, 패턴
SELECT 학번, 이름 FROM 학생 WHERE 학년 IN (3, 4);
SELECT * FROM 학생 WHERE 이름 LIKE '이%' ORDER BY 이름 DESC;

-- 중복 제거와 집계
SELECT DISTINCT 학과 FROM 학생;
SELECT 학과, COUNT(*) AS 학생수 FROM 학생 GROUP BY 학과;

-- 조인
SELECT a.이름, b.학과명
FROM 학생정보 a JOIN 학과정보 b ON a.학과 = b.학과;

-- 삽입·수정·삭제
INSERT INTO 학생 (학번, 이름) VALUES (1, '홍길동');
UPDATE 학생 SET 점수 = 점수 + 5 WHERE 점수 >= 90;
DELETE FROM 학생 WHERE 이름 = '민수';

-- 구조 변경과 인덱스
ALTER TABLE 학생 ADD 주소 VARCHAR(20);
CREATE INDEX idx_name ON student(name);
```

헷갈리기 쉬운 점

- `SELECT 학과 FROM 학생`은 행 수만큼, `SELECT DISTINCT 학과`는 서로 다른 학과 수만큼 나온다.
- `LIKE`의 `%`는 0글자 이상, `_`는 정확히 한 글자.
- **CROSS JOIN**은 두 테이블의 모든 행 조합(카티션 곱)을 만든다. 행이 m개, n개면 결과는 m × n개.
- **WHERE vs HAVING**: `WHERE`는 그룹을 만들기 **전에** 행을 거르고, `HAVING`은 `GROUP BY`로 만든 **그룹을** 집계 결과로 거른다. 그룹 기준이 여러 개면 `GROUP BY` 뒤에 나열한다.

```sql
-- 팀·직급별 성과급 합계
SELECT 팀명, 직급, SUM(성과급) AS 성과급 FROM 급여 GROUP BY 팀명, 직급;

-- 편의점이 4곳 이상인 광역시에서, 판매액 100만 원 초과 편의점의 평균 판매액
SELECT 광역시, AVG(판매액)
FROM 편의점
WHERE 판매액 > 1000000      -- 행 조건: 그룹 만들기 전
GROUP BY 광역시
HAVING COUNT(*) >= 4;       -- 그룹 조건: 집계 후
```

## 관계대수

관계(테이블)를 입력받아 관계를 결과로 내놓는 연산들.

### 순수 관계 연산자

| 연산 | 기호 | 의미 |
| --- | --- | --- |
| Select | σ | 조건을 만족하는 **튜플(행)** 추출 — 수평 연산 |
| Project | π | 지정한 **속성(열)** 만 추출, 중복 제거 — 수직 연산 |
| Join | ⋈ | 공통 속성을 기준으로 두 릴레이션을 결합 |
| Division | ÷ | R에서 S의 모든 값과 관련된 튜플을 찾아, S의 속성을 뺀 나머지만 남김 |

### 일반 집합 연산자

합집합·교집합·차집합은 두 릴레이션의 속성 수와 도메인이 같아야(합병 가능) 한다.

| 연산 | 결과 | 결과 카디널리티(튜플 수) |
| --- | --- | --- |
| 합집합 UNION (∪) | 두 릴레이션의 튜플을 합치고 중복 제거 | 두 카디널리티의 합 **이하** |
| 교집합 INTERSECTION (∩) | 양쪽에 모두 있는 튜플 | 작은 쪽 카디널리티 **이하** |
| 차집합 DIFFERENCE (−) | 앞 릴레이션에만 있는 튜플 | 앞(빼지는) 릴레이션 카디널리티 **이하** |
| 카티션 곱 CARTESIAN PRODUCT (×) | 모든 튜플의 순서쌍 | 두 카디널리티의 **곱** (차수는 두 차수의 합) |

## DB 설계 단계

```text
요구사항 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현
```

| 단계 | 하는 일 | 산출물 |
| --- | --- | --- |
| 개념적 설계 | 현실 세계를 추상화 | E-R 다이어그램 |
| 논리적 설계 | 특정 DB 모델(관계형)에 맞게 변환, **정규화** | 릴레이션 스키마 |
| 물리적 설계 | 저장 구조·인덱스·접근 경로 결정 | 테이블 정의서 |

## 스키마와 인덱스

- **스키마**: 데이터베이스의 구조와 제약 조건을 기술한 메타데이터의 집합. 외부(사용자 관점), 개념(전체 논리 구조), 내부(물리 저장 구조) 스키마로 나뉜다.
- **인덱스**: `<키 값, 레코드 주소>` 쌍으로 이루어진 자료구조로, 검색 속도를 높인다. 파일 구조는 크게 순차, 인덱스, 해싱 방식이 있다.
