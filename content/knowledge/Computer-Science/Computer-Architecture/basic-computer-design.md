컴퓨터 구조 교재(『컴퓨터 시스템 구조』, Mano)는 설명을 위해 단순한 16비트 **기본 컴퓨터(Basic Computer)** 를 정의하고, 그 구조와 제어 장치를 처음부터 설계한다. 규모는 작지만 "명령어를 메모리에서 꺼내 해석하고 실행한다"는 현대 CPU의 기본 설계 구조가 그대로 들어 있다.

## 컴퓨터는 어떻게 동작하나

- 컴퓨터는 프로그램을 기억 장치에 저장해 두고 명령어를 하나씩 꺼내 실행하는 **튜링 머신**(프로그램 내장 방식)이다.
- 각 명령어는 레지스터에 저장된 데이터에 대한 **마이크로 연산의 시퀀스**로 정의된다([[register-transfer|레지스터 전송과 마이크로 연산]]).

| 용어 | 의미 |
| --- | --- |
| 명령어 코드 | 컴퓨터에 동작을 지시하는 비트 묶음. 보통 연산 코드(opcode)와 주소로 구성 |
| 컴퓨터 명령어(기계어) | 마이크로 연산들을 묶어 하나의 동작으로 정의한 바이너리 코드. 데이터와 함께 메모리에 저장 |
| 프로그램 | 명령어들의 집합. 명령어 처리 과정을 제어하는 추상적인 개념 |
| 내장 프로그램 | 실제로 메모리·레지스터에 올라가 있는 명령어들 |

## 명령어 형식

모든 명령어는 설계할 때 정해 둔 형식을 따른다. 기본 컴퓨터의 명령어와 레지스터는 16비트다.

```text
 15   14  13  12   11                      0
[ I | Opcode (3) | Address (12)             ]
```

| 필드 | 크기 | 역할 |
| --- | --- | --- |
| I | 1비트 | 0이면 직접 주소, 1이면 간접 주소 |
| Opcode | 3비트 | 수행할 연산 |
| Address | 12비트 | 피연산자의 주소 → 2¹² = **4096워드** 메모리를 지정 |

메모리는 16비트 워드 4096개(4K)이며, 명령어(코드 세그먼트)와 피연산자(데이터 세그먼트), 임시 데이터(스택 세그먼트)를 서로 다른 영역에 둔다. 연산 결과는 누산기(AC)에 저장된다.

### 직접 주소와 간접 주소

- **직접 주소(I = 0)**: 주소 필드 값이 곧 피연산자의 주소다. 예: 22번지의 명령어 `ADD 457` → 457번지의 값을 더함
- **간접 주소(I = 1)**: 주소 필드가 가리키는 곳에 **피연산자의 주소**가 들어 있다. 예: 35번지의 명령어 `ADD 300 (I)` → 300번지에 적힌 1350이 실제 피연산자 주소

## 레지스터

| 레지스터 | 비트 | 역할 |
| --- | --- | --- |
| PC (Program Counter) | 12 | **다음에 실행할 명령어의 주소** |
| AR (Address Register) | 12 | 메모리 주소 지정 |
| IR (Instruction Register) | 16 | 현재 실행 중인 명령어(해독 대상) |
| DR (Data Register) | 16 | 메모리에서 읽어 온 피연산자 |
| AC (Accumulator) | 16 | 연산 결과를 저장하는 누산기 |
| TR (Temporary Register) | 16 | 임시 데이터 |
| INPR (Input Register) | 8 | 입력 장치에서 받은 문자 |
| OUTR (Output Register) | 8 | 출력 장치로 보낼 문자 |

주소를 다루는 PC와 AR은 메모리 크기에 맞춰 12비트다. 명령어는 보통 연속된 메모리에 놓이고 한 번에 하나씩 순차적으로 실행된다.

## 버스 시스템

| 버스 | 연결 |
| --- | --- |
| 내부 버스 | CPU 내부 레지스터끼리 |
| 외부 버스 | CPU 레지스터와 메모리 |
| 입출력 버스 | CPU와 주변 장치 |

**공통 버스(common bus)** 는 CPU 내부 버스를 가리키며, 버스의 폭이 CPU의 워드 크기를 결정한다. 기본 컴퓨터는 16비트 공통 버스에 메모리, AR, PC, DR, AC, IR, TR을 연결하고, 선택 입력(S2 S1 S0)으로 제어되는 멀티플렉서가 버스에 올릴 하나를 고른다. 버스에 실린 데이터는 **LD(load) 입력이 활성화된 레지스터**가 다음 클럭에 받아 저장한다. 한 순간에 하나의 값만 버스를 지날 수 있다.

## 명령어의 종류

| 종류 | 구분 방법 | 개수 | 예 |
| --- | --- | --- | --- |
| 메모리 참조 명령어(MRI) | Opcode가 000~110 | 7 | AND, ADD, LDA, STA, BUN, BSA, ISZ |
| 레지스터 참조 명령어(RRI) | Opcode 111, I = 0 | 12 | CLA, CMA, INC, HLT … (주소 필드 12비트가 각각의 연산을 지정) |
| 입출력 명령어(IO) | Opcode 111, I = 1 | 6 | INP, OUT, SKI, SKO, ION, IOF |

## 타이밍과 제어

- IR의 Opcode(12~14비트)를 **3×8 디코더**로 해독해 D0~D7 중 하나를 1로 만든다.
- 4비트 **순차 카운터(SC)** 의 출력을 **4×16 디코더**로 해독해 T0~T15 타이밍 신호를 만든다. 매 클럭마다 T0, T1, T2 … 순으로 바뀐다.
- 제어 신호는 이 둘의 조합으로 표현한다. 예: `D3T4: SC ← 0`은 D3가 1이고 타이밍이 T4일 때 SC를 0으로 클리어(다음 명령어로).

## 명령어 사이클

모든 명령어는 거의 같은 단계를 거친다.

1. 메모리에서 명령어를 가져온다(**fetch**).
2. 명령어를 해독한다(**decode**).
3. 간접 주소이면 메모리에서 **유효 주소**를 읽어 온다.
4. 명령어를 **실행**한다.
5. 1단계로 돌아간다.

### Fetch와 Decode

```text
T0: AR ← PC
T1: IR ← M[AR],  PC ← PC + 1
T2: D0..D7 ← Decode IR(12-14),  AR ← IR(0-11),  I ← IR(15)
```

- T0: 다음 명령어 주소(PC)를 AR로 옮긴다.
- T1: 그 주소의 명령어를 IR로 읽고, PC를 1 증가시켜 다음 명령어를 가리키게 한다.
- T2: Opcode를 해독하고, 주소 부분을 AR로, 간접 비트를 I 플립플롭으로 옮긴다.
- T3: 메모리 참조 명령어이면서 I = 1이면 `AR ← M[AR]`로 유효 주소를 읽고, 이후 타이밍에서 실행한다.

## 입출력과 인터럽트

### 입출력 구성과 플래그

| 플래그 | 의미 |
| --- | --- |
| FGI | 입력 장치 상태. 1이면 INPR에 새 데이터가 있음(입력 가능) |
| FGO | 출력 장치 상태. 1이면 출력 장치가 준비됨(출력 가능) |
| IEN (Interrupt Enable) | 1이면 인터럽트 허용 |

### 입출력 명령어 (앞 4비트가 1111)

| 명령어 | 코드 | 동작 |
| --- | --- | --- |
| INP | F800 | INPR의 문자를 AC로 입력 |
| OUT | F400 | AC의 문자를 OUTR로 출력 |
| SKI | F200 | FGI = 1이면 다음 명령어를 건너뜀 |
| SKO | F100 | FGO = 1이면 다음 명령어를 건너뜀 |
| ION | F080 | IEN ← 1 (인터럽트 허용) |
| IOF | F040 | IEN ← 0 (인터럽트 금지) |

### 프로그램 인터럽트

CPU가 플래그를 계속 확인(polling)하는 대신, I/O 장치가 준비되면 **CPU에 알리는** 방식이다. 인터럽트 사이클 진입 여부는 R 플립플롭으로 표시한다.

**R = 0 (명령어 사이클)**: 명령을 수행하면서 T0~T2가 아닐 때 `IEN = 1`이고 `FGI` 또는 `FGO`가 1이면 R을 1로 세팅한다.

**R = 1 (인터럽트 사이클)**: fetch 대신 다음을 수행한다.

```text
RT0: AR ← 0,  TR ← PC
RT1: M[AR] ← TR,  PC ← 0          복귀 주소를 메모리 0번지에 저장
RT2: PC ← PC + 1,  IEN ← 0,  R ← 0,  SC ← 0
```

1번지에는 입출력 처리 루틴(BIOS 같은 I/O 프로그램)으로 분기하는 명령어가 있어, 그곳으로 가서 인터럽트를 처리한다. IEN을 0으로 만들어 처리 중에 다른 인터럽트가 끼어들지 못하게 하고, 루틴의 마지막에 0번지에 저장된 주소로 간접 분기해 원래 프로그램으로 돌아온다.

현대 컴퓨터는 여러 인터럽트를 **인터럽트 벡터 테이블(IVT)** 로 관리한다. 인터럽트 우선순위와 처리 흐름은 [[io-organization|입출력 구조]]와 [[cpu-instructions|CPU와 명령어 구조]]를 참고한다.

## 기본 컴퓨터의 설계

기본 컴퓨터 설계의 핵심은 **제어 장치**를 만드는 일이다. 기본 컴퓨터의 하드웨어 구성은 다음과 같다.

- 16비트 × 4096워드 메모리
- 레지스터 9개: AR, PC, DR, AC, IR, TR, OUTR, INPR, SC
- 플립플롭 7개: I, S(start/stop), E(캐리 확장), R, IEN, FGI, FGO
- 디코더 2개: 3×8(Opcode), 4×16(타이밍)
- 16비트 공통 버스
- **제어 논리 게이트** ← 설계할 부분
- AC 입력에 연결된 가산·논리 회로(ALU)

### 제어 장치 설계 방법

각 레지스터·플립플롭의 제어 입력(LD, INR, CLR 등)마다 다음을 반복한다.

1. 전체 명령어 동작 중 그 레지스터와 관련된 마이크로 연산을 모두 모은다.
2. 동작 종류별로 분류한다.
3. 같은 동작을 일으키는 조건들을 **OR 게이트**로 묶는다.

예: **AR**과 관련된 동작을 모으면

```text
LD(AR)  = R'T0 + R'T2 + D7'IT3      AR에 값을 적재
CLR(AR) = RT0                        AR을 0으로
INR(AR) = D5T4                       AR을 1 증가
```

예: **IEN** (p = D7IT3, 즉 입출력 명령어 실행 시점, Bi는 IR의 i번째 비트)

```text
pB7: IEN ← 1     (ION)
pB6: IEN ← 0     (IOF)
RT2: IEN ← 0     (인터럽트 사이클)
```

### 누산기(AC) 논리 설계

AC를 바꾸는 명령어(AND, ADD, LDA, CLA, CMA, INC, 시프트, INP 등)를 모두 모아 같은 방식으로 제어 게이트를 만들고, AC 입력 쪽에 비트마다 가산기·논리 회로(ALU)를 붙여 결과를 AC에 적재한다.

## 핵심 정리

- 명령어 = I(1) + Opcode(3) + Address(12). I로 직접·간접 주소를 구분한다.
- 명령어 사이클은 fetch(T0~T1) → decode(T2) → 유효 주소(T3) → 실행. 타이밍은 SC + 4×16 디코더가 만든다.
- 인터럽트는 R 플립플롭으로 감지해 복귀 주소를 0번지에 저장하고 1번지의 처리 루틴으로 간다.
- 제어 장치 설계는 "관련 동작 수집 → 분류 → OR로 묶기"의 반복이다.
