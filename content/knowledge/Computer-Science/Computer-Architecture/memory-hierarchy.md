> 「계층별 접근 시간의 자릿수」, 「하드 디스크의 구성」, 「플래시 메모리와 SSD」, 「RAID」 등 일부 절은 강민철의 「혼자 공부하는 컴퓨터 구조+운영체제」 강의(한빛미디어)를 바탕으로 보강했다.

빠른 메모리는 비싸고 작으며, 큰 메모리는 느리다. 그래서 컴퓨터는 여러 종류의 저장 장치를 **계층**으로 쌓고, 자주 쓰는 데이터를 위쪽에 두는 방식으로 "빠르면서도 큰" 메모리처럼 보이게 만든다.

## 메모리 계층

```text
         ▲ 빠름 · 비쌈 · 작음
  레지스터
  L1 캐시
  L2 / L3 캐시
  메인 메모리 (DRAM)
  보조 기억 장치 (SSD / HDD / RAID)
  원격 보조 저장소 (네트워크 스토리지, 클라우드 백업, 테이프)
         ▼ 느림 · 저렴 · 큼
```

| 계층 | 역할 | 휘발성 |
| --- | --- | --- |
| 레지스터 | CPU 안의 아주 작은 저장소. 지금 계산 중인 값을 담는다 | 휘발 |
| 캐시(L1~L3, SRAM) | CPU 가까이에서 자주 쓰는 메모리 내용을 복사해 둔다 | 휘발 |
| 메인 메모리(DRAM) | 실행 중인 프로그램과 데이터 | 휘발 |
| SSD | 반도체로 된 영속 저장소. 움직이는 부품이 없어 빠르다 | 비휘발 |
| HDD | 회전하는 디스크와 헤드로 된 대용량 장기 저장소 | 비휘발 |
| 원격 보조 저장소 | 네트워크로 접근하는 백업·보관용 저장소 | 비휘발 |

### 계층별 접근 시간의 자릿수

계층 사이의 속도 차이는 몇 배가 아니라 **몇 자릿수**다. Jeff Dean이 정리해 널리 퍼진 「모든 프로그래머가 알아야 할 지연 시간」 표의 대표값은 다음과 같다. 정확한 값은 하드웨어 세대마다 다르므로 자릿수만 본다.

| 동작 | 대략의 시간 |
| --- | --- |
| L1 캐시 참조 | 0.5ns |
| L2 캐시 참조 | 7ns |
| 메인 메모리 참조 | 100ns |
| 메모리에서 1MB 순차 읽기 | 250µs |
| 하드 디스크 탐색(seek) | 10ms |
| 하드 디스크에서 1MB 순차 읽기 | 20ms |
| 캘리포니아 ↔ 네덜란드 패킷 왕복 | 150ms |

L1 참조와 디스크 탐색은 약 2천만 배 차이다. 하드 디스크에서 1MB를 읽는 시간은 대륙 간 네트워크 왕복과 같은 자릿수다. 웹 쪽 지연 숫자는 [[frontend-latency-numbers|프론트엔드 개발자가 알아야 할 지연 시간 숫자]]에 있다.

시스템 설계에서도 같은 원리를 쓴다. 자주 읽는 데이터는 위 계층(메모리 캐시)에, 오래 보관할 데이터는 아래 계층(오브젝트 스토리지·아카이브)에 둔다. [[block-file-object-storage|블록·파일·오브젝트 스토리지]]

### 계층을 잇는 버스

| 버스 | 연결 대상 |
| --- | --- |
| 내부 버스 | CPU 내부의 레지스터, 캐시 |
| 외부(시스템) 버스 | CPU ↔ 메인 메모리 |
| 입출력 버스 | I/O 프로세서 ↔ 디스크 등 외부 장치 |

## 주기억 장치

실행 중인 프로그램과 데이터를 담는 빠른 저장소로, RAM과 ROM으로 구성된다.

- **RAM**: 읽기/쓰기 가능. 실행 중인 프로그램을 담는다.
- **ROM**: 읽기 전용(현재는 주로 Flash). 전원이 꺼져도 남아야 하는 펌웨어(BIOS, 현재 PC는 UEFI)와 부트스트랩 코드를 담는다.

### RAM의 종류

RAM은 전원이 꺼지면 내용이 사라지는 **휘발성** 저장 장치다. CPU는 보조기억장치에 직접 접근하지 못하므로, 실행할 프로그램은 보조기억장치에서 RAM으로 복사된 뒤 실행된다. 그래서 보조기억장치에는 "보관할 대상"을, RAM에는 "실행할 대상"을 둔다. RAM이 크면 미리 올려 둘 수 있는 데이터가 많아 실행이 빨라지지만, 필요 이상으로 크면 효과가 없다.

| 종류 | 특징 | 주된 용도 |
| --- | --- | --- |
| DRAM (Dynamic) | 시간이 지나면 데이터가 사라져 주기적으로 다시 써야(refresh) 한다. 소비 전력이 낮고 싸며 집적도가 높다 | 주기억장치 |
| SRAM (Static) | 전원만 있으면 데이터가 유지되고 DRAM보다 빠르다. 집적도가 낮고 전력 소모가 크며 비싸다 | 캐시 메모리 |
| SDRAM (Synchronous) | 클럭에 동기화되어 클럭마다 CPU와 데이터를 주고받는 DRAM. SDR SDRAM이라고도 한다 | 주기억장치 |
| DDR SDRAM (Double Data Rate) | 한 클럭에 두 번 데이터를 주고받아 대역폭을 두 배로 넓힌 SDRAM. DDR2·DDR3·DDR4·DDR5로 갈수록 대역폭이 넓어진다. 2026년 기준 새 데스크톱·서버는 DDR5(JEDEC 규격 최대 8800MT/s), 노트북·스마트폰은 저전력판 LPDDR5·LPDDR5X를 쓴다 | 주기억장치 |

### SRAM과 DRAM이 다른 이유

| | SRAM | DRAM |
| --- | --- | --- |
| 한 비트 | 트랜지스터 6개(서로 물린 인버터 두 쌍) | 트랜지스터 1개 + 커패시터 1개 |
| 유지 | 전원만 있으면 그대로 | 커패시터의 전하가 새므로(leakage) **64ms마다 재충전**(refresh). 재충전 중인 행은 읽을 수 없다 |
| 읽기 | 신호가 곧바로 나온다 | 읽으면 전하가 빠지고, 신호가 약해 감지 증폭기가 필요하며, 충·방전에 시간이 걸린다 |
| 크기·값 | 셀이 커서 비싸다 | 셀이 작고 규칙적이라 촘촘히 싸게 만든다 |

그래서 빠르지만 비싼 SRAM은 CPU 캐시에, 느리지만 싼 DRAM은 주기억장치에 쓴다. **주기억장치는 원리적으로 느리다**는 것이 캐시를 고려해 코드를 짜야 하는 출발점이다([[cache-friendly-code|캐시를 고려한 코드]]).

### DRAM 접근은 왜 느리고, 왜 순서대로 읽으면 빠른가

DRAM 칩의 셀은 행과 열의 격자다. 주소선을 아끼려고 주소를 **두 번에 나눠** 보낸다.

```text
1. RAS(행 주소 선택): 행 주소를 보내 한 행 전체를 감지 증폭기로 연다
   ── tRCD(RAS→CAS 지연) 기다림
2. CAS(열 주소 선택): 열 주소를 보낸다
   ── CL(CAS 지연) 기다림
3. 데이터 전송: 한 번에 여러 워드를 연속 전송(burst) → 캐시 라인 하나를 채운다
4. 다른 행을 열려면 지금 행을 닫고 프리차지
   ── tRP(행 프리차지 시간), 행을 연 뒤 최소 tRAS가 지나야 닫을 수 있다
```

모듈 사양의 `CL-tRCD-tRP-tRAS`(예: `2-3-2-8`) 숫자가 이 대기 클럭 수다.

- 이미 열린 행 안에서는 RAS 없이 **CAS만 다시 보내면** 되므로, 연속 주소를 읽는 순차 접근이 훨씬 빠르다. 행을 계속 바꾸는 무작위 접근은 프리차지·활성화 대기가 매번 붙는다.
- 버스의 최고 속도는 「전송만 계속할 때」의 값이다. 행을 바꿀 때마다 쉬는 클럭이 생겨, 이론상 6.4GB/s인 버스가 무작위 접근에서는 1.8GB/s까지 떨어지는 예도 있다.
- DDR은 클럭의 올라가는 쪽과 내려가는 쪽에서 모두 전송해 셀 배열의 주파수를 올리지 않고 대역폭을 늘린다. 대역폭은 늘지만 **첫 데이터가 나오기까지의 지연은 줄지 않는다.** 메모리 지연이 세대가 바뀌어도 약 100ns 근처에 머무는 이유다.

### NUMA: 모든 메모리가 같은 거리에 있지 않다

과거 PC는 모든 CPU가 하나의 버스(FSB)로 노스브리지의 메모리 컨트롤러에 붙어, 메모리 대역폭을 모두가 나눠 썼다. 지금은 **메모리 컨트롤러가 CPU 안에** 들어 있고 소켓마다 자기 메모리가 붙는다. 소켓이 둘 이상인 서버에서는 다른 소켓의 메모리를 읽으려면 소켓 간 연결을 건너야 하므로 더 느리다. 이를 **NUMA**(Non-Uniform Memory Access)라 하고, 추가 비용을 NUMA 계수라 한다. 대역폭은 소켓 수만큼 늘지만, 스레드와 그 스레드가 쓰는 메모리를 같은 노드에 두어야 빠르다(Linux `numactl`, 첫 접근 시 할당되는 first-touch 정책).

### 칩 예시

- **128 × 8 RAM**: 8비트 워드 128개 → 주소선 7개(2^7 = 128). 칩 선택(CS) 신호가 활성일 때만 동작하고, RD/WR 신호로 읽기/쓰기를 고른다.
- **512 × 8 ROM**: 읽기만 가능, 주소선 9개(2^9 = 512).
- 작은 칩 여러 개를 묶어 큰 메모리를 만들며, 주소의 상위 비트로 어느 칩을 쓸지 선택한다.

### DRAM 모듈

DRAM 칩을 기판에 모아 꽂아 쓰는 형태로 발전해 왔다: SIMM(한쪽 면 접점) → DIMM(양면 독립 접점, SDRAM/DDR 세대) → 노트북용 소형 SO-DIMM. 세대(DDR … DDR5)마다 핀 수와 슬롯이 달라 서로 꽂히지 않는다.

## 보조 기억 장치

### 하드 디스크의 구성

- **플래터**: 데이터가 기록되는 원판 (트랙 → 섹터, 같은 반경의 트랙 묶음이 실린더)
- **스핀들**: 플래터를 회전시키는 모터
- **헤드 / 암**: 헤드가 읽고 쓰며, 암(액추에이터)이 헤드를 원하는 트랙으로 옮긴다
- **컨트롤러**: 기계 제어와 버스 인터페이스를 맡는 작은 컴퓨터

플래터는 보통 여러 장이고 양면을 모두 쓴다. 면마다 헤드가 하나씩 있고, 모든 헤드는 한 디스크 암에 붙어 **함께** 움직인다. 그래서 연속된 데이터는 한 트랙을 다 채운 뒤 옆 트랙으로 가지 않고 **같은 실린더의 다른 면**에 이어서 기록한다. 헤드를 옮기지 않고(탐색 없이) 면만 바꿔 가며 읽을 수 있기 때문이다. 섹터 하나 이상을 묶은 단위를 블록이라 부르며, 파일 시스템은 이 블록 단위로 공간을 관리한다([[file-system-implementation|파일 시스템 구현]]).

접근 시간(탐색 + 회전 지연 + 전송)과 용량 계산, 헤드 이동을 줄이는 스케줄링은 [[disk-scheduling|디스크 관리와 스케줄링]]에 있다.

자기 테이프는 순차 접근만 가능하지만 용량당 가격이 싸고 오래 보관할 수 있어, 지금도 데이터센터의 백업·아카이브에 LTO 테이프가 쓰인다.

### 플래시 메모리와 SSD

플래시 메모리는 전기적으로 데이터를 읽고 쓰는 반도체 저장 장치다. USB 메모리, SD 카드, SSD가 모두 플래시 메모리이고, 대용량 저장에는 주로 NAND 플래시가 쓰인다. 데이터를 저장하는 가장 작은 단위인 **셀**에 몇 비트를 담느냐에 따라 종류가 나뉜다.

| 종류 | 셀당 비트 | 특징 |
| --- | --- | --- |
| SLC (Single Level Cell) | 1 | 가장 빠르고 수명이 길지만 용량 대비 비싸다. 산업용, 그리고 SSD 안에서 일부 영역을 SLC처럼 쓰는 쓰기 캐시(SLC 캐시) |
| MLC (Multi Level Cell) | 2 | 한때 고급 소비자 SSD의 주류였지만 지금은 드물다 |
| TLC (Triple Level Cell) | 3 | 속도·수명·가격의 균형이 좋아 2026년 기준 소비자·서버 SSD의 주류 |
| QLC (Quad Level Cell) | 4 | 가장 고밀도이고 용량 대비 싸지만, 쓰기 속도와 수명이 TLC보다 낮다. 대용량·읽기 위주 용도 |

셀당 비트가 늘수록 용량은 커지고 속도·수명은 줄어든다. 여기서 수명은 셀을 **쓰고 지울 수 있는 횟수**(P/E 사이클)다. 한 셀에 구분해야 할 전압 단계가 많아질수록 셀이 닳는 영향을 크게 받아, 같은 용량이라도 셀 종류에 따라 가격·속도·수명이 달라진다. 실제 체감 속도는 셀보다 **인터페이스**가 크게 좌우한다. SATA SSD는 SATA 3(6Gb/s)에 묶여 순차 읽기가 약 550MB/s에 머물고, NVMe SSD는 PCIe 레인을 직접 써서 PCIe 4.0 제품이 약 7GB/s, PCIe 5.0 제품이 약 14GB/s대까지 나온다.

```text
셀 → 페이지 → 블록 → 플레인 → 다이
읽기·쓰기는 페이지 단위, 삭제는 더 큰 블록 단위
```

하드 디스크와 가장 다른 점은 **덮어쓰기가 안 된다**는 것이다. 페이지는 세 상태를 가진다.

| 상태 | 의미 |
| --- | --- |
| Free | 비어 있어 새 데이터를 쓸 수 있다 |
| Valid | 유효한 데이터가 들어 있다. 이 상태에서는 덮어쓸 수 없다 |
| Invalid | 더 이상 쓰지 않는 쓰레기값이 들어 있다 |

데이터를 고치면 새 내용은 Free 페이지에 쓰고 기존 페이지는 Invalid가 된다. Invalid 페이지가 쌓이면 SSD는 **가비지 컬렉션**으로 블록 안의 Valid 페이지만 새 블록으로 옮긴 뒤 기존 블록을 통째로 지운다.

## RAID

여러 디스크를 묶어 하나처럼 쓰면서 성능이나 안정성을 높이는 기술(Redundant Array of Independent Disks).

| 레벨 | 방식 | 특징 |
| --- | --- | --- |
| RAID 0 | 블록 스트라이핑 | 여러 디스크에 나눠 저장 → 빠르지만 중복이 없어 하나만 고장 나도 전체 손실 |
| RAID 1 | 미러링 | 같은 데이터를 두 디스크에 저장 → 안정적이지만 용량 효율 50% |
| RAID 2 | 비트 단위 스트라이핑 + 해밍 코드 | 해밍 코드로 오류 정정. 실제로는 거의 쓰이지 않음 |
| RAID 3 | 바이트 단위 스트라이핑 + 전용 패리티 디스크 | 큰 순차 전송에 유리 |
| RAID 4 | 블록 단위 스트라이핑 + 전용 패리티 디스크 | 쓰기마다 패리티 디스크가 병목 |
| RAID 5 | 블록 스트라이핑 + 패리티 분산 | 패리티를 모든 디스크에 돌려 저장 → 병목 해소, 디스크 1개 고장까지 복구 |
| RAID 6 | 블록 스트라이핑 + 이중 패리티 | 디스크 2개 동시 고장까지 복구 |

- RAID 1은 복구가 간단하지만 쓰기가 RAID 0보다 느리고, 같은 데이터를 두 번 저장하는 만큼 비용이 든다.
- RAID 4는 완전한 복사본 대신 패리티만 따로 저장해 RAID 1보다 적은 디스크로 안전성을 얻는다. RAID 5는 그 패리티를 모든 디스크에 나눠 RAID 4의 병목을 없앤 것이다.
- RAID 6은 쓰기 속도를 조금 희생하더라도 더 안전하게 보관하고 싶을 때 쓴다. 여러 레벨을 섞은 RAID 10, RAID 50 같은 구성(Nested RAID)도 있다.
- 디스크 여러 장에 줄무늬처럼 나뉘어 놓인 데이터 조각을 **스트라이프**(stripe), 그렇게 나눠 저장하는 일을 **스트라이핑**이라 한다. 한 디스크에 연속으로 쓰는 조각의 크기(stripe size)는 RAID 볼륨을 만들 때 정한다.
- 일반적인 패리티 비트는 오류를 **검출**만 하지만, RAID의 패리티는 나머지 디스크의 데이터와 XOR해 고장 난 디스크 한 장의 내용을 **복구**할 수 있다.
- RAID는 메인보드 펌웨어(BIOS·UEFI 설정의 RAID 모드), 전용 RAID 컨트롤러, 운영체제의 소프트웨어 RAID([[disk-scheduling|디스크 관리와 스케줄링]]의 md) 중 어디서든 구성할 수 있다.

| 가장 원하는 것 | 고를 만한 레벨 |
| --- | --- |
| 입출력 속도 | RAID 0 (데이터가 사라져도 되는 임시 작업 공간) |
| 단순하고 확실한 복구 | RAID 1 |
| 용량 효율과 안전성의 균형 | RAID 5 |
| 디스크 두 장 고장까지 견디기 | RAID 6 |
| 속도와 안전성 모두 | RAID 10 |

RAID는 디스크 고장에 대비할 뿐 **백업이 아니다.** 실수로 지운 파일, 랜섬웨어, 컨트롤러 고장은 모든 디스크에 똑같이 반영된다.

## 연관 메모리 (Associative Memory)

- 일반 메모리는 **주소**로 찾지만, 연관 메모리(CAM)는 **내용**으로 찾는다.
- **인자 레지스터(argument)에** 찾을 값을, **키 레지스터(key)에** 비교할 비트 위치(마스크)를 넣으면 모든 워드를 동시에 비교해 일치하는 위치를 알려준다.
- 병렬 비교 회로가 필요해 비싸지만 매우 빠르다. 캐시의 태그 비교, TLB 등에 쓰인다.

## 핵심 정리

- 위쪽 계층일수록 빠르고 비싸고 작다. 계층 구조는 지역성을 이용해 평균 접근 시간을 줄인다.
- 디스크 접근 시간은 탐색 시간이 지배한다.
- RAID는 스트라이핑(성능), 미러링·패리티(안정성)의 조합이다.
