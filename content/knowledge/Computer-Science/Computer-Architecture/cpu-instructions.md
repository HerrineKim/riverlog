CPU가 실행하는 것은 결국 메모리에 놓인 기계어 명령어다. 명령어가 피연산자를 어디서 가져오는지, 실행 흐름이 어떻게 바뀌는지를 이해하면 컴파일러와 운영체제가 하는 일도 함께 보이기 시작한다.

## 소스 코드에서 명령어로

사람이 읽기 쉬운 고급 언어는 CPU가 직접 실행할 수 있는 저급 언어로 바뀌어야 실행된다. 저급 언어에는 0과 1로 된 **기계어**와, 기계어를 사람이 읽기 쉬운 기호로 옮긴 **어셈블리어**가 있다.

| 방식 | 변환 단위 | 특징 | 예 |
| --- | --- | --- | --- |
| 컴파일 | 소스 코드 **전체**를 컴파일러가 한 번에 목적 코드로 변환 | 한 곳이라도 문법 오류가 있으면 실행되지 않는다 | C |
| 인터프리트 | 인터프리터가 **한 줄씩** 변환하며 실행 | N번째 줄에 오류가 있어도 N−1번째 줄까지는 실행된다. 보통 컴파일 언어보다 느리다 | Python |

현대 언어는 두 방식을 섞어 쓰는 경우가 많아 경계가 모호하다. C의 컴파일 단계는 [[c-basics|C 기초]]에서 다룬다.

## CPU 내부: ALU, 제어장치, 레지스터

### ALU

- **받는 것**: 레지스터에서 피연산자, 제어장치에서 "무슨 연산을 할지"를 담은 제어 신호.
- **내보내는 것**: 연산 결과(바로 메모리로 가지 않고 일단 레지스터에 저장)와 **플래그**(결과에 대한 부가 정보, 아래 상태 플래그 참고).
- 안에는 가산기, 뺄셈용 보수기, 시프터, 오버플로우 검출기 같은 회로가 있다.

### 제어장치

제어 신호를 내보내고 명령어를 해석하는 부품이다.

| 받아들이는 것 | 내보내는 것 |
| --- | --- |
| 클럭 신호 (모든 부품이 같은 박자로 움직이는 시간 단위) | CPU 외부: 제어 버스로 메모리·입출력장치에 제어 신호 |
| 명령어 레지스터의 "해석할 명령어" | CPU 내부: ALU에 연산 지시, 레지스터에 데이터 이동 지시 |
| 플래그 레지스터의 플래그 값 | |
| 제어 버스로 들어온 제어 신호 (예: 입출력장치의 인터럽트 요청) | |

### 반드시 알아야 할 레지스터

프로그램 속 명령어와 데이터는 실행 전후로 반드시 레지스터를 거친다. 그래서 레지스터 값만 따라가도 실행 흐름이 보인다.

| 레지스터 | 저장하는 것 |
| --- | --- |
| 프로그램 카운터(PC) | 메모리에서 **다음에 읽을 명령어의 주소**. 명령어 포인터라고도 한다 |
| 명령어 레지스터(IR) | 방금 읽어 들여 해석할 명령어 |
| 메모리 주소 레지스터(MAR) | 주소 버스로 내보낼 메모리 주소 |
| 메모리 버퍼 레지스터(MBR) | 데이터 버스로 주고받을 값. MDR(Memory Data Register)이라고도 한다 |
| 플래그 레지스터 | 연산 결과나 CPU 상태에 대한 부가 정보 |
| 범용 레지스터 | 데이터와 주소를 모두 담을 수 있는 자유로운 레지스터 |
| 스택 포인터 | 메모리의 스택 영역에서 마지막으로 저장한 값의 위치 |
| 베이스 레지스터 | 기준 주소. 변위 주소 지정에 쓴다 |

```text
1000번지의 명령어를 실행하는 흐름
1. PC = 1000 → MAR = 1000
2. 제어 버스로 '메모리 읽기', 주소 버스로 1000을 보낸다
3. 1000번지 값이 데이터 버스를 타고 MBR로 들어오고, PC는 1001로 증가한다
4. MBR의 값이 IR로 옮겨지고, 제어장치가 해석해 제어 신호를 낸다
5. 끝나면 PC가 가리키는 1001번지를 읽는다
   (점프 명령어나 인터럽트가 있으면 이 순차 흐름이 끊긴다)
```

1~4가 메모리에서 명령어를 가져오는 인출 사이클, 해석해 실행하는 단계가 실행 사이클이다. 간접 주소처럼 메모리에 한 번 더 가야 하면 간접 사이클이 끼어든다. 이렇게 반복되는 흐름을 **명령어 사이클**이라 한다.

## CPU 구조에 따른 명령어 형식

| 구조 | 예 | 의미 |
| --- | --- | --- |
| 단일 누산기 | `ADD X` | AC ← AC + M[X] |
| 범용 레지스터 | `ADD R1, R2, R3` | R1 ← R2 + R3 |
| 스택 | `PUSH X`, `ADD` | 스택 위 두 값을 더해 다시 push |

### 주소 개수에 따른 분류

명령어에 피연산자 주소를 몇 개 적는지에 따라 나눈다. 주소가 적을수록 명령어는 짧아지지만 필요한 명령어 개수는 늘어난다.

`X = (A + B) * (C + D)` 계산 예시:

```text
; 3주소 — 출발지와 목적지를 모두 명시
ADD  R1, A, B      ; R1 ← A + B
ADD  R2, C, D      ; R2 ← C + D
MUL  X, R1, R2     ; X ← R1 * R2

; 2주소 — 첫 피연산자가 목적지를 겸함
MOV  R1, A
ADD  R1, B
MOV  R2, C
ADD  R2, D
MUL  R1, R2
MOV  X, R1

; 1주소 — 누산기(AC)를 암묵적으로 사용
LOAD  A
ADD   B
STORE T            ; 중간 결과를 임시 위치에
LOAD  C
ADD   D
MUL   T
STORE X

; 0주소 — 스택만 사용
PUSH A
PUSH B
ADD
PUSH C
PUSH D
ADD
MUL
POP  X
```

RISC 방식에서는 값을 먼저 레지스터로 `LOAD`한 뒤 레지스터끼리만 연산하고, 마지막에 `STORE`로 메모리에 쓴다.

## 주소 지정 방식 (Addressing Mode)

같은 명령어라도 피연산자를 찾는 방법을 다양하게 두면 포인터·배열·카운터를 표현하기 쉽고, 프로그램을 메모리 어디에 두어도(재배치) 동작하게 만들 수 있으며, 주소 필드의 비트 수도 줄일 수 있다.

| 방식 | 피연산자 위치 / 유효 주소(EA) |
| --- | --- |
| 묵시적(Implied) | 명령어에 암묵적으로 정해짐 (AC, 스택 top) |
| 즉시(Immediate) | 명령어 안에 값 자체가 있음. 상수 초기화에 사용 |
| 레지스터 | CPU 레지스터 안에 피연산자 |
| 레지스터 간접 | 레지스터가 피연산자의 **주소**를 가짐 |
| 자동 증가/감소 | 레지스터 간접 후 레지스터 값을 자동으로 ±1 |
| 직접 | 주소 필드가 곧 EA |
| 간접 | 주소 필드가 가리키는 곳에 EA가 저장됨 |
| 상대 | EA = 주소 필드 + PC (분기에 유용) |
| 인덱스 | EA = 주소 필드 + 인덱스 레지스터 (배열 원소) |
| 베이스 레지스터 | EA = 주소 필드 + 베이스 레지스터 (프로그램 재배치) |
| 스택 | 스택 포인터가 가리키는 스택 top |

- 명령어 안의 피연산자 칸(오퍼랜드 필드)에는 값보다 **값이 있는 위치**를 적는 경우가 많다. 명령어 길이는 정해져 있어 값을 직접 넣으면 표현할 수 있는 크기가 작아지기 때문이다.
- 속도와 표현 범위는 맞바꾼다. 즉시 주소는 메모리를 찾지 않아 가장 빠르지만 담을 수 있는 값이 작다. 간접 주소는 범위가 넓지만 메모리에 두 번 접근해 느리다. 레지스터 간접은 메모리 접근을 한 번으로 줄인다.
- 상대·베이스 레지스터 방식은 "특정 레지스터 값 + 오퍼랜드(변위)"로 주소를 구하므로 묶어서 **변위 주소 지정**이라 부른다. 상대 주소에서 오퍼랜드가 −3이면 PC가 가리키는 곳보다 세 칸 앞을 뜻하고, 베이스 레지스터가 200이고 오퍼랜드가 40이면 240번지를 뜻한다.

## 연산 코드의 종류

명령어는 **연산 코드**(무엇을 할지)와 **오퍼랜드**(무엇으로 할지)로 이뤄진다. 연산 코드의 생김새는 CPU마다 다르지만 대부분의 CPU가 공통으로 가진 유형은 네 가지다.

| 유형 | 대표 명령어 |
| --- | --- |
| 데이터 전송 | MOVE, LOAD(메모리 → CPU), STORE(CPU → 메모리), EXCHANGE, PUSH, POP |
| 산술·논리 연산 | ADD, SUBTRACT, MULTIPLY, DIVIDE, INCREMENT, DECREMENT, AND, OR, NOT, COMPARE, 시프트 |
| 제어 흐름 변경 | JUMP, CONDITIONAL JUMP, HALT, CALL(복귀 주소를 저장하고 이동), RETURN |
| 입출력 제어 | READ(INPUT), WRITE(OUTPUT), START IO, TEST IO |

## 프로그램 제어

### 상태 플래그

| 플래그 | 의미 |
| --- | --- |
| C (Carry) | ALU 출력의 캐리 |
| S (Sign) | 결과의 부호 비트 |
| Z (Zero) | 결과가 0인지 |
| V (Overflow) | 오버플로우 여부 (마지막 두 캐리의 XOR) |
| 인터럽트 플래그 | 하드웨어 인터럽트를 받아들일 수 있는지 |
| 슈퍼바이저 플래그 | 커널 모드인지 사용자 모드인지 ([[system-structure\|모드 비트]]) |

예: A = `11110000`, B = `00010100`일 때 A − B를 2의 보수 덧셈으로 계산하면

```text
      A : 11110000
 B'+1   : 11101100
  A - B : 11011100   → C=1, S=1, Z=0, V=0
```

조건부 분기 명령어는 이 플래그 값을 보고 점프 여부를 결정한다.

### 서브루틴 호출과 복귀

```text
; CALL
SP ← SP - 1          ; 스택 포인터 감소
M[SP] ← PC           ; 복귀 주소 push
PC ← 유효 주소        ; 서브루틴으로 이동

; RETURN
PC ← M[SP]           ; 복귀 주소 pop
SP ← SP + 1
```

복귀 주소를 스택에 두기 때문에 서브루틴이 자기 자신을 호출하는 **재귀 호출**도 복귀 주소를 덮어쓰지 않고 처리할 수 있다.

### 인터럽트

서브루틴 호출과 비슷해 보이지만 차이가 있다.

- 프로그램 내부 명령이 아니라 **내·외부 신호**로 흐름이 바뀐다.
- 처리 루틴의 주소가 하드웨어적으로 정해져 있다.
- PC뿐 아니라 CPU 상태 전체를 저장해야 한다. 이 상태 묶음을 **PSW(Program Status Word)라** 하며 PC, 레지스터 값, 상태 플래그(C, S, Z, V)를 포함한다.

인터럽트는 원인에 따라 외부(하드웨어) 인터럽트, 내부 인터럽트(트랩·예외), 소프트웨어 인터럽트(시스템 콜)로 나눈다. 분류표는 [[system-structure|컴퓨터 시스템 구조와 인터럽트]]에 있다. 하드웨어 인터럽트 덕분에 CPU는 프린터가 일을 끝낼 때까지 기다리지 않고 다른 일을 하다가 "끝났다"는 알림만 받으면 된다.

```text
하드웨어 인터럽트 처리 순서
1. 입출력장치가 CPU에 인터럽트 요청 신호를 보낸다
2. CPU는 실행 사이클이 끝나고 다음 명령어를 인출하기 전에 인터럽트 여부를 확인한다
3. 인터럽트 플래그로 지금 받아들일 수 있는지 본다
   (정전·하드웨어 고장처럼 플래그로 막을 수 없는 인터럽트도 있다)
4. 받아들이면 지금까지의 작업을 백업한다
5. 인터럽트 벡터로 인터럽트 서비스 루틴(ISR, 인터럽트 핸들러)의 시작 주소를 찾아 실행한다
6. ISR이 끝나면 백업한 작업을 복구해 하던 일을 이어 간다
```

입출력장치마다 처리 방법이 달라 ISR도 장치마다 따로 있다. 여러 인터럽트가 동시에 들어올 때의 우선순위 처리는 [[io-organization|입출력 구조]]에 있다.

## RISC와 CISC

CPU가 이해하는 명령어의 모음을 **명령어 집합 구조(ISA, Instruction Set Architecture)라고** 한다. 인텔·AMD의 PC CPU는 x86(x86-64) ISA를, 아이폰과 애플 실리콘의 CPU는 ARM ISA를 이해한다. ISA는 CPU의 언어인 셈이라, ISA가 다르면 명령어 해석 방식, 레지스터 종류와 개수, 메모리 관리 방법, 하드웨어 설계가 모두 달라진다. 현대 ISA의 양대 산맥이 CISC(x86)와 RISC(ARM)다.

CISC는 복잡하고 다양한 가변 길이 명령어로 적은 수의 명령어만으로 프로그램을 돌리고 메모리를 아낀다. 하지만 명령어마다 길이와 수행 시간이 제각각이라 파이프라인에 넣기 어렵고, 복잡한 명령어 대부분은 실제로 잘 쓰이지 않았다. 이 한계에서 두 가지 교훈이 나왔다. 빠르려면 파이프라인을 십분 활용해야 하므로 명령어 길이와 수행 시간이 짧고 규격화되어야 한다. 그리고 자주 쓰는 기본 명령어를 작고 빠르게 만드는 편이 낫다.

RISC(Reduced Instruction Set Computer)는 1980년경 UC 버클리의 데이비드 패터슨 등이 제안한 설계 철학이다. 대표 아키텍처로 MIPS, SPARC, PowerPC, Alpha, 그리고 오늘날의 ARM, RISC-V가 있다.

| CISC | RISC |
| --- | --- |
| 명령어 수가 많고 일부는 거의 안 쓰임 | 명령어 수가 적음 |
| 다양한 주소 지정 방식 | 주소 지정 방식이 적음 |
| 가변 길이 명령어 | 고정 길이 명령어 → 디코딩이 단순 |
| 메모리의 피연산자를 직접 연산 | 메모리 접근은 load/store로만, 연산은 레지스터끼리 |
| 마이크로프로그램 제어 | 하드와이어드 제어, 명령어 대부분 1사이클 |
| 프로그램을 이루는 명령어 수가 적음 | 프로그램을 이루는 명령어 수가 많음 |
| 여러 클럭에 걸쳐 실행 → 파이프라이닝 어려움 | 1클럭 내외로 실행 → 파이프라이닝 쉬움 |

RISC의 장점

- 제어 장치가 단순해져 남는 칩 면적에 많은 레지스터를 둘 수 있다.
- 파이프라인을 효율적으로 구성하기 쉽다.
- 컴파일러 최적화가 성능의 큰 몫을 담당한다.

### 중첩 레지스터 윈도우

프로시저 호출마다 메모리 스택으로 인자를 주고받으면 느리다. Berkeley RISC I은 많은 레지스터를 여러 "윈도우"로 나누고, 호출하는 쪽과 호출되는 쪽의 윈도우가 일부 **겹치도록** 했다. 겹친 레지스터에 인자를 두면 복사 없이 바로 전달되어 호출·복귀가 빨라진다.

## 핵심 정리

- CPU는 PC → MAR → MBR → IR 순으로 명령어를 인출하고, 제어장치가 해석해 실행하는 명령어 사이클을 반복한다.
- 주소 개수가 적을수록 명령어는 짧고, 대신 명령어 수가 늘어난다.
- 주소 지정 방식은 포인터·배열·재배치를 지원하기 위한 장치다.
- 인터럽트는 외부 신호로 흐름이 바뀌므로 PSW 전체를 저장해야 한다.
- RISC는 단순한 고정 길이 명령어 + load/store 구조로 파이프라인 효율을 높인다.
