CPU가 실행하는 것은 결국 메모리에 놓인 기계어 명령어다. 명령어가 피연산자를 어디서 가져오는지, 실행 흐름이 어떻게 바뀌는지를 이해하면 컴파일러와 운영체제가 하는 일도 함께 보이기 시작한다.

## CPU 구조에 따른 명령어 형식

| 구조 | 예 | 의미 |
| --- | --- | --- |
| 단일 누산기 | `ADD X` | AC ← AC + M[X] |
| 범용 레지스터 | `ADD R1, R2, R3` | R1 ← R2 + R3 |
| 스택 | `PUSH X`, `ADD` | 스택 위 두 값을 더해 다시 push |

### 주소 개수에 따른 분류

명령어에 피연산자 주소를 몇 개 적는지에 따라 나눈다. 주소가 적을수록 명령어는 짧아지지만 필요한 명령어 개수는 늘어난다.

`X = (A + B) * (C + D)` 계산 예시:

```text
; 3주소 — 출발지와 목적지를 모두 명시
ADD  R1, A, B      ; R1 ← A + B
ADD  R2, C, D      ; R2 ← C + D
MUL  X, R1, R2     ; X ← R1 * R2

; 2주소 — 첫 피연산자가 목적지를 겸함
MOV  R1, A
ADD  R1, B
MOV  R2, C
ADD  R2, D
MUL  R1, R2
MOV  X, R1

; 1주소 — 누산기(AC)를 암묵적으로 사용
LOAD  A
ADD   B
STORE T            ; 중간 결과를 임시 위치에
LOAD  C
ADD   D
MUL   T
STORE X

; 0주소 — 스택만 사용
PUSH A
PUSH B
ADD
PUSH C
PUSH D
ADD
MUL
POP  X
```

RISC 방식에서는 값을 먼저 레지스터로 `LOAD`한 뒤 레지스터끼리만 연산하고, 마지막에 `STORE`로 메모리에 쓴다.

## 주소 지정 방식 (Addressing Mode)

같은 명령어라도 피연산자를 찾는 방법을 다양하게 두면 포인터·배열·카운터를 표현하기 쉽고, 프로그램을 메모리 어디에 두어도(재배치) 동작하게 만들 수 있으며, 주소 필드의 비트 수도 줄일 수 있다.

| 방식 | 피연산자 위치 / 유효 주소(EA) |
| --- | --- |
| 묵시적(Implied) | 명령어에 암묵적으로 정해짐 (AC, 스택 top) |
| 즉시(Immediate) | 명령어 안에 값 자체가 있음. 상수 초기화에 사용 |
| 레지스터 | CPU 레지스터 안에 피연산자 |
| 레지스터 간접 | 레지스터가 피연산자의 **주소**를 가짐 |
| 자동 증가/감소 | 레지스터 간접 후 레지스터 값을 자동으로 ±1 |
| 직접 | 주소 필드가 곧 EA |
| 간접 | 주소 필드가 가리키는 곳에 EA가 저장됨 |
| 상대 | EA = 주소 필드 + PC (분기에 유용) |
| 인덱스 | EA = 주소 필드 + 인덱스 레지스터 (배열 원소) |
| 베이스 레지스터 | EA = 주소 필드 + 베이스 레지스터 (프로그램 재배치) |

## 데이터 전송과 처리 명령어

- 전송: Load, Store, Move, Exchange, Push, Pop
- 처리: 산술 연산, 논리·비트 연산, 시프트

## 프로그램 제어

### 상태 플래그

| 플래그 | 의미 |
| --- | --- |
| C (Carry) | ALU 출력의 캐리 |
| S (Sign) | 결과의 부호 비트 |
| Z (Zero) | 결과가 0인지 |
| V (Overflow) | 오버플로우 여부 (마지막 두 캐리의 XOR) |

예: A = `11110000`, B = `00010100`일 때 A − B를 2의 보수 덧셈으로 계산하면

```text
      A : 11110000
 B'+1   : 11101100
  A - B : 11011100   → C=1, S=1, Z=0, V=0
```

조건부 분기 명령어는 이 플래그 값을 보고 점프 여부를 결정한다.

### 서브루틴 호출과 복귀

```text
; CALL
SP ← SP - 1          ; 스택 포인터 감소
M[SP] ← PC           ; 복귀 주소 push
PC ← 유효 주소        ; 서브루틴으로 이동

; RETURN
PC ← M[SP]           ; 복귀 주소 pop
SP ← SP + 1
```

복귀 주소를 스택에 두기 때문에 서브루틴이 자기 자신을 호출하는 **재귀 호출**도 복귀 주소를 덮어쓰지 않고 처리할 수 있다.

### 인터럽트

서브루틴 호출과 비슷해 보이지만 차이가 있다.

- 프로그램 내부 명령이 아니라 **내·외부 신호**로 흐름이 바뀐다.
- 처리 루틴의 주소가 하드웨어적으로 정해져 있다.
- PC뿐 아니라 CPU 상태 전체를 저장해야 한다. 이 상태 묶음을 **PSW(Program Status Word)**라 하며 PC, 레지스터 값, 상태 플래그(C, S, Z, V)를 포함한다.

| 종류 | 원인 |
| --- | --- |
| 외부 인터럽트 | 입출력 장치, 타이머, 전원 이상 |
| 내부 인터럽트(트랩) | 잘못된 명령·데이터: 오버플로우, 0으로 나누기, 세그멘테이션 폴트 |
| 소프트웨어 인터럽트 | 명령어 실행으로 발생: 시스템 콜(supervisor call) |

## RISC와 CISC

RISC(Reduced Instruction Set Computer)는 1980년경 UC 버클리의 데이비드 패터슨 등이 제안한 설계 철학이다. 대표 아키텍처로 MIPS, SPARC, PowerPC, Alpha, 그리고 오늘날의 ARM, RISC-V가 있다.

| CISC | RISC |
| --- | --- |
| 명령어 수가 많고 일부는 거의 안 쓰임 | 명령어 수가 적음 |
| 다양한 주소 지정 방식 | 주소 지정 방식이 적음 |
| 가변 길이 명령어 | 고정 길이 명령어 → 디코딩이 단순 |
| 메모리의 피연산자를 직접 연산 | 메모리 접근은 load/store로만, 연산은 레지스터끼리 |
| 마이크로프로그램 제어 | 하드와이어드 제어, 명령어 대부분 1사이클 |

RISC의 장점

- 제어 장치가 단순해져 남는 칩 면적에 많은 레지스터를 둘 수 있다.
- 파이프라인을 효율적으로 구성하기 쉽다.
- 컴파일러 최적화가 성능의 큰 몫을 담당한다.

### 중첩 레지스터 윈도우

프로시저 호출마다 메모리 스택으로 인자를 주고받으면 느리다. Berkeley RISC I은 많은 레지스터를 여러 "윈도우"로 나누고, 호출하는 쪽과 호출되는 쪽의 윈도우가 일부 **겹치도록** 했다. 겹친 레지스터에 인자를 두면 복사 없이 바로 전달되어 호출·복귀가 빨라진다.

## 핵심 정리

- 주소 개수가 적을수록 명령어는 짧고, 대신 명령어 수가 늘어난다.
- 주소 지정 방식은 포인터·배열·재배치를 지원하기 위한 장치다.
- 인터럽트는 외부 신호로 흐름이 바뀌므로 PSW 전체를 저장해야 한다.
- RISC는 단순한 고정 길이 명령어 + load/store 구조로 파이프라인 효율을 높인다.
