키보드, 디스크, 네트워크 카드 같은 주변 장치는 CPU보다 훨씬 느리고 데이터 형식도 제각각이다. 입출력 구조는 이 차이를 메우고, CPU가 기다리느라 시간을 낭비하지 않도록 하는 방법을 다룬다.

## 입출력 인터페이스

CPU와 주변 장치 사이의 통로로, 다음 차이를 해결한다.

- 동작 방식과 신호의 차이 (전기·기계적 신호 변환)
- 전송 속도의 차이 (느린 장치와의 동기화)
- 데이터 형식의 차이 (장치의 코드 ↔ 메모리 워드)
- 여러 장치 간의 동작 순서와 우선순위 조정

인터페이스는 버스에서 제어·상태 검사·데이터 출력·데이터 입력 커맨드를 받아 CPU와 데이터를 주고받는다. 내부에는 버스 버퍼, 제어 로직, 포트 레지스터(데이터/제어/상태)가 있다.

### 격리형 I/O vs 메모리 맵 I/O

| 구분 | 격리형 I/O (Port-mapped) | 메모리 맵 I/O |
| --- | --- | --- |
| 주소 공간 | 메모리와 I/O 주소가 분리 | 메모리 주소 일부를 I/O 장치에 할당 |
| 명령어 | IN/OUT 같은 전용 입출력 명령 | 일반 load/store로 접근 |
| 장점 | 메모리 주소 공간을 온전히 사용, 코드에서 I/O 구분이 쉬움 | 전용 명령이 필요 없어 구조가 단순 (임베디드에서 흔함) |

## 비동기 데이터 전송

송신과 수신이 같은 클럭을 공유하지 않을 때는 신호로 타이밍을 맞춘다.

- **스트로브 제어**: 한쪽이 스트로브 신호로 "지금 데이터가 버스에 있다"고 알린다. 송신 측이 시작할 수도, 수신 측이 요청할 수도 있다. 단, 상대가 실제로 받았는지는 확인할 수 없다.
- **핸드셰이킹**: 스트로브의 한계를 보완해 *data valid*(데이터 준비됨)와 *data accepted*(받았음) 두 신호를 주고받는다. 선이 끊기는 등 문제가 생기면 타임아웃으로 감지할 수 있다.

### 비동기 직렬 전송

- 문자 하나를 보낼 때 **시작 비트 1개 + 데이터 비트 + 정지 비트**를 붙인다. 예: 시작 1 + 데이터 8 + 정지 2 = 11비트로 8비트 문자 하나 전송.
- 한 비트의 시간 = 1 / 전송 속도(bps).
- 이를 처리하는 칩이 **UART**로, 내부의 시프트 레지스터가 병렬 데이터를 직렬로 바꿔 내보낸다.

## 데이터 전송 모드

| 방식 | 동작 | 특징 |
| --- | --- | --- |
| 프로그램 I/O | CPU가 상태 플래그를 계속 확인(폴링)하다 준비되면 전송 | 구현이 단순하지만 CPU가 대기에 시간을 낭비 |
| 인터럽트 I/O | 장치가 준비되면 인터럽트로 CPU에 알림 | 기다리는 동안 CPU가 다른 일을 함 |
| DMA | 전용 컨트롤러가 CPU 개입 없이 메모리와 장치 사이를 직접 전송 | 대량 전송에 효율적 |

## 우선순위 인터럽트

여러 장치가 동시에 인터럽트를 걸면 누구를 먼저 처리할지 정해야 한다. 소프트웨어로 장치를 하나씩 조사(폴링)하면 느리므로 하드웨어 방식을 쓴다.

- **비벡터 인터럽트**: 처리 루틴의 주소가 메모리의 고정 위치에 있다.
- **벡터 인터럽트**: 인터럽트를 건 장치가 처리 루틴의 위치 정보(벡터 주소, VAD)를 CPU에 알려준다.

### 데이지 체인

- 장치들을 우선순위 순서대로 직렬 연결한다.
- 인터럽트 요청이 오면 CPU가 승인(acknowledge) 신호를 보내고, 이 신호는 우선순위가 높은 장치부터 차례로 전달된다.
- 요청한 장치가 신호를 받으면 자신의 VAD를 버스에 올리고 전달을 멈춘다. 요청하지 않았다면 다음 장치로 넘긴다.

### 병렬 우선순위 인터럽트

- 장치마다 비트 하나씩 할당된 **인터럽트 레지스터**와, 개별 요청을 허용/차단하는 **마스크 레지스터**를 둔다.
- 두 레지스터를 AND한 결과가 **우선순위 인코더**로 들어가 가장 높은 우선순위 요청의 VAD만 출력된다.
- **IEN(인터럽트 인에이블) 플립플롭**으로 인터럽트 전체를 켜고 끈다. CPU는 인터럽트를 인식하면 보통 IEN을 자동으로 0으로 만든다.

### 인터럽트 처리 흐름

```text
[시작 처리]
1. 같은/낮은 우선순위 인터럽트를 마스크로 막는다
2. 프로세서 레지스터를 저장한다
3. IEN을 1로 켜서 더 높은 우선순위 인터럽트는 허용한다 (중첩 인터럽트)
4. 서비스 루틴 실행

[종료 처리]
1. IEN을 0으로 끈다
2. 레지스터를 복원하고 처리한 요청 비트를 지운다
3. 마스크를 원래대로 돌린다
4. 복귀 주소를 PC에 넣고 IEN을 다시 1로 켠다
```

## DMA (Direct Memory Access)

- DMA 컨트롤러가 **버스 요청(bus request)**을 보내고 CPU가 **버스 승인(bus grant)**을 하면, 컨트롤러가 버스를 넘겨받아 직접 전송한다. 그동안 CPU는 메모리 버스를 쓸 수 없다.
- 전송 방식
  - **버스트 전송**: 버스를 잡은 동안 블록 전체를 연속 전송. 빠르지만 CPU가 오래 기다린다.
  - **사이클 스틸링**: 한 번에 한 워드만 보내고 버스를 돌려준다. CPU는 메모리 사이클 하나씩만 "도둑맞는다".
- 컨트롤러 레지스터: **주소 레지스터**(메모리 위치), **워드 카운트 레지스터**(남은 전송량), **제어 레지스터**(읽기/쓰기 모드).
- CPU는 시작 주소, 워드 수, 모드를 설정하고 시작만 시킨다. 전송이 끝나면 DMA가 인터럽트로 알린다.

## 입출력 프로세서 (IOP)

- 입출력만 전담하는 별도 프로세서(데이터 채널이라고도 함). DMA 컨트롤러와 달리 **자체 명령어 프로그램**을 실행할 수 있다.
- 장치의 데이터 형식을 재구성한다. 예: 8비트 문자를 모아 32비트 워드로 만든 뒤 메모리에 전송.
- CPU와는 주로 메모리를 통해 소통한다: CPU가 명령을 남기면 IOP가 정해진 위치에 상태를 기록하고 DMA로 전송을 수행, 끝나면 인터럽트로 알린다. 그동안 CPU는 다른 프로그램을 실행한다.

## 직렬 통신

### 전송 에러 검출

- **LRC**(Longitudinal Redundancy Check): 블록 내 모든 문자를 XOR한 값을 덧붙인다.
- **CRC**(Cyclic Redundancy Check): 다항식 나눗셈(시프트 레지스터 + XOR)으로 검사 값을 만든다. 연속으로 여러 비트가 깨지는 **버스트 에러** 검출에 강하다.
- 수신 측이 다시 계산한 값이 다르면 재전송을 요청한다.

### 전송 방향

| 방식 | 설명 | 예 |
| --- | --- | --- |
| 단방향(simplex) | 한쪽으로만 | 방송 |
| 반이중(half-duplex) | 양방향이지만 동시에는 불가 | 무전기 |
| 전이중(full-duplex) | 동시에 양방향 | 전화 |

### 데이터 링크 프로토콜

- **문자 지향 프로토콜**: 특수 제어 문자로 프레임의 시작·끝과 제어 정보를 표시한다. 데이터 안에 제어 문자와 같은 패턴이 나오면 오해될 수 있는 **데이터 투명성 문제**가 있어, DLE(escape) 문자를 덧붙여 회피하지만 번거롭다.
- **비트 지향 프로토콜**: 플래그 비트 패턴 `01111110`으로 프레임 경계를 표시한다. 데이터에 같은 패턴이 생기지 않도록 **1이 다섯 번 연속되면 0을 끼워 넣고(비트 스터핑)**, 수신 측에서 다시 제거한다. (HDLC 등)

## 핵심 정리

- 폴링 → 인터럽트 → DMA → IOP 순으로 CPU의 입출력 부담이 줄어든다.

운영체제가 인터럽트·시스템 콜·DMA를 어떻게 활용하는지는 [[system-structure|컴퓨터 시스템 구조와 인터럽트]]에 정리했다.
- 인터럽트 우선순위는 데이지 체인(직렬) 또는 마스크 + 우선순위 인코더(병렬)로 정한다.
- 직렬 통신은 CRC로 에러를 검출하고, 비트 스터핑으로 데이터 투명성을 확보한다.
