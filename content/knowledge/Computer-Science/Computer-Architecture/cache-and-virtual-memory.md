캐시와 가상 메모리는 같은 아이디어를 메모리 계층의 서로 다른 층에 적용한 것이다. 캐시는 "느린 메인 메모리를 빠르게", 가상 메모리는 "작은 메인 메모리를 크게" 보이게 만든다. 둘 다 프로그램이 최근에 쓴 데이터나 그 근처를 다시 쓰는 경향(**지역성**)에 기대고 있다.

## 캐시 메모리

- 메인 메모리보다 수십 배 빠르고 용량은 훨씬 작다.
- 보통 L1·L2는 코어 안에, L3는 여러 코어가 공유하는 계층 구조다.
- CPU는 주소만 내보낼 뿐, 데이터가 캐시에 있는지 메인 메모리에 있는지 신경 쓰지 않는다. 이를 연결하는 것이 **주소 매핑**이다.
  - **캐시 히트**: 캐시에 있음 → 바로 전달
  - **캐시 미스**: 없음 → 메인 메모리에서 가져와 캐시에 채움
- **히트율** = 히트 횟수 / 전체 접근 횟수. 지역성 덕분에 실제 프로그램에서는 보통 90% 이상이다.

### 주소 매핑 방식

| 방식 | 동작 | 장단점 |
| --- | --- | --- |
| 연관 매핑 (fully associative) | 주소(태그)와 데이터를 함께 저장하고, 들어온 주소를 **모든 항목과 동시에** 비교 | 어디든 저장 가능해 유연하지만 비교 회로가 비쌈 |
| 직접 매핑 (direct) | 주소를 **태그 + 인덱스**로 나누고 인덱스로 캐시 위치를 바로 결정, 태그만 비교 | 단순·저렴하지만 같은 인덱스를 쓰는 주소끼리 계속 충돌 |
| 집합 연관 매핑 (set-associative) | 한 인덱스(집합)에 2개·4개 등 여러 블록을 저장 (2-way, 4-way) | 직접 매핑의 충돌을 줄이는 절충안. way를 끝까지 늘리면 연관 매핑과 같아짐 |

블록 단위로 매핑할 때는 주소를 태그 / 인덱스(블록) / 블록 내 워드로 나눈다.

### 쓰기 정책

| 정책 | 동작 | 특징 |
| --- | --- | --- |
| Write-through | 캐시와 메인 메모리에 **동시에** 기록 | 메모리가 항상 최신이라 안전하지만 쓰기가 느림 |
| Write-back | 캐시에만 기록하고, 블록이 교체될 때 메모리에 반영 | 쓰기가 빠르지만 반영 전 장애 시 데이터 손실 위험, 일관성 관리 필요 |

### 초기화

각 캐시 항목에 **valid 비트**를 두고, 시작할 때 모두 0으로 만들어 "아직 유효한 데이터가 없음"을 표시한다. 메모리에서 데이터를 채울 때 1로 바꾼다.

## 가상 메모리

보조 기억 장치를 메인 메모리의 연장처럼 사용해, 프로그래머가 실제 물리 메모리보다 큰 메모리가 있는 것처럼 프로그램을 작성하게 해 주는 기법이다.

| 용어 | 의미 |
| --- | --- |
| 가상 주소 / 주소 공간 | 프로그램이 사용하는 주소와 그 전체 집합 |
| 물리 주소 / 메모리 공간 | 실제 메인 메모리의 주소와 그 집합 |
| 페이지 | 주소 공간을 같은 크기로 나눈 단위 |
| 프레임(블록) | 메모리 공간을 같은 크기로 나눈 단위 |

### 페이징을 이용한 주소 변환

```text
가상 주소 = [ 페이지 번호 | 페이지 내 오프셋 ]
                 │
           페이지 테이블 조회
                 ▼
물리 주소 = [ 프레임 번호 | 페이지 내 오프셋 ]
```

- 페이지 테이블의 각 항목에는 프레임 번호와 **존재(presence/valid) 비트**가 있다. 존재 비트가 0이면 그 페이지는 아직 디스크에 있다.
- 페이지 수가 프레임 수보다 훨씬 많으면(예: 페이지 1024개, 프레임 32개) 테이블 대부분이 비어 낭비된다. 이때 (페이지 번호, 프레임 번호) 쌍만 **연관 메모리**에 담는 방식으로 테이블 크기를 줄일 수 있다.

### 페이지 폴트와 교체

- 참조한 페이지가 메모리에 없으면 **페이지 폴트**가 발생한다. 프로그램은 잠시 멈추고, 운영체제가 디스크에서 페이지를 읽어 온다(입출력 작업이므로 DMA/IOP가 담당).
- 메모리가 가득 차 있으면 어떤 페이지를 내보낼지 정해야 한다.

| 알고리즘 | 내보낼 페이지 |
| --- | --- |
| FIFO | 가장 먼저 들어온 페이지 |
| LRU | **가장 오랫동안 참조되지 않은** 페이지 |

LRU를 하드웨어로 구현하는 한 가지 방법은 페이지마다 카운터를 두고 주기적으로 증가시키되 참조되면 0으로 초기화하는 것이다. 그러면 카운터가 가장 큰 페이지가 가장 오래 안 쓰인 페이지가 된다(에이징 방식).

## 메모리 관리 장치 (MMU)

여러 프로그램이 동시에 메모리를 쓰는 환경에서 MMU의 역할은 세 가지다.

1. **동적 재배치**: 가상 주소를 실행 시점에 물리 주소로 변환한다.
2. **공유**: 컴파일러나 라이브러리처럼 공통 프로그램을 사용자마다 복사하지 않고 하나만 두고 함께 쓴다.
3. **보호**: 다른 프로그램이나 운영체제 영역에 허락 없이 접근하지 못하게 막는다.

### 세그먼트와 TLB

- **세그먼트**: 코드, 데이터, 스택처럼 프로그램의 **논리적 단위**로 나눈 가변 크기 영역.
- 세그먼트 + 페이징을 함께 쓰면 논리 주소는 [세그먼트 | 페이지 | 워드]로 구성되고, 변환하려면 세그먼트 테이블 → 페이지 테이블 → 실제 메모리까지 여러 번 메모리를 참조해야 해서 느리다.
- 그래서 최근 변환 결과를 연관 메모리에 저장해 두는 **TLB(Translation Lookaside Buffer)**를 둔다. TLB에 있으면 바로 변환하고, 없을 때만 테이블을 따라가 변환한 뒤 TLB에 저장한다.

### 메모리 보호 필드

세그먼트 테이블 항목에 베이스 주소 외에 **길이 필드**(범위를 넘는 접근 차단)와 **보호 필드**(접근 권한)를 둔다.

| 권한 | 용도 |
| --- | --- |
| 읽기/쓰기 모두 허용 | 일반 사용자 데이터 |
| 읽기 전용 | 공유 라이브러리·유틸리티 보호 |
| 실행 전용 | 프로그램 복사 방지 |
| 시스템 전용 | 운영체제 영역 보호 |

## 핵심 정리

- 캐시: 매핑(연관/직접/집합 연관)과 쓰기 정책(write-through/back)이 핵심이다.
- 가상 메모리: 페이지 테이블로 주소를 변환하고, 없으면 페이지 폴트 후 FIFO·LRU 등으로 교체한다.
- MMU는 재배치·공유·보호를 맡고, TLB로 주소 변환을 빠르게 한다.
