> 「컴퓨터 구조를 알아야 하는 이유」, 「네 가지 핵심 부품과 시스템 버스」 절과 「클럭과 멀티코어」·「코어와 스레드」 절의 일부는 강민철의 「혼자 공부하는 컴퓨터 구조+운영체제」 강의(한빛미디어)를 바탕으로 보강했다.

현대 컴퓨터는 "계산하는 CPU + 프로그램과 데이터를 기억하는 메모리 + 오래 보관하는 저장 장치"라는 단순한 틀 위에 서 있다. 이 틀이 어떻게 생겨났는지 역사를 따라가 보면 각 부품의 역할이 자연스럽게 이해된다.

## 컴퓨터 구조를 알아야 하는 이유

프로그래밍 언어의 문법만으로는 풀리지 않는 문제가 있다. 컴퓨터 구조와 운영체제는 그 아래층, 즉 코드가 하드웨어에서 실제로 어떻게 실행되는지를 다룬다.

| 얻는 것 | 설명 |
| --- | --- |
| 문제 해결 능력 | 문법상 문제없는 코드가 다른 환경에서 동작하지 않을 때, 원인은 대개 언어 밖(하드웨어, OS, 실행 환경)에 있다. 컴퓨터를 입력하면 결과가 나오는 미지의 상자가 아니라 **분석할 수 있는 대상**으로 보고 내부를 따라가 원인을 찾는다 |
| 성능·용량·비용 판단 | 서비스를 올릴 서버는 무조건 싼 것도, 무조건 최신인 것도 답이 아니다. 클라우드를 써도 CPU 종류, 메모리, 스토리지를 직접 고르고 그에 따라 비용이 달라진다. 코드에 필요한 성능·용량을 스스로 가늠하려면 각 부품의 특성을 알아야 한다 |

## 컴퓨터의 발전 과정

스위치 부품의 세대교체와 프로그램 입력 수단의 변천 같은 더 긴 흐름은 [[computing-history|컴퓨터의 역사]]에 있다.

### ENIAC (1946)

- 에커트와 모클리가 만든, 프로그래밍이 가능한 초기 전자식 컴퓨터.
- 다만 소프트웨어를 "저장"하는 개념이 없어서, 작업을 바꿀 때마다 사람이 직접 전선을 다시 꽂아 회로를 바꿔야 했다.

### 폰 노이만과 프로그램 내장 방식

- 프로그램도 데이터처럼 메모리에 저장해 두면 CPU는 그것을 읽어 계산만 하면 된다는 아이디어(stored-program).
- 이로써 **계산하는 CPU / 명령을 담은 소프트웨어 / 그것을 저장하는 하드웨어**라는 구성 체계가 자리 잡았다. 오늘날 대부분의 컴퓨터가 이 구조를 따른다.

### 논리 회로와 CPU

- 전구를 켜고 끄는 것처럼, 스위치의 on/off(1/0)에 약속된 의미를 부여하면 정보를 표현할 수 있다.
- 이런 스위칭으로 논리 연산을 구현한 것이 논리 회로이고, CPU는 엄청난 수의 논리 회로로 이루어져 있다.

### 집적회로 (1958, 잭 킬비)

- 트랜지스터, 저항, 커패시터 같은 부품을 반도체 공정으로 한 칩에 함께 만드는 **IC(Integrated Circuit)를** 고안했다.
- 덕분에 회로를 극도로 작게 만들 수 있게 되었고, 오늘날의 소형 CPU로 이어졌다.

## 컴퓨터의 기본 구조

```text
입력 → [ CPU (제어 장치 + 연산 장치) ↔ 메모리 ↔ I/O ] → 출력
```

| 구성 요소 | 역할 |
| --- | --- |
| CPU | 연산 장치(ALU)가 계산을, 제어 장치가 명령 해석과 흐름 제어를 맡는다. 스스로는 기억 공간이 거의 없어 메모리가 필요하다. |
| 메모리(RAM) | 실행 중인 프로그램과 데이터를 0/1로 기억한다. 전원이 꺼지면 사라진다(휘발성). |
| 저장 장치(HDD/SSD) | 전원이 꺼져도 남는 대용량 영구 저장소. 당장 쓰는 부분만 RAM으로 올린다. |

### 네 가지 핵심 부품과 시스템 버스

컴퓨터가 이해하는 정보는 0과 1로 된 두 가지다. **명령어**는 데이터를 움직이고 컴퓨터를 작동시키는 정보이고, **데이터**는 명령어의 재료가 되는 숫자·문자·이미지 같은 정보다. 아두이노든 서버든 이 정보를 다루는 핵심 부품은 네 가지로 같다.

| 부품 | 역할 |
| --- | --- |
| CPU | 메모리의 명령어를 읽고 해석해 실행한다. 안에 ALU(계산), 레지스터(작은 임시 저장소), 제어장치(명령어 해석과 제어 신호 발생)가 있다. |
| 메모리(주기억장치) | **현재 실행 중인** 프로그램의 명령어와 데이터를 저장한다. 프로그램이 실행되려면 반드시 메모리에 있어야 하고, 각 값의 위치는 **주소**로 찾는다. 주기억장치에는 RAM과 ROM이 있지만 보통 「메모리」는 RAM을 가리킨다. |
| 보조기억장치 | HDD·SSD·USB 메모리처럼 전원이 꺼져도 남는 장치. **보관할** 프로그램을 저장한다. |
| 입출력장치 | 키보드·마우스·스피커처럼 외부와 정보를 주고받는다. 보조기억장치도 넓게 보면 메모리를 보조하는 특별한 입출력장치라, 둘을 묶어 **주변 장치**라고도 부른다. |

크기가 달라도 구성은 같다. 데스크톱은 메인보드에 CPU(발열 때문에 쿨러 아래에 있다)·RAM·SSD를 꽂고 USB 포트로 입출력장치를 잇는다. 라즈베리 파이는 손바닥만 한 보드에 CPU와 RAM이 붙어 있고 SD 카드가 보조기억장치를 맡는다.

이 부품들은 메인보드(마더보드)에 꽂히고, 메인보드 안의 **버스**라는 통로로 정보를 주고받는다. 그중 네 부품을 잇는 가장 중요한 버스가 **시스템 버스**다.

| 시스템 버스 | 주고받는 것 |
| --- | --- |
| 주소 버스 | 읽거나 쓸 주소 |
| 데이터 버스 | 명령어와 데이터 |
| 제어 버스 | 메모리 읽기·쓰기 같은 제어 신호 |

```text
CPU가 메모리의 값을 읽을 때
1. 제어 버스로 '메모리 읽기' 신호를 보낸다
2. 주소 버스로 읽을 주소를 보낸다
3. 메모리가 그 주소의 내용을 데이터 버스로 돌려준다 → CPU의 레지스터에 저장
```

쓸 때는 정보가 세 가지 필요하다. 어디에(주소 버스), 무엇을 할지(제어 버스의 '메모리 쓰기'), 무엇을(데이터 버스)이다. 네 부품이 함께 명령어 두 개를 실행하는 흐름은 다음과 같다.

```text
메모리  1번지: 더하라 3번지, 4번지     3번지: 120
        2번지: 결과를 5번지에 저장하라  4번지: 100

1. 제어장치가 1번지에 '메모리 읽기' → 명령어가 레지스터로 온다
2. 제어장치가 해석: 3번지와 4번지 값이 필요하다 → 다시 '메모리 읽기' → 120, 100이 레지스터로
3. ALU가 120 + 100 = 220을 계산해 레지스터에 둔다
4. 2번지 명령어를 읽어 해석 → '메모리 쓰기' 신호, 주소 5번지, 데이터 220을 보낸다
```

실제 CPU는 이보다 단계가 많다. 명령어를 가져오는 경로(PC·MAR·MBR·IR)는 [[cpu-instructions|CPU와 명령어 구조]]에 있다.

### 속도 계층

```text
CPU ← 캐시(SRAM) ← 메인 메모리(DRAM) ← 디스크
       빠름                              느림 (수십~수천 배 차이)
```

데이터는 디스크 → 메모리 → 캐시를 거쳐 CPU에 전달된다. 위로 갈수록 빠르고 비싸며 용량이 작다. 캐시에 쓰는 SRAM과 주기억장치에 쓰는 DRAM의 차이를 비롯한 자세한 내용은 [[memory-hierarchy|메모리 계층 구조]]에 있다.

## 클럭과 멀티코어

- CPU는 **클럭**에 맞춰 "메모리에서 읽기 → 계산 → 결과 쓰기"를 반복한다.
- 클럭 속도는 1초에 클럭이 반복되는 횟수로, 헤르츠(Hz)로 잰다. 2.5GHz면 1초에 25억 번이다. 클럭이 빠를수록 명령어 사이클을 빨리 돌기 때문에 클럭 속도는 CPU 속도의 단위처럼 쓰인다. 다만 항상 일정하지는 않아서, 부하가 클 때 순간적으로 높이기도 하고 최대치 이상으로 끌어올리는 것을 **오버클럭킹**이라 한다. 클럭만 높이면 발열이 커지므로 코어와 스레드를 늘리는 방식이 함께 발전했다.
- **멀티코어(듀얼 코어 등)**: 여러 코어로 작업을 나눠 병렬로 처리한다.
  - 코어를 늘려도 성능이 비례해 오르지는 않는다. 전력 소모와 발열이 커지고, 프로그램 중 병렬화할 수 없는 부분이 전체 속도 향상의 상한을 정하기 때문이다(암달의 법칙).
  - 작업을 코어마다 고르게 나누지 못하면 일부 코어만 바쁘고 나머지는 논다. 처리할 일 자체가 코어 수보다 적어도 코어를 더 늘린 효과가 없다. 멀티코어 성능은 **일을 얼마나 고르게 나누느냐**에 달려 있다.
  - 이런 한계 때문에 다른 계산 패러다임(예: 양자 컴퓨팅)에 대한 연구도 활발하다.

### 코어와 스레드

**코어**는 명령어를 실행하는 하드웨어 부품이다. 예전에 "CPU"라고 부르던 단위가 이제 CPU 안의 코어 하나에 해당한다. 8코어 CPU는 명령어 실행 부품을 8개 가진 CPU다.

**스레드**는 "실행 흐름의 단위"인데, 하드웨어와 소프트웨어에서 뜻이 다르다.

| 구분 | 의미 | 예 |
| --- | --- | --- |
| 하드웨어 스레드 | 코어가 OS에 보여 주는 **논리 프로세서** 하나. 자기 아키텍처 상태를 가진다 | 인텔의 하이퍼스레딩. 2코어 4스레드 CPU |
| 소프트웨어 스레드 | 프로그램 안에서 **독립적으로 실행되는 흐름** | Java·Python으로 만드는 스레드([[process-and-thread\|프로세스와 스레드]]) |

- 하드웨어 스레드를 만드는 기술이 **SMT**(동시 멀티스레딩, 인텔 이름은 하이퍼스레딩)다. 코어가 프로그램 카운터·레지스터 같은 **아키텍처 상태만 여러 벌** 두고, 실행 유닛·캐시는 스레드끼리 나눠 쓴다. OS에는 코어마다 논리 프로세서가 여러 개로 보이지만, 처리량이 그 배수로 늘지는 않는다. 한 스레드가 메모리를 기다리며 비워 둔 실행 유닛을 다른 스레드가 채워 **사용률**을 높이는 기술이다([[cpu-microarchitecture|현대 CPU의 마이크로아키텍처]]).
- 실행 중인 프로그램은 코어와 하드웨어 스레드가 몇 개인지 알지 못한다. 명령어를 동시에 몇 개씩 처리해 주는지만 느끼므로, 하드웨어 스레드 수가 곧 프로그램이 보는 CPU 수다. 윈도우 작업 관리자가 코어 수와 별도로 「논리 프로세서」 수를 보여 주는 이유다.
- 두 스레드 개념은 서로 독립이다. **1코어 1스레드 CPU에서도 소프트웨어 스레드를 여러 개 실행할 수 있다.** 운영체제가 스레드들을 아주 빠르게 번갈아 실행해 동시에 도는 것처럼 보이게 한다([[process-scheduling|프로세스 상태와 CPU 스케줄링]]).
- 전력 효율을 위해 SMT를 빼는 설계도 있어, 인텔 Core Ultra 200 계열(Lunar Lake·Arrow Lake, 2024)은 코어당 스레드가 하나다.

| 용어 | 한 줄 정의 |
| --- | --- |
| 멀티코어 프로세서 | 명령어를 실행하는 부품(코어)을 2개 이상 가진 CPU |
| 멀티스레드(SMT) 프로세서 | 코어 하나가 여러 하드웨어 스레드의 명령어를 섞어 실행하는 CPU |

## 운영체제와의 연결

- 디스크에 파일로 있던 프로그램이 실행되어 메모리에 올라오면 **프로세스**가 된다([[process-and-thread|프로세스와 스레드]]).
- 메모리는 비싸므로 프로그램 전체가 아니라 필요한 부분만 올라간다.
- 운영체제는 수많은 프로세스가 동시에 실행되는 것처럼 CPU 시간을 나누고, 어떤 데이터를 어떤 순서로 메모리·캐시·버스를 통해 옮길지 관리해 성능을 최적화한다.

## 핵심 정리

- 프로그램 내장 방식(폰 노이만 구조)이 현대 컴퓨터의 기본 틀이다.
- CPU는 계산, 메모리는 실행 중 데이터 보관, 디스크는 영구 보관을 맡는다.
- 캐시(SRAM)·메인 메모리(DRAM)·디스크의 계층으로 속도와 비용의 균형을 맞춘다.
