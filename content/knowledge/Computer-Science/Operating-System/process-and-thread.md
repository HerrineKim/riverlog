> 노션 정리와 개발장의 「[프로세스와 스레드의 차이](https://velog.io/@raejoonee/프로세스와-스레드의-차이)」(2020.08)를 바탕으로 재구성한 노트입니다.

**프로세스**는 실행 중인 프로그램이다. 디스크에 있던 실행 파일이 메모리에 올라와 CPU를 받을 수 있는 상태가 되면, 운영체제는 그것을 하나의 프로세스로 관리한다. 프로세스를 이해하려면 "지금 어디까지 실행했는가"를 나타내는 **문맥(context)** 을 알아야 한다.

## 프로세스의 문맥

| 구분 | 내용 |
| --- | --- |
| CPU 수행 상태 | PC(Program Counter), 각종 레지스터 값 |
| 프로세스의 주소 공간 | Code(실행할 명령어), Data(전역·static 변수), Stack(함수 호출 정보) |
| 커널이 가진 프로세스 정보 | PCB, 커널 스택 |

사용자 영역에 올라간 프로세스의 주소 공간을 힙까지 포함해 나누면 다음과 같다.

| 영역 | 담는 것 | 할당 |
| --- | --- | --- |
| 코드(텍스트) | 실행할 기계어 명령어. 읽기 전용 | 정적 (크기 고정) |
| 데이터 | 전역 변수처럼 프로그램이 끝날 때까지 유지할 데이터 | 정적 |
| 힙 | 프로그래머가 직접 할당하는 공간. 다 쓰면 반환해야 하며, 반환하지 않으면 **메모리 누수**가 된다 | 동적. 낮은 주소 → 높은 주소로 자란다 |
| 스택 | 매개변수·지역 변수처럼 함수가 끝나면 사라질 임시 데이터. PUSH/POP으로 쌓고 뺀다 | 동적. 높은 주소 → 낮은 주소로 자란다 |

C 프로그램 관점에서 본 주소 공간(힙 포함)은 [[pointers-and-memory|포인터와 메모리]]의 메모리 영역 표와 같은 이야기다.

프로세스 상태(new, ready, running, blocked, suspended, terminated)와 전이는 [[process-scheduling|CPU 스케줄링]] 노트에 정리했다. `suspended`는 `blocked`와 달리 스와퍼 같은 **외부 요인**으로 정지된 상태라서, 외부에서 재개해 줘야 다시 active 상태가 된다.

## PCB (Process Control Block)

커널이 프로세스마다 유지하는 관리 정보다. 커널 주소 공간의 data 영역에 있고, 프로세스가 생성될 때 만들어져 실행이 끝나면 폐기된다. 프로세스를 식별하는 고유 번호가 **PID**다.

1. **OS가 관리용으로 쓰는 정보**: PCB를 큐에 연결하기 위한 포인터, 프로세스 ID, 프로세스 상태, 스케줄링 정보, 우선순위
2. **CPU 수행 관련 정보(문맥)**: PC, 레지스터
3. **메모리 관련 정보**: code·data·stack 영역의 위치
4. **파일 관련 정보**: 프로세스가 열어 둔 파일들

## 문맥 교환 (Context Switch)

CPU를 실행 중인 프로세스에서 다른 프로세스로 넘기는 과정이다.

1. 실행 중이던 프로세스의 문맥을 그 프로세스의 PCB에 저장한다.
2. 새로 실행할 프로세스의 PCB에서 문맥을 읽어 CPU에 복원한다.

시스템 콜이나 인터럽트로 커널 모드에 들어갔다가 **같은 프로세스로 돌아오는 것은 문맥 교환이 아니다.** 이때도 PCB에 일부 정보를 저장하긴 하지만, 캐시를 비우는 것처럼 비용이 큰 작업은 하지 않는다. 문맥 교환은 사용자 프로세스가 바뀔 때만 일어난다.

## 스케줄링 큐와 스케줄러

PCB는 커널 data 영역의 큐(job·ready·device queue)에 매달려 관리되고, 단기·장기·중기 스케줄러가 그 사이를 옮긴다. 큐와 세 스케줄러의 역할은 [[process-scheduling|CPU 스케줄링]]에 정리했다.

## 스레드 (Thread)

스레드는 프로세스 안에서 **CPU를 수행하는 단위**다. 프로세스는 운영체제에게서 자원을 할당받는 단위이고, 스레드는 그 자원을 쓰며 코드를 실행하는 흐름이다. 모든 프로세스는 스레드를 하나 이상 가지며, 처음 실행되는 흐름이 메인 스레드다.

한 프로세스 안의 여러 스레드는 주소 공간과 자원을 공유하고, 실행 흐름에 필요한 부분만 따로 가진다.

| 공유하는 것 (Task) | 스레드마다 따로 갖는 것 |
| --- | --- |
| Code 영역, Data 영역, Heap 영역, OS 자원(열린 파일 등) | PC, 레지스터 집합, Stack 영역 |

스택을 따로 갖는 이유는 스레드마다 함수 호출 흐름이 독립적이기 때문이다. 힙을 공유하므로 한 스레드가 `new`·`malloc`으로 만든 객체를 다른 스레드가 포인터로 바로 읽을 수 있다.

즉 프로세스 주소 공간의 stack과 PCB의 문맥 부분만 스레드 단위로 나눠 쓴다. 그래서 스레드는 생성과 문맥 교환이 가벼워 **경량 프로세스(Lightweight Process)** 라고도 부르고, 스레드가 하나뿐인 전통적인 프로세스는 **중량 프로세스(Heavyweight Process)** 라고 부른다.

### 스레드의 장점

- **응답성(Responsiveness)**: 한 스레드가 blocked 되어도 다른 스레드가 작업을 계속할 수 있다. 예: 웹 브라우저가 이미지를 받는 동안에도 텍스트를 먼저 보여 줌
- **자원 공유(Resource Sharing)**: 코드·데이터·자원을 공유해 메모리를 효율적으로 쓴다.
- **경제성(Economy)**: 프로세스를 여러 개 만드는 것보다 생성·문맥 교환 비용이 훨씬 적다.
- **멀티프로세서 활용**: 스레드들을 여러 CPU에서 병렬로 실행해 작업 시간을 줄인다.

반대로 자원을 공유하기 때문에 **한 스레드에 문제가 생기면 프로세스 전체가 영향을 받는다.** 한 스레드에서 세그멘테이션 폴트가 나면 같은 프로세스의 모든 스레드가 함께 종료된다. 다른 프로세스는 영향을 받지 않는다.

### 멀티프로세스와 멀티스레드

여러 일을 동시에 처리하는 방법은 두 가지다. 프로세스를 여러 개 띄우거나(멀티프로세스), 한 프로세스 안에 스레드를 여러 개 둔다(멀티스레드). 운영체제가 여러 프로세스를 번갈아 실행하는 것은 **멀티태스킹**이라고 부른다.

| 기준 | 멀티프로세스 | 멀티스레드 |
| --- | --- | --- |
| 메모리 | 프로세스마다 독립된 주소 공간 | 스택만 따로, 나머지는 공유 |
| 생성·문맥 교환 비용 | 크다 (주소 공간 전환, 캐시·TLB 비우기) | 작다 |
| 데이터 공유 | IPC가 필요하다 | 공유 메모리를 바로 읽고 쓴다 |
| 장애 격리 | 한 프로세스가 죽어도 나머지는 산다 | 한 스레드가 죽으면 프로세스 전체가 죽는다 |
| 주된 위험 | 통신 비용, 메모리 사용량 | 경쟁 상태, 교착 상태, 재현하기 어려운 버그 |
| 예 | 크롬의 탭·사이트별 렌더러 프로세스, Nginx 워커, PostgreSQL 연결별 프로세스 | 자바·C# 서버의 스레드 풀, 게임 엔진 |

스레드도 커널 스레드라면 **운영체제가 스케줄링한다.** 프로그래머가 맡는 것은 스케줄링이 아니라 공유 자원에 대한 **동기화**다. 스레드 A가 값을 읽은 직후 스레드 B로 CPU가 넘어가 그 값을 바꾸면, A는 낡은 값으로 계속 계산한다. 어느 시점에 전환될지 알 수 없으므로 뮤텍스·세마포어 같은 도구로 임계 구역을 지켜야 한다([[process-synchronization|프로세스 동기화]]).

안정성이 중요하면 멀티프로세스, 데이터를 자주 주고받는 작업이면 멀티스레드가 유리하다. 둘을 섞어 프로세스 여러 개가 각각 스레드 풀을 갖는 구성도 흔하다.

CPU의 하이퍼스레딩처럼 코어 하나가 명령어를 동시에 처리하는 **하드웨어 스레드**는 여기서 말하는 스레드와 다른 개념이다([[computer-system-basics|컴퓨터 시스템의 기본 구성]]).

### 스레드 구현 방식

| 방식 | 설명 |
| --- | --- |
| 커널 스레드 | 커널이 제공하며, 커널이 스레드의 존재를 알고 직접 스케줄링 |
| 사용자 스레드 | 라이브러리로 제공되며, 커널은 스레드의 존재를 모름 (프로세스 안에서 스케줄링) |
| 실시간 스레드 | 실시간 기능을 지원하는 스레드 |

## 프로세스 생성과 종료

### 생성

부모 프로세스가 자식 프로세스를 만들어 **트리 형태의 계층 구조**가 생긴다. 자식은 부모와 다른 PID를 받고, 자식의 PCB에 부모의 PID인 **PPID**가 기록되기도 한다. 사용자 눈앞에서 실행되는 포그라운드 프로세스와 달리, 보이지 않는 곳에서 도는 백그라운드 프로세스를 유닉스에서는 **데몬**, 윈도우에서는 **서비스**라고 부른다.

- 자식의 자원: 보통 운영체제에게서 새로 받거나, 부모와 공유한다. 부모의 주소 공간을 바로 복사하지 않고 공유하다가 **쓰기가 일어날 때 복사**하는 기법을 COW(Copy-On-Write)라고 한다.
- 부모의 실행: 자식과 별개로 계속 실행하거나, 자식이 끝날 때까지 기다린다(wait).
- 생성 과정: ① 부모의 주소 공간과 PCB를 복사(`fork()`) → ② 그 공간에 새 프로그램을 덮어써 실행(`exec()`)

### 종료

- **자발적 종료**: 마지막 명령 실행 후 `exit()` 시스템 콜로 운영체제에 알린다.
- **비자발적 종료(abort)**: 부모가 자식을 종료시킨다.
  - 자식이 할당 자원의 한계를 넘었을 때
  - 자식에게 맡긴 일이 더 이상 필요 없을 때
  - 부모가 종료될 때(자식을 먼저 모두 종료시킨 뒤 부모가 종료된다)
  - `kill` 같은 명령으로 외부에서 종료시킬 때

## 프로세스 관련 시스템 콜

### fork(): 자식 프로세스 생성

```c
#include <stdio.h>
#include <unistd.h>

int main(void)
{
    int pid = fork();

    if (pid == 0)          // 자식은 fork()의 반환값으로 0을 받는다
        printf("Hello, I am child!\n");
    else if (pid > 0)      // 부모는 자식의 PID를 받는다
        printf("Hello, I am parent!\n");
}
```

자식은 부모의 문맥(PC 포함)까지 복제하므로 `fork()` 다음 줄부터 실행을 이어 간다. 둘을 구분하는 유일한 단서가 반환값이다.

### exec(): 새로운 프로그램 실행

```c
#include <stdio.h>
#include <unistd.h>

int main(void)
{
    printf("Hello, Now I'll run date\n");
    execlp("/bin/date", "/bin/date", (char *)0);
    printf("After exec()\n");   // 실행되지 않는다 — 주소 공간이 date로 덮어써졌기 때문
}
```

| exec 계열 접미사 | 의미 |
| --- | --- |
| `l` | 인자를 리스트로 나열. 마지막에 `(char *)0`(NULL)을 넣어야 함 |
| `v` | 인자를 배열(vector)로 전달 |
| `p` | 실행 파일을 환경 변수 `PATH`에서 찾음 |
| `e` | 새 프로그램에 환경 변수를 직접 전달 |

### wait()와 exit()

- `wait()`: 부모가 호출하면 커널이 자식이 끝날 때까지 부모를 **sleep(blocked)** 시키고, 자식이 종료되면 부모를 깨운다.
- `exit()`: 프로세스를 종료한다. 코드에 명시하지 않아도 컴파일러가 `main`의 끝에 넣어 준다.

## 프로세스 간 협력

프로세스는 원칙적으로 서로 독립적으로 실행되며 다른 프로세스의 주소 공간을 볼 수 없다. 협력이 필요하면 IPC(Interprocess Communication)를 쓴다.

| 방식 | 설명 |
| --- | --- |
| Message Passing | **커널을 통해** 메시지를 주고받음 |
| ├ Direct Communication | 통신할 상대 프로세스의 이름을 명시 |
| └ Indirect Communication | mailbox(또는 port)를 통해 간접 전달 |
| Shared Memory | 서로 다른 프로세스의 주소 공간 일부를 공유 매핑 |

구체적인 IPC 수단은 다음과 같다.

| 방법 | 설명 |
| --- | --- |
| Shared Memory | 여러 프로세스가 함께 접근하는 메모리 영역을 만들어 통신 |
| Pipe / Named Pipe | FIFO 형태의 버퍼를 공유해 한 방향으로 데이터 전달 |
| Message Queue | 메시지 단위로 큐에 넣고 꺼내 전달 |
| Socket | 네트워크 소켓으로 통신 (다른 컴퓨터의 프로세스와도 가능) |
| Semaphore | 데이터 전달보다는 공유 자원 접근을 제어하는 동기화 수단 |

Shared Memory처럼 같은 데이터를 함께 쓰거나, 한 프로세스 안의 스레드들이 data 영역을 공유하면 경쟁 상태가 생길 수 있다. 이를 막는 방법은 [[process-synchronization|프로세스 동기화]]에서 다룬다.

## 핵심 정리

- 프로세스 = 실행 중인 프로그램, 그 상태는 문맥(PC·레지스터·주소 공간·PCB)으로 표현된다.
- 문맥 교환은 PCB 저장 → 다른 PCB 복원. 커널 모드에 갔다 같은 프로세스로 돌아오는 건 문맥 교환이 아니다.
- 스레드는 code·data·heap·자원을 공유하고 PC·레지스터·스택만 따로 가진다.
