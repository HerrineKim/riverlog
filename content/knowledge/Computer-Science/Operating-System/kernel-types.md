커널은 운영체제의 핵심으로, 하드웨어와 프로그램 사이를 중재한다. 커널에 **어떤 기능까지 넣느냐**에 따라 구조가 나뉘며, 이 선택은 성능·안정성·이식성 사이의 트레이드오프가 된다.

## 단일형 커널 (Monolithic Kernel)

파일 시스템, 장치 드라이버, 메모리 관리, 프로세스 관리 등 대부분의 기능이 **하나의 커널 공간**에 함께 들어 있다.

- 장점: 기능 간 통신이 함수 호출 수준이라 빠르고, 시스템 콜 처리 성능이 좋다.
- 단점: 한 모듈의 오류가 커널 전체에 영향을 줄 수 있고, 커널이 커진다.
- 예: UNIX, Linux, MS-DOS, Windows 9x 계열

> 데니스 리치는 하드웨어 간 이식성을 높이려고 C 언어를 만들고, 그 C로 UNIX를 다시 작성했다. UNIX 계열이 다양한 하드웨어로 퍼질 수 있었던 이유다.

- **UNIX**: 오늘날 순수 UNIX는 입지가 줄었고, BSD 계열이 특정 장비 등에서 쓰인다.
- **Linux 배포판**: Unix-like 운영체제로, 데비안·레드햇 계열 등 여러 계열이 활발히 발전 중이다.

## 마이크로 커널 (Micro Kernel)

커널에는 IPC, 스케줄링, 기본 메모리 관리 같은 **최소 기능만** 남기고, 파일 시스템·드라이버 등은 사용자 모드의 별도 모듈(서버)로 분리한다.

- 장점: 모듈이 분리되어 안정적이고, 필요한 기능만 골라 구성할 수 있어 임베디드·실시간 시스템에 유리하다.
- 단점: 구성 요소 간 통신이 **메시지 전달**로만 이루어져 전반적인 성능이 떨어진다.
- 예: MINIX

## 하이브리드 커널 (Hybrid Kernel)

두 방식을 절충한 구조로, 성능이 중요한 부분(IPC 등)은 커널 안에 두고 일부 서비스는 사용자 모드에 설계한다.

- 예: Windows NT 계열, macOS(XNU)

## 비교

| 구분 | 단일형 | 마이크로 | 하이브리드 |
| --- | --- | --- | --- |
| 커널 크기 | 큼 | 작음 | 중간 |
| 내부 통신 | 함수 호출 | 메시지 전달 | 혼합 |
| 성능 | 높음 | 상대적으로 낮음 | 중간~높음 |
| 안정성·모듈성 | 낮음 | 높음 | 중간 |
| 예 | Linux, UNIX | MINIX | Windows, macOS |
