> 「세 가지 핵심 주제」 절은 팔만코딩경(42Seoul 커뮤니티 위키)의 「[운영체제] 개요 - 3가지 이야기」를 바탕으로 보강했다.

운영체제(Operating System)는 컴퓨터 하드웨어 바로 위에 설치되어 사용자·응용 프로그램과 하드웨어를 연결하는 소프트웨어 계층이다. 사용자에게는 컴퓨터를 편하게 쓸 수 있는 환경을, 컴퓨터 입장에서는 한정된 자원을 효율적으로 나눠 주는 **자원 할당자** 역할을 한다.

## 협의의 운영체제와 광의의 운영체제

| 구분 | 의미 |
| --- | --- |
| 협의 (커널, kernel) | 운영체제의 핵심으로, 부팅 이후 **메모리에 상주**하며 시스템 전체를 통제하는 부분 |
| 광의 | 커널에 더해 셸, 각종 시스템 유틸리티까지 포함한 개념 |

보통 "운영체제"를 공부한다고 하면 커널의 동작을 다룬다.

### 커널 영역과 이중 모드

운영체제도 프로그램이지만 특별한 프로그램이라, 부팅할 때 메모리의 **커널 영역**에 따로 적재된다. 나머지 응용 프로그램은 **사용자 영역**에 올라간다. 바탕화면 같은 사용자 인터페이스(GUI·CLI)는 운영체제가 제공하지만 커널에는 속하지 않는다.

운영체제는 응용 프로그램이 하드웨어 자원에 직접 접근하지 못하게 막고, 자신을 거쳐서만 쓰게 하는 문지기 역할을 한다. 이를 위해 CPU는 **이중 모드**로 명령어를 실행한다.

| 모드 | 할 수 있는 일 |
| --- | --- |
| 사용자 모드 | 커널 영역의 코드를 실행할 수 없다. 일반 응용 프로그램은 이 모드로 실행되어 자원에 직접 접근하지 못한다 |
| 커널 모드 | 자원에 접근하는 명령어를 포함한 모든 명령어를 실행한다 |

응용 프로그램이 파일을 읽거나 메모리를 더 받는 등 운영체제의 서비스가 필요하면 **시스템 호출(system call)로** 커널 모드로 전환한다. 시스템 호출은 특정 명령어가 일으키는 **소프트웨어 인터럽트**라서, 처리 흐름도 인터럽트와 같다. 작업을 백업 → 커널 영역의 처리 코드 실행 → 원래 프로그램으로 복귀. 하드웨어 쪽 구조는 [[system-structure|컴퓨터 시스템 구조와 인터럽트]]에 있다.

## 운영체제의 목적과 역할

### 1. 자원의 효율적 관리 (가장 중요)

- 프로세서, 메모리, 입출력 장치를 여러 사용자·프로그램에 **형평성 있게** 나누면서도 **전체 성능을 최대화**한다.
- 사용자와 운영체제 자신을 보호한다.

### 2. 편리한 실행 환경 제공

- 여러 프로그램이 동시에 돌아가도 각자 독립된 컴퓨터를 쓰는 것 같은 환상을 준다.
- 하드웨어를 직접 다루는 복잡한 일을 대신해 준다. 덕분에 응용 프로그램은 작성이 쉬워지고, 하드웨어가 바뀌어도 수정할 필요가 없다.

### 주요 관리 대상

| 기능 | 하는 일 |
| --- | --- |
| 메모리 관리 | 프로그램을 보조기억장치에서 메인 메모리로 올리고(폰 노이만 구조), 작고 비싼 메인 메모리를 효율적으로 배분 |
| 프로세스 관리 | 실행 중인 프로그램(프로세스)에 CPU와 자원을 할당·회수 |
| 입출력 장치 관리 | 프로세스를 대신해 장치에 작업을 요청하고 결과를 돌려줌 |
| 파일 관리 | 파일의 저장 위치·검색을 관리하고 여러 사용자의 접근을 제어 |
| 시스템 보호 | 사용자·프로세스의 자원 접근 권한 통제, 네트워킹, 명령 해석기 제공 |

## 운영체제의 분류

### 동시 작업 가능 여부

- **단일 작업(single tasking)**: 한 번에 하나의 작업만 처리. 예) MS-DOS 프롬프트에서는 한 명령이 끝나야 다음 명령을 실행할 수 있다.
- **다중 작업(multi tasking)**: 여러 작업을 동시에 처리. 예) UNIX, Windows

### 사용자 수

- **단일 사용자**: MS-DOS, 초기 Windows
- **다중 사용자**: 여러 계정이 동시에(원격 포함) 접속 가능. 예) UNIX, Windows NT 서버

### 처리 방식

| 방식 | 특징 | 예 |
| --- | --- | --- |
| 일괄 처리(batch) | 작업을 모아서 한꺼번에 처리, 끝날 때까지 기다려야 함 | 초기 펀치 카드 시스템 |
| 시분할(time sharing) | CPU 시간을 잘게 나눠 여러 작업에 번갈아 할당, 응답이 빠르고 대화형 | UNIX |
| 실시간(real-time) | 정해진 시간 안에 반드시 작업이 끝나야 함 | 공장·원자로·로봇 제어 |

실시간 시스템은 다시 둘로 나뉜다.

- **Hard real-time**: 마감 시간을 어기면 치명적 (로켓, 반도체 장비)
- **Soft real-time**: 마감이 있지만 가끔 어겨도 큰 문제는 없음 (동영상 재생)

## 세 가지 핵심 주제: 가상화·병행성·영속성

운영체제 교재 『Operating Systems: Three Easy Pieces』는 운영체제가 하는 일을 세 주제로 묶는다. 이 창고의 OS 노트도 대체로 이 셋으로 나뉜다.

| 주제 | 운영체제가 만드는 환상 | 관련 노트 |
| --- | --- | --- |
| 가상화(virtualization) | CPU 하나를 여러 개처럼(CPU 가상화), 물리 메모리를 프로세스마다 독립된 주소 공간처럼(메모리 가상화) 보이게 한다. 그래서 운영체제를 가상 머신이라고도 부른다 | [[process-scheduling\|CPU 스케줄링]], [[virtual-memory\|가상 메모리]], [[virtualization\|가상화와 하이퍼바이저]] |
| 병행성(concurrency) | 여러 실행 흐름이 같은 데이터를 동시에 건드려도 망가지지 않게 한다. 운영체제 자신도, 메모리를 공유하는 멀티스레드 프로그램도 이 문제를 겪는다 | [[process-synchronization\|프로세스 동기화]], [[pthread-sync-api\|POSIX 스레드와 동기화 API]] |
| 영속성(persistence) | 전원이 꺼져도 데이터가 남게 디스크를 관리한다. 파일 시스템이 데이터의 위치를 추적하고, 저널링이나 쓰기 시 복사(copy-on-write)로 쓰다가 멈춰도 일관성을 되찾게 한다 | [[file-system\|파일 시스템]], [[unix-file-io\|UNIX 파일 입출력]] |

응용 프로그램은 이 기능들을 **시스템 콜**이라는 API로 쓴다([[system-structure|컴퓨터 시스템 구조와 인터럽트]]).

## 운영체제의 예

- **MS-DOS**: 1981년 IBM PC용. 단일 사용자, 메모리 관리 한계(640KB).
- **MS Windows**: GUI 기반 다중 작업 OS. Plug and Play(장치를 연결하면 별도 설정 없이 바로 사용), 풍부한 소프트웨어 생태계.
- **UNIX**: 벨 연구소에서 개발했고 C로 다시 작성되어 이식성이 높다. 단일형 커널이며 System V, BSD 계열로 갈라졌고 macOS·iOS도 유닉스 계열이다([[c-history-and-standards|C의 역사와 표준]]).
- **Linux**: 유닉스와 기능적으로 비슷한 Unix-like OS지만 유닉스 코드에서 파생된 것은 아니다. 엄밀히는 커널 이름이고, 실제로 쓰는 것은 배포판이다([[linux-distributions|리눅스 배포판과 패키지 관리]]).
- **임베디드·소형 기기용**: 예전에는 PalmOS, Windows CE가 대표적이었지만 둘 다 단종되었다. 지금은 스마트폰의 Android·iOS, 마이크로컨트롤러용 FreeRTOS·Zephyr 같은 실시간 OS, 센서 네트워크용 TinyOS 등이 쓰인다.

## 핵심 정리

- 운영체제 = 하드웨어 위의 소프트웨어 계층, 핵심은 메모리에 상주하는 **커널**([[kernel-types|커널의 종류]]).
- 목적은 **자원의 효율적 관리**와 **편리한 실행 환경 제공** 두 가지.
- 동시 작업 여부, 사용자 수, 처리 방식(일괄·시분할·실시간)으로 분류한다.
