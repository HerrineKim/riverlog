> 고려사이버대학교 「운영체제이론 및 실습」(2024-1학기) 강의 내용을 바탕으로 정리했다.

운영체제는 프로세스끼리 서로의 메모리를 볼 수 없게 막는다. 그래서 프로세스가 협력하려면 커널에 부탁해야 한다. IPC 수단 전체를 한 표로 비교한 것은 [[process-and-thread#프로세스 간 협력|프로세스와 스레드]]에 있고, 이벤트만 알리는 시그널은 [[unix-signals|UNIX 시그널]]에 있다. 이 노트는 데이터를 실제로 옮기는 파이프, FIFO, 공유 메모리를 쓰는 법과 차이를 다룬다.

## 두 갈래: 복사해 주기와 같이 보기

| 방식 | 수단 | 데이터 경로 | 비용 |
| --- | --- | --- | --- |
| 커널 경유 | 파이프, FIFO, 메시지 큐, 소켓 | 보내는 쪽 버퍼 → 커널 버퍼 → 받는 쪽 버퍼 | 주고받을 때마다 시스템 콜과 복사 2번 |
| 메모리 공유 | 공유 메모리 | 두 프로세스의 페이지 테이블이 같은 물리 프레임을 가리킨다 | 설정할 때만 시스템 콜. 이후는 일반 메모리 읽기·쓰기 |

커널 경유 방식은 느린 대신 커널이 순서와 동기화를 대신 처리한다. 버퍼가 비면 읽는 쪽을, 차면 쓰는 쪽을 재운다. 공유 메모리는 빠르지만 두 프로세스가 동시에 쓰면 결과를 예측할 수 없으므로 동기화를 직접 해야 한다.

## 익명 파이프

`pipe(fd)`는 커널 안에 버퍼 하나를 만들고 fd 두 개를 돌려준다. `fd[0]`이 읽는 끝, `fd[1]`이 쓰는 끝이다. 이름이 없으므로 **fd를 물려받은 프로세스끼리만** 쓸 수 있다. 그래서 `fork()` 전에 만들어 부모와 자식이 나눠 갖는다.

```c
int fd[2];
pipe(fd);
if (fork() == 0) {            /* 자식: 읽기만 */
    close(fd[1]);
    char buf[64];
    ssize_t n = read(fd[0], buf, sizeof buf);
    write(STDOUT_FILENO, buf, n);
    _exit(0);
}
close(fd[0]);                 /* 부모: 쓰기만 */
write(fd[1], "ping\n", 5);
close(fd[1]);                 /* 닫아야 자식의 read가 EOF를 받는다 */
wait(NULL);
```

- **단방향**이다. 양쪽으로 주고받으려면 파이프를 두 개 만든다.
- 쓰지 않는 끝은 반드시 닫는다. 쓰는 끝이 하나라도 열려 있으면 읽는 쪽은 EOF를 받지 못하고 영원히 기다린다. 셸이 파이프라인을 만들 때 이 규칙을 어떻게 지키는지는 [[shell-pipeline|셸이 명령을 실행하는 방식]]에 있다.
- 읽는 끝이 모두 닫힌 파이프에 쓰면 `SIGPIPE`를 받는다.
- Linux의 기본 버퍼는 64KiB다. `PIPE_BUF`(Linux 4096바이트) 이하의 쓰기는 원자적이라, 여러 프로세스가 동시에 써도 서로 섞이지 않는다.
- 데이터는 바이트 스트림이다. "메시지 하나"라는 경계가 없으므로 길이를 앞에 붙이거나 줄바꿈으로 구분한다.

## FIFO (이름 있는 파이프)

익명 파이프의 두 한계(친족 관계에서만 쓸 수 있다, 프로세스가 끝나면 사라진다)를 풀기 위해 파이프에 **파일 시스템 경로**를 붙인 것이 FIFO다. 경로만 알면 관계없는 프로세스끼리도 `open`해서 쓴다.

```bash
mkfifo /tmp/jobs              # 또는 C에서 mkfifo("/tmp/jobs", 0600)
ls -l /tmp/jobs               # prw------- : 첫 글자 p가 FIFO
cat /tmp/jobs &               # 읽는 쪽이 먼저 열고 기다린다
echo "build" > /tmp/jobs      # 쓰는 쪽이 열면 둘이 연결된다
```

- 디스크에 남는 것은 이름뿐이고, 데이터는 익명 파이프처럼 커널 버퍼만 지난다.
- 블로킹 모드에서 `open`은 상대편이 반대 방향으로 열 때까지 기다린다. 이 성질 때문에 FIFO는 "준비됐다"는 신호로도 쓰인다.
- 파일 권한으로 누가 읽고 쓸지 정한다. 쓰고 나면 `unlink`(또는 `rm`)로 지운다.

## 공유 메모리

메모리 영역 하나를 여러 프로세스의 주소 공간에 붙인다. 운영체제의 보호를 일부러 풀어 주는 것이므로, 참여하는 프로세스끼리 같은 키나 이름에 합의해야 한다. 순서는 **만들기 → 붙이기 → 읽고 쓰기 → 떼기 → 지우기**다.

### System V 방식

| 호출 | 하는 일 |
| --- | --- |
| `shmget(key, size, IPC_CREAT \| 0600)` | 키에 해당하는 세그먼트를 찾거나 만들고 식별자를 돌려준다. `IPC_EXCL`을 함께 주면 이미 있을 때 실패한다 |
| `shmat(id, NULL, 0)` | 세그먼트를 내 주소 공간에 붙이고 시작 주소를 돌려준다. 주소는 커널이 고르게 `NULL`을 준다 |
| `shmdt(addr)` | 내 주소 공간에서 뗀다. 세그먼트는 남아 있다 |
| `shmctl(id, IPC_RMID, NULL)` | 삭제를 예약한다. 붙어 있는 프로세스가 모두 떼면 실제로 사라진다 |

세그먼트는 프로세스가 아니라 **커널에 속한다.** `IPC_RMID`를 하지 않고 프로세스가 죽으면 재부팅할 때까지 남는다. 쌓인 것은 `ipcs -m`으로 보고 `ipcrm -m <id>`로 지운다.

### POSIX 방식

지금 새로 짠다면 이름을 파일 경로처럼 쓰는 POSIX 방식이 다루기 쉽다. Linux에서는 `/dev/shm` 아래 파일로 보인다.

```c
int fd = shm_open("/counter", O_CREAT | O_RDWR, 0600);
ftruncate(fd, sizeof(long));
long *p = mmap(NULL, sizeof(long), PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
/* 다른 프로세스도 같은 이름으로 shm_open + mmap 하면 같은 값을 본다 */
munmap(p, sizeof(long));
shm_unlink("/counter");       /* 이름 제거. 열려 있는 매핑은 닫힐 때까지 유효 */
```

### 공유 메모리에서 지킬 것

- 동기화를 직접 한다. 공유 영역 안에 `pshared` 세마포어나 프로세스 공유 뮤텍스를 두거나, 작은 값이면 원자 연산을 쓴다([[pthread-sync-api|POSIX 스레드와 동기화 API]]).
- 붙는 가상 주소가 프로세스마다 다를 수 있다. 영역 안에 포인터를 저장하지 말고 시작점으로부터의 오프셋을 저장한다.
- "데이터가 준비됐다"는 알림은 공유 메모리만으로는 안 된다. 세마포어, 시그널, 파이프 한 바이트 같은 별도 신호와 함께 쓴다.

## 메시지 큐

커널 안의 큐에 **경계가 있는 메시지** 단위로 넣고 꺼낸다(System V `msgget`/`msgsnd`/`msgrcv`, POSIX `mq_open`/`mq_send`/`mq_receive`). 바이트 스트림인 파이프와 달리 메시지 하나가 통째로 오가고, 메시지 타입이나 우선순위로 골라 꺼낼 수 있다. 파이프처럼 매번 시스템 콜과 복사 두 번이 든다.

## 무엇을 고를까

| 상황 | 고를 것 |
| --- | --- |
| 부모가 자식의 출력을 받는다, 명령을 이어 붙인다 | 익명 파이프 |
| 관계없는 로컬 프로세스 사이의 단순한 스트림 | FIFO |
| 메시지 경계와 우선순위가 필요하다 | 메시지 큐 |
| 큰 데이터를 자주, 빠르게 공유한다(영상 프레임, 캐시) | 공유 메모리 + 세마포어 |
| 다른 컴퓨터와도 통신할 수 있어야 한다 | 소켓 |

| 수단 | 수명 |
| --- | --- |
| 익명 파이프 | 마지막 fd가 닫히면 사라진다 |
| FIFO | 이름은 지울 때까지, 데이터는 열린 동안만 |
| System V 공유 메모리·메시지 큐 | 명시적으로 지우거나 재부팅할 때까지 |
| POSIX 공유 메모리 | `shm_unlink`하고 모든 매핑이 풀릴 때까지 |

## 핵심 정리

- IPC는 커널이 복사해 주는 방식(파이프·FIFO·메시지 큐)과 메모리를 같이 보는 방식(공유 메모리)으로 나뉜다.
- 파이프는 fork 전에 만들어 친족끼리 쓰는 단방향 바이트 스트림이고, 안 쓰는 끝을 닫아야 EOF가 온다.
- FIFO는 파이프에 경로를 붙인 것이라 관계없는 프로세스도 쓴다.
- 공유 메모리는 가장 빠르지만 동기화와 알림을 직접 해야 하고, System V 세그먼트는 지우지 않으면 남는다.
