> 고려사이버대학교 「운영체제이론 및 실습」(2024-1학기) 강의 내용을 바탕으로 정리했다.

입출력 장치는 CPU보다 훨씬 느리고, 종류마다 데이터 단위와 제어 방법이 다르다. 운영체제의 입출력 시스템은 이 차이를 숨겨서 응용 프로그램이 디스크든 키보드든 `open`·`read`·`write`·`close`로 다루게 하고, 느린 장치 때문에 CPU가 노는 시간을 줄인다. 하드웨어 쪽(인터페이스 회로, 인터럽트 우선순위, DMA 제어기)은 [[io-organization|입출력 구조]]에, 모드 비트와 시스템 콜은 [[system-structure|컴퓨터 시스템 구조와 인터럽트]]에 있다.

## 계층 구조

```text
응용 프로그램           read(fd, buf, n)
──────────────── 시스템 콜 경계 ────────────────
커널 입출력 서브시스템  VFS, 페이지 캐시, 입출력 스케줄러, 버퍼, 권한 검사
장치 드라이버           장치별 코드: driver_read(), driver_write(), ioctl 처리
──────────────── 하드웨어 경계 ────────────────
장치 컨트롤러           상태·제어·데이터 레지스터, 내부 버퍼
장치                    디스크, 키보드, NIC ...
```

- **커널 입출력 서브시스템**은 모든 장치에 공통인 일을 한다. 같은 API, 스케줄링, 버퍼와 캐시, 오류 처리, 보호.
- **장치 드라이버**는 장치마다 다른 부분을 맡는다. 서브시스템이 정한 함수 표(`open`, `read`, `write`, `ioctl` …)를 채워 넣으면, 위쪽 코드는 장치를 몰라도 된다. 새 장치를 지원하려면 드라이버만 추가하면 된다.
- **장치 컨트롤러**는 장치에 붙은 회로다. CPU는 컨트롤러의 레지스터에 정해진 비트를 쓰고 읽는 것으로 장치를 움직이고, 기계적인 타이밍이나 신호 형식은 컨트롤러가 처리한다.

## 컨트롤러 레지스터에 닿는 두 방법

| 방식 | 원리 | 예 |
| --- | --- | --- |
| 포트 맵 I/O (격리형) | 메모리와 별도인 I/O 주소 공간. 전용 명령(`in`, `out`)으로 접근 | x86의 레거시 장치(타이머, 키보드 컨트롤러). Linux `/proc/ioports` |
| 메모리 맵 I/O | 장치 레지스터를 물리 주소 공간 일부에 배치. 일반 load/store로 접근 | 그래픽 카드 프레임버퍼, PCIe 장치, 대부분의 ARM 장치. Linux `/proc/iomem` |

## 데이터를 옮기는 세 방식

| 방식 | CPU가 하는 일 | 맞는 경우 |
| --- | --- | --- |
| 폴링 (프로그램 I/O) | 상태 레지스터를 반복해서 읽다가 준비되면 직접 옮긴다 | 장치가 아주 빨라 곧 끝나는 경우. 기다리는 동안 CPU를 쓴다 |
| 인터럽트 | 명령만 내리고 다른 일을 하다가, 장치가 인터럽트를 걸면 처리한다 | 언제 올지 모르는 입력(키보드, 네트워크) |
| DMA | 전송 방향·주소·길이를 DMA 제어기에 맡기고, 블록이 끝났을 때 인터럽트 한 번만 받는다 | 디스크·네트워크처럼 큰 블록 전송 |

인터럽트가 항상 이기지는 않는다. 초당 수백만 패킷이 오는 NIC에서 패킷마다 인터럽트를 걸면 CPU가 인터럽트 처리만 하다 끝난다. 그래서 Linux 네트워크 스택(NAPI)은 부하가 높을 때 인터럽트를 끄고 폴링으로 바꾸고, 빠른 NVMe SSD나 `io_uring`도 폴링 모드를 둔다. 인터럽트 비용(문맥 저장, 캐시 오염)이 기다리는 시간보다 클 때는 폴링이 낫다.

## 장치의 세 분류

| 분류 | 단위와 접근 | 예 | Linux에서 |
| --- | --- | --- | --- |
| 블록 장치 | 고정 크기 블록, 임의 위치 접근(seek) | 디스크, SSD | `ls -l /dev`에서 `b`. 파일 시스템이 그 위에 올라간다 |
| 문자 장치 | 바이트 스트림, 대개 순차 접근 | 키보드, 마우스, 직렬 포트, 터미널 | `ls -l /dev`에서 `c` |
| 네트워크 장치 | 패킷, 소켓 인터페이스 | NIC | `/dev`에 없고 `ip link`로 본다 |

블록 장치만 페이지 캐시와 입출력 스케줄러를 거치고, 문자 장치는 대개 드라이버로 바로 간다. 표준 연산으로 표현하기 어려운 장치별 기능(터미널 속도, 디스크 형상 질의)은 `ioctl`이라는 비상구로 넘긴다.

## 블로킹과 논블로킹

| 방식 | 동작 |
| --- | --- |
| 블로킹 | 데이터가 없으면 커널이 프로세스를 대기 큐로 옮기고, 끝나면 준비 큐로 돌려놓는다. 프로그램은 단순하다 |
| 논블로킹 | 기다리지 않고 지금까지 된 만큼(또는 `EAGAIN`)을 바로 돌려준다. 다시 시도하는 코드를 직접 짜야 한다 |
| 비동기 | 요청만 걸어 두고, 완료되면 커널이 알려 준다 |

논블로킹 fd를 여러 개 감시하는 `select`·`poll`·`epoll`은 [[unix-file-io|UNIX 파일 입출력과 파일 디스크립터]]에, 동기·비동기와 블로킹·논블로킹의 구분은 [[concurrency-models|동시성 모델]]에 있다.

## 커널 입출력 서브시스템이 하는 일

| 서비스 | 하는 일 |
| --- | --- |
| 입출력 스케줄링 | 요청 순서를 바꿔 장치 효율과 공정성을 높인다. 디스크의 경우 [[disk-scheduling\|디스크 관리와 스케줄링]] |
| 버퍼링 | 장치와 응용 사이에서 데이터를 잠시 담아 둔다(아래) |
| 캐싱 | 자주 쓰는 데이터의 사본을 메모리에 두어 장치 접근 자체를 줄인다. 파일 데이터는 페이지 캐시([[file-system-implementation\|파일 시스템 구현]]) |
| 스풀링 | 한 번에 한 작업만 받는 느린 장치(프린터) 앞에 디스크를 큰 대기열로 둔다. 여러 프로세스가 동시에 출력을 보내도 섞이지 않고 차례로 나간다 |
| 장치 예약 | 테이프처럼 공유할 수 없는 장치를 한 프로세스에 독점 할당한다 |
| 오류 처리 | 일시적 오류는 재시도하고, 실패하면 `errno`로 알린다 |
| 보호 | 입출력 명령은 특권 명령이라 사용자 프로그램은 시스템 콜로만 장치에 닿는다 |

### 버퍼링을 하는 세 가지 이유

1. **속도 차이 흡수**: 느린 장치가 데이터를 모으는 동안 다른 일을 한다. 버퍼를 두 개 두고 하나를 채우는 동안 다른 하나를 비우면(이중 버퍼링) 생산과 소비가 겹친다.
2. **전송 단위 차이 맞추기**: 네트워크는 작은 패킷으로 받고 응용은 큰 메시지로 읽는다. 버퍼에서 조각을 모으거나 나눈다.
3. **복사 의미 보장**: `write()`가 돌아오면 응용은 버퍼를 곧바로 다시 써도 된다. 커널이 그 시점의 내용을 자기 버퍼로 복사해 두기 때문이다. 대신 디스크에 실제로 써졌다는 뜻은 아니므로, 그것이 필요하면 `fsync`를 부른다.

버퍼는 데이터의 **유일한** 사본일 수 있고, 캐시는 다른 곳에 원본이 있는 사본이다. 페이지 캐시는 두 역할을 함께 한다.

## 입출력 성능을 높이는 원칙

실제 프로그램은 대부분 계산보다 입출력을 기다리는 시간이 길다. 그래서 연산을 다듬는 것보다 입출력 경로를 줄이는 쪽이 효과가 크다.

| 원칙 | 예 |
| --- | --- |
| 문맥 교환을 줄인다 | 작은 `write` 여러 번 대신 버퍼에 모아 한 번에(stdio 버퍼, `writev`) |
| 메모리 복사를 줄인다 | 파일을 소켓으로 보낼 때 `read`+`write`(사용자 공간을 거쳐 복사가 늘어남) 대신 `sendfile`로 커널 안에서 바로 보낸다 |
| 인터럽트 빈도를 줄인다 | 큰 블록 전송, NIC의 인터럽트 결합(coalescing), 부하가 높을 때 폴링 |
| CPU 대신 하드웨어가 옮기게 한다 | DMA, 체크섬·TCP 분할을 NIC에 맡기는 오프로드 |
| 병목을 옮겨 가며 균형을 맞춘다 | CPU, 메모리, 버스, 장치 중 하나만 빠르게 해도 전체는 가장 느린 곳에 맞춰진다 |

## 핵심 정리

- 입출력 시스템은 서브시스템(공통 기능)과 드라이버(장치별 기능)로 나뉘어, 응용에는 같은 API를 보여 준다.
- CPU는 컨트롤러 레지스터를 포트 맵 또는 메모리 맵 방식으로 읽고 쓴다.
- 데이터 이동은 폴링, 인터럽트, DMA 중 장치 속도와 전송량에 맞춰 고른다. 아주 빠른 장치에서는 폴링이 다시 쓰인다.
- 장치는 블록·문자·네트워크로 나뉘고, 블록 장치만 캐시와 입출력 스케줄러를 거친다.
- 버퍼링은 속도·단위 차이와 복사 의미를, 캐싱은 접근 횟수를, 스풀링은 공유할 수 없는 장치의 순서를 해결한다.
