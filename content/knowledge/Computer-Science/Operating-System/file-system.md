메모리는 **주소**로 접근하지만 파일은 **이름**으로 접근한다. 운영체제는 하드디스크·SSD·USB처럼 서로 다른 저장 장치를 "파일"이라는 같은 논리적 단위로 보이게 해 주는데, 이 일을 담당하는 부분이 파일 시스템이다.

## 파일과 메타데이터

- **파일**: 이름이 붙은, 서로 관련된 정보의 모음. 보통 비휘발성 보조기억장치에 저장된다.
- **파일 연산**: create, read, write, reposition(lseek), delete, open, close. 모두 I/O를 하는 시스템 콜이다.
  - `lseek`: 파일에서 현재 접근 중인 위치(offset)를 옮긴다.
  - `open`: 작업 전에 파일의 메타데이터를 메모리에 올려 둔다.
- **메타데이터(attribute)**: 파일 내용이 아니라 파일을 관리하기 위한 정보. 이름, 유형, 저장 위치, 크기, 접근 권한, 생성·수정·접근 시각, 소유자 등이 해당한다.
- **파일 시스템**: 파일과 메타데이터, 디렉터리를 관리하고 저장 방법과 보호를 결정하는 OS의 구성 요소.

## 디렉터리와 파티션

- **디렉터리**: 그 아래 있는 파일들의 이름과 메타데이터 일부를 내용으로 가지는 특별한 파일. 파일 찾기·생성·삭제, 목록 보기, 이름 변경, 파일 시스템 순회 같은 연산을 지원한다.
- **파티션(논리 디스크)**: OS가 보는 디스크 단위. 하나의 물리 디스크를 여러 파티션으로 나누거나, 여러 물리 디스크를 하나의 파티션으로 묶을 수 있다. 각 파티션에는 파일 시스템을 설치하거나 스왑 영역 등 다른 용도로 쓸 수 있다.

## open()은 무슨 일을 하나

`open("/a/b/c")`를 호출하면 파일 c의 메타데이터를 메모리로 가져와야 한다. 이를 위해 경로를 한 단계씩 따라간다.

1. 루트 디렉터리 `/`의 메타데이터를 열고, 그 내용에서 `a`의 위치를 찾는다.
2. `a`를 열어 읽고 `b`의 위치를 찾는다.
3. `b`를 열어 읽고 `c`의 위치를 찾는다.
4. `c`를 연다.

경로 탐색은 비용이 크기 때문에 open을 read/write와 분리해 두고, **한 번 연 파일은 이후 탐색 없이** 바로 읽고 쓴다.

### 관련 자료구조

| 구조 | 위치 | 내용 |
| --- | --- | --- |
| Open file table | 커널 메모리(시스템 전체) | 현재 열린 파일들의 메타데이터, 열고 있는 프로세스 수 등 |
| File descriptor(fd) | 프로세스별 | open file table의 몇 번째 항목인지 가리키는 번호 |
| 파일 오프셋 테이블 | 프로세스별 | 각 프로세스가 파일의 어디를 읽고 있는지 |

UNIX 계열에서 C 표준 라이브러리의 `fopen()`이 돌려주는 `FILE *`도 내부적으로는 이 fd를 감싼 것이다([[file-io|C 파일 입출력]]). 흐름을 정리하면, open이 메타데이터를 메모리에 올리고 **fd를 반환**하면, 이후 `read(fd, ...)`는 그 fd로 파일에 접근한다. 읽은 내용은 커널의 **버퍼 캐시**에 복사해 두었다가 사용자에게 전달한다. 파일 접근은 항상 시스템 콜이라 OS가 모든 접근을 알고 있으므로, 버퍼 캐시에서는 LRU·LFU 같은 교체 알고리즘을 자유롭게 쓸 수 있다.

## 파일 보호

각 파일에 대해 **누가**, **어떤 접근**(읽기·쓰기·실행)을 할 수 있는지 정해야 한다.

| 방법 | 특징 |
| --- | --- |
| Access Control Matrix | 사용자 × 파일 전체 권한을 표로 관리. 정확하지만 오버헤드가 큼 |
| Grouping | owner / group / others 세 그룹 × rwx — 단 9비트로 표현 (UNIX 방식) |
| Password | 파일마다 비밀번호. 관리가 어려움 |

대부분의 시스템은 Grouping을 쓴다. 예를 들어 `chmod 751 file`은 소유자 `rwx`, 그룹 `r-x`, 그 외 `--x`다.

## 마운트 (Mounting)

파티션마다 다른 파일 시스템을 설치할 수 있는데, 다른 파일 시스템의 루트 디렉터리를 현재 파일 시스템의 특정 디렉터리에 **연결(mount)** 하면 그 경로로 바로 접근할 수 있다.

## 접근 방식 (Access Methods)

- **순차 접근(sequential)**: 카세트테이프처럼 앞에서부터 차례로 접근. 읽거나 쓰면 오프셋이 자동으로 증가한다.
- **직접 접근(direct, random)**: LP 레코드판처럼 임의 위치에 바로 접근.

직접 접근이 가능한 매체라도, 데이터를 어떻게 관리하느냐(예: 연결 할당)에 따라 순차 접근만 가능할 수 있다. 디스크에 실제로 어떻게 저장하는지는 [[file-system-implementation|파일 시스템 구현]]에서 다룬다.
