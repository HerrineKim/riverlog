운영체제가 어떻게 하드웨어를 통제하는지 이해하려면 먼저 컴퓨터 시스템의 구성 요소와, 이들이 **인터럽트**로 CPU와 소통하는 방식을 알아야 한다. 현대 운영체제는 "인터럽트에 의해 구동된다"고 할 만큼 인터럽트가 핵심이다.

## 구성 요소 한눈에 보기

| 요소 | 역할 |
| --- | --- |
| CPU · 레지스터 | 메모리의 명령어를 순서대로 실행. 레지스터는 메모리보다 빠른 저장 공간 |
| 모드 비트 | 지금 CPU에서 실행 중인 것이 OS인지 사용자 프로그램인지 구분 |
| 인터럽트 라인 | 키보드 입력·디스크 완료 같은 외부 이벤트를 CPU에 알림 |
| 타이머 | 한 프로그램이 CPU를 독점하지 못하게 함 |
| 장치 제어기 + 로컬 버퍼 | 각 I/O 장치를 관리하는 작은 CPU와 그 데이터 버퍼 |
| DMA 제어기 | CPU 대신 로컬 버퍼의 데이터를 메모리로 직접 복사 |
| 메모리 제어기 | CPU와 DMA가 동시에 메모리에 접근할 때 충돌 조정 |

디스크는 저장 장치이면서 동시에 입출력 장치이기도 하다.

## 모드 비트 (Mode bit)

사용자 프로그램의 잘못된 동작이 다른 프로그램이나 OS를 망가뜨리지 않도록 하드웨어가 두 가지 실행 모드를 지원한다.

- `1` **사용자 모드**: 사용자 프로그램 실행
- `0` **커널 모드**(모니터·시스템 모드): OS 코드 실행

보안에 영향을 주는 명령은 **특권 명령**으로 지정되어 커널 모드에서만 실행할 수 있다. 인터럽트나 예외가 발생하면 하드웨어가 모드 비트를 0으로 바꾸고, OS는 사용자 프로그램에 CPU를 넘기기 직전에 다시 1로 바꾼다.

## 타이머 (Timer)

무한 루프 같은 이유로 한 프로그램이 CPU를 계속 쥐고 있는 것을 막는다. OS는 CPU를 넘겨줄 때 타이머에 아주 짧은 시간을 설정하고, 시간이 다 되면 타이머 인터럽트로 제어권을 되찾는다. 시분할 시스템의 기반이다.

## 장치 제어기와 장치 드라이버

- **장치 제어기(device controller)**: 각 I/O 장치를 통제하는 일종의 작은 CPU(하드웨어). 제어·상태 레지스터와 로컬 버퍼를 가진다. 실제 I/O는 장치와 로컬 버퍼 사이에서 일어나고, 끝나면 인터럽트로 CPU에 알린다.
- **장치 드라이버(device driver)**: OS 코드 중 장치별 처리 루틴(소프트웨어).

## 인터럽트

인터럽트가 발생하면 CPU는 현재 레지스터와 프로그램 카운터(PC)를 저장한 뒤 제어를 **인터럽트 처리 루틴**으로 넘긴다. CPU는 명령어 하나를 실행할 때마다 인터럽트가 들어왔는지 확인한다.

| 종류 | 발생 원인 |
| --- | --- |
| 하드웨어 인터럽트 | 장치 제어기, 타이머 등 하드웨어 |
| 트랩(소프트웨어 인터럽트) — 예외 | 0으로 나누기, 잘못된 메모리 접근 등 프로그램 오류 |
| 트랩 — 시스템 콜 | 사용자 프로그램이 커널 함수를 호출 |

- **인터럽트 벡터**: 인터럽트 종류별로 처리 루틴의 주소를 담은 테이블
- **인터럽트 처리 루틴(ISR, 인터럽트 핸들러)**: 실제로 인터럽트를 처리하는 커널 함수

## 시스템 콜과 입출력

모든 입출력 명령은 특권 명령이다. 그렇다면 사용자 프로그램은 어떻게 I/O를 할까?

1. 사용자 프로그램이 **시스템 콜**로 OS에 I/O를 요청한다.
2. 트랩이 발생해 인터럽트 벡터의 해당 위치로 이동하고, 모드가 커널 모드로 바뀐다.
3. OS가 올바른 요청인지 확인한 뒤 I/O를 수행한다.
4. 완료되면 제어권을 시스템 콜 다음 명령으로 돌려준다.

### 동기식 vs 비동기식 입출력

- **동기식(synchronous)**: I/O가 끝날 때까지 기다렸다가 제어가 사용자 프로그램으로 넘어간다.
- **비동기식(asynchronous)**: I/O를 시작만 시켜 두고 즉시 제어가 돌아와 다른 일을 한다.

## DMA (Direct Memory Access)

I/O 장치가 바이트 단위로 데이터를 보낼 때마다 CPU가 인터럽트를 받아 메모리로 옮기면 오버헤드가 너무 크다. DMA 제어기는 장치의 버퍼 내용을 **CPU 개입 없이 블록 단위로** 메모리에 직접 복사하고, 블록 전송이 끝났을 때 한 번만 인터럽트를 건다. 빠른 장치를 메모리에 가까운 속도로 처리할 수 있게 해 준다.

## 입출력 주소 방식

| 방식 | 특징 | 장점 |
| --- | --- | --- |
| I/O Mapped (Port Mapped) I/O | I/O 장치용 주소 공간과 전용 명령어가 따로 있음 | 메모리 주소 공간을 온전히 사용, 코드에서 I/O 접근이 구분됨 |
| Memory Mapped I/O | I/O 장치를 메모리 주소의 일부처럼 취급 | 별도 명령어가 필요 없어 구조가 단순 (임베디드에 유리) |

## 저장장치 계층과 프로그램 실행

- **Primary**(레지스터, 캐시, 메인 메모리): CPU가 바이트 단위로 직접 접근해 실행할 수 있다.
- **Secondary**(디스크 등): 섹터 단위로 접근하며, 실행하려면 메모리로 올려야 한다.
- 위로 갈수록 빠르고 비싸며 용량이 작다.

실행 파일은 실행되면 자신만의 **주소 공간**(code, data, stack)을 가진 프로세스가 된다. 당장 필요한 부분만 물리 메모리에 올리고 나머지는 디스크의 스왑 영역에 둔다. 커널도 code·data·stack을 가지며, 커널 data 영역에는 각 프로세스를 관리하는 **PCB(Process Control Block)** 가 있다.

### 프로그램이 쓰는 함수

- **사용자 정의 함수**, **라이브러리 함수**: 프로세스 자신의 주소 공간에서 실행 (사용자 모드)
- **커널 함수**: OS의 함수. 호출하는 것이 곧 시스템 콜 (커널 모드)

프로그램은 실행되는 동안 사용자 모드와 커널 모드를 계속 오간다.
