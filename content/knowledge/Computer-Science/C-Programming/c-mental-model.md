## C의 사고방식이란

Java·Python은 메모리, 객체 수명, 범위 검사를 런타임이 대신 맡는다. C는 그 일을 **프로그래머에게 돌려준다.** 문법은 비슷해 보여도 「언어가 무엇을 보장하는가」가 정반대라서, 고수준 언어의 직관을 그대로 들고 오면 컴파일은 되는데 틀린 코드가 나온다. 이 노트는 그 차이를 한 장의 지도로 정리하고, 항목별 자세한 내용은 각 개념 노트로 넘긴다.

## 고수준 언어와 C의 차이

| 주제 | Java·Python | C | 자세히 |
| --- | --- | --- | --- |
| 메모리 | 객체 그래프, 내부 배치는 감춰진다 | 주소가 붙은 바이트의 나열. 배열·구조체는 연속 배치(구조체는 패딩이 낄 수 있다)라서 `memcpy`로 어떤 객체든 바이트째 복사할 수 있다 | [[c-struct-and-function-pointer\|구조체와 패딩]] |
| 변수 전달 | 객체는 참조로 공유된다 | **기본이 값 의미(value semantics)**: 구조체도 대입·인자 전달 때 통째로 복사된다. 호출한 쪽 변수를 바꾸려면 `&`로 주소를 넘긴다 | [[pointers-and-memory\|포인터와 메모리]] |
| 참조의 수명 | GC가 살아 있는 객체만 남긴다 | 포인터는 가리키던 객체가 사라져도 남는다(댕글링). 지역 변수의 주소를 반환하면 그대로 깨진다 | [[pointers-and-memory\|포인터와 메모리]] |
| 타입 안전 | 잘못된 캐스트는 예외 | 캐스트로 어떤 포인터든 만들 수 있고 검사하지 않는다. 객체의 바이트를 `unsigned char *`로 읽는 것만은 표준이 허용한다 | [[c-struct-and-function-pointer\|타입 퍼닝]] |
| 배열 | 길이를 알고 범위를 검사한다 | `a[i]`는 정의상 `*(a + i)`다. 길이를 저장하지 않으니 따로 들고 다니거나 종단 표시를 둔다. 범위 밖 접근은 검사 없이 남의 메모리를 건드린다 | [[c-basics\|C 기초]] |
| 객체 생성 | `new Foo()`, GC가 회수 | `malloc(sizeof(Foo))`가 반환하는 `void *`는 어떤 포인터에도 대입되므로 **크기를 틀려도 컴파일된다.** 할당마다 `free` 하나가 짝이고, 누가 해제할지(소유권)를 설계로 정한다 | [[pointers-and-memory\|동적 할당]] |
| 잘못된 연산 | 예외를 던지거나 정의된 결과 | 부호 있는 정수 오버플로, 범위 밖 접근은 **미정의 동작**. 컴파일러는 그런 일이 없다고 가정하고 최적화한다 | [[c-integer-types\|C의 정수 자료형]] |
| 문자열 | 길이를 아는 불변 객체 | `'\0'`으로 끝나는 `char` 배열. 길이를 알려면 처음부터 센다 | [[c-basics\|C 기초]] |
| 객체 지향 | 클래스, 상속, 다형성 | 없다. 함수 포인터를 담은 구조체로 흉내 내고, 캐스트 실수는 컴파일러가 잡아 주지 않는다 | [[c-struct-and-function-pointer\|C로 객체 흉내 내기]] |
| 모듈 | `import` | `#include`는 파일 내용을 그 자리에 붙이는 텍스트 포함이다. 헤더에는 선언, `.c`에는 정의 | [[gcc-compile-and-link\|GCC 컴파일과 링크]] |

## 미정의 동작이 검사를 지운다

```c
int add100(int n) {
    int r = n + 100;
    if (r < n) return -1;   /* 오버플로 검사의 의도 */
    return r;
}
```

부호 있는 오버플로는 일어나지 않는다고 가정해도 되므로, 컴파일러는 `n + 100 < n`을 항상 거짓으로 보고 검사를 통째로 지울 수 있다. **검사는 연산 전에** `if (n > INT_MAX - 100)`처럼 하거나, C23 `ckd_add`(GCC·Clang `__builtin_add_overflow`)를 쓴다. 부호 없는 정수는 오버플로가 2ⁿ으로 나눈 나머지로 정의돼 있어 이런 일이 없다. 자세한 규칙은 [[c-integer-types|C의 정수 자료형과 형 변환]]에 있다.

## 문자열을 다룰 때 표준 함수가 늘 답은 아니다

- **제자리 토큰화**: 구분자 자리에 `'\0'`을 써 넣고 각 토큰의 시작 주소만 포인터 배열에 모으면 복사 없이 문자열을 쪼갤 수 있다. `strtok`이 이 방식이고, 원본을 바꾼다는 점과 내부 정적 상태 때문에 `strtok_r`을 권한다([[c-basics|C 기초]]).
- **반복 `strcat`은 O(n²)이다.** `strcat`은 매번 대상 문자열의 끝을 처음부터 찾는다. 작은 조각을 많이 이어 붙일 때는 끝 위치 포인터를 들고 다니며 거기에 쓴다.

```c
char buf[256], *end = buf;
for (int i = 0; i < n; i++)
    end += sprintf(end, "%s,", parts[i]);   /* 끝에서 바로 이어 쓴다 */
```

실제 코드에서는 남은 크기를 함께 관리하는 `snprintf`를 쓰고, 반환값이 남은 공간보다 크면 잘린 것이다.

## 전처리기는 텍스트 치환이다

`#define`은 문법을 모르고 글자를 바꿔 넣는다. 그래서 함수처럼 보이는 매크로가 함수처럼 동작하지 않는다.

```c
#define TRIANGLE(n) (n*(n+1)/2)
TRIANGLE(b+c)        /* (b+c*(b+c+1)/2) 로 펼쳐져 우선순위가 깨진다 */

#define TRIANGLE(n) ((n)*((n)+1)/2)   /* 인자마다, 전체에 괄호 */
```

- 괄호를 다 쳐도 인자가 두 번 평가되는 문제는 남는다(`TRIANGLE(i++)`). 그래서 매크로 이름은 대문자로 써서 「함수가 아니다」라고 경고하는 관례가 있고, 가능하면 `static inline` 함수를 쓴다.
- 매크로가 꼭 필요한 곳은 컴파일 타임 상수(배열 크기, `case` 라벨: C17까지 `const` 변수는 상수식이 아니다), 조건부 컴파일(`#if`·`#elif`·`#else`·`#endif`, 지원하지 않는 플랫폼에서 `#error`로 멈추기)이다. 상수 정의 방법 비교는 [[c-scope-and-linkage|C의 스코프와 링키지]]에 있다.
- 헤더의 선언과 `.c`의 정의가 어긋나면 링크는 되는데 호출이 깨진다. **정의하는 `.c` 파일에서도 자기 헤더를 `#include`** 하면 컴파일러가 둘을 대조해 준다.

## C가 이렇게 생긴 이유

| 특징 | 이유 |
| --- | --- |
| 포인터, 널 종단 문자열, 수동 메모리 | 하드웨어가 실제로 그렇게 생겼다. C는 기계를 거의 그대로 보여 주는 얇은 층이다 |
| 오버플로 같은 미정의 동작 | 서로 다른 기계(정수 표현, 트랩 여부가 다른 CPU)에서 모두 빠르게 돌도록 결과를 정하지 않았다 |
| 텍스트 치환 전처리기 | 1970년대 컴파일러를 단순하게 두려는 지름길이 굳었다 |
| 범위·타입 검사 없음 | 검사를 빼서 빠르다. 대가는 버그가 조용히 지나가는 것이다 |
| 거의 없는 런타임 | GC·예외 처리기 없이 돌아서 운영체제 커널, 임베디드, 다른 언어의 인터프리터(CPython)를 쓰는 언어가 된다 |
| 지금도 널리 쓰임 | 쌓인 코드, 모든 플랫폼에 있는 컴파일러, 다른 언어가 C ABI로 서로 부르는 네트워크 효과 |

역사와 표준의 변천은 [[c-history-and-standards|C의 역사와 표준]]에 있다.

## 정리

- C는 고수준 언어가 런타임에 맡기던 메모리·수명·범위 검사를 프로그래머에게 돌려준다.
- 값 의미가 기본이고, 공유하려면 주소를 넘긴다. 포인터는 대상보다 오래 살 수 있다.
- 컴파일된다는 것은 맞다는 뜻이 아니다. `malloc` 크기, 캐스트, 범위 밖 접근, 오버플로는 조용히 틀린다.
- 미정의 동작에 기댄 검사는 사라질 수 있으니 검사는 연산 전에 한다.
- 매크로는 텍스트 치환이다. 괄호를 치고, 되도록 `inline` 함수와 상수 문법을 쓴다.
