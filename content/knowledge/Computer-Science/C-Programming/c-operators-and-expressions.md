## 수식과 연산자

수식(expression)은 값을 내는 코드 조각이다. 상수 `10` 하나, 변수 `x` 하나도 수식이고, 연산자(operator)와 피연산자(operand)를 조합해 더 큰 수식을 만든다. 수식 끝에 `;`를 붙이면 문장(statement)이 된다.

C의 연산자 체계는 C++, Java, JavaScript, Go 같은 후속 언어가 거의 그대로 물려받았다. 그래서 여기 나오는 함정 대부분은 다른 언어에도 있다.

| 분류 | 연산자 |
| --- | --- |
| 산술 | `+ - * / %`, 단항 `+ -` |
| 증감 | `++ --` |
| 대입 | `=`, `+= -= *= /= %= &= \|= ^= <<= >>=` |
| 관계 | `== != < > <= >=` |
| 논리 | `&& \|\| !` |
| 비트 | `& \| ^ ~ << >>` |
| 기타 | `?:`, `,`, `sizeof`, 형 변환 `(type)`, 주소 `&`, 역참조 `*`, 멤버 `. ->` |

## 산술: 나눗셈과 나머지

- **정수끼리 나누면 결과도 정수**이고, 소수부는 0 쪽으로 잘린다(C99부터 표준으로 고정). `7 / 2`는 `3`, `-7 / 2`는 `-3`이다. 실수 결과가 필요하면 한쪽을 실수로 만든다: `7 / 2.0`, `(double)a / b`.
- `%`는 정수에만 쓴다. 결과의 부호는 **왼쪽 피연산자를 따른다**. `-7 % 3`은 `-1`이다. 그래서 `x % 2 == 1`로 홀수를 판별하면 음수 홀수를 놓친다. `x % 2 != 0`으로 쓴다.
- 0으로 나누는 정수 연산은 미정의 동작이다. 대부분의 환경에서 프로그램이 죽는다.
- 거듭제곱 연산자는 없다. `^`는 XOR이다. 작은 정수 제곱은 `x * x`, 일반적인 경우는 `<math.h>`의 `pow`(실수 연산)를 쓴다.
- 나눗셈과 나머지는 단위 변환에 자주 쓴다. 초를 분·초로: `min = sec / 60; s = sec % 60;`. 거스름돈 계산처럼 큰 단위부터 몫과 나머지를 차례로 구하는 식이다.

서로 다른 타입이 섞이면 계산 전에 형 변환이 일어난다. 정수 승격과 부호 없는 정수가 섞일 때의 함정은 [[c-integer-types|C의 정수 자료형과 형 변환]]에 있다.

## 증감 연산자

| 형태 | 수식의 값 | 변수 |
| --- | --- | --- |
| `++x` (전위) | 증가한 **뒤**의 값 | 1 증가 |
| `x++` (후위) | 증가하기 **전**의 값 | 1 증가 |

`y = x++;`는 `y = x; x = x + 1;`, `y = ++x;`는 `x = x + 1; y = x;`와 같다. 변수에만 쓸 수 있고 `10++`, `(x + 1)++`은 컴파일 오류다.

**한 수식 안에서 같은 변수를 두 번 바꾸거나, 바꾸면서 따로 읽으면 미정의 동작이다.** 피연산자를 어떤 순서로 평가할지 C 표준이 정하지 않았기 때문이다.

```c
i = i++ + 1;              /* 미정의 동작 */
a[i] = i++;               /* 미정의 동작 */
printf("%d %d", i, i++);  /* 함수 인자의 평가 순서도 정해져 있지 않다 */
```

컴파일러마다, 최적화 옵션마다 결과가 다르다. 증감은 독립된 문장으로 떼어 쓴다. `-Wall`의 `-Wsequence-point`(Clang은 `-Wunsequenced`)가 이런 코드를 경고한다.

## 대입도 수식이다

대입 `x = 3`은 문장이 아니라 **값이 3인 수식**이다. 그래서 `y = x = 3;`은 오른쪽부터 `x = 3`을 먼저 하고 그 값 3을 `y`에 넣는다. 왼쪽에는 메모리 위치를 가리키는 것(lvalue)만 올 수 있으므로 `100 = x;`는 오류다.

이 성질 때문에 생기는 대표적인 버그가 있다.

```c
if (x = 0) { ... }        /* 비교가 아니라 대입. 값이 0이라 절대 실행되지 않고 x도 망가진다 */
```

컴파일러는 `-Wparentheses`(`-Wall`에 포함)로 경고한다. 일부러 대입하며 검사할 때는 `while ((c = getchar()) != EOF)`처럼 괄호로 감싸고 비교를 명시한다.

복합 대입 `x op= e`는 `x = x op (e)`다. 오른쪽 전체가 먼저 계산되므로 `x *= y + 1`은 `x = x * (y + 1)`이다.

## 관계 연산자

- 결과는 **`int` 1(참) 또는 0(거짓)**이다. C에는 원래 불리언 타입이 없었고, 0이 아닌 모든 값을 참으로 본다. `(3 >= 2) + 5`는 `6`이다. C99의 `_Bool`·`<stdbool.h>`가 생겼고, C23부터 `bool`, `true`, `false`가 키워드가 됐다.
- `2 < x < 5`는 수학처럼 동작하지 않는다. `(2 < x) < 5`로 묶여 0이나 1을 5와 비교하므로 항상 참이다. `2 < x && x < 5`로 쓴다.
- 실수는 `==`로 비교하지 않는다. `0.3 * 3 + 0.1 == 1.0`은 거짓이다. 차이의 절댓값이 허용 오차보다 작은지 본다: `fabs(a - b) < 1e-9`.

## 논리 연산자와 단락 평가

`&&`, `||`는 **왼쪽부터 평가하고, 결과가 정해지면 오른쪽을 평가하지 않는다**(단락 평가, short-circuit evaluation). `&&`는 왼쪽이 거짓이면, `||`는 왼쪽이 참이면 멈춘다. 이 지점이 순서점(sequence point)이라 왼쪽의 부수 효과는 오른쪽 평가 전에 끝난다.

```c
if (p != NULL && p->count > 0)   /* p가 NULL이면 p->count를 읽지 않는다 */
if (n == 0 || total / n > 10)    /* n이 0이면 나눗셈을 하지 않는다 */
```

이 성질을 가드로 쓰는 것은 정상적인 관용구다. 반대로 오른쪽에 꼭 실행돼야 하는 함수 호출을 두면, 왼쪽 결과에 따라 호출이 빠질 수 있다.

## 비트 연산자

정수를 비트 단위로 다룬다. 플래그 묶음, 마스크, 2의 거듭제곱 곱셈·나눗셈에 쓴다. 활용 기법은 [[bit-manipulation|비트 조작]]에 있다.

| 함정 | 설명 |
| --- | --- |
| `&`와 `&&` 혼동 | `&`는 비트 AND라 단락 평가가 없다. `1 & 2`는 0, `1 && 2`는 1 |
| 음수 오른쪽 시프트 | 부호 비트를 채울지(산술) 0을 채울지(논리)가 구현 정의다. 비트 연산은 부호 없는 타입으로 한다 |
| 폭 이상 시프트 | 32비트 `int`를 32 이상 시프트하면 미정의 동작이다 |
| 부호 있는 값 왼쪽 시프트 | 음수를 시프트하거나 결과가 표현 범위를 넘으면 미정의 동작이다 |

## 조건, 쉼표, sizeof

- **조건 연산자** `c ? a : b`: `c`가 참이면 `a`, 아니면 `b`를 평가한 값. 둘 중 하나만 평가된다. 값을 고르는 짧은 식에만 쓰고, 중첩하면 `if`로 바꾼다.
- **쉼표 연산자** `a, b`: `a`를 평가하고 버린 뒤 `b`의 값을 낸다. 실제로는 `for (i = 0, j = n - 1; i < j; i++, j--)`에서만 쓴다. 함수 인자 사이의 쉼표는 이 연산자가 아니다.
- **`sizeof`**: 타입이나 수식이 차지하는 바이트 수(`size_t`)를 **컴파일 시점에** 낸다. 피연산자를 실행하지 않으므로 `sizeof(i++)`에서 `i`는 증가하지 않는다. 배열 매개변수는 포인터로 바뀌므로 함수 안에서 `sizeof(arr)`는 배열 크기가 아니라 포인터 크기다([[pointers-and-memory|포인터와 메모리]]).

## 우선순위 함정

우선순위표 전체를 외울 필요는 없다. 대략 **단항 > 산술 > 시프트 > 관계 > 비트 > 논리 > 조건 > 대입 > 쉼표** 순이고, 단항·조건·대입만 오른쪽부터 묶인다. 실수가 잦은 곳은 정해져 있다.

| 코드 | 실제 해석 | 의도 |
| --- | --- | --- |
| `flags & MASK == 0` | `flags & (MASK == 0)` | `(flags & MASK) == 0` |
| `x << 1 + 1` | `x << 2` | `(x << 1) + 1` |
| `*p++` | `*(p++)`: 값을 읽고 포인터를 다음으로 | `(*p)++`: 가리키는 값을 증가 |
| `a \|\| b && c` | `a \|\| (b && c)` | 의도가 다르면 괄호 |
| `!x == y` | `(!x) == y` | `!(x == y)` |

비트 연산자가 비교 연산자보다 낮은 것은 `&&`가 없던 초기 C에서 `&`를 논리 AND로 쓰던 흔적이다. **비트 연산과 비교·산술이 섞이면 괄호를 친다.**

## 정리

- 정수 나눗셈은 0 쪽으로 자르고, `%`의 부호는 왼쪽을 따른다. `^`는 거듭제곱이 아니다
- 증감은 독립된 문장으로. 한 수식에서 같은 변수를 두 번 바꾸면 미정의 동작
- 대입은 값을 내는 수식이다. `if (x = 0)`을 컴파일러 경고로 잡는다
- 관계 연산 결과는 0 또는 1이다. 범위 비교는 `&&`로, 실수 비교는 오차로
- `&&`·`||`는 단락 평가로 가드에 쓴다. 비트 연산은 부호 없는 타입으로, 비교와 섞이면 괄호로
