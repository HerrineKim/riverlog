피보나치 수열을 재귀로 그대로 구하면 `fib(5)`를 구하려고 `fib(3)`을 두 번, `fib(2)`를 세 번 계산하는 식으로 **같은 연산이 반복**된다. 호출 수가 지수적으로(O(2ⁿ)) 늘어나는 이 낭비를 없애기 위해 고안된 것이 **동적 계획법(Dynamic Programming)**이다.

큰 문제를 작은 문제로 나눠 풀고 그 답으로 원래 문제를 푼다는 점은 분할 정복과 같다. 차이는 **하위 문제가 겹치느냐**다. 동적 계획법의 하위 문제는 여러 번 반복해서 등장하므로, 한 번 구한 답을 저장해 두고 재사용한다.

## 적용 조건

1. **겹치는 부분 문제(Overlapping Subproblems)**: 같은 하위 문제가 여러 번 반복해서 등장한다. 예: 피보나치 수열
2. **최적 부분 구조(Optimal Substructure)**: 큰 문제의 최적해를 하위 문제의 최적해들로 구성할 수 있다.

두 조건을 확인했다면, 문제를 하위 문제로 나누는 **점화식**을 세우는 것이 핵심이다. 피보나치라면 `F(n) = F(n-1) + F(n-2)`.

## Top-Down: 메모이제이션 (Memoization)

큰 문제에서 시작해 재귀로 내려가면서, **이미 계산한 하위 문제는 저장해 둔 값을 바로 꺼내 쓴다.** 같은 하위 문제의 답은 언제 구해도 같으므로 캐시에 메모해 두는 것이다.

```python
memo = [0] * 100
memo[0] = memo[1] = 1      # 이 노트에서는 F(0) = F(1) = 1로 둔다

def fib_memo(n):
    if memo[n] == 0:                               # 아직 계산하지 않았다면
        memo[n] = fib_memo(n - 1) + fib_memo(n - 2) # 자기 자신을 재귀 호출
    return memo[n]

print(fib_memo(10))  # 89
```

> 원래 노트의 코드는 메모 함수 안에서 메모이제이션이 없는 다른 함수 `fib`를 호출해 캐시 효과가 없었다. 반드시 **자기 자신(`fib_memo`)**을 호출해야 한다.

파이썬에서는 데코레이터로 더 간단히 쓸 수 있다.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n <= 1:
        return 1
    return fib(n - 1) + fib(n - 2)
```

## Bottom-Up: 타뷸레이션 (Tabulation)

가장 작은 하위 문제부터 차례로 표(DP 테이블)를 채워 올라간다. 재귀가 없어 재귀 깊이 제한에 걸리지 않고, 보통 더 빠르다.

```python
def fib_tab(n):
    if n <= 1:
        return 1
    dp = [0] * (n + 1)              # n = 0이면 dp[1]이 없으므로 위에서 먼저 처리
    dp[0] = dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

print(fib_tab(10))  # 89
```

직전 두 값만 필요하므로 변수 두 개로 공간을 O(1)까지 줄일 수도 있다.

```python
def fib_tab2(n):
    a, b = 1, 1
    for _ in range(2, n + 1):
        a, b = b, a + b
    return b
```

| | Top-Down (메모이제이션) | Bottom-Up (타뷸레이션) |
| --- | --- | --- |
| 구현 | 재귀 + 캐시 | 반복문 + 테이블 |
| 계산 범위 | 필요한 하위 문제만 | 모든 하위 문제 |
| 주의점 | 재귀 깊이 제한 | 계산 순서를 직접 정해야 함 |

두 방식 모두 피보나치를 O(n)에 구한다.

## DP 문제에 접근하는 순서

1. 이 문제가 **최적성의 원리**(부분 문제의 최적해가 전체 최적해를 만드는 데 쓰이는가)를 만족하는지 판단한다.
2. `dp[i]`가 무엇을 의미하는지 정의한다.
3. 점화식을 세운다.
4. 초기값(기저 사례)을 정한다.
5. Top-Down 또는 Bottom-Up으로 구현한다.

## 다른 기법과 비교

### 동적 계획법 vs 분할 정복

- **동적 계획법**: 하위 문제가 **서로 겹치고 종속적**이다. 피보나치처럼 한 하위 문제의 답이 여러 상위 문제에 쓰인다.
- **분할 정복**: 하위 문제가 **독립적**이다. 병합 정렬·퀵 정렬에서 나뉜 부분은 정렬 과정에서 서로 영향을 주지 않는다.

### 동적 계획법 vs 그리디

- **동적 계획법**: 가능한 경우를 모두 고려(하되 중복 계산은 피함)하므로 **항상 최적해**를 구한다.
- **그리디**: 현재 상태에서 가장 좋아 보이는 선택만 하므로 빠르지만, 문제에 따라 최적해를 보장하지 못한다.

## 핵심 정리

- DP = 겹치는 부분 문제 + 최적 부분 구조, 답을 저장해 재사용
- Top-Down(메모이제이션, 재귀)과 Bottom-Up(타뷸레이션, 반복문) 두 방식
- 핵심은 `dp[i]`의 정의와 점화식
