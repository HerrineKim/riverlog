## 알고리즘이란

알고리즘은 어떤 값(또는 값의 집합)을 입력으로 받아 원하는 출력으로 바꾸는 **잘 정의된 계산 절차**다. 계산 문제는 "입력과 출력이 어떤 관계여야 하는가"로 정의되고, 알고리즘은 그 관계를 실제로 만들어 내는 단계별 방법을 제시한다. (참고: Cormen 외, *Introduction to Algorithms*)

같은 문제를 푸는 알고리즘이 여러 개라면 다음 기준으로 고른다.

| 조건 | 뜻 |
| --- | --- |
| 정확성 | 모든 올바른 입력에 올바른 답을 내고, 유한한 단계 안에 끝난다 |
| 효율성 | 시간과 메모리를 적게 쓴다 |
| 범용성 | 특정 입력이 아니라 다양한 상황에 쓸 수 있다 |
| 수정·확장 용이성 | 읽고 고치기 쉽고 다른 알고리즘과 엮기 쉽다 |

이 중 효율성을 기계와 상관없이 비교하는 기준이 **빅오(Big O) 표기법**이다. 입력이 커질수록(사용자가 수백만 명이거나 응답 시간 약속(SLA)이 빡빡할수록) 알고리즘·자료구조 선택이 비용과 확장성을 좌우한다. 알고리즘을 설계하고 의사 코드·순서도로 적는 과정은 [[computational-thinking|컴퓨팅 사고]]에 있다.

## 시간을 직접 재면 안 되는 이유

`performance.now()` 같은 함수로 실행 시간을 직접 잴 수도 있다.

```javascript
function addUpTo(n) {
  return n * (n + 1) / 2;
}

const t1 = performance.now();
addUpTo(100000000);
const t2 = performance.now();
console.log(`Time Elapsed: ${(t2 - t1) / 1000} seconds.`);
```

하지만 실행 시간은 기계 성능, 다른 프로세스, 런타임 최적화에 따라 매번 달라지고, 아주 빠른 코드는 차이를 측정하기조차 어렵다. 그래서 연산 횟수가 입력 크기 n에 따라 어떻게 늘어나는지를 센다.

## 연산 횟수 세기

```javascript
// 반복문: n에 비례해 연산이 늘어난다
function addUpTo(n) {
  let total = 0;
  for (let i = 1; i <= n; i++) {
    total += i;
  }
  return total;
}

// 공식: n과 상관없이 곱셈·덧셈·나눗셈 3번
function addUpToFast(n) {
  return n * (n + 1) / 2;
}
```

세는 순서는 세 단계다. (1) 기본 연산(대입, 비교, 산술, 출력)을 고르고, (2) 각 연산이 몇 번 실행되는지 세고, (3) 모두 더해 n에 대한 식으로 만든다. `addUpTo`를 문장 하나를 연산 하나로 보고 세면 다음과 같다.

| 코드 | 실행 횟수 | 이유 |
| --- | --- | --- |
| `let total = 0` | 1 | 반복문 밖 |
| `let i = 1` | 1 | 초기화는 한 번 |
| `i <= n` | n + 1 | 참인 n번 + 반복을 끝내는 거짓 한 번 |
| `i++` | n | 본문이 끝날 때마다 |
| `total += i` | n | 본문 n번 |
| `return total` | 1 | 반복문 밖 |
| 합계 | 3n + 4 | - |

`+=`와 `++`를 덧셈과 대입 두 연산으로 쪼개 세면 5n + 4가 된다. 세는 단위에 따라 계수와 상수는 달라지지만 n에 비례한다는 사실은 같다. 그래서 첫 번째는 O(n), 두 번째는 O(1)이다. 정확한 횟수는 중요하지 않고, n이 커질 때의 증가 추세만 본다.

## 빅오 표기의 단순화 규칙

- 코딩 테스트와 면접에서는 보통 최악의 경우를 기준으로 빅오를 말한다. (빅오 자체는 "상한"이라는 뜻이고, 최선·평균·최악 어느 경우에나 붙일 수 있다. 아래 절 참고)
- **상수 계수는 버린다**: O(2n) → O(n), O(500) → O(1)
- **최고차항만 남긴다**: O(n² + 5n + 8) → O(n²)
- **로그의 밑은 쓰지 않는다**: log₂ n = log₁₀ n / log₁₀ 2 ≈ 3.32 · log₁₀ n처럼 밑이 달라도 상수 배 차이라 모두 O(log n)이다.
- 산술 연산, 변수 대입, 배열 인덱스 접근, 객체 키 접근은 O(1)로 본다.
- 반복문은 (반복 횟수) × (안쪽 연산)이다. 중첩 반복문이면 곱해진다.

## 빅오(O)·빅오메가(Ω)·빅세타(Θ)

빅오는 점근 표기법 중 하나다. 모두 "n이 충분히 클 때 상수 배를 무시하고 비교한다"는 점은 같고, 어느 쪽에서 묶느냐가 다르다. 주로 쓰는 것은 O·Ω·Θ 셋이고, 소문자 o·ω는 같은 차수를 빼고 엄격하게 묶는 변형이다.

| 표기 | 의미 | 정의(대략) | 비유 |
| --- | --- | --- | --- |
| O(g(n)) | 점근적 **상한** | 어떤 상수 c > 0, n₀가 있어 n ≥ n₀이면 f(n) ≤ c·g(n) | "아무리 느려도 이보다 빠르게 늘지는 않는다" (≤) |
| Ω(g(n)) | 점근적 **하한** | 어떤 상수 c > 0, n₀가 있어 n ≥ n₀이면 f(n) ≥ c·g(n) | "적어도 이만큼은 늘어난다" (≥) |
| Θ(g(n)) | **딱 맞는(tight) 범위** | O(g(n))이면서 동시에 Ω(g(n)) | "정확히 이 정도로 늘어난다" (=) |
| o(g(n)) | **여유 있는** 상한 | lim f(n)/g(n) = 0 (n → ∞) | "g보다 확실히 느리게 는다" (<) |
| ω(g(n)) | **여유 있는** 하한 | lim f(n)/g(n) = ∞ (n → ∞) | "g보다 확실히 빠르게 는다" (>) |

예를 들어 f(n) = 3n² + 5n이면

- f(n) = Θ(n²)이다. n²보다 빨리 늘지도, 느리게 늘지도 않는다.
- 상한일 뿐이므로 f(n) = O(n³)도 수학적으로는 맞지만, 정보가 적어 보통 가장 작은 상한(O(n²))을 쓴다.
- 마찬가지로 f(n) = Ω(n)도 맞지만, 가장 큰 하한은 Ω(n²)이다.
- 소문자 표기는 같은 차수를 허용하지 않는다. f(n) = o(n³)이고 ω(n)이지만, o(n²)도 ω(n²)도 아니다.

**표기법과 "최선·평균·최악"은 별개의 축**이다. "최악의 경우"는 어떤 입력을 기준으로 할지 고르는 것이고, O·Ω·Θ는 그렇게 정한 함수의 증가율을 위·아래·양쪽에서 묶는 방법이다. 예를 들어 삽입 정렬은

- 최악의 경우(역순 입력) Θ(n²), 최선의 경우(이미 정렬된 입력) Θ(n)
- 그래서 입력에 상관없이 말하면 실행 시간은 O(n²)이고 Ω(n)이다.

흔히 「최선은 Ω, 평균은 Θ, 최악은 O」로 짝지어 외우지만 틀린 대응이다. 위처럼 최악의 경우에도 Θ로 딱 맞게 말할 수 있고, 최선의 경우에도 O로 상한을 말할 수 있다. 복잡도 치트 시트가 최선 칸에 Ω, 평균 칸에 Θ, 최악 칸에 O를 붙여 두는 것도 이 짝짓기라서, 표의 기호보다 칸 이름(최선·평균·최악)을 보고 읽는다.

**보통 최악의 경우를 기준으로 삼는 이유**는 세 경우가 주는 정보가 다르기 때문이다. 카지노에 n달러를 들고 가는 상황에 빗대면 최선은 카지노를 통째로 따는 것이고, 최악은 n달러를 모두 잃는 것이다.

| 경우 | 성질 | 순차 탐색의 예 |
| --- | --- | --- |
| 최선 | 특별한 입력에서만 나오고, n이 커질수록 드물어진다. 성능을 약속하는 데 쓸 수 없다 | 찾는 값이 맨 앞에 있을 때 O(1) |
| 평균 | 입력이 어떤 분포로 오는지 가정해야 계산된다. 가정이 실제 입력과 맞는지 따로 따져야 한다 | 값이 어디든 같은 확률로 있다고 가정하면 약 n/2번 비교 |
| 최악 | 입력에 대한 가정 없이 계산되고, 어떤 입력이 와도 이보다 느려지지 않는다는 보장이 된다 | 값이 맨 끝에 있거나 없을 때 O(n) |

그래서 응답 시간을 약속하거나 공격적인 입력을 견뎌야 할 때는 최악을 본다. 반대로 최악이 드물고 무작위화로 피할 수 있는 알고리즘(무작위 피벗 퀵 정렬, 해시 테이블)은 평균(기대) 복잡도로 말하고, 최악은 따로 적어 둔다.

또 비교 기반 정렬은 최악의 경우 Ω(n log n)번의 비교가 반드시 필요하다는 하한이 증명되어 있다. 병합 정렬이 최악 O(n log n)이므로, 비교 정렬로는 이보다 점근적으로 빠를 수 없다는 뜻이다.

실무와 코딩 테스트에서 "이 알고리즘은 O(n log n)"이라고 할 때는 대개 최악의 경우에 대한 딱 맞는 상한, 즉 엄밀히는 Θ에 가까운 의미로 쓴다.

## 자주 보는 복잡도

연산을 일일이 세지 않아도 대부분의 복잡도는 코드 모양에서 보인다.

| 표기 | 이름 | 코드 모양 | 예시 |
| --- | --- | --- | --- |
| O(1) | 상수 시간 | 입력 크기와 상관없이 정해진 몇 단계 | 배열 인덱스 접근, 해시 조회, 첫 원소 출력, 마지막 비트로 짝·홀 판정(`n & 1`) |
| O(log n) | 로그 시간 | 매 단계 남은 범위를 절반(일정 비율)으로 줄이거나, 반복 변수가 두 배씩 커진다 | 이분 탐색, 균형 이진 탐색 트리 탐색, 힙 삽입/삭제 |
| O(n) | 선형 시간 | 입력을 상수 번 순회한다(한 번이든 세 번이든) | 배열 한 번 순회, 정렬되지 않은 배열에서 값 찾기, 트리 순회(전위·중위·후위, DFS·BFS, n = 노드 수) |
| O(n log n) | 선형 로그 시간 | O(log n) 작업을 n번 하거나, 반씩 나눈 단계마다 전체를 한 번 훑는다 | 병합 정렬, 힙 정렬, 내장 정렬 |
| O(n²) | 이차 시간 | n번 도는 반복문 안에서 다시 n번 돈다 | 버블·선택·삽입 정렬, 모든 순서쌍 만들기 |
| O(2ⁿ), O(n!) | 지수·팩토리얼 | 원소마다 넣고 빼는 두 갈래로 분기하거나, 모든 순서를 나열한다 | 부분집합·순열 완전 탐색 |

중첩 반복문이 O(n²)인 것은 **두 반복이 모두 n에 비례할 때**다. 안쪽이 n과 무관하게 상수 번 돌면 O(n)이고, 두 반복이 서로 다른 입력(길이 n과 m)을 돌면 O(n·m)이다. 그래서 n이 무엇인지 먼저 정한다. n×n 행렬의 모든 칸을 훑는 탐색은 한 변의 길이 n으로 말하면 O(n²)이고, 칸 수 N = n²으로 말하면 O(N)이다.

반복 변수를 1씩 늘리지 않고 두 배씩 키우면 반복 횟수가 log₂ n이 된다. 바깥에 n번 도는 반복을 씌우면 O(n log n)이다.

반복 변수가 3배씩 커지거나, 종료 조건이 제곱이거나, 안쪽 횟수가 바깥 변수에 묶이는 경우를 세는 법은 [[loop-complexity|루프 실행 횟수로 시간 복잡도 세기]]에 있다.

```javascript
// O(log n): i가 1, 2, 4, 8, …로 커진다. 0에서 시작하면 0 * 2 = 0이라 끝나지 않는다
for (let i = 1; i < n; i *= 2) {
  // 상수 시간 작업
}

// O(n log n): 바깥 n번 × 안쪽 log n번
for (let i = 0; i < n; i++) {
  for (let j = 1; j < n; j *= 2) {
    // 상수 시간 작업
  }
}
```

```javascript
// O(n²): n = 10이면 100줄, n = 1,000이면 1,000,000줄을 출력한다
function printAllOrderedPairs(items) {
  for (const first of items) {
    for (const second of items) {
      console.log(first, second);
    }
  }
}
```

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!) 순으로 느려진다. 그래프로 그리면 O(n²)부터는 n이 조금만 커져도 거의 수직으로 치솟는다. 다만 O(n²)는 n의 거듭제곱인 **다항 시간**이고, n이 지수 자리에 올라간 O(2ⁿ)부터가 **지수 시간**이다.

복잡도 치트 시트는 이 순서에 등급을 매겨 O(1)을 아주 좋음, O(log n)을 좋음, O(n)을 보통, O(n log n)을 나쁨, O(n²) 이상을 매우 나쁨으로 칠한다. 이 등급은 연산 하나의 비용을 볼 때의 기준이다. 비교 정렬처럼 Ω(n log n)이 하한인 문제에서는 O(n log n)이 도달할 수 있는 최선이고, 입력을 다 읽어야 하는 문제에서는 O(n)이 최선이다. 등급은 문제의 하한과 함께 읽는다.

### 입력이 커질 때의 체감

선택 정렬(O(n²))과 병합 정렬(O(n log n))에 같은 입력을 넣으면 차이가 숫자로 보인다.

| n | n² | log₂ n | n log₂ n |
| --- | --- | --- | --- |
| 8 | 64 | 3 | 24 |
| 80 | 6,400 | 약 6.3 | 약 506 |
| 8,000 | 64,000,000 | 약 13 | 약 104,000 |

- O(n²)는 입력이 10배면 연산이 100배다. 중첩 반복문이 n번 안에서 다시 n번 돌기 때문이다.
- O(log n)은 입력을 두 배로 늘려도 한 단계만 는다. 반씩 나누는 횟수를 세는 것이라 8개는 3번, 16개는 4번이다. 입력이 1,000배(8 → 8,000)가 돼도 3단계가 13단계로 늘 뿐이다.
- 가능한 순열을 모두 만들어 정렬된 것을 찾는 무차별 대입(brute force) 정렬은 O(n!)이다. n = 8이면 40,320가지로, 이미 n²의 600배가 넘는다.

연산 횟수를 시간으로 바꾸면 차이가 더 실감 난다. 아래는 **연산 하나에 1ns(초당 10억 번)** 가 걸린다고 치고 계산한 시간이다. `-`는 앞 칸보다도 훨씬 길어 의미가 없다는 뜻이다(n = 40의 n!은 약 2.6 × 10³¹년으로, 우주의 나이 약 1.4 × 10¹⁰년을 아득히 넘는다).

| n | log₂ n | n | n log₂ n | n² | 2ⁿ | n! |
| --- | --- | --- | --- | --- | --- | --- |
| 10 | 3.3 ns | 10 ns | 33 ns | 100 ns | 1 µs | 3.6 ms |
| 20 | 4.3 ns | 20 ns | 86 ns | 400 ns | 1 ms | 77년 |
| 30 | 4.9 ns | 30 ns | 147 ns | 900 ns | 1.1초 | 8.4 × 10¹⁵년 |
| 40 | 5.3 ns | 40 ns | 213 ns | 1.6 µs | 18분 | - |
| 50 | 5.6 ns | 50 ns | 282 ns | 2.5 µs | 13일 | - |
| 100 | 6.6 ns | 100 ns | 664 ns | 10 µs | 4 × 10¹³년 | - |
| 1,000 | 10 ns | 1 µs | 10 µs | 1 ms | - | - |
| 10⁴ | 13 ns | 10 µs | 133 µs | 100 ms | - | - |
| 10⁵ | 17 ns | 100 µs | 1.7 ms | 10초 | - | - |
| 10⁶ | 20 ns | 1 ms | 20 ms | 17분 | - | - |
| 10⁷ | 23 ns | 10 ms | 0.23초 | 1.2일 | - | - |
| 10⁸ | 27 ns | 0.1초 | 2.7초 | 116일 | - | - |
| 10⁹ | 30 ns | 1초 | 30초 | 32년 | - | - |

- O(log n)은 n = 10억이어도 30단계다. O(n)과 O(n log n)은 n이 10억까지 늘어도 초 단위에 머문다.
- O(n²)는 n = 10만에서 10초, 100만에서 17분이 걸린다. 입력이 수십만을 넘으면 O(n²)는 쓸 수 없다.
- O(2ⁿ)는 n = 40, O(n!)은 n = 20에서 이미 현실적으로 끝나지 않는다. 완전 탐색이 n ≤ 20 안팎에서만 통하는 이유다.
- 채점 서버는 단순 연산을 초당 10⁸번(파이썬은 10⁷번) 안팎으로 어림하므로 실제로는 이 표보다 10~100배 느리다([[coding-test|코딩 테스트 접근법]]).

### 자료구조 연산의 복잡도

자료구조를 고를 때는 어떤 연산을 자주 하느냐를 본다. 평균과 최악이 다른 구조는 최악이 언제 오는지도 함께 기억한다.

| 자료구조 | 접근 | 탐색 | 삽입 | 삭제 | 최악이 되는 때 |
| --- | --- | --- | --- | --- | --- |
| 배열 | O(1) | O(n) | O(n) | O(n) | 중간 삽입·삭제는 뒤 원소를 민다. 동적 배열 끝 추가는 분할 상환 O(1) |
| 정렬된 배열 | O(1) | O(log n) | O(n) | O(n) | 탐색은 이분 탐색이지만, 순서를 지키며 넣고 빼느라 뒤 원소를 민다. 읽기가 대부분이고 쓰기가 드물 때 맞다 |
| 스택·큐 | O(n) | O(n) | O(1) | O(1) | 맨 위·양 끝만 다룬다 |
| 연결 리스트(단일·이중) | O(n) | O(n) | O(1) | O(1) | 삽입·삭제 O(1)은 위치를 이미 알 때다. 위치를 찾는 데 O(n). 꼬리 포인터가 없는 단일 연결 리스트는 끝 추가도 O(n)이다(머리 추가는 늘 O(1)) |
| 해시 테이블 | - | 평균 O(1) | 평균 O(1) | 평균 O(1) | 충돌이 몰리면 O(n) |
| 이진 탐색 트리 | 평균 O(log n) | 평균 O(log n) | 평균 O(log n) | 평균 O(log n) | 정렬된 순서로 넣으면 한쪽으로 기울어 O(n) |
| 균형 트리(레드-블랙, AVL, B-트리) | O(log n) | O(log n) | O(log n) | O(log n) | 최악도 O(log n). DB 인덱스가 B-트리를 쓰는 이유 |
| 스플레이 트리 | 분할 상환 O(log n) | 분할 상환 O(log n) | 분할 상환 O(log n) | 분할 상환 O(log n) | 연산 한 번은 트리가 한쪽으로 뻗어 있으면 O(n)이다. 연산을 여러 번 하면 평균이 O(log n)으로 묶인다 |
| 트립(카테시안 트리 + 무작위 우선순위) | - | 기대 O(log n) | 기대 O(log n) | 기대 O(log n) | 우선순위가 운 나쁘게 정렬 순서와 맞으면 O(n) |
| k-d 트리 | 평균 O(log n) | 평균 O(log n) | 평균 O(log n) | 평균 O(log n) | 점 하나를 찾는 기준. 넣고 빼며 한쪽으로 기울면 O(n)이고, 범위·최근접 검색은 차원이 높을수록 O(n)에 가까워진다 |
| 스킵 리스트 | 기대 O(log n) | 기대 O(log n) | 기대 O(log n) | 기대 O(log n) | 확률적 구조라 최악은 O(n) |
| 이진 힙 | 최솟값 O(1) | O(n) | O(log n) | 최솟값 O(log n) | - |

공간은 모두 O(n)이다(스킵 리스트는 최악 O(n log n)).

표의 「분할 상환」과 「평균」은 다른 보장이다. **분할 상환(amortized) O(1)** 은 연산을 여러 번 했을 때 총비용을 횟수로 나누면 상수라는 뜻이고, 어떤 순서로 연산해도 성립한다. 동적 배열은 가득 차면 두 배로 늘리며 O(n) 복사를 하지만, 그 비용이 앞선 n번의 추가에 나뉜다([[data-structures#크기를 늘리면 무슨 일이 생기나|기초 자료구조]]). **평균 O(1)** 은 입력이나 해시값 분포에 대한 기대값이라, 해시 테이블은 키가 한 버킷에 몰리면 연산 하나가 O(n)이 된다. 해시 테이블에서는 리사이즈 비용이 분할 상환으로 나뉘고, 조회 자체는 평균 O(1)이다.

### 정렬 알고리즘의 복잡도

최선·평균·최악, 추가 공간, 안정성을 한 표로 비교한 것은 [[merge-quick-sort#정렬 알고리즘 비교|병합 정렬과 퀵 정렬]]에 있다. 비교 기반 정렬은 최악의 경우 Ω(n log n)번의 비교가 하한이고, Python `sorted`, Java 객체 정렬, V8의 `Array.prototype.sort`는 팀소트를 쓴다.

## 공간 복잡도

알고리즘이 추가로 사용하는 메모리가 입력 크기에 따라 어떻게 늘어나는지도 같은 방식으로 표현한다.

- 숫자, 불리언, `undefined` 같은 원시 값은 상수 공간 O(1)
- 문자열은 길이 n에 대해 O(n)
- 배열·객체는 원소(키) 개수 n에 대해 O(n)

예를 들어 배열의 합을 변수 하나에 누적하면 O(1) 공간, 각 원소를 두 배로 만든 새 배열을 반환하면 O(n) 공간이다.

데이터가 메모리보다 크면 공간 복잡도가 풀이 가능 여부를 정한다. 모든 값을 해시 맵에 담는 O(n) 풀이 대신, 한 번 훑으며 합계·최댓값·상위 k개(크기 k짜리 힙)만 들고 가는 스트리밍 처리는 O(1)이나 O(k) 공간으로 끝난다.

프로그램이 쓰는 전체 공간은 **고정 공간 + 가변 공간**으로 나눠 볼 수 있다. 고정 공간은 코드, 단순 변수, 상수처럼 입력 크기와 상관없는 부분이고, 가변 공간은 입력 크기에 따라 달라지는 배열·동적 할당·재귀 호출 스택이다. 복잡도 분석은 가변 공간만 본다. 재귀 함수는 따로 배열을 만들지 않아도 **호출 깊이만큼 스택 프레임**을 쓰므로, 깊이 n인 재귀는 O(n) 공간이다.

### 시간과 공간의 트레이드오프

시간과 공간은 서로 맞바꿀 수 있다. 계산 결과를 저장해 두고 다시 쓰는 메모이제이션([[dynamic-programming|동적 계획법]])은 메모리를 더 써서 같은 계산의 반복을 없애고, 해시 테이블·트라이([[data-structures|기초 자료구조]])는 추가 공간으로 탐색을 O(1)에 가깝게 만든다. 반대로 메모리 제한이 빡빡하면 저장 대신 매번 다시 계산한다. 코딩 테스트의 시간 제한과 메모리 제한이 각각 이 두 축이다.

## 입력 크기와 허용 복잡도

문제의 N 범위를 보면 허용되는 복잡도를 거꾸로 정할 수 있다. N 범위별 목표 복잡도와 떠올릴 기법 표는 [[coding-test|코딩 테스트 접근법]]의 「입력 크기로 풀이 방향 정하기」에 있다.

## 빅오가 말하지 않는 것

빅오는 절대 속도가 아니라 **증가율**이다. 계산하며 버린 정보 때문에 실제 실행 시간과 어긋날 때가 있다.

| 버린 것 | 어긋나는 경우 | 대응 |
| --- | --- | --- |
| 상수 계수·낮은 차수 항 | n이 작으면 O(n²) 삽입 정렬이 O(n log n) 정렬보다 빠르다 | 퀵 정렬·팀소트는 작은 구간을 삽입 정렬로 넘긴다([[merge-quick-sort#실전에서는\|병합 정렬과 퀵 정렬]]) |
| 메모리 배치·캐시 | 같은 O(n) 순회라도 배열이 연결 리스트보다 빠르고, 같은 O(n³) 행렬 곱도 접근 순서만 바꿔 열 배 가까이 빨라진다 | 복잡도와 함께 데이터가 메모리에 놓이는 방식을 본다([[cache-friendly-code\|캐시를 고려한 코드]]) |

그래서 빅오로 후보를 먼저 거르고, 점근적으로 비슷한 후보끼리는 실제 입력 크기로 재서 고른다.

## 핵심 정리

- 빅오는 입력이 커질 때의 증가율을 나타낸다. 상수, 낮은 차수 항, 로그의 밑은 무시한다.
- 연산 횟수를 세기 전에 코드 모양으로 먼저 짐작한다. 상수 번 순회는 O(n), 절반씩 줄이면 O(log n), n번 안에서 다시 n번이면 O(n²)다.
- O는 상한, Ω는 하한, Θ는 둘 다 만족하는 딱 맞는 범위다. 최선·평균·최악은 이와 별개로 "어떤 입력을 기준으로 하느냐"다. 보통 최악을 보는 것은 입력에 대한 가정 없이 보장을 주기 때문이다.
- 연산 하나에 1ns라 쳐도 O(n²)는 n = 100만에서 17분, O(2ⁿ)는 n = 40에서 18분이 걸린다.
- 시간뿐 아니라 공간 복잡도도 같은 방식으로 따진다.
- 문제의 N 범위를 보고 허용되는 복잡도를 먼저 정하면 풀이 방향이 좁혀진다.
- 빅오가 같거나 비슷하면 작은 n의 상수와 메모리 배치가 승부를 가른다. 그때는 잰다.
