> 고려사이버대학교 「자료구조」(2024-1학기) 강의 내용을 바탕으로 정리했다.

스택을 쓸 때 우리는 `push`와 `pop`만 알면 된다. 안에서 배열을 쓰는지 연결 리스트를 쓰는지는 몰라도 된다. 이렇게 **자료와 연산의 동작만 약속하고 구현은 감춘 정의**를 추상 자료형(ADT, Abstract Data Type)이라고 한다. 자료구조 과목에서 리스트·[[stack|스택]]·[[queue-deque|큐]]·[[tree|트리]]를 배울 때마다 "ADT 정의 → 구현" 순서를 밟는 이유가 여기 있다.

## 추상화의 세 갈래

추상화는 복잡한 것에서 지금 필요한 성질만 남기고 나머지를 숨기는 일이다. 프로그래밍에서는 무엇을 숨기느냐에 따라 셋으로 나눠 볼 수 있다.

| 종류 | 숨기는 것 | 예 |
| --- | --- | --- |
| 데이터 추상화 | 값이 메모리에 놓이는 방식 | 정수형을 쓰면서 2의 보수 표현은 신경 쓰지 않는다 |
| 절차 추상화 | 계산의 세부 단계 | `sort(a)`를 부르면서 내부 정렬 알고리즘은 모른다 |
| 제어 추상화 | 실행 흐름의 기계적 세부 | `for`·`while`이 점프 명령으로 바뀌는 과정 |

ADT는 이 중 데이터 추상화와 절차 추상화를 합친 것이다.

## 자료형 = 값의 집합 + 연산의 집합

정수형(int)도 사실 ADT처럼 볼 수 있다. 값의 집합 `{…, -1, 0, 1, …}`과 연산의 집합 `{+, -, ×, /, mod}`이 함께 묶여야 비로소 "정수형"이 된다. 값만 있고 연산이 없으면 쓸 수 없다.

ADT는 이 생각을 사용자가 정의하는 자료에 넓힌 것이다. 예를 들어 **리스트 ADT**는 "순서가 있는 항목들"이라는 값과 다음 연산으로 정의된다.

| 연산 | 동작 |
| --- | --- |
| `create()` | 빈 리스트를 만든다 |
| `is_empty()` | 비어 있는지 알려 준다 |
| `length()` | 항목 수를 알려 준다 |
| `insert(pos, item)` | `pos` 위치에 항목을 넣는다 |
| `delete(pos)` | `pos` 위치의 항목을 지운다 |
| `retrieve(pos)` | `pos` 위치의 항목을 돌려준다 |

이 표 어디에도 배열이나 포인터라는 말이 없다. 그게 핵심이다.

## 인터페이스와 구현의 분리

ADT를 코드로 옮기면 두 부분이 생긴다.

- **인터페이스**: 사용자가 보는 약속. 연산의 이름, 인자, 반환값, 동작 설명.
- **구현**: 약속을 지키는 실제 코드. 내부 자료 표현과 알고리즘.

사용자는 인터페이스에만 기대어 코드를 쓴다. 그래서 구현을 배열에서 연결 리스트로 바꿔도 사용자 코드는 그대로다. 성능 문제가 생겼을 때 구현만 갈아 끼울 수 있다는 것이 ADT의 실질적인 이득이다.

### C: 헤더와 소스를 나눈다

C에는 클래스가 없으므로 파일로 나눈다. 헤더(`.h`)에 타입과 함수 원형을, 소스(`.c`)에 함수 본문을 둔다.

```c
/* list.h: 인터페이스 */
typedef struct List List;          /* 내부를 감춘 불완전 타입 */

List *list_create(void);
int   list_length(const List *l);
void  list_insert(List *l, int pos, int item);
void  list_delete(List *l, int pos);
int   list_get(const List *l, int pos);
```

```c
/* list.c: 구현. 사용자는 이 파일을 보지 않는다 */
#define CAP 100
struct List { int count; int items[CAP]; };

int list_length(const List *l) { return l->count; }
/* ... */
```

헤더에서 `struct List`의 멤버를 공개하지 않으면(불완전 타입) 사용자는 `l->count`에 직접 손댈 수 없고 함수를 통해서만 다룰 수 있다. 대신 크기를 모르니 사용자가 `List`를 스택에 직접 만들 수 없어 생성·해제 함수를 따로 줘야 한다. 구조체 정의를 헤더에 그대로 두는 방식도 흔한데, 이때 은닉은 "멤버를 직접 건드리지 않는다"는 약속에 기댄다. 헤더 분리와 링크 과정은 [[c-scope-and-linkage|C의 스코프와 링키지]], 포인터는 [[pointers-and-memory|포인터와 메모리]]를 참고한다.

### C++·Java: 클래스가 경계를 강제한다

클래스는 자료와 연산을 한 단위로 묶고, 접근 제어자로 경계를 언어 차원에서 지킨다.

```cpp
class IntList {
public:                       // 인터페이스
    IntList();
    int  length() const;
    void insert(int pos, int item);
    void remove(int pos);
    int  get(int pos) const;
private:                      // 구현 세부
    static const int CAP = 100;
    int count;
    int items[CAP];
};
```

Java의 `List` 인터페이스와 `ArrayList`·`LinkedList` 구현체 관계가 ADT와 구현의 관계를 그대로 보여 준다. 변수를 `List<Integer> xs = new ArrayList<>();`처럼 인터페이스 타입으로 선언하면 나중에 구현을 바꾸기 쉽다.

## ADT와 자료구조의 차이

| | 추상 자료형 | 자료구조 |
| --- | --- | --- |
| 묻는 것 | 무엇을 할 수 있나 | 어떻게 저장하고 처리하나 |
| 예 | 리스트, 스택, 큐, 우선순위 큐, 맵 | 배열, 연결 리스트, 힙, 해시 테이블, 균형 트리 |
| 관계 | 하나의 ADT를 여러 자료구조로 구현할 수 있다 | 하나의 자료구조가 여러 ADT를 구현하기도 한다 |

우선순위 큐(ADT)는 정렬된 배열로도, [[heap-priority-queue|힙]] 자료구조으로도 만들 수 있다. 맵(ADT)은 [[hash-table|해시 테이블]]로도 [[tree|균형 이진 탐색 트리]]로도 만든다. 같은 ADT라도 구현에 따라 연산의 시간 복잡도가 달라지므로, 어떤 연산을 자주 쓰는지 보고 구현을 고른다.

## 정리

- ADT는 값의 집합과 연산의 집합을 동작으로만 정의한 것이다.
- 인터페이스와 구현을 나누면 사용자 코드를 건드리지 않고 구현을 바꿀 수 있다.
- C는 헤더·소스 분리와 불완전 타입으로, C++·Java는 클래스와 접근 제어로 경계를 만든다.
- ADT는 "무엇", 자료구조는 "어떻게"다.
