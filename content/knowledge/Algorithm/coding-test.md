## 문제 풀이 순서

1. **주석으로 먼저 설계한다.** 풀이 단계를 한국어 주석으로 적고, 그 아래에 코드를 채운다.
2. **떠오르는 테스트 케이스(TC)를 적어 둔다.** 특히 경계 조건(최솟값, 최댓값, 빈 입력, 정답이 없는 경우)을 미리 적는다.
3. **주석을 읽으며 코딩한다.** 설계와 구현을 분리하면 실수가 줄고 막혔을 때 어디서 막혔는지 바로 보인다.
4. **감정도 적는다.** "여기 헷갈림", "시간 초과 걱정" 같은 메모가 나중에 복습할 때 약점을 알려 준다.
5. **다 풀면 정리한다.** 불필요한 디버깅 코드는 지우고 TC와 핵심 아이디어만 남긴다.

```python
# 1. 입력: N(≤ 100,000), 수열 A
# 2. 아이디어: 정렬 후 투 포인터 → O(N log N)
# 3. TC: N=1, 모두 같은 값, 정답이 없는 경우
# 4. 출력: 조건을 만족하는 쌍의 개수
```

## 출제 유형과 우선순위

기업 코딩 테스트에 자주 나오는 알고리즘·자료구조를 출제 빈도 순으로 묶었다. 「반드시」부터 개념을 익힌 뒤 유형별 문제로 연습하고 범위를 넓힌다.

| 우선순위 | 유형 | 핵심·쓰는 곳 | 노트 |
| --- | --- | --- | --- |
| 반드시 | 정렬 | 순서대로 놓아야 탐색·비교가 효율적이다 | [[elementary-sorts\|기본 정렬]], [[merge-quick-sort\|병합·퀵 정렬]] |
| 반드시 | 완전 탐색·백트래킹 | 가능한 경우를 모두 보고 가지치기한다. 재귀·순열로 변형된다 | [[brute-force\|완전 탐색과 백트래킹]] |
| 반드시 | BFS / DFS | 그래프·격자 전체 훑기. 미로 탈출, 영역 세기, 가중치 없는 최단 거리 | [[bfs\|BFS]], [[dfs\|DFS]] |
| 반드시 | 스택·큐·덱·해시 | LIFO·FIFO, 평균 O(1) 조회. 자료구조 선택이 곧 풀이인 문제 | [[stack\|스택]], [[queue-deque\|큐와 덱]] |
| 반드시 | 우선순위 큐 / 힙 | 넣은 순서와 상관없이 우선순위가 높은 값이 먼저 나온다 | [[heap-priority-queue\|힙과 우선순위 큐]] |
| 반드시 | 동적 계획법 | 반복되는 부분 답을 저장해 재사용한다 | [[dynamic-programming\|동적 계획법]] |

| 반드시 | 구현·시뮬레이션, 문자열 | 요구 사항을 그대로 옮기는 문제 | |

| 자주 | 다익스트라, 플로이드-워셜 | 한 점에서 모든 점, 모든 점 사이 최단 거리 | [[dijkstra\|다익스트라]] |
| 자주 | 유니온 파인드, 크루스칼·프림 | 같은 집합 판별, 최소 신장 트리 | [[disjoint-set\|서로소 집합]] |

## 연습 방법

1. 쉬운 단계(프로그래머스 1레벨)로 **언어 문법부터** 손에 붙인다. 문법이 막히면 알고리즘을 떠올려도 못 쓴다.
2. 유형별 문제집(프로그래머스 고득점 Kit, 백준 단계별·solved.ac 태그)으로 위 표를 차례로 훑는다.
3. 문제를 읽으면 제한 조건의 입력 크기로 허용 복잡도를 먼저 계산해 후보 알고리즘을 좁힌다(아래 표).
4. 맞혀도 **다른 사람의 풀이를 반드시 본다.** 더 짧고 빠른 방법을 배운다.

막혔을 때 풀이를 볼 시점을 미리 정해 두면 시간을 버리지 않는다.

| 상황 | 기준 | 다음 행동 |
| --- | --- | --- |
| 손도 못 댐 | 30분 | 아직 준비가 안 된 유형이다. 개념을 공부하거나 풀이를 본다 |
| 풀었는데 시간 초과 | 1시간 | 다른 알고리즘·자료구조를 검토한다. 떠오르지 않으면 풀이를 본다 |
| 일부 케이스만 틀림 | 2시간 | 엣지 케이스를 못 찾으면 처음부터 다시 풀거나 풀이를 본다 |
| 풀이를 보고 풂 | 1주 뒤 | 같은 문제를 다시 혼자 푼다 |

목표 난이도는 회사마다 다르다. 흔히 대형 IT 기업은 프로그래머스 3레벨, 그 밖의 기업은 2레벨을 안정적으로 푸는 것을 기준으로 삼는다. 연습 사이트는 국내 기업 대비로 백준·프로그래머스, 삼성 대비로 SW Expert Academy, 해외 기업 대비로 LeetCode·Codeforces가 대표적이다.

코딩 테스트는 입구일 뿐이다. 프로젝트와 CS 기초 공부를 함께 가져간다.

## 반례 찾기: 랜덤 비교 테스트

예제도 통과하고 알려진 반례도 통과하는데 틀렸다면, **작은 입력을 무작위로 만들어 확실히 맞는 풀이와 결과를 비교**한다. 스트레스 테스트(stress test)라고도 부른다.

| 구성 요소 | 역할 |
| --- | --- |
| 입력 생성기 | 문제 조건을 지키는 입력을 `random`으로 만든다. 범위는 **아주 작게**(N ≤ 10, 값 ≤ 20) 잡아야 찾은 반례를 손으로 따라갈 수 있다 |
| 정답 풀이 | 느려도 확실한 풀이. 완전 탐색이 가장 좋다. 남의 정답 코드를 써도 된다 |
| 검사 풀이 | 제출해서 틀린 내 풀이 |
| 비교 루프 | 두 결과가 다를 때까지 반복하고, 다르면 입력과 두 답을 출력하고 멈춘다 |

```python
from random import randint

def gen():
    k = randint(1, 5)
    return [randint(1, 20) for _ in range(k)], randint(1, 10)

for _ in range(10_000):                 # 재귀 대신 반복문: 깊이 제한에 걸리지 않는다
    lines, n = gen()
    expected, got = brute(lines, n), solve(lines, n)
    if expected != got:
        print(lines, n, "정답:", expected, "내 답:", got)
        break
```

- 반례가 나오면 그 입력을 고정해 두고 디버깅한다. 이분 탐색의 경계(`>` vs `>=`, 시작값 0 vs 1), 0으로 나누기, 정수 오버플로 같은 실수가 주로 걸린다.
- C·C++ 풀이도 같은 방식으로 비교할 수 있다. 셸 스크립트로 생성기·두 실행 파일을 돌려 출력 파일을 `diff`하면 언어와 무관하게 쓸 수 있다.
- 시간 초과는 이 방법으로 못 찾는다. 최대 크기 입력을 따로 만들어 실행 시간을 잰다.

## 입력 크기로 풀이 방향 정하기

문제를 읽으면 먼저 **N의 범위를 보고 허용되는 시간 복잡도**를 정한다. 파이썬은 1초에 대략 10⁷ ~ 10⁸번의 단순 연산을 한다고 어림잡는다.

| N | 목표 복잡도 | 떠올릴 기법 |
| --- | --- | --- |
| ~10 | O(N!) | 순열 완전 탐색 |
| ~20 | O(2ᴺ) | 부분집합, 비트마스크, 백트래킹 |
| ~500 | O(N³) | 삼중 반복문, 플로이드-워셜 |
| ~5,000 | O(N²) | 이중 반복문, 2차원 DP |
| ~1,000,000 | O(N log N) | 정렬, 이분 탐색, 힙, 다익스트라 |
| 그 이상 | O(N), O(log N) | 투 포인터, 누적 합, 수학 |

## 자주 하는 선택

- **최단 거리 / 최소 횟수**, 가중치 없음 → BFS
- **최단 거리, 가중치 있음(음수 없음)** → 다익스트라
- **모든 경우를 봐야 함** → DFS / 백트래킹, 경우의 수부터 계산
- **최적값 + 같은 하위 문제가 반복** → DP
- **정렬 후 매 순간 최선의 선택이 정당함** → 그리디
- **정렬된 데이터에서 찾기, "최댓값/최솟값을 구하라"** → 이분 탐색, 파라메트릭 서치
- **구간 합 쿼리가 많음** → 누적 합

## 파이썬 실전 팁

```python
import sys
from collections import deque
import heapq

input = sys.stdin.readline          # 입력이 많을 때 input()보다 훨씬 빠르다
sys.setrecursionlimit(10 ** 6)      # 재귀 DFS 사용 시 기본 한도(약 1000) 늘리기

n = int(input())
arr = list(map(int, input().split()))
s = input().rstrip()                # readline은 줄바꿈 문자를 포함하므로 제거
```

- 큐는 `list.pop(0)`(O(n)) 대신 `deque.popleft()`(O(1))
- 우선순위 큐는 `heapq`(최소 힙). 최대 힙은 음수로 넣기
- 원소 존재 여부를 자주 확인하면 리스트(O(n)) 대신 `set`/`dict`(평균 O(1))
- 순열·조합은 `itertools`의 `permutations`, `combinations`, `product`(중복 순열), `combinations_with_replacement`(중복 조합)
- 개수 세기는 `collections.Counter`, 정렬된 리스트의 위치 찾기는 `bisect_left`·`bisect_right`
- 실수 계산은 오차가 있다(`0.3 + 0.6 == 0.8999999999999999`). 비교는 `abs(a - b) < 1e-9`나 `math.isclose`로 하고, 가능하면 정수로 바꿔 계산한다.
- 2차원 리스트는 `[[0] * m for _ in range(n)]`으로 만든다. `[[0] * m] * n`은 같은 행을 공유하는 버그가 생긴다.
- 문자열을 반복해서 이어 붙일 때는 리스트에 모은 뒤 `''.join()`
- 출력이 많으면 `print('\n'.join(map(str, result)))`로 한 번에 출력
- 리스트를 공백으로 구분해 한 줄에 출력할 때는 `print(*arr)`. `*`는 iterable을 개별 인자로 풀어 넘기는 언패킹 연산자다. 딕셔너리는 `**`로 키워드 인자로 풀 수 있다(`'{y}-{m}'.format(**info)`). 이때 이미 넘긴 인자와 같은 키가 겹치면 `TypeError`가 난다.

## 핵심 정리

- 주석 설계 → TC 작성 → 구현 → 정리 순서로 푼다.
- N의 범위에서 허용 복잡도를 역산해 알고리즘을 고른다.
- 막히면 30분·1시간·2시간 기준으로 풀이를 보고, 1주 뒤 다시 푼다.
- `sys.stdin.readline`, `deque`, `heapq`, `setrecursionlimit`은 기본 장비다.
