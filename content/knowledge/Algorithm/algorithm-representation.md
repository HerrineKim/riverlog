> 고려사이버대학교 「알고리즘과 문제해결」(2023-2학기) 강의 내용을 바탕으로 정리했다.

코드를 쓰기 전에 먼저 할 일은 문제를 "컴퓨터가 풀 수 있는 모양"으로 바꾸는 것이다. 이 과정을 **컴퓨팅 사고(Computational Thinking)** 라고 부른다. 지넷 윙(Jeannette Wing)이 2006년 글에서 이 말을 널리 알렸고, 이후 사람이든 기계든 계산하는 주체가 효과적으로 실행할 수 있도록 문제와 해법을 표현하는 사고 과정이라고 정리했다. 프로그래머만의 기술이 아니라 읽기·쓰기·셈하기처럼 누구나 갖출 기초 능력이라는 것이 윙의 주장이다. 컴퓨팅 사고를 요구사항 → 데이터 → 구조 → 알고리즘으로 옮기는 관점과 훈련법은 [[computational-thinking|컴퓨팅 사고와 개발 실력 늘리는 법]]에 있다.

## 네 가지 구성 요소

| 단계 | 하는 일 | 지하철 경로 안내 앱으로 보면 |
| --- | --- | --- |
| 분해 | 큰 문제를 다룰 수 있는 작은 문제로 쪼갠다 | 입력 받기, 경로 계산, 결과 출력으로 나눈다 |
| 패턴 인식 | 반복되거나 비슷한 부분을 찾는다 | "최소 시간"과 "최소 환승"은 같은 그래프에서 가중치만 다르다 |
| 추상화 | 문제에 필요 없는 세부를 버리고 핵심만 남긴다 | 역은 정점, 구간은 간선, 소요 시간은 가중치. 역 건물 모양은 버린다 |
| 알고리즘 | 남은 모델을 푸는 단계별 절차를 만든다 | [[dijkstra\|다익스트라]]로 최단 경로를 구한다 |

여기에 **자동화**(만든 절차를 실제 프로그램으로 돌리기)를 마지막 단계로 붙이기도 한다. 분해 → 모델링 → 알고리즘 → 자동화 순서로 보면 문제 해결 흐름과 그대로 겹친다.

블록 코딩 실습에서 사람 그림을 그릴 때도 같은 흐름이 나온다. 머리부터 발끝까지 한 붓에 그리면 코드가 길고 고치기 어렵다. 팔과 다리가 같은 모양이라는 패턴을 찾아 함수 하나로 만들고, 크기를 인자로 받게 하면 같은 함수로 여러 사람을 그릴 수 있다. 패턴 인식이 함수(재사용)로, 추상화가 매개변수로 이어지는 셈이다.

## 문제 해결 절차

1. **문제 정의**: 입력과 출력을 분명히 적는다. 무엇이 주어지고 무엇을 내야 하는지가 흐리면 알고리즘도 흐려진다.
2. **설계**: 위의 네 단계로 해법을 만든다.
3. **표현**: 아래 네 가지 방법 중 하나로 적는다.
4. **구현과 검증**: 코드로 옮기고 경계 사례로 시험한다. 실전 감각은 [[coding-test|코딩 테스트 접근법]]에 정리했다.
5. **분석**: 다른 해법과 시간·공간을 비교한다([[big-o|빅오 표기법]]).

## 알고리즘을 적는 네 가지 방법

같은 알고리즘, 예를 들어 "임시 변수 `tmp`를 써서 `x`와 `y`의 값을 바꾼다"를 네 가지로 적어 볼 수 있다.

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| 자연어 | 누구나 읽는다 | 모호하다. "그것을 옮긴다"의 "그것"이 무엇인지 해석이 갈린다 |
| 순서도(flowchart) | 흐름과 분기가 한눈에 보인다 | 프로그램이 커지면 그리기도 읽기도 어렵다 |
| 의사 코드(pseudo code) | 자연어보다 정확하고 특정 언어 문법에 매이지 않는다 | 정해진 표준이 없어 쓰는 사람마다 모양이 다르다 |
| 프로그래밍 언어 | 바로 실행된다 | 언어의 세부 문법이 생각을 가린다 |

실무에서 가장 쓸모 있는 것은 의사 코드다. 코딩 전에 생각을 정리하고, 리뷰할 때 핵심 논리만 놓고 이야기할 수 있다.

```text
swap(x, y):
    tmp ← x
    x ← y
    y ← tmp
```

순서도는 도형마다 뜻이 정해져 있다. 둥근 사각형은 시작·끝, 평행사변형은 입출력, 직사각형은 처리, 마름모는 조건 분기다.

## 세 가지 제어 구조

어떤 알고리즘이든 다음 세 구조의 조합으로 적을 수 있다(뵘-야코피니 정리). 이 셋만으로 프로그램을 짜자는 규율이 [[programming-paradigms|구조적 프로그래밍]]이다.

| 구조 | 뜻 | 예 |
| --- | --- | --- |
| 순차 | 위에서 아래로 차례대로 실행 | 입력 → 계산 → 출력 |
| 선택 | 조건에 따라 다른 명령을 실행 | 최소 환승이면 A, 아니면 B로 계산 |
| 반복 | 조건이 맞는 동안 같은 명령을 되풀이 | 벽에 닿을 때까지 한 걸음씩 전진 |

```python
def largest(nums):          # 순차
    best = nums[0]
    for n in nums[1:]:      # 반복
        if n > best:        # 선택
            best = n
    return best
```

## 좋은 알고리즘의 조건

여러 해법이 나왔다면 다음 기준으로 고른다.

- **정확성**: 모든 올바른 입력에 대해 올바른 답을 내고 유한한 단계 안에 끝난다.
- **효율성**: 시간과 메모리를 적게 쓴다. 실행 시간을 직접 재기보다 입력 크기에 따른 연산 횟수의 증가율로 비교한다.
- **범용성**: 특정 입력에서만이 아니라 다양한 상황에서 쓸 수 있다.
- **수정·확장 용이성**: 읽기 쉽고 고치기 쉬우며 다른 알고리즘과 엮기 쉽다.

## 정리

- 컴퓨팅 사고는 분해·패턴 인식·추상화·알고리즘으로 문제를 실행 가능한 절차로 바꾸는 과정이다.
- 알고리즘은 자연어·순서도·의사 코드·코드로 적을 수 있고, 설계 단계에서는 의사 코드가 가장 실용적이다.
- 모든 절차는 순차·선택·반복의 조합이다.
