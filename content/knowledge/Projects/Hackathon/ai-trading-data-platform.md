블록체인 해커톤(트랙 주제: *AI Infra — Building Shovels*, 즉 AI 개발자를 위한 "삽"을 만드는 인프라)에 내기 위해 정리한 기획이다. AI 에이전트가 크립토 시장을 예측하고 자동 매매하는 데 필요한 **실시간 데이터를 API로 제공**하고, 결제·정산은 해당 체인의 토큰과 스마트 컨트랙트로 처리한다. 무엇을 만들지보다 **해커톤 기간 안에 무엇을 온체인에, 무엇을 오프체인에 둘지** 정하는 과정이 핵심이었다.

## 서비스 개요

```text
AI 개발자(소비자)                         데이터 제공자
 지갑 로그인 → 토큰 예치 → API 키 발급     데이터 소스 등록 → 수요 발생 시 보상
        │                                        ▲
        └─ API 호출 → 백엔드가 사용량 집계 → 컨트랙트 정산(차감·분배) ─┘
```

- **예치(stake) 후 종량 과금**: 미리 넣어 둔 토큰에서 호출량만큼 차감한다.
- **양면 시장**: 개인·기관이 자기 데이터 소스를 등록하고, 쓰이는 만큼 토큰으로 보상받는다.

## 1. 제공할 데이터 카테고리

| 카테고리 | 예 | 예측에 주는 신호 |
| --- | --- | --- |
| 온체인 | 대규모 이체, 거래소 입출금, 활성 지갑 수, 최신 블록 | 개인 지갑 → 거래소로 대량 이동 = 매도 압력 |
| 거래소 시장 | 가격, 거래량, 호가창 깊이, 스프레드 | 시장 추세, 수급 |
| 파생상품 | 펀딩비, 미결제약정, 청산량 | 펀딩비가 계속 높으면 롱 과열, 급변은 추세 전환 신호 |
| 소셜 미디어 | 언급량, 감성(긍정·부정), 영향력 있는 인물의 발언 | 단기 급등락 |
| 뉴스·이벤트 | 규제 발표, 거래소 해킹, 신규 상장, 금리 결정 | 돌발 상황 대응 |
| 거시경제 | 금리, 환율, 주가 지수 | 전통 금융과의 동조화 |
| 프로젝트 생태계 | 깃허브 커밋 수, 컨트랙트 배포 수, 거버넌스 투표 | 중장기 펀더멘털 |
| 대체 데이터 | 검색 트렌드, 공포·탐욕 지수, 스테이블코인 발행량 | 시장 심리, 역발상 전략 |

여러 형태의 데이터를 한곳에서 받을 수 있다는 **데이터 어그리게이터**로서의 가치를 강조하고, 실시간성을 위해 WebSocket 스트림·알림도 고려했다.

## 2. 스마트 컨트랙트 설계

### 예치와 API 키

- 사용자가 토큰을 **예치 컨트랙트**에 넣으면 주소별 잔액이 기록된다.
- 백엔드는 **지갑 서명으로 본인 확인** 후 그 주소에 연결된 API 키를 발급한다.
- 매 호출마다 키로 사용자를 찾고, 잔액이 충분할 때만 데이터를 준다.

### 과금: 매 호출 결제 vs 예치 후 차감

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| 매 호출 마이크로페이먼트 (HTTP 402 Payment Required로 결제 요구) | 가장 탈중앙적 | 호출마다 트랜잭션 → 느리고 불편 |
| **예치 후 차감** (선택) | 지연 없이 응답, 사용자 경험 좋음 | 사용량 측정이 서버에 의존 |

- 호출마다 온체인 트랜잭션을 만들면 수수료와 지연이 커진다. **사용량은 오프체인에서 집계**하고, 일정 주기·누적량마다 한꺼번에 정산한다.
- 정산 함수 예: `billUsage(user, amount, provider)` — 사용자 잔액을 차감하고 제공자 몫을 적립. 이중 청구와 악용을 막기 위해 **플랫폼 운영 주소만 호출 가능**하게 제한한다.
- 데모에서는 API 몇 번 호출 → "정산" 버튼 → 컨트랙트 잔액 변화 확인 시나리오로 충분하다.

### 제공자 보상

1. 제공자가 데이터 소스 ID와 수령 주소를 등록한다(선택적으로 신뢰 담보용 스테이킹).
2. 호출 비용 중 일부(예: 80%)는 제공자 몫으로 적립, 나머지는 플랫폼 수수료.
3. 제공자는 `withdrawReward()`로 적립금을 언제든 인출한다.
4. 잔액이 부족하면 정산이 실패하고 API는 "잔액 부족"을 응답한다.

모든 정산이 체인에 기록되므로 제공자는 자기 보상을 직접 검증할 수 있다.

## 3. 추가 아이디어

- **데이터 신뢰성**: 여러 제공자의 같은 데이터를 교차 검증(오라클 네트워크의 합의 방식 참고), 정확도·가용성·응답 시간 기반 **평판 점수**, 허위 데이터에 대한 스테이킹 **슬래싱**, 원본 URL·해시 저장으로 무결성 증명.
- **참여 유도**: 데이터 제공·소비량에 따른 보너스, 추천인 보상, NFT 배지, 대량·장기 예치 할인.
- **개발자 경험**: LangChain 같은 에이전트 프레임워크용 툴·SDK, 사용량·잔액 대시보드, 잔액 임박 알림(webhook·디스코드).
- **보안**: 키별 레이트 리밋, 키 재발급·폐기.
- **거버넌스**: 새 데이터 카테고리 추가나 수수료율을 토큰 보유자 투표로 결정(DAO 전환 로드맵).

## 4. 평가와 보완점

**강점**

- AI × 블록체인 × 데이터의 교차점, 해커톤 트랙 주제("삽 팔기")와 정확히 맞는다.
- 토큰이 데이터 경제의 결제 수단이 되어 체인 생태계에 실질적인 쓰임새를 만든다.
- 정산은 온체인, 데이터 전달은 오프체인인 **하이브리드 구조**로 해커톤 기간 내 구현이 현실적이다(EVM 호환 체인이라 Solidity로 구현 가능).

**과제**

- **중앙화된 사용량 측정**: 서버가 과금을 트리거하므로 완전한 탈중앙은 아니다. 호출 로그의 해시를 주기적으로 온체인에 기록해 조작되지 않았음을 보이는 선에서 타협한다(장기적으로는 영지식 증명 등).
- **초기 데이터 확보**: 공개 API(블록 탐색기, 시세, 소셜)로 기본 데이터셋을 먼저 채우고, 데모에서는 팀원이 제공자로 등록하는 시나리오를 보여 준다.
- **차별화**: 기존 오라클(Chainlink)은 *스마트 컨트랙트*에 데이터를 넣어 주고, 데이터 마켓(Ocean Protocol)은 범용 데이터셋을 거래한다. 이 기획은 **오프체인 AI 에이전트를 위한 실시간 트레이딩 데이터 API**에 집중한다는 점이 다르다.
- **확장**: 캐싱·부하 분산, 정액 구독, 과거 데이터 판매, 플랫폼 안에서 바로 도는 트레이딩 봇 호스팅.

## 배운 점

- 해커톤 기획에서는 "모든 것을 온체인에"가 아니라, **신뢰가 필요한 부분(돈의 이동)만 온체인**에 두고 나머지는 평범한 웹 서비스로 만드는 판단이 구현 가능성을 좌우한다.
- 데모 시나리오(예치 → 호출 → 정산 → 잔액 변화)를 먼저 정하고 거꾸로 범위를 자르면 기간 안에 끝낼 수 있다.
