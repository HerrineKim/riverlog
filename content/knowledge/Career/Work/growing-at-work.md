스타트업에서 자주 언급되는 말이 있다. **사람은 선형적으로 성장하고, 회사는 기하급수적으로 성장한다.** 회사가 너무 빨리 크면 내가 페이스를 따라가지 못해 힘들고, 너무 완만하게 크면 지루해진다. 결국 개인이 의식적으로 성장 속도를 끌어올리는 장치를 만들어 두어야 한다.

## 1. 피드백 사이클을 짧게 만든다

성장은 피드백의 빈도에 비례한다. 사이클이 짧은 것부터 나열하면 다음과 같다.

| 주기 | 방법 |
| --- | --- |
| 매일·매주 | 자기 회고 (가장 짧은 피드백 루프) |
| 주/격주 | 리더와의 1on1 피드백 |
| 분기 | 사내·외 멘토 3~5명에게 연락해 조언 구하기 |
| 반기·연 | 정기 리뷰 (제도가 없으면 자청해서 받기) |

- 멘토는 멀리 있는 구루보다 **나보다 한두 단계 앞서 있으면서 잘한다고 알려진 사람**이 현실적인 조언을 준다.

## 2. 나는 드라이버인가, 병목인가

처음에는 모든 일을 조금씩 하다가 점점 많은 일을 맡게 되고, 어느 순간 내 역량을 넘어서는 시점이 온다. 이때 스스로에게 물어야 한다. *나는 조직을 앞으로 끌고 가는 드라이버인가, 일을 막고 있는 병목인가?* 병목이라면 위임·자동화·역량 확장 중 무엇이 필요한지 판단한다.

## 3. 업무 난이도를 스스로 올린다

같은 일을 반복하면 성장이 멈춘다. 주어진 과제에 다음을 하나씩 얹어 보면 자연스럽게 난이도가 올라간다.

- **품질**: 테스트 코드 작성, 성능 프로파일링
- **구조**: 공통 모듈 만들기, 익숙하지 않은 라이브러리로 바꿔 보기
- **자동화**: CI/CD 붙이기, Docker 이미지로 테스트 환경 구성, 반복 운영 작업 자동화, 모니터링 붙이기
- **문서화**: 소스 코드에서 바로 빌드되는 문서, API 문서, 문서화 사이트
- **사람**: 팀원에게 가르치기 (설명할 수 있어야 진짜 아는 것)

## 4. 이직은 '도망'이 아니라 '목표'일 때

- 퇴사하고 싶을 때가 아니라 **가고 싶은 회사가 생겼을 때** 옮긴다.
- 짧은 주기의 잦은 이직은 면접에서 불리하게 작용할 수 있다.

## 핵심 정리

- 피드백 주기를 짧게, 멘토는 가까운 선배로.
- 일이 많아질수록 드라이버인지 병목인지 점검한다.
- 업무에 테스트·자동화·문서화·교육을 얹어 난이도를 올린다.
- 이직은 끌림(pull)으로, 밀림(push)으로 하지 않는다.
