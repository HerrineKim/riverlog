> 웹액츄얼리가 번역한 Smashing Magazine의 「성공적인 콘텐츠 전략을 세우는 효과적인 방법」(2015.04)과 Ida Aalen의 「핵심 모델로 더 나은 성과 달성하기」(2016.03, 원문 A List Apart)를 요약·재구성한 노트입니다. 사례의 수치는 글 작성 시점 기준입니다.

## 콘텐츠 전략이란

콘텐츠 전략(content strategy)은 **무엇을, 왜, 누구에게, 어떻게 계속 내보낼지**를 정하는 일이다. 잘 쓴 문장과 전략적인 문장은 다르다. 한 콘텐츠 작가는 연말 캠페인에 캐럴 가사를 넣은 재치 있는 슬로건을 써 갔다가 상사에게 이런 질문을 받았다. "어떤 결과를 바라고 이걸 썼나?" 답하지 못했다. **창의적이지만 전략적이지 않은 콘텐츠**였다.

가장 중요한 원칙은 하나다. **사용자를 안다.** 누구인지, 무엇을 이미 알고 무엇을 원하는지, 정보를 어떻게 찾는지. 온라인 독자는 잡지 독자와 다르게 행동한다. 대부분은 요점이 분명하고, 이해하기 쉽고, 검색어가 들어간 문장을 원한다.

## 전략을 세우는 다섯 가지

| 순서 | 할 일 | 점검 질문 |
| --- | --- | --- |
| 1. 목적 | 동료와 콘텐츠의 목적을 문장으로 써서 늘 보이는 곳에 둔다 | 이 콘텐츠로 사업 목표와 고객 요구를 각각 어떻게 채우나? |
| 2. 핵심 메시지 | 목적을 전달할 핵심 메시지를 정하고 모든 콘텐츠에 녹인다 | 같은 말을 되풀이하지 않으면서 메시지가 일관되게 드러나나? |
| 3. 다음 궁금증 | 독자가 이 글을 읽은 뒤 더 알고 싶어 할 것을 예측한다 | 충성 고객은 무엇을 묻는가? 피드백 창구가 있는가? |
| 4. 운영 계획 | 편집·검색 최적화·관리·운영·배포 계획을 세우고 담당자를 정한다 | 팀 모두가 계획의 존재를 알고 쉽게 열어 볼 수 있나? |
| 5. 사람 | 분석·종합 능력과 UX·정보 구조 이해를 갖춘 웹 콘텐츠 작가를 둔다 | 헤드라인만 잘 뽑는 사람으로 채우고 있지 않나? |

3번이 가장 어렵고 가장 중요하다. 기본 콘텐츠를 만든 뒤가 진짜 시작이다.

### 흔한 실수

- **너무 길다**: 요점을 빨리 못 찾으면 떠난다.
- **너무 짧다**: 이해하기에도, 검색에 걸리기에도 부족하다.
- **업데이트하지 않는다**: 가장 흔하고 가장 고치기 쉬운 실수다.

## 핵심 모델: 안에서 밖으로 설계하기

여러 사람이 사이트를 만들면 메인 페이지 구성과 상단 메뉴를 두고 끝없이 논쟁한다. 하지만 **메인 페이지를 둘러보려고 오는 사람은 없다.** 대부분 검색으로 특정 페이지에 바로 들어온다. 그런데도 프로젝트를 정보 구조나 메인 시안부터 보여 주면, 고객은 그것이 사이트의 핵심이라고 여긴다.

핵심 모델(core model)은 정보 설계자 Are Halland가 2007년에 제안한 방법이다. **사용자가 목표로 하는 핵심 작업에서 출발해 거꾸로 설계한다.** "어떤 정보를 찾으러 왔나요?" 대신 "어떻게 도와드릴까요?"를 묻는 방식이다.

```text
모든 콘텐츠 나열
   │
사업 목표 ∩ 사용자 작업  → 겹치는 곳 = 핵심 페이지
   │
겹치지 않는 콘텐츠 → 삭제·간소화·병합 (지난 뉴스, 지루한 비전 소개 등)
   │
핵심 페이지부터 설계 → 메인 페이지는 맨 마지막
```

메인 페이지는 다른 페이지의 요약이다. **무엇이 들어갈지 모르는데 요약부터 만들 수는 없다.**

준비물은 두 가지다.

- **사업 목표**: 우선순위가 있고 측정 가능한 목표
- **사용자 작업**: 조사로 확인한, 우선순위가 있는 사용자 작업 (상위 작업 조사 등)

## 핵심 모델 워크숍

웹을 잘 모르는 담당자도 전략에 참여시키는 장치다. 디자인·개발 능력은 필요 없다. 각자 자기 분야를 잘 알면 된다.

| 항목 | 내용 |
| --- | --- |
| 시간 | 워크숍당 3~4시간 |
| 참석자 | 제작팀 1~3명 + 고객사 관계자 6~14명. 콘텐츠를 관리할 사람, 사이트에 강한 의견이 있는 사람, 협업해야 하지만 아직 참여하지 않은 사람을 꼭 부른다 |
| 준비물 | 사용자 작업·사업 목표 요약 출력물, A3 작업지, 포스트잇, 마커 |
| 진행 | 둘씩 짝지어 작업지를 채우고, 단계마다 다른 조에 발표한다 |

### 다섯 단계 (노르웨이 암 협회 "폐암" 페이지 예)

| 단계 | 질문 | 예시 |
| --- | --- | --- |
| 1. 핵심 파악 | 이 페이지의 사업 목표와 사용자 작업은? | 목표: 환자와 가족을 돕는다, 예방 정보를 알린다 / 작업: 증상 구분, 예방법, 치료 정보 |
| 2. 유입 경로 | 사람들은 어떻게 여기 도착하나? | 구글에서 "폐암"·증상 검색, 메인 링크, 팸플릿 |
| 3. 핵심 콘텐츠 | 양쪽을 만족시키려면 무엇이 어떤 순서로 있어야 하나? | 조사 결과 예방법 수요가 가장 커서 예방법을 넣었다 |
| 4. 이동 경로 | 궁금증을 푼 사람을 어디로 보내나? | 암 상담 서비스, 일반 예방법, 환자의 권리, 협회 활동 |
| 5. 모바일 우선순위 | 좁은 화면에서는 어떤 순서인가? | 좁은 칸의 새 종이에 요소를 다시 배치한다 |

4번 이동 경로(forward path)가 성패를 가른다. 맥락에 맞아야 한다. 피부암이 아닐까 두려워 찾아온 사람에게 "기부하세요!"를 내미는 것은 무례하고 효과도 없다. 암 연구 정보를 찾으러 온 사람에게는 "연구가 중요하다고 생각하면 후원으로 도울 수 있다"가 자연스럽다.

### 와이어프레임보다 핵심 스케치

와이어프레임은 요소가 **어디에** 들어가는지 보여 주지만 **왜** 들어가는지는 보여 주지 않는다. 워크숍에서 나온 핵심 스케치는 이유까지 담고 있어서 콘텐츠 전략가, UX 디자이너, 그래픽 디자이너, 개발자 모두가 같은 근거로 일할 수 있다. 이후에는 진짜 콘텐츠를 넣은 HTML·CSS 프로토타입으로 넘어간다.

## 결과 (노르웨이 암 협회, 글 작성 시점)

- 검색 최적화를 따로 하지 않았는데 순방문자가 해마다 늘었다.
- 이동 경로로 연결한 암 상담 건수가 이전 7년 대비 최대 40% 늘었다. 기초 정보는 사이트에서 해결되니 상담 내용은 더 깊어졌다.
- 후원 배너를 없애고 메뉴 하나만 남겼는데 온라인 기부는 크게 늘었다(지속적인 기부 페이지 개선의 효과도 함께였다).
- 일부 신청 페이지는 모바일 전환율이 PC보다 높았다.

## 정리

- 콘텐츠는 **목적**을 말할 수 있어야 전략이다. 창의적인 것과 전략적인 것은 다르다.
- 기본 콘텐츠를 만든 뒤 "독자가 다음에 궁금해할 것"을 예측하는 일이 가장 중요하다.
- 사이트는 메인 페이지가 아니라 **사업 목표와 사용자 작업이 겹치는 핵심 페이지**부터 만든다. 메인은 맨 마지막이다.
- 핵심 모델 워크숍은 유입 경로 → 핵심 콘텐츠 → 이동 경로 → 모바일 우선순위로 진행하고, 이동 경로는 맥락에 맞춘다.
- 메뉴를 두고 싸우는 대신 사용자 작업에 집중하면 팀의 대화가 바뀐다.
