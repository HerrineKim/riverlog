> 고려사이버대학교 「UI/UX 디자인」(2024-2학기) 강의 내용을 바탕으로 정리했다.

## UX 시나리오란

**UX 시나리오**는 서비스를 만들기 전에 사용자가 그 서비스를 쓰는 과정을 이야기로 먼저 그려 보는 방법이다. 사용자가 처한 환경과 문제, 그리고 서비스가 그 문제를 어떻게 풀어 주는지를 순서대로 적는다.

기능 목록만 보면 "있으면 좋은 기능"이 끝없이 늘어난다. 이야기로 그리면 **어떤 순간에 무엇이 가장 가치 있는지**가 드러나고, 없어도 되는 기능도 보인다.

| 쓰임 | 어떻게 |
| --- | --- |
| UI 설계의 근거 | 사용자와 상황이 구체적이라 정보 구조, 화면 흐름, 상호작용을 정할 때 기준이 된다 |
| 경쟁 비교 | 같은 시나리오를 경쟁 서비스로 따라가 보면 단계별 강점과 빈틈이 보인다 |
| 팀 커뮤니케이션 | 기획·디자인·개발이 결과물을 같은 장면으로 상상한다 |
| 검증 | 완성된 화면으로 시나리오를 끝까지 따라갈 수 있는지 확인한다 |

### 시나리오에 들어갈 것

| 항목 | 정의할 내용 |
| --- | --- |
| 사용자 | 성격, 선호, 생활 방식, 직업, 가치관, 태도 |
| 니즈와 문제 | 이 서비스가 풀어 주려는 핵심 필요 |
| 사용 맥락 | 언제, 어디서, 어떤 일이 계기가 되어 쓰나. 쓰기 전후에 무슨 일이 있나 |
| 핵심 기능 | 사용자가 실제로 쓰게 될 기능 |
| 과업 흐름 | 목표 하나를 이루기까지 거치는 경로 |
| 사용자 가치 | 이 서비스를 쓰는 가장 큰 이유, 어느 정도면 만족하나 |

경험은 동기에서 시작해 행동을 낳고, 행동의 결과를 기대와 비교해 평가하고, 그 평가가 기억과 태도로 남는다. 시나리오는 이 흐름 전체를 따라간다.

## 페르소나

**페르소나**는 사용자 리서치에서 찾은 사용자 유형을 한 명의 가상 인물로 구체화한 것이다. 이름, 나이, 직업, 생활 방식, 목표, 불편을 가진 "그 사람"을 만들어 두고, 그 사람이 서비스를 어떻게 쓸지를 시나리오로 쓴다(페르소나 시나리오).

### 왜 쓰나

- 수많은 사용자의 동기, 욕구, 행동 패턴을 한 장으로 요약한다.
- 회의에서 "사용자는 이렇게 생각할 거예요"라는 각자의 짐작 대신 "민지라면 이 버튼을 찾을까?"로 대화한다.
- 사용자의 기술 수준에 대한 부서 간 시각차를 좁힌다. 개발자는 사용자를 과대평가하고 영업은 과소평가하기 쉽다.
- 막연한 "모든 사용자"가 아니라 특정한 사람을 위해 디자인한다는 감각을 준다.

### 페르소나 카드에 쓸 것

| 영역 | 예 |
| --- | --- |
| 기본 정보 | 이름, 연령대, 직업, 거주지, 가족 |
| 생활 방식 | 여가를 어떻게 보내나, 어디에 돈을 쓰나, 정보를 어디서 얻나 |
| 디지털 습관 | 주로 쓰는 앱, SNS 활동 정도, 새 기술에 대한 태도 |
| 목표(Goal) | 이루고 싶은 것 |
| 니즈(Needs) | 목표를 위해 필요한 것 |
| 불편(Pain point) | 지금 방식에서 막히는 지점 |
| 가치관 | 무엇에서 만족과 행복을 느끼나 |

### 흔한 실수

- **근거 없는 페르소나**: 리서치 없이 회의실에서 만든 인물은 팀의 고정관념을 그럴듯하게 포장할 뿐이다. 인터뷰·관찰에서 반복된 패턴을 근거로 만든다. 리서치 방법은 [[user-research|사용자 리서치]]에 있다.
- **인구통계만 있는 페르소나**: "35세 남성, 서울 거주, 금융사 중간 관리자"만으로는 설계 결정에 쓸 수 없다. 행동, 목표, 불편이 핵심이다.
- **너무 많은 페르소나**: 다섯 명이 넘으면 아무도 기억하지 못한다. 주 페르소나 하나, 부 페르소나 한두 명이면 충분하다.

### 시나리오 쓰기

페르소나 시나리오는 **사용 전, 사용 중, 사용 후**로 나눠 쓴다.

| 단계 | 쓸 것 |
| --- | --- |
| 사용 전 | 지금 상황은 어떤가, 서비스를 알기 전 어떤 정보를 갖고 있나, 무엇이 계기가 되나 |
| 사용 중 | 서비스를 어떻게 쓰나, 어디서 문제가 생길 수 있나, 그 원인은 무엇인가 |
| 사용 후 | 무엇이 달라졌나, 다음에 무엇을 하나 |

짧은 예: *"퇴근길 지하철에서 지민(29, 직장인 3년 차)은 주말에 갈 만한 북카페를 찾는다. 인스타그램에서 저장해 둔 곳은 많지만 다시 찾기가 어렵고, 가 보면 자리가 없던 적이 많다. 앱에서 저장한 카페를 지도로 모아 보고, 오늘 저녁 좌석 혼잡도를 확인한 뒤 독서 모임이 있는 곳을 예약한다. 모임이 끝나면 좋았던 문장을 사진으로 남기고 다음 모임 알림을 켠다."* 이 한 단락에서 저장 목록, 지도 보기, 실시간 혼잡도, 모임 예약, 기록, 알림이라는 기능 후보와 그 우선순위가 나온다.

## 유저 스토리와 구분하기

"유저 스토리"라는 말은 두 맥락에서 쓰인다.

| | UX의 유저 스토리(유저 시나리오) | 애자일의 사용자 스토리 |
| --- | --- | --- |
| 형식 | 장면별 스케치와 매트릭스: 시나리오, 니즈, 사용자 행동, 필요한 기능 | "~로서, ~을 위해, ~을 원한다" 한 문장 + 인수 조건 |
| 목적 | 리서치 결과를 풍부한 이야기로 바꿔 이해관계자에게 전달하고 기능을 도출한다 | 개발 백로그의 작업 단위로 쪼개고 추정한다 |
| 시점 | 기획 초기 | 개발 계획 |

UX 쪽 유저 스토리는 사용자가 어떤 성향이고, 언제 제품을 쓰고, 어떻게 쓰고, 쓰면서 어떤 갈등을 겪고, 그래서 무엇이 필요한지를 순서대로 담는다. 관찰 몇 번으로는 모든 사용자의 경험을 대변할 수 없으니 가상의 이야기로 빈 곳을 채우는 것이다. 장면이 사용자의 동선대로 끊김 없이 이어져야 하고, 단계별 기능이 순서대로 들어 있어야 한다. 애자일 쪽 사용자 스토리는 [[backlog-and-estimation|백로그와 추정]]에 있다.

## UX 전략으로 잇기

시나리오와 페르소나는 **조사 → 분석 → 전략 도출**의 세 단계 중 분석에 해당한다.

| 단계 | 할 일 |
| --- | --- |
| 사용자 조사 | 대상 사용자를 정하고 조사 방법과 질문을 설계해 수행한다 |
| 사용자 분석 | 결과에서 요구와 핵심 이슈를 뽑고, 시나리오를 쓰고, 개발 방향을 세운다 |
| 전략 도출 | 포지셔닝, 차별화, 디자인 방향을 정한다 |

### 포지셔닝: 누구를 먼저

| | 주 사용자 | 부 사용자 |
| --- | --- | --- |
| 뜻 | 경험 설계의 중심이 되는 핵심 그룹 | 추가로 특정한 니즈가 있지만 잘 드러나지 않는 그룹 |
| 디자인 요구 예 | 단순한 인터페이스, 빠른 검색, 얕은 메뉴 깊이 | 콘셉트에 맞는 룩앤필, 공유 기능, 다시 보기 같은 배려 기능 |

주 사용자의 기능적 만족을 먼저 확보하고, 부 사용자의 정서적 만족을 그 위에 더한다.

### 차별화: 세 방향에서 점검

- **비즈니스**: 차별화된 경험을 어떻게 서비스 품질로 연결하고, 경쟁 우위를 어떻게 유지하나. 경험을 계속 개선할 팀은 어떻게 꾸리나.
- **기술**: 실제로 구현할 수 있나. 혁신적이어도 경제성과 쓸모가 있나. 출시 후 확장성, 호환성, 지속 가능성은 어떤가.
- **사용자**: 조사에서 찾은 사용자 가치에 맞는 디자인 원칙을 세우고, 흩어진 문제들을 하나로 정리한다.

### 디자인 방향: 세 영역

| 영역 | 지향 | 피할 것 |
| --- | --- | --- |
| 상호작용 | 한눈에 알 수 있는 조작, 짧은 동선, 즉각적 피드백 | 단계가 많은 입력, 지나친 선택지, 깊은 메뉴 |
| 정보 | 사용자의 멘탈 모델에 맞는 분류, 길잡이 역할을 하는 내비게이션, 뜻이 모호한 아이콘엔 레이블 | 일관성 없는 분류, 예측과 다른 위치의 콘텐츠 |
| 시각 | 단순한 레이아웃, 크기·대비가 충분한 글자, 콘텐츠 목적과 브랜드에 맞는 색 | 복잡한 화면, 이해하기 어려운 아이콘, 조화롭지 않은 배색 |

이 방향은 이후 와이어프레임과 목업([[wireframe-mockup-prototype|와이어프레임, 목업, 프로토타입]])에서 판단 기준이 되고, 완성된 화면은 처음 쓴 시나리오를 그대로 따라가 보는 사용성 테스트([[usability-heuristic-evaluation|사용성 평가]])로 검증한다.

## 정리

- UX 시나리오는 사용자, 맥락, 문제, 기능, 흐름, 가치를 하나의 이야기로 엮어 먼저 그려 보는 것이다.
- 페르소나는 리서치 근거 위에 행동·목표·불편을 중심으로 만들고, 수는 적게 유지한다.
- 시나리오는 사용 전·중·후로 쓰고, 그 문장들에서 기능 후보와 우선순위를 뽑는다.
- UX의 유저 스토리와 애자일의 사용자 스토리는 목적과 형식이 다르다.
- 분석 결과는 주 사용자 포지셔닝, 비즈니스·기술·사용자 차별화, 상호작용·정보·시각의 디자인 방향으로 정리한다.
