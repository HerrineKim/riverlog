## 파운딩 엔지니어란

**파운딩 엔지니어(Founding Engineer)는 회사 초기에 합류해 기술적·문화적 토대를 만드는 엔지니어다.** 공동 창업자는 아니지만 첫 몇 명의 엔지니어로서 이후 모든 것의 기본값을 정한다.

### 맡는 일

| 영역 | 일 |
| --- | --- |
| 기술 | 핵심 아키텍처 설계, 속도와 품질의 균형 |
| 제품 | 고객 대화, 기능 우선순위 결정. 정리된 스펙이 없는 상태에서 일한다 |
| 운영 | 고객 지원, 모니터링·온콜 체계 구축, 장애 대응 |
| 조직 | 채용, 코드 리뷰·배포 같은 문화의 기본값 설정 |
| 사업 | 투자 유치(IR)·영업 자리의 기술 지원 |

### 필요한 역량

- **안정성과 품질을 함께 챙길 실무 경험.** 대규모 시스템을 본 경험이 초기의 잘못된 선택을 줄인다.
- **주인의식.** 일을 자원해서 끝까지 책임진다.
- **모호함을 다루는 판단.** 언제 묻고 언제 합리적으로 가정할지 정하고, 여러 역할 사이를 빠르게 오간다.

### 얻는 것과 치르는 것

| 얻는 것 | 치르는 것 |
| --- | --- |
| 제품·사업 전체를 빠르게 배운다 | 역할이 모호하고 체계가 없어 방향을 스스로 잡아야 한다 |
| 창업, CTO·VPE, 스태프 엔지니어, PM, 투자자 등으로 경로가 넓어진다 | 업무 강도가 높고 장애 대응 긴장이 계속된다 |

## 개발자가 창업할 때의 세 가지 함정

### 1. 기술을 중심에 둔 피벗

기술을 고정하고 시장을 바꾸면 **쌓은 고객 지식을 버리고 새 시장을 처음부터 배운다.** 쓸 곳이 많은 기술일수록 「맞는 시장」을 찾는 피벗이 반복된다. 들인 비용 때문에 기술을 내려놓기는 점점 어려워진다.

→ **한 산업·고객에 머물고 가설을 바꾼다.** 실패해도 고객 이해가 쌓인다.

### 2. 복잡해지는 사업 모델

이해관계자가 하나 늘 때마다(양면 시장에 중개 사업자가 끼는 식) 검증 시간이 크게 는다. 개발자는 사업 모델의 빈틈을 기술 문제로 쪼개 풀려는 경향이 있어 모델이 점점 복잡해진다. 기술 자체는 QR, 블루투스, 직접 입력 같은 값싼 대체재가 있는 경우가 많아 기술 제공만으로는 돈이 되기 어렵다.

→ **복잡한 해법이 명쾌해 보여도, 검증 속도를 떨어뜨리는지 따진다.**

### 3. 린을 알면서도 빠지는 장인 정신

「필요한 만큼」보다 「잘 만들고 싶은」 욕구가 개발 시간을 늘린다. 외부 SaaS가 완벽히 맞지 않는다는 이유로 직접 만들면 실험이 느려지고 유지 비용이 쌓인다.

→ **조금 어긋나도 붙여서 빨리 실험할 수 있으면 그쪽을 택한다.** 개발 범위를 사업 필요에 맞게 깎아 주는 제품 관리 역할이 필요하다.

이런 습관은 방법론을 알아도 무의식중에 결정에 스며든다. 선배 창업가나 비슷한 단계의 창업가에게 **정기적으로 결정을 점검받는다.**

## 첫 제품에서 지킬 원칙

| 원칙 | 내용 |
| --- | --- |
| **작게 시작해 한 바퀴 돈다** | 첫 제품은 실패할 확률이 높다. 큰 투자 없이 기획→출시→운영 전체를 경험한다 |
| **출시는 시작점이다** | 만들기 전에는 알 수 없던 정보가 출시 뒤에 나온다 |
| **시장 크기보다 차별점** | 큰 시장이라도 경쟁이 많고 뾰족한 강점이 없으면 성과가 없다 |
| **지표가 돈으로 이어지는지** | 다운로드·트래픽보다 유료 전환과 실사용을 본다 |
| **ROI를 먼저 계산한다** | 기능 추가나 기술 고도화 전에 예상 효과와 드는 시간을 비교한다 |
| **매몰비용에 묶이지 않는다** | 중단·전환 기준을 미리 정해 둔다 |
| **단가와 응대 부담** | 싼 상품을 많은 고객에게 파는 것보다 비싼 상품을 적은 고객에게 파는 쪽이 운영이 가벼울 수 있다 |
| **짧게 여러 번** | 성공 확률이 낮다는 전제에서 작은 제품을 자주 내 학습 횟수를 늘린다 |

## 정리

- 초기 스타트업 엔지니어는 코드 밖의 일(고객, 운영, 채용)까지 맡는다. 모호함을 다루는 판단이 핵심 역량이다.
- 개발자 창업자는 **기술 중심 피벗, 복잡한 모델, 과한 완성도**를 경계한다.
- 고객과 산업은 고정하고 가설을 바꾼다.
- 작은 제품을 빨리 내고, 지표가 실제 수익으로 이어지는지 본다.
