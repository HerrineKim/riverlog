## 미국 채용의 특징

미국 개발자 채용은 경력과 관계없이 **레주메와 LinkedIn 프로필 두 가지**를 중심으로 돌아간다. 회사별 지원서 양식이나 경력기술서를 따로 쓰는 경우가 드물다. 리크루터가 LinkedIn에서 먼저 연락하는 일도 많으므로, 레주메를 먼저 다듬고 그 내용으로 LinkedIn을 채운다.

결과는 내 역량만으로 정해지지 않는다. 회사는 지원자 여럿을 **병렬로 비교**하므로, 면접을 잘 봐도 조금 더 나은 사람이 있으면 떨어진다. 운이 크게 작용한다는 사실을 알면 구직 기간의 마음 관리가 쉬워진다.

## 채용 10단계

| 단계 | 하는 일 |
| --- | --- |
| 1. 레주메·LinkedIn 준비 | 레주메를 먼저 완성하고 LinkedIn에 옮긴다 |
| 2. 지원 | 우선순위가 **낮은** 회사부터 지원해 면접 경험을 쌓는다 |
| 3. Recruiter Call | 15~30분 통화(Phone Screen). Knockout 질문으로 필수 요건을 거른다 |
| 4. OA (Online Assessment) | LeetCode형 코딩 테스트, 미니 과제, 페어 프로그래밍, LLD 테스트 등. 없는 회사도 있다 |
| 5. Hiring Manager 인터뷰 | 경력·기술 적합성 확인. 보통 1시간 이내 |
| 6. Live Coding | Final Round(On-site, Full Loop)의 일부. 알고리즘·자료구조 |
| 7. System Design | 경력이 많을수록 비중이 커진다. 주니어는 Live Coding으로 대체되기도 한다 |
| 8. Behavioral | Culture Fit 평가. HM·팀원 인터뷰로 대체되기도 한다 |
| 9. 오퍼 협상 | 연봉·주식·시작일 협상. **오퍼 2개 이상**이 있어야 협상력이 생긴다. 레퍼런스 체크가 이 즈음 있다 |
| 10. 최종 선택 | 오퍼 레터 서명 후 백그라운드 체크. 해고가 많은 시기엔 서명 뒤에도 취소될 수 있다 |

4단계까지는 「이 사람에게 면접관들의 시간을 쓸 가치가 있나」를 거르는 과정이다. HM이 엔지니어링 매니저 업무를 병행하므로 OA로 기본기를 먼저 확인한다.

## 지원 경로 네 가지

| 경로 | 흐름 | 서류 통과 가능성 |
| --- | --- | --- |
| Referral | 재직자에게 공고 번호·URL 전달 → 재직자가 추천 시스템(주로 ATS)에 등록 | **가장 높다** |
| Outbound | 리크루터·소서가 LinkedIn DM·메일로 먼저 연락 → Recruiter Call | 높다. 이미 프로필을 보고 연락한 것이다 |
| Platform | 채용 플랫폼에 프로필 등록 → 공고 추천·회사 매칭 | 플랫폼마다 다르다 |
| Inbound | 공고에 직접 지원 → ATS 필터 → 리크루터 검토 | 가장 낮다 |

- Referral은 회사마다 조건이 있다. 전 직장 동료만 가능하거나, 최근 1년 안에 떨어진 지원자는 막는 식이다. 추천을 받아도 Recruiter Call부터 다시 시작하는 경우가 많다.
- Outbound로 연락이 와도 레주메 PDF를 따로 달라고 한다. HM 보고, ATS 등록, LinkedIn에 없는 정보 확인에 쓰기 때문이다.
- 개발자가 많이 쓰는 플랫폼은 LinkedIn Jobs, Welcome to the Jungle(옛 Otta), Indeed, Wellfound다. 학생·인턴은 Handshake를 쓴다.
- 어떤 경로든 불합격 통보 없이 연락이 끊기는 고스팅(Ghosting)이 흔하다.

## 누가 평가하나

| 역할 | 하는 일 | 대하는 법 |
| --- | --- | --- |
| Sourcer | LinkedIn에서 Outbound 후보를 찾아 파이프라인에 넣는다. 목표 숫자가 있다 | 큰 회사에만 따로 있다 |
| Inbound Sourcer | 공고 지원자를 1차로 거른다 | 지원자가 수천 명인 회사에 있다 |
| Recruiter | 지원자와 회사 사이 소통을 주도하고 HM에게 후보를 넘긴다 | **면접관으로 대한다.** 경력을 자신 있게 어필하고 회사에 대한 관심을 보여 준다 |
| Hiring Manager | JD를 쓰고 프로세스를 정하고 채용을 결정한다 | 가장 큰 결정권자다 |
| Interviewer | 레주메를 읽고 질문을 준비한다 | Live Coding 외 면접은 레주메 기반 질문을 예상한다 |

리크루터가 HM에게 넘기지 않으면 아무리 뛰어나도 면접 기회가 없다. 시간 약속을 지키고 끝까지 존중하는 태도를 유지한다. 리크루터가 정규직인지, 계약직인지, 에이전시 소속인지 LinkedIn에서 미리 보면 질문 방향을 정하기 쉽다.

## ATS(Applicant Tracking System)

ATS는 지원자를 관리하는 소프트웨어다. Greenhouse, Lever, Workday, iCIMS, Ashby 등이 널리 쓰인다.

| 기능 | 지원자에게 미치는 영향 |
| --- | --- |
| Resume Parsing | 파일에서 이름·지역·현 직무·학력을 뽑아 목록으로 보여 준다. **파싱이 깨지면 읽히지도 않고 버려진다** |
| Knockout 질문 필터 | CS 학위, 비자 스폰서십 필요 여부, 거주지, 희망 연봉, 근무 형태 같은 질문 답으로 점수를 매기거나 거른다 |
| Hiring Pipeline | 지원자를 Tier·Rank로 나눠 단계별로 관리한다 |

**ATS가 레주메를 직접 평가해 떨어뜨린다는 것은 오해다.** ATS는 파싱하고, 사용자가 정한 조건대로 분류할 뿐이다. 사람이 모든 레주메를 볼 수 없으니 조건 미달자는 열어 보지 않고 떨어진다. 그래서 할 일은 둘이다. 파싱이 잘되는 단순한 서식을 쓰고, Knockout 질문에 정확히 답한다.

## 레주메는 7초 안에 분류된다

평가자는 레주메 하나를 평균 7.4초 훑는다. 이 짧은 시간에 먼저 보는 정보는 넷이다.

```text
경력 연차 → 기술 스택 → 회사와 직함 → 현재 거주 지역
```

목적은 버릴 레주메를 빠르게 고르는 것이다. 완벽한 사람을 찾기보다 탈락 이유를 먼저 찾는 편이 효율적이어서, 적합한 사람을 잘못 떨어뜨리는 일(False Negative)도 감수한다. 남은 레주메는 다시 시간을 들여 Work Experience를 읽는다.

| 더미(Pile) | 처리 |
| --- | --- |
| No | 대부분이 여기 들어가고 다시 보지 않는다 |
| Maybe | Yes가 모자랄 때만 본다. Yes가 5명쯤 차면 더 보지 않는다 |
| Yes | 보통 5명 이하로 유지하고 다음 단계로 보낸다 |

### 공고가 뜨면 바로 지원한다

많은 회사가 Yes 더미를 **배치(Batch)** 로 처리한다. 예를 들어 매주 월요일 Yes 중 5명을 다음 단계로 보낸다. 앞 배치에서 합격자가 나오면 뒤 배치는 역량과 무관하게 기회를 잃는다. 배치 간격은 보통 일주일이고 최종 결과는 3주 안에 나오는 경우가 많으므로, **처음 세 배치 안에** 들어가도록 공고를 보자마자 지원한다.

면접을 잘 봤는데 떨어졌다면 앞 배치에서 이미 합격자가 정해졌을 수 있다. 결과가 오래 안 나오면 여러 배치를 비교하는 중일 수 있다.

## 레퍼런스 체크와 백그라운드 체크

| 구분 | 시점 | 확인하는 것 |
| --- | --- | --- |
| 레퍼런스 체크 | 오퍼 전후, 채용 진행 중 | 전 동료·매니저에게 성과, 태도, 소통 능력을 묻는다 |
| 백그라운드 체크 | 최종 합격 후 | 전문 업체가 학력·경력·자격증·범죄 경력의 진위를 확인한다. 한국 학력·경력도 현지 학교·회사에 직접 확인한다 |

그래서 레주메의 학위명·재직 기간은 **정확하게** 쓴다.

## 정리

- 미국 채용은 레주메와 LinkedIn이 전부다. 레주메를 먼저 완성한다.
- 서류 통과 가능성은 Referral > Outbound > Inbound 순이다.
- 리크루터도 면접관이다.
- ATS는 거르는 도구이지 평가자가 아니다. 파싱되는 서식과 Knockout 답이 관건이다.
- 레주메는 7초 안에 분류되고, 배치 때문에 일찍 지원할수록 유리하다.
