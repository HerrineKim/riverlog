## Code Review Rules

This repository is a personal knowledge base of Korean study notes (`content/knowledge/**/*.md`). When reviewing notes, check **factual accuracy**, not style:

- API names, parameters, tool/model identifiers, version numbers, CLI flags, config keys and default values must match the current official documentation.
- Claims about how a library, framework, protocol or service behaves must be correct. Flag statements that are wrong or outdated as of the review date, and cite the official source.
- Numbers, dates, complexity bounds, formulas and code samples must be correct; code samples should run as written.
- Do not flag wording, tone, Korean grammar, formatting, summarization choices, or opinions clearly marked as the author's.
- Report every concrete factual error you find, including minor ones, as an inline comment on the line.
- Write all review comments in English.
